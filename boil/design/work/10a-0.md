# 10a rung 0: the root phase's baseline counters

Status: work doc, 2026-10-27. Specification: note 11 sections 9, 10 (rung
0) and 12, and question 13.6. Baseline: c2ab4382dea, whose C code is
ac59664de47's (the commits since touch only boil/); it is the merged
predecessor of 10a's first rung, as note 11 section 9 requires.

## What changes

1. **Root-phase counters**, kept by the live mark and summed per
   interpreter. A struct `_PyGCRootStats` (pycore_gc_trace.h) holds, per
   collection and in total:
   - `collections`;
   - words scanned and words that hit an object, per class: `stack` (the C
     stack of every thread, the collecting one from its entry capture,
     kept threads included), `regs` (the captured register arrays),
     `mem` (PyMem blocks the conservative scans queued, transitively),
     `shallow` (blocks of objects marked without traversal), `data` (the
     writable segments), `structs` (thread and interpreter structs and
     the data stacks, `_PyGC_TRACE_ROOT_STRUCTS`);
   - `eval_words_skipped`, the words of eval-loop activations the stack
     scan excluded, and `activations_skipped`;
   - `threads`, the stacks scanned;
   - times in nanoseconds of the precise roots, the stack phase (stacks,
     registers and the PyMem blocks they lead to), the data segments and
     the structs, each including the transitive marking its roots cause,
     and of the whole root phase;
   - `frames_walked`, `cache_hits`, `cache_misses`, `cache_flushes`,
     `fallbacks`: zero until rung 1's walk fills them, present now so that
     before and after have one schema.
   Words are counted where the live mark reads them
   (`live_scan_words()`), after the clipping to readable memory and the
   skips, by a class the caller sets. The queue of blocks to scan carries
   each block's class (mem or shallow) with it, and `scan_queued()` sets it
   when it scans the block, so a hit inside a queued block is charged to
   that block's class and nothing is counted at enqueue. A hit is every
   word for which `live_lookup()` returns an object, already marked or
   not. The cost is one add per scanned range and one per hit. Neither the
   verifier of step 4 nor the diagnostic mark of `gc_live_roots_of()` is
   counted. `collections` counts marks that completed: a collection
   request that runs two passes counts two, and a mark that fails for
   memory counts nothing.
2. **Access.** `_PyGC_LiveGetRootStats(interp, &total, &last)`
   (gc_live.c, which accumulates each mark's struct from
   `_PyGCMarkResult`, charged once to the interpreter that ran the mark),
   and `_testinternalcapi.gc_root_stats()` returning
   `{"total": {...}, "last": {...}}`, both copied before the dicts are
   built.
3. **The suite sum.** `PYTHON_GCROOTSTATS=path`: at `_PyGC_Fini()` of
   every interpreter, main and subinterpreters, its totals are appended
   to `path` as one JSON line with the pid and the interpreter id. The
   counters remember the pid they were counted in: a forked child starts
   from zero at its first collection and writes nothing if it never
   collects, so a parent's counts are never counted twice. Not counted:
   processes that clear the environment, and processes that exit without
   finalizing (`os._exit()`, a crash, a kill at timeout); the number of
   lines is recorded beside the sum. `boil/tools/measure/root_stats.py
   run OUT -- CMD` runs a command with the variable set and sums the
   lines. The variable is a measurement switch like
   `PYTHON_GCVERIFY_LOG`, read with `getenv()` at the dump, not a
   configuration option.
   **The benchmark samples** bypass boil/bench/run.py, whose children run
   without any `PYTHON*` variable: each is one process,
   `PYTHONHASHSEED=0 python -S -X pycache_prefix=DIR
   boil/bench/internal/driver.py run boil/bench/internal/memory/collector.py
   1 1 MB` for MB in 16, 128, 512, under `root_stats.py run`. The sample
   is the whole process: start-up, the benchmark's setup (which builds
   the live heap), one loop, and the shutdown collections. The phase times
   include the transitive marking their roots cause, so they depend on the
   order of the phases (precise first); they compare like with like across
   the step, not as the cost of each class alone.
   **Pauses.** The pause distribution of section 9 (median, p99, max) is
   taken on the same runs from `gc.callbacks`' `duration`, which an
   inline collection (no Python) does not report; the count of those is
   recorded beside it.
4. **c_roots** committed as `boil/tools/measure/c_roots.py`: the
   token-level probe of note 11 section 12, rewritten from its
   description (the probe was not committed): per function in Objects/,
   Python/, Modules/ (without vendored libraries and clinic output) and
   Parser/, does an object-typed local or parameter (`PyObject *`,
   `Py*Object *`, `PyValue`) appear before and after a call that is not in
   a small non-collecting list. Output: the table of section 12 and the
   largest files. Its numbers are recorded beside note 11's; a difference
   is reported, not tuned away. The non-collecting list is explicit and
   commented: type predicates, sizes, raw data accessors, stores,
   reference-count macros, assertions and libc helpers. Item and cell
   reads (`PyTuple_GET_ITEM`, `PyList_GET_ITEM`, `PyCell_GET`) are not on
   it, since they box inline values. `--self-test` checks the
   classification on twelve fixtures.
5. **The ASan build tried** (13.6), configured as note 11 section 8.3
   needs it: `build/asan`, `--with-address-sanitizer --with-pydebug
   CC=gcc`; mimalloc selected as the default allocator under ASan
   (obmalloc.c chose libc malloc there, which the collector cannot walk);
   `MI_TRACK_ASAN` (pycore_mimalloc.h), so freed blocks are poisoned;
   `_Py_NO_SANITIZE_ADDRESS` on the functions that read words
   conservatively (`scan_range()`, `live_scan_words()`) and the free-list
   check that reads freed blocks; `ASAN_OPTIONS=detect_leaks=0:
   detect_stack_use_after_return=0`, since a fake stack frame is memory
   the stack scan never reads. Then `python -c pass` and test_gc. If it
   fails, the reason is recorded here and 13.6's recommendation applies;
   the changes stay only if the build works.
6. **The counters' cost**, measured now: instructions and time of the
   three collector runs on this rung's build against c2ab4382dea's
   (`.worktrees/boil-10a-base`, a detached worktree removed at the step's
   end).

Nothing in the files 6c is editing is touched: the counters are in
Python/gc_trace.c, Python/gc_live.c, pycore_gc_trace.h and
Modules/_testinternalcapi.c.

## Ladder

`python -c pass`; `_testinternalcapi.gc_root_stats()` after `gc.collect()`
has nonzero stack and data words and a time; test_gc's
`test_root_stats` (schema, movement, hits at most words, total at least
last, a diagnostic mark not counted) and `test_root_stats_dump` (a line
per finalized interpreter, a subinterpreter's own line, a forked child's
own counts); collector_live16, then 128 and 512, through the driver with
the variable set; the suite sum on build/default. Gate 0 and gate 1
(test_gc, test_capi, test_internal) before the commit; gates 2 and 3
before the rung is called done.

## Risks

- The counters add work to the scan loop: one add per range and one per
  hit. Their cost is measured now (item 6).
- A dump at fini that fails to open its file is ignored silently: the
  variable is for measurement and must not change a test's outcome.
- Counting the suite through an inherited variable undercounts
  environment-clearing subprocesses; recorded, not corrected.

## Review

boil/design/work/reviews/10a-0-review.md, verdict revise. Each blocking
issue was taken as a change before the code was committed:

1. *The suite sum omits subinterpreters; forked children double count.*
   Every interpreter writes its own line with its id; a mark is charged
   once, to the interpreter that ran it; the counters remember their pid,
   so a forked child starts from zero and writes nothing if it never
   collects; the omissions (environment clearing, exit without
   finalizing) are listed (item 3). `test_root_stats_dump` covers a
   subinterpreter and a forked child.
2. *Queued scans lose their class.* The queue carries the class of each
   block; words are counted where read, after clipping, never at
   enqueue; a hit is every successful lookup (item 1).
3. *The bench runner strips the switch.* The samples run the driver
   directly, with the exact command, and the sample boundary is the
   whole process (item 3).
4. *The ASan trial did not configure the collector.* It is configured as
   section 8.3 needs (item 5), which the first attempt showed was
   necessary: with libc malloc under ASan, the first `PyObject_Realloc`
   of an object crashed in `gc_block_object()`.

Non-blocking, taken: the probe's list no longer exempts item and cell
reads, which box, and has fixtures (item 4); the tests check hits at most
words, total at least last, and that a diagnostic mark is not counted;
the counters' cost is measured now (item 6); the gate ladder is the
process's. Questions: `collections` counts completed marks (item 1); the
pause distribution comes from `gc.callbacks` (item 3); the sample
boundary is the whole process (item 3).
