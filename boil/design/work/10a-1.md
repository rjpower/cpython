## 1. root_check's C mode (one day, note 11 question 10)

**Where.** `Tools/cases_generator/root_check_c.py`, sharing `lexer.py`; a
CLI (`root_check_c.py [--function NAME] FILE...`) that checks every
function in FILE marked `Py_GC_PRECISE` (or the named one), and a
`check_source(text) -> list[Error]` entry for tests. Tests in
`Lib/test/test_generated_cases.py`, class `TestRootCheckC`.

**Parse.** Unexpanded source, as root_check reads handlers: macros are
names, classified by tables (below). A recursive-descent parser over the
lexer's tokens builds statements (declarations, expression statements,
blocks, `if`, `while`, `do`, `for`, `switch` with `case` and `default`,
`break`, `continue`, `return`, `goto`, labels) and a small expression tree
(calls, assignments, `.` and `->`, indexing, unary `&` and `*`, casts,
`?:`, the binary operators). Preprocessor conditionals inside a body are
both branches (an unknown condition). Rejected, with an error naming the
construct: computed `goto`, `setjmp`, statement expressions, `asm`, the
address of an object-typed local passed anywhere except the listed
out-parameter forms (`PyDict_Next`'s key and value, borrowed from the
dict, which anchors nothing across a reentrant call), and a struct local
other than the span type that has object pointers (known struct types
only; an unknown struct type is rejected if a field of it is used as an
object), an object value stored into a local, field or array that is not
object-typed (a cast of an object to `void *`, `uintptr_t` or another
integer hides it; a cast as a call argument is the callee's), and the
address or any non-call use of a `Py_GC_ARGS_ANCHORED` function. Object
out-parameters are rejected: `PyDict_Next()` and `_PyDict_Next()` box
inline keys and values into them, and a box is fresh, not a borrow; a
precise function iterates with `_PyDict_NextValue()`, whose `PyValue`
out-parameters are borrows of the dict's entries (a strong, mutable
field). A rejected function cannot be marked precise.

**Types.** Object-typed: `PyObject *`, `Py*Object *` (one level), and
`PyValue` by value. A `PyValue *` is a slot pointer only by provenance:
assigned from `frame->base`, `_PyFrame_GetLocalsArray(frame)`, a
parameter declared `Py_GC_SLOTS`, or another slot pointer plus or indexed
by an offset. Return types of calls come from a table built from the
prototypes and definitions in `Include/` and in the file (`PyAPI_FUNC(T)
name(`, `static inline T name(`, and file-level definitions); a call of
unknown return type returns an object if its result is assigned to an
object local or used as one.

**Calls.** Three kinds (2.1, as corrected by question 12):
- *non-collecting*: a reviewed table in the module (type predicates,
  sizes, field accessors and value readers that do not box, stores,
  reference-count macros, `assert`, libc memory and string helpers), and
  any `static inline` function in `Include/` or the file whose body the C
  mode parses and finds calls only non-collecting functions (computed once,
  recursively, cycles counted collecting). Object-returning item and cell
  readers (`PyTuple_GET_ITEM`, `PyList_GET_ITEM`, `PyCell_GET`, the dict
  value getters) are not on it: they box;
- *collecting, not reentrant*: the allocators (analyzer.py's allocating
  calls, `PyLong_From*`, `PyFloat_FromDouble`, `PyTuple_New`, `PyList_New`,
  `_PyTuple_FromValues`, the boxing functions, `PyCell_New`, the boxing
  item readers, `PyMem_*` and `PyObject_Malloc` and their realloc forms),
  a table;
- *reentrant*: every other call, every unknown macro used as a call, and
  `Py_BEGIN_ALLOW_THREADS` (a detach: another thread may run Python and
  collect while this one is detached).

**Sources.** A forward may-analysis over the control-flow graph gives each
object local, parameter and temporary the set of sources its value may
have come from; it is anchored at a safepoint iff every source is
anchored there:
- `const`: `NULL`, `Py_None` and the other statics, `_Py_ID`, `&_Py*`
  objects, numbers: always;
- `fresh`: a call's result, a parameter (unless the function is
  `Py_GC_ARGS_ANCHORED`): never;
- `slot(p)`: a load through a slot pointer `p` (`p[i]`, `*p`): anchored
  until any store through any `PyValue *` (slot pointers alias one
  another: `q = p` makes `q` a slot pointer too), a store through a
  pointer the C mode cannot place, a call that writes memory it is given
  (`memset`, `memcpy`, `memmove`, the `*_SET_*` macros, and every
  collecting call for the slots it is passed), or a reassignment of `p`;
  each turns every `slot(...)` source into `fresh`;
- `span(r)`: the value of a one-value root (`r.value = x`), or a value
  appended to a span by `_PyValueSpan_Append(&r, x)`, which stores at the
  prefix's end and raises `n` in one step. Anchored while `r` is pushed and,
  for the one-value root, until `r.value` is written again. A store into
  a span's buffer by index is not credited, so an element is never counted
  before the prefix covers it;
- `field(b, f)`: a load of field `f` through a local `b`, or through a
  value accessor of `b` (`PyTuple_GET_VALUE(b, i)` is `field(b, items)`).
  A table classifies fields: *immutable* (a tuple's items, a code
  object's `co_*`, a bound method's `im_func` and `im_self`), *strong*
  (traced fields the eval loop and the call layer borrow through: the
  frame's `f_executable`, `f_funcobj`, `f_globals`, `f_builtins`,
  `f_locals`, a function's `func_*`, a type's `tp_mro`, `tp_dict`,
  `tp_bases`, `tp_base`, `ob_type`), *weak* (`wr_object`, and every
  field not in the table). Anchored across a non-reentrant call if strong
  or immutable and `b` is anchored there; across a reentrant call only if
  immutable and `b` is anchored. A store to `b->f`, or a reassignment of
  `b`, turns every `field(b, f)` into `fresh`; since fields alias across
  objects, a store to `f` through any base invalidates `field(*, f)`, and
  the `*_SET_*` macros and `memset`/`memcpy` on an object invalidate its
  item fields. The default for an unknown field is weak: an unlisted field
  never anchors, and the table grows by reviewed entries.

**Liveness.** A backward analysis over the same graph. At a call c in a
statement S, the values to check are those live after S that S does not
assign, those S uses outside c's own arguments (evaluated before or after
c in some order), and every temporary of S that may hold an object while
c runs: the result of a call that is an argument of an enclosing call
together with c, `f(g(), h())`, is a temporary at h (question 11). The
arguments of c itself are c's to anchor, except when c's callee is
`Py_GC_ARGS_ANCHORED`, when each must be anchored; the C mode then also
checks that such a callee is `static` and every call of it is in a
precise function.

**Derived pointers.** A non-object pointer local assigned from an
expression that reads an object (`PyBytes_AS_STRING(o)`,
`PyUnicode_DATA(o)`, `&o->field`, `_PyTuple_ITEMS(o)`) depends on that
object: in liveness, every use of the pointer is a use of its owners, so
the owner must be anchored at every safepoint the pointer is live across
(a buffer pointer kept while its owner is dead is the `PyUnicode_Join`
case of note 08's release barrier).

**Spans.** `_PyThreadState_PushValueRoot()` and the span form (item 2)
open a scope that the matching pop closes. A forward analysis carries the
stack of pushed spans: at every merge the stacks must agree, at a return
it must be empty, a pop must be of the innermost span, and a store into a
span that is not pushed is an error.

**Parameters.** An object parameter used after a collecting call must be
covered by a span on entry, unless the function is `Py_GC_ARGS_ANCHORED`.

**Diagnostics.** `file:line: 'x' is held only in a C local across the
collecting call to 'f' (sources: ...)`, one per variable and call, and
the build fails on any.

**Negative tests** (note 11 section 2.1), each a small function that must
produce the named error: a value held across a call with no span; one
stored into a span after its pop; a span popped on one path and not on a
cleanup `goto`; a `PyValue *` from `PyMem_Malloc` treated as slots; an
anchor overwritten before the use; a list item (`PyList_GET_ITEM`)
borrowed across a reentrant call; a weakref's target borrowed across an
allocation; a parameter used after a collecting call without a span; a
temporary across a sibling argument's call. From the review: a slot
overwritten through an alias; a field overwritten through another base;
a `memset` over the slots; a store into a span's buffer without
`_PyValueSpan_Append`; a buffer pointer used after a collection while its
owner is dead; `PyDict_Next` into object locals; an object cast to
`uintptr_t` and kept; the address of an `Py_GC_ARGS_ANCHORED` function.
**Positive tests**, which must
pass: a value in a span across a reentrant call; a slot load across a
reentrant call with no store; a tuple item across a reentrant call; a
strong field across an allocation; `Py_GC_ARGS_ANCHORED` with anchored
arguments; a parameter covered by a span; a `goto error` cleanup that
pops on every path; a buffer pointer whose owner is in a span. The
inline audit's negative test is item 3's.

**The build.** A stamp rule in Makefile.pre.in
(`Python/gc_precise.stamp`, a prerequisite of the interpreter's link)
runs the C mode over every source file that contains `Py_GC_PRECISE`,
found by `grep -l`, so marking a function that fails the check fails the
build. An integration test runs the CLI over a temporary file with an
unchecked precise function and expects exit status 1 and the error; the
work doc records one run of `make` failing on a deliberately broken
marked function in a scratch copy.

**Ladder.** The parser on every function of Objects/call.c and
Python/ceval_gil.c (parse only, counting rejections); the tests above;
then the C mode over call.c's functions without marking any, to size the
work of rung 2, recorded here.

**Time box.** The day starts when the first line of root_check_c.py is
written, recorded below with `date`. At its end, if a negative test does
not fail, question 10's fallback applies.

## 2. Spans

`_PyValueRoot` gains `PyValue *base` and `Py_ssize_t n` (pycore_structs.h);
`_PyThreadState_PushValueSpan(tstate, root, base)` pushes a span with
`n = 0`, `_PyValueSpan_Append(root, v)` stores `v` at `base[n]` and then
raises `n`, the one way to fill a span, `_PyValueSpan_Rebase(root, base)`
replaces the buffer with one that holds the same prefix, as
`PyMem_Realloc` leaves it (values appended before it stay credited; it is
called before any other collecting call, since until then the root points
at the freed buffer). A one-value root is a span of one over its own
`value`. The span tests of note 11 section 8.4 are rung 2's and 3's, where
spans are used: a raw box of a non-NaN float kept as the same pointer,
NULL entries, a rebase, an allocation failure mid-fill and its cleanup. The thread-state visitor
(`_PyGC_TraceVisitThreadState`) visits `[base, base + n)` of each root.
Debug builds check in the visitor that `n` is not past the buffer when
the buffer is a PyMem block (`mi_usable_size`). The pop keeps its clear
until rung 2 (an opaque frame's popped span is a stale word; the clear
goes with the flag in rung 3).

## 3. The inline audit

`Tools/build/gc_inline_audit.py IMAGE`: reads `readelf --debug-dump=info`
of the linked image (`python` or `libpython`), streaming, and for every
`DW_TAG_subprogram` whose low pc lies in `py_gc_precise` lists its
`DW_TAG_inlined_subroutine` entries by abstract origin. Each must be a
function marked precise, a non-collecting function of the C mode's table,
or a `static inline` function the C mode checked. It fails on a `.cold`
symbol of a precise function, a clone (`.isra`, `.constprop`, `.part`) of
one outside the section, a precise symbol with no DWARF entry, and an
image without `.debug_info`. A make target `check-gc-inline` runs it; the
gated builds carry `-g` already (configure's default `-g` is kept). Tests:
a precise test function in `_testinternalcapi` that inlines an opaque
static helper (built with `__attribute__((always_inline))` so that `-O0`
and `-O3` agree) fails the audit; the same file built without `-g` fails
it. The negative fixtures are compiled by the test itself into a scratch
object (the configured compiler, skipped without one), never into the
interpreter, and the audit runs over that object. In the build, a stamp
rule (`gc_inline.stamp`, a prerequisite of `all`, after the interpreter
is linked) runs the audit over the linked image, about 20 s (readelf
alone takes 2.7 s for the 9.3 M lines of build/default's DWARF). Until 6c
lands the section holds only the walk's test functions.

## 4. The walk (note 11 3.1 to 3.4)

**Where.** `Python/gc_walk.c` and `Include/internal/pycore_gc_walk.h`: the
`.eh_frame` decoder, the descriptor cache, the walk and the frame
classes; `Python/gc_capture.S`: `_PyGC_CaptureCaller()`, x86-64 and
arm64; a C fallback for other platforms (no walk, full conservative scan).
Makefile.pre.in and configure gain the `.S` object (`PYTHON_OBJS`).

**Decoding.** `_dl_find_object()` gives the object's `.eh_frame_hdr`; a
binary search of its table gives the FDE; the CIE's augmentation
(`z`, `R`, `P`, `L`, `S`) and pointer encodings are decoded; the CFA
program is interpreted to the lookup pc (`ra - 1`) with the row
instructions `advance_loc*`, `def_cfa*`, `offset*`, `restore*`,
`same_value`, `undefined`, `register`, `remember_state`, `restore_state`,
`GNU_args_size`, `nop`. An expression rule, a `val_*` rule, `S` and an
unknown opcode give no descriptor. The descriptor is copied into the cache
(per interpreter, open addressing keyed by lookup pc, flushed when
`dl_iterate_phdr()`'s `dlpi_subs` changes).

**Classes.** By the pc: in `[__start_py_gc_precise, __stop_py_gc_precise)`
of the interpreter's image: precise; in a registered range (the JIT range
table, process-wide under a mutex, which tests also register into):
its registered class; otherwise core opaque if in the interpreter's image
(found once with `_dl_find_object()` on a core function), else extension
opaque. **Until the eval loop is marked** (rung 1b), a frame whose extent
lies inside a recorded `_PyEvalActivation` range is classified precise,
except on the collecting thread of an inline collection
(`scan_activations`), where it is opaque: today's semantics, with the
saves its callees made of its registers now owned by it. That transitional
rule is deleted with the activations in rung 1b.

**Ownership and scanning** as 3.1: each word of `[sp, stack base)` has one
owner; a word is scanned iff its owner is opaque; pending locations per
callee-saved register; the convention clause for "preserves nothing"
frames (registered tier 0 ranges; the tail-call handlers once marked).
Opaque frames' words are scanned with PyMem blocks followed, as today.

**Start contexts** as 3.3. The collecting thread captures at
`collect_from_entry()`, which stays on the stack. A detaching thread, in
`PyEval_SaveThread`, `PyEval_ReleaseThread`, `detach_thread` and the swap
paths (Python/ceval_gil.c, Python/pystate.c), captures and unwinds at once
to the innermost precise frame P and stores P's pc, sp and pending
register values, and the capture's sp and registers; a collection scans
`[capture sp, P's sp)` and the captured registers as one opaque region and
walks from P. No P, or a failed unwind: the whole stack is that region.
This replaces `_PyGC_TraceCaptureThread()`. (Superseded by note 11
question 16 after the measurement under item 4: no unwind at detach; a
pinned record is walked from the capture by the collector, an unpinned one
scanned conservatively.)

P must persist while the thread is detached, and precision alone does not
ensure it: a detach helper that returns while the thread stays detached
must never be P. The detach and swap functions (`PyEval_SaveThread`,
`PyEval_ReleaseThread`, `_PyThreadState_Detach`, `detach_thread`,
`_PyThreadState_Swap`, `PyThreadState_Swap`, `_PyEval_ReleaseLock` and
every function between them and the capture) are on a list in
root_check_c.py that may not be marked precise: the C mode rejects the
mark. They stay opaque, so the unwind passes through them, and a test
checks that marking one fails the check.

**Validation and fallback** as 3.4, with counters (`frames_walked`,
`cache_hits`, `cache_misses`, `cache_flushes`, `fallbacks` of rung 0). A
fallback scans the rest of the stack conservatively; debug builds print
the pc and object once. The suite must record zero fallbacks
(`PYTHON_GCROOTSTATS` sum).

**Tests** (test_gc and `_testinternalcapi`): a chain of compiled C test
functions in `Modules/_testinternalcapi/gc_walk.c`, each keeping a
different callee-saved register live across a callback (`register ...
asm("r12")` locals on x86-64, with a compiler barrier), alternating
precise (registered into the range table) and opaque frames; the walk
must report each opaque value and no precise one
(`_testinternalcapi.gc_walk_owners()`, which returns the owner of each
scanned word); a thread blocked in `Py_BEGIN_ALLOW_THREADS` with an
object only in a callee-saved register; a helper that detaches and
returns before blocking; the swap path in a function built `-O0`
(`__attribute__((optimize("O0")))`); a kept thread state of an exited
thread; a frame built with `-fno-asynchronous-unwind-tables`
(`__attribute__((optimize("no-asynchronous-unwind-tables")))`, or a
separate object if gcc ignores the attribute) that counts a fallback.
The fixtures fix their registers with asm operand constraints on the
values at the callback (a local register variable is only placed at an
asm operand), prevent sibling calls (`noinline`, a use after the call,
`optimize("no-optimize-sibling-calls")`), and the test first checks
their CFI with `readelf --debug-dump=frames` for the saves it relies on.
Expected fallbacks: the fallback fixture counts its own (a counter of
fallbacks whose pc is in a registered test range); the suite gate is zero
fallbacks outside test ranges.

## 6. The data-stack and chain visits (4.3, 4.4), outside 6c's files

`_PyGC_TraceVisitFrames()` visits every frame on the thread's data stack
by header (the chunks from `datastack_limit` to each chunk's end and from
each earlier chunk's saved top), skipping a NULL executable, and then the
chain, so that a running generator frame is visited too. The push in
`_PyThreadState_PushFrame()` stores a NULL executable;
`_PyFrame_Initialize()` (pycore_interpframe.h) already NULLs the slots
past the arguments. The entry frame's visitor (4.3) and the return order
are in ceval.c and bytecodes.c and wait for rung 1b. The struct scan
keeps covering the data stack until rung 3 deletes it.

## 7. The verifier: retain and kill modes

`PYTHON_GCVERIFY=retain|kill`. Each collection marks A, the roots of
note 11 section 1 as far as they are implemented (until rung 1b: today's
roots without the struct scan and without PyMem blocks reached from core
opaque frames; after it, without the words of precise frames too). Then
it marks B on top of A, with the same mark bit, from every word A skips;
every object that B's phase marks is listed (Q) with a side-table record:
the word's address, its owner as image path and offset (symbolized
offline by `addr2line`, since local symbols are not in the dynamic
table), class, collection number. Retain (debug and release builds): Q
stays marked and lives; a later collection that marks a Q object from A
reports a candidate with its record. Kill (debug builds): Q's mark bits
are cleared before the walk of the heaps, so Q dies with the ordinary
semantics. Quarantine intercepts the physical frees where they happen:
`_PyGC_FreeDeadBlock()` of a Q object, and every `PyObject_Free`,
`PyMem_Free` and realloc-free called while a Q object's dealloc or hook
runs (a thread-state field names the Q object being destroyed), append
the block to the quarantine list instead of freeing it, after clearing
its object-map bit. After the sweep, its finalizers and hooks having run,
each quarantined block is filled with the debug pattern and, under ASan,
poisoned; 16 collections later it is unpoisoned and freed. The trap type
(a header whose type's slots abort with the record) needs 6c's header:
it lands with rung 1b; until then a read of a quarantined block is caught
by ASan or by the pattern's crash, and the demonstration's slot-call and
store cases wait for it. The cached-interior-pointer case is
demonstrated under ASan with allocation pressure between the free and the
read.
`_testinternalcapi.gc_verify_missed_root(kind)` is the demonstration of
8.3 (field read, cached interior pointer, slot call, finalizer, list
store, and the weakref counterexample). Until rung 1b, A and B differ only
by the struct scan and PyMem from core frames, so the gate run comes after
promotion; the demonstration and the modes are tested now.

## 8. Injection and stress

`_testinternalcapi.gc_collect_at(site)` arms a one-shot collection at a
named site, checked by `_PyGC_INJECT(tstate, site)` (a load and a compare
of a per-thread field in release builds too, so that the gated builds run
the injection tests). Sites now: the detach capture, inside
`_PyThreadState_PushFrame()` before initialization, a span rebase, inside
`do_mkstack()`; the ceval.c and bytecodes.c sites (inside
`initialize_locals`, return before the store, `take_ownership`, between a
weakref load and its use) come with rung 1b. `PYTHON_GCSTRESS=N`: every
Nth object allocation collects through the inline path
(`_PyGC_LiveCollectHere`). Stress runs at each rung end on note 11's set
at N = 1,000.

## Risks

- The compiler holds its units' dicts and lists (`struct compiler_unit`,
  `u_metadata`) in PyMem across collections, in compile.c, flowgraph.c and
  assemble.c, where only the core frames' transitive PyMem scan keeps them.
  Reproduction: `PYTHON_GCVERIFY=kill:pymem ./build/debug/python -m test
  test_json` crashes at start-up in `dict_keys_inorder()` (assemble.c).
  Ruled (coordinator, 2026-10-27): not fixed in rung 1; the units are rung
  3's first core site, rooted with `_PyGCRoot` or spans (note 11 section
  6.2's inventory).
- A root-finding test must hold the object's address only where the mode
  under test should find it, and nowhere a conservative scan can: the
  first test_detached_register passed with the main thread's registers
  never scanned, because its probe kept the address on the checking
  thread's own stack (the test_socket crash, under Measurements).
- The C mode overruns (question 10): the parser on unexpanded C is the
  likely sink. Mitigation: the subset rejects what it cannot parse; the
  ladder parses real files first.
- The walk's descriptors: gcc's `.eh_frame` for the python binary uses
  only register and offset rules on x86-64 (to be confirmed by a count of
  FDEs with expression rules, recorded here); signal frames and PLT stubs
  are not on a collecting stack.
- The transitional eval-loop classification by activation ranges: a
  frame that straddles `lo` (the entry wrapper's) is opaque, as today.
- Detach cost (question 13.7): measured on a pipe-read loop when item 4
  lands.
- Slot anchors across reentrant calls assume that the callee does not
  write the caller's slots. A debugger writing `frame.f_locals` (PEP 667
  proxies write slots) breaks it for the eval loop as it breaks it for
  root_check's handlers today; recorded, not addressed in 10a.
- The data stack's chunks reserve their final word (pystate.c); the
  visit's bounds are each earlier chunk's `data` to its saved top, and
  `datastack_limit` to the current chunk's end minus that word for the
  frame headers, with a test that pushes frames across a chunk boundary.
- `.eh_frame` of build/default: 8,002 FDEs; the only expression rule
  (`DW_CFA_def_cfa_expression`) is the PLT's, which is never a caller on
  a collecting stack.

## Review

boil/design/work/reviews/10a-1-review.md, verdict revise. Each blocking
issue was taken as a change:

1. *Aliases and mutating helpers.* Any store through any `PyValue *`,
   through an unplaced pointer, or by a mutating helper invalidates every
   slot anchor; a field store through any base invalidates that field's
   borrows; negative tests for each (item 1, Sources).
2. *A span store credited before the prefix covers it.* Spans are filled
   only by `_PyValueSpan_Append`, which stores and grows in one step;
   stores by index are not credited; a negative test (items 1 and 2).
3. *Interior pointers.* Derived pointers depend on their owners in
   liveness; hiding an object in a non-object type is rejected; the
   address of an `Py_GC_ARGS_ANCHORED` function is rejected (item 1).
4. *`PyDict_Next` boxes.* Object out-parameters are rejected; precise
   code uses `_PyDict_NextValue` (item 1, Parse).
5. *The detach boundary.* The detach and swap helpers may never be
   marked precise, enforced by the C mode, so P is always a frame that
   persists (item 4).
6. *Quarantine.* The interception points, the ownership record, the
   object-map removal, the A and B separation and the expiry are named;
   the trap type waits for 6c's header (item 7).
7. *Gates.* Both checks are stamp rules of the build, with the negative
   fixtures compiled apart from the interpreter (items 1 and 3).

Non-blocking, taken: the chunk bounds (Risks); the span tests are placed
in the rungs that use spans (item 2); expected and unexpected fallbacks
are distinguished (item 4); fixtures fix registers by asm constraints and
check their CFI (item 4); owners are image and offset (item 7); the
measurements have commands. Questions: A is the implemented policy as
stated (item 7); the trap type lands with 1b; retain mode runs in release
builds too.
