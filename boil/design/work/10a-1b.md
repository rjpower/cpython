## 1. The return order and the entry frame (4.3, 4.4)

Today `_RETURN_VALUE` reads the result into the C local `temp`. The
operand slot is then cleared (`IR_CONSUME_INPUT`), the frame is unlinked
and `_PyEval_FrameClearAndPop()` runs, and only then does
`IR_STORE_RETURN` store `temp` in the caller. `take_ownership()` can
allocate inside the clear when a frame object exists. A collection there
finds `temp` only in the eval loop's C frame. Today the inline
collection's full scan covers that; after item 5 nothing does.

**The change.** The transferred value is stored in its final destination
before the source frame is unlinked or cleared, in each of four cases:

- *An ordinary return* (`_RETURN_VALUE`, the caller a function frame):
  `_PyFrame_SetReturnValue(caller, temp)`, where `caller` is
  `dying->previous`, before the unlink.
- *A generator's return to `SEND` or `FOR_ITER`*:
  `_PyEval_GeneratorReturnTarget(caller)` runs first. It reads only the
  caller's instruction and sets `caller->return_slot` to the cleanup slot
  past the iterator window for `FOR_ITER`, so the value never lands in
  the loop target. Then the store, then the unlink and the clear. Today
  the target is chosen after the clear. Moving it earlier changes nothing
  else, since it reads no state that the clear changes.
- *A return or yield to the interpreter entry frame* (`gen_send_ex2()`,
  `_PyEval_EvalFrame()` from C): the store goes to `entry.stack[0]`,
  which the visitor below covers until `INTERPRETER_EXIT` returns it.
- *A yield* (`_YIELD_VALUE`) stores in the caller before
  `gen_frame->previous` is cleared. `RETURN_GENERATOR` stores the
  generator object in the caller before `_PyThreadState_PopFrame()`.

**Stack effects and layouts stay.** The ops keep their declared outputs
(`res`, `value`), so `_PyOpcode_num_pushed`, the resume stack effects,
the IR field layouts and the pyc magic do not change. The body stores
early through `IR_RETURN_EARLY(caller, var)`, a macro over
`_PyFrame_SetReturnValue()`. A new annotation, `stores_early`, tells the
IR generator that the body has stored the output, so it emits no
`IR_STORE_RETURN` after the switch. That leaves one runtime store, not
two. The generator rejects a `stores_early` op whose body does not use
`IR_RETURN_EARLY` on every path that reaches the switch, and `returns`
keeps its meaning.

**Tests** for the order, besides the injection tests below:

- a warmed, specialized `for` loop over a generator whose last yielded
  value differs from its return value, with the loop variable checked
  after exhaustion;
- the same through `yield from`;
- a sent value used inside a larger expression (`x = 1 + (yield)`);
- generator and coroutine creation.

Each runs with a collection injected at `_PyGC_SITE_RETURN`.

**The entry frame's visitor.** `_PyGC_TraceVisitFrames()` skips frames
owned by the interpreter. It now visits exactly `entry.stack[0]` of each
`FRAME_OWNED_BY_INTERPRETER` frame on the chain: the slot that a
returning frame writes and `INTERPRETER_EXIT` returns. The entry frame's
other fields are poisoned in debug builds and are not read.

**Push before initialize.** `_PyFrame_Initialize()` sets the slots past
the arguments to NULL. No call between a push (`_PyThreadState_PushFrame`,
`_PyFrame_PushUnchecked`) and the initialize of the pushed frame may
collect. The C mode and root_check check this as an adjacency rule:

- in the C mode, a collecting call between the two on a path is an error;
- in root_check, a handler body that pushes and calls a collecting
  function before `_PyFrame_Initialize` is an error.

Today's code passes. Each check has a negative fixture.

**Injection sites** (`_PyGC_INJECT`, 10a-1.md item 8):

- `_PyGC_SITE_INIT_LOCALS`, in `initialize_locals()` after `*args` and
  `**kwargs` are stored;
- `_PyGC_SITE_RETURN`, in `_RETURN_VALUE` between the early store and the
  clear;
- `_PyGC_SITE_TAKE_OWNERSHIP`, in `take_ownership()` before
  `_PyFrame_GetFrameObject()`.

**Tests** (test_gc, 8.4):

- a collection injected inside `initialize_locals` with `*args` and
  `**kwargs`, each checked after the call;
- a collection injected during a return whose frame has a frame object
  (`sys._getframe()` taken), with the result used afterwards. Both
  builds; also under kill on debug.
- the visitor: a C function that calls back into Python. The callback
  returns a fresh object to the entry frame, and the test collects at
  `_PyGC_SITE_RETURN`.

Negative controls: the eval loop's frame is scanned until item 4 marks it
(the section check precedes the activation override in `frame_class()`),
so the injected cases cannot fail before item 4. At item 4's commit each
of them is run with item 1's change reverted, under kill, and must trap;

## 2. Allocations are safepoints (4.2)

After item 4, an inline collection run by an allocation past the second
threshold scans no eval-loop frame. A handler then must not hold an
unanchored object in a C local across an allocation, including the
allocations the generator itself emits.

- **One table of call effects.** analyzer.py's `NON_ESCAPING_FUNCTIONS`
  and root_check_c.py's `NON_COLLECTING` and `ALLOCATING` describe the
  same property of the same functions in two places. They move to one
  module, `Tools/cases_generator/call_effects.py`, with three sets:
  - non-collecting;
  - allocating (it may collect and runs no Python code);
  - everything else, which is reentrant.

  analyzer.py, root_check.py and root_check_c.py all import it. The
  analyzer's "escaping" stays its own notion (it decides stack syncing)
  and is computed from the table: every call that is not non-collecting
  and not allocating. Each moved entry keeps a reviewed comment.
  - The allocating set includes `PyCell_New`, `PyFloat_FromDouble`,
    `PyLong_FromLong`, `PyLong_FromSsize_t`, `PySlice_New`,
    `_PyTuple_FromValues`, `PyUnicode_Concat`, `_PyUnicode_JoinArray`,
    `PyValue_FromDouble`, `PyValue_Object`, `_PyValue_BoxInline`,
    `_PyValue_ObjectRooted`, `_PyValue_BoxInt64`, `_PyValue_LshiftInt32`,
    and the boxing readers `PyTuple_GET_ITEM` and `PyList_GET_ITEM`
    (question 12).
  - The comment saying boxing "cannot start a collection" is corrected.
- **root_check.py** checks at every collecting call, and `ALLOCATING`
  and its exemption are deleted. One rule is added: a value loaded from a
  frame slot stays anchored across an allocating call until that slot is
  written. A slot is in the frame, so this is a borrow from an anchor
  that a non-reentrant call cannot change. Fields of objects, caches
  included, do not qualify. A borrow out of a traced field keeps
  root_check's existing rules for escaping calls, and the C mode's 2.1
  rules where they apply.
  - `MAKE_CELL` passes by this rule: `initial` is loaded from its slot,
    which is written only after `PyCell_New`.
  - `_ALLOCATE_OBJECT` does not pass. `init_func` comes from
    `_spec_cache.init`, a field `type_traverse()` does not visit, so the
    handler is changed: it stores `callable = PyValue_FromObject(init_func)`
    before `PyType_GenericAlloc(tp, 0)`. The generator's save before a
    collecting call puts it in its slot, which anchors it. `tp` is then
    only an argument of the allocation, which is the callee's to anchor
    (item 3).
  - Negative fixtures: a value loaded from an untraced cache field, and
    one from a slot that is written before the use, each held across an
    allocating call. A runtime test calls a class whose `__init__` is
    inherited, with collections injected by `PYTHON_GCSTRESS=1`, under
    kill.
- **Stack-passed arguments (question 13) in handlers.** A handler passing
  a C local at position 7 or later to a callee that is not precise must
  anchor it. root_check gains the C mode's rule and its error.
- **The generator's own allocations.** `convert_object_inputs()` boxes
  the inline inputs one after another, so the second `_PyValue_BoxInline()`
  can collect the first box. Box k's unlikely branch pushes the value
  roots of boxes 1 to k-1 that are boxes, makes box k, pops them, and on
  failure pops before it jumps to `error`. Roots are declared for every
  uop with two or more boxed inputs or a collecting call.
  - In the body, `emit_box_roots()` pushes the roots across every
    collecting statement, not only the escaping ones.
  - ir_generator.py's `escaping` checks become `collecting`: a value
    without a slot of its own is not live across an allocation, and dst
    takes a result before one only through a temporary.
- **Tests:**
  - in test_generated_cases, a two-box uop's expected output (the push
    around the second box, the pops on both exits);
  - a handler holding a fresh object across `PyLong_FromLong` fails
    root_check;
  - a slot load held across an allocating call passes;
  - a box held across `PyFloat_FromDouble` gets its root pushed;
  - at run time, a generic binary op and a comparison on two inline
    floats under `PYTHON_GCSTRESS=1` and kill, in a child, checking the
    results.

**Size**, measured before the work: with the allocating calls treated as
escaping, an experimental regeneration at d348fd4b198 changed 100 lines
of generated_ir_cases.c.h (box roots around the call handlers' boxed
inputs), and root_check flagged only `MAKE_CELL`. That excludes the
generator's own boxing above.

**The work.**

- *Classification, settled before any call effect is assigned.*
  `_PyObject_Init` and `_PyObject_InitVar` count as reentrant today
  through three calls:
  - `_PyShape_InitRoot` only writes the root shape's fields, so it is
    non-collecting.
  - `_PyObject_CheckObjectHeap` (debug) reads mimalloc's page and
    segment metadata. It is non-collecting once its body checks under the
    C mode.
  - `_Py_NewReference` calls the reference tracer. Its documented
    contract forbids creating Python objects and changing the exception.
    That does not show that a tracer cannot collect, so the contract is
    made enforceable. While a tracer runs, the thread's
    `gc_trace.in_tracer` count is raised; `can_collect()` refuses, and so
    the trigger defers, as it does under the head lock. The tracer is then
    non-collecting by construction. That it does not change existing
    edges is the documented contract ("observational"), which the docs
    state and nothing enforces.
  - A test installs a tracer that allocates past the threshold on each
    event and checks that no collection ran inside it (the collection
    count) and that one runs after.
  - With all three settled, `_PyObject_Init` and `_PyObject_InitVar` are
    non-collecting. No object is published half-built across a
    collection, since none can start between the allocation and the
    header's initialization. Fields that constructors set later are the
    constructor's, under the ordinary rule.
  - `__builtin_return_address` is an intrinsic.
- *Known immediates.* `box_*`'s `v` is asserted inline. The C mode treats
  a `PyValue` under `assert(PyValue_IsInline(v))` as holding no object
  from the assertion on. The assertion vanishes in release builds, but
  the fact does not. Tested both ways.
- *Spans.* `gc_alloc`, `_PyObject_GC_New*` and `_PyType_AllocNoTrack` use
  `tp` after the allocation, and question 11 makes the parameter the
  callee's to anchor. Each pushes a span of `tp`. Since the init is
  non-collecting, the result needs none. This is the one cost added to
  the allocation fast path, and it is measured (section 8).
- *The clinic wrapper.* `gc_collect` in clinic/gcmodule.c.h is generated.
  Where the C mode rejects the parse ("unexpected 'struct' after
  expression", the `_kwtuple` initializer), the C mode learns that
  construct, the static initializer of a local struct with no object
  fields.

## 6. The trap type and the demonstration (8.3)

6c's header points at a shape whose `type` names the type. A quarantined
block's header gets the root shape of `_PyGC_TrapType`, a static type
whose slots (`tp_repr`, `tp_getattro`, `tp_setattro`, `tp_call`,
`tp_hash`, `tp_richcompare`, `tp_traverse`, `tp_dealloc`, `tp_iter`) abort
with the block's side-table record. In debug builds, `Py_TYPE` aborts on
the trap type: `_Py_TYPE_impl()`'s assertion gains the check. The fill
pattern stays on the rest of the block.

`gc_verify_missed_root` gains:

- `slot_call`: the object's `tp_repr` is called after the collection;
- `store`: the object is stored into a list after the collection, and
  the list is repr'd.

Under kill on debug both abort with the record. test_gc checks the
abort, its message and the record's owner in a child, with
`assert_python_failure`. Retain reports the store as a candidate. Under
ASan all five cases trap.

**The record outlives the collection.** `_PyGC_Quarantine()` keeps a
block's address and collection number only, and kill mode keeps no
record list. Each quarantined block now keeps its side-table record
(owner pc and class, word address, collection) in the quarantine entry
until the block is freed 16 collections later. The trap's abort prints
it. A test uses the hidden object after a second, unrelated collection
and checks the record in the abort message.

## Review

boil/design/work/reviews/10a-1b-review.md, verdict revise. Each blocking
issue was taken as a change:

1. *The generator's own boxing is a safepoint.* Box k pushes the roots of
   the earlier boxes around its conversion and pops them on both exits;
   a two-box fixture and a stress test (item 2).
2. *The early store's destination.* The generator return target is chosen
   before the store, so `FOR_ITER`'s loop variable never takes the return
   value; the four cases are specified, with a warmed loop test whose
   last yield differs from the return (item 1).
3. *Stack effects.* The outputs stay declared, so metadata, layouts and
   the magic do not change; `stores_early` and `IR_RETURN_EARLY` replace
   the generated store with the body's (item 1).
4. *`_ALLOCATE_OBJECT`.* Its `init_func` is stored in its slot before the
   allocation; caches never qualify as borrows; a negative fixture
   (item 2).
5. *The allocator's tracer.* A collection cannot start while a reference
