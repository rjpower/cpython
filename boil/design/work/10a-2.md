## 0. The C mode

- *Done (afc23a2239c).* `--function NAME` fails when the file has no such
  function. Before, it exited 0, which read as a clean check. Typedef
  names come from the file and the headers, so a cast to a file-local
  function-pointer typedef parses.
- *0b, call classification.* With reviewed comments in the tables:
  - `va_start`, `va_copy`, `va_arg` and `va_end` are non-collecting;
  - `PyMem_Malloc`, `PyMem_Realloc`, `PyMem_Calloc` and `PyMem_Free` are
    non-collecting, since the mem domain never collects (Objects/obmalloc.c,
    `gc_count_alloc`);
  - `Py_GC_PRECISE` on a variadic definition is an error.
- *0c, header definitions.* The stamp rule's discovery and the inline
  audit's source list include `Include/internal/*.h`. The C mode checks a
  `Py_GC_PRECISE` static inline definition in a header as it checks one
  in a `.c` file. A marked header fixture that fails the C mode fails the
  build's check in a test, before any header helper is marked.
- *0d, boxes.* `PyValue_FromObject(x)` is the canonical value of `x`, an
  immediate for an exact finite float or a small int. Appending it to a
  span anchors the value but not the box `x`. The C mode tracks the two
  apart:
  - `_PyValueSpan_Append(&r, PyValue_FromObject(x))` anchors a value
    local, not the object local `x`;
  - only the raw form, `_PyValueSpan_AppendObject(&r, x)` (new; it stores
    `_PyValue_FromBits((uintptr_t)x)`, the box's pointer), anchors `x`.

  A negative fixture: a float box appended canonically and used as
  `PyObject *` after a collecting call.
- *0e, out-parameters into a span.* `&buf[k]`, where `buf` is a pushed
  span's base and `k` is inside its prefix, may be passed as a
  `PyValue *` out-parameter. The callee's store through it is a store into
  a covered slot. Any other address of an object or value local still
  escapes.
- *0g, rule 4 (step 4).* A pointer declared as `(T *)args - 1`, where
  `args` is a received array, points at a lent slot; so does `args[-1]`.
  A store into the slot is an error unless a pushed span holds the slot's
  value: an append of `p[0]`, or of a local that read it. The restore
  happens before the pop.
- *0f, found in step 2* (with tests in test_generated_cases and
  test_gc_inline_audit):
  - An assignment kills at its call: in `x = f(x)` the old `x` is an
    argument of `f`, and dead once `f` returns. The check held it across.
  - A copy, `kwdict = keywords`, shares its source's anchors; they end
    together.
  - A variable anchored by a store on one path only (a span append) keeps
    that anchor through the join, as a source. The join used to drop it.
  - An alias macro, `#define PyUnstable_Long_IsCompact _PyLong_IsCompact`,
    classifies as its target.
  - Reviewed non-collecting entries: `isnan`, `_Py_get_machine_stack_pointer`
    (an intrinsic or an asm that reads the stack pointer),
    `_PyValue_HIDE_ORIGIN` (an empty asm), and `_PyValue_FromLongObject`
    (an exact int's conversion, which calls no `__index__` and allocates
    nothing).
  - `values_of` is a copy of a received array (`COPIES_RECEIVED`): the
    copy holds what the caller's array holds (rule 3).
  - The inline audit checks the body of each collecting function inlined
    into a precise one with the C mode, as a precise function's (rule 6).

## 1. The rules the call layer follows

1. **The parameter rule** (question 11). A precise function anchors each
   object parameter it uses after a collecting call.
   - Loading a field of the parameter into a local only moves that
     obligation to the local. An immutable strong edge (`m_self`,
     `im_self`) anchors the loaded object while its owner is anchored, and
     not otherwise.
   - The hot path is free only where no collecting call lies between
     entry and the function's final call. Checks that can raise, such as
     the recursion check `cfunction_enter_call` makes, split into two
     parts:
     - a non-collecting test (`_Py_ReachedRecursionLimit`);
     - a slow path, taken when the test fails, that pushes the frame's
       span and then raises or continues.

     The common path then has nothing to anchor.
   - `Py_GC_ARGS_ANCHORED` applies only to a static function whose callers
     are all precise; the C mode checks that.
   - A vectorcall function is called through a pointer from opaque code,
     so it is never `Py_GC_ARGS_ANCHORED`.
2. **The frame's span.** A precise function that needs anchors pushes one
   span per activation.
   - The buffer is a local `PyValue` array, laid out in this order, and
     the layout is written in a comment above each function:
     1. the object parameters and object locals that need anchors, in raw
        form (0d);
     2. the saved values of borrowed slots it overwrites (rule 4);
     3. the result slots it passes as out-parameters (0e);
     4. then the argument array it builds, if any.
   - The `PY_VECTORCALL_ARGUMENTS_OFFSET` slot of an array the function
     creates is appended as `PyValue_NULL`.
   - Values enter only through `_PyValueSpan_Append` and
     `_PyValueSpan_AppendObject`.
   - A heap buffer (past the small size) is the span's base from the
     start; the span is popped before the free, on every path.
3. **The argument array rule.**
   - The creator of an argument array anchors its elements: the eval
     loop's frame slots, a frame's span, or an opaque caller's scanned
     frame. A callee does not anchor what it receives.
   - A callee that loads an element into a local and holds it across a
     collecting call anchors the local; the C mode checks that.
   - The creator's side, for arrays the C mode does not see built, is
     checked by kill mode.
   - A copy of a received array (`values_of`, which makes canonical
     values of an object array) holds what the received array holds. The
     creator of the original anchors both, so the copy needs no span.
4. **Borrowed slots that a callee overwrites.** `PY_VECTORCALL_ARGUMENTS_OFFSET`
   lets a callee write `args[-1]`, and that slot may hold a live value of
   its creator (the eval loop's `self_or_null`, an outer prepend's
   argument).
   - A callee that saves the slot, overwrites it and restores it (the
     `*Prepend*` forms, `method_vectorcall`) appends the saved value to its
     own span before the overwrite.
   - A slot the function created itself as `PyValue_NULL` scratch needs
     no save.
5. **Results.** A call's result held across a later collecting call is an
   object local (question 11): it goes in the frame's span. The result of
   the final call is returned, not held.
6. **Statics and header helpers inlined into precise functions are
   precise.** Their locals live in the precise frame. The inline audit
   reads the DWARF of the linked image. It accepts an inlined function that
   is marked (and so checked by the stamp's C mode, 0c), that is
   non-collecting, or whose body passes the C mode as a precise
   function's (0f). A public header helper such as `PyValue_Object` cannot
   carry the internal marker, so the last form covers it. A static that
   cannot pass stays opaque and `Py_NO_INLINE`.

The C mode checks every rule at build time, except rule 3's creator side,
which kill mode checks at run time.

## 3. Ownership across helpers

- **`values_of`.** It fills the caller's span. The caller pushes the span
  over its small array, and `values_of` appends. When the values need the
  heap, `values_of` allocates, copies what was appended and rebases the
  span, then goes on appending. The caller pops before `free_values`.
- **`gen_send_ex2(gen, arg, PyValue *presult, int exc)`.** `presult`
  points at a slot in the caller's span, appended as `PyValue_NULL`. The
  callee stores the result through it, and the caller reads it from the
  span.
- **`gen_iternext`.** It passes such a slot instead of `&result`.

## 4. Tests

- **Borrowing** (8.4). `_PyGC_TestBorrowAcross(list, callback, kind)` is a
  core function in Python/gc_trace.c; a shared module is extension opaque,
  so the test function must be in the image.
  - It is marked precise. It borrows `list[0]` into its span, calls
    `callback`, which clears the list and collects, and then returns the
    item's type name.
  - Its counterpart without the span registers itself as a precise test
    range, as item 7's demonstration does, so that the C mode never sees
    it. Under kill it crashes, in a child, and the test asserts the crash.
  - The weak reference pair loads `wr_object`, collects by a direct call
    between the load and the use, asserts from the collection count that
    the collection ran, then uses the target.
  - Runs: kill on build/debug, and ASan on build/asan, with
    use-after-poison expected for each counterpart.
- **Boxes** (0d). A builtin called through `method_check_args` with an
  exact float receiver. A collection is injected between the receiver's
  boxing and its use, and the test reads the original box afterwards.
  Kill on build/debug, ASan on build/asan.
- **The probe's call-layer cases** (8.1), each inside a `sorted(key=...)`
  callback, so that list.sort's opaque frame lies between eval-loop
  frames, and each collected while the callback still runs:
  1. *tp_call.* `obj(A())`, where `obj`'s class defines `__call__`, which
     stores `weakref.ref(x)` and returns. The `A` instance was held only
     by `_PyObject_MakeTpCall`'s argument tuple and the popped frames.
  2. *context.run.* `ctx.run(f, A())` with `f` storing a weak reference
     and returning.
  3. *A generator resumed by `send`.* `g.send(A())`, where the generator
     stores a weak reference to the received value, deletes its local and
     yields again.

  After each case, the callback collects and checks that the reference

## Risks

- Every call from C pays for the public entries' spans. Rule 1's split
  keeps the common path free where it can; the measurements attribute the
  rest.
- If rule 4 is missed in a callee that overwrites `args[-1]`, the
  creator's value is unanchored for the length of the inner call. The
  C mode does not see the creator's slot, so the nested prepend tests and
  kill mode are the check.
- typeobject.c's `slot_*` functions stay opaque until 1b. A stale word in
  one of their live frames can keep an object; the probe cases avoid
  those frames: `__call__` is reached through `slot_tp_call`, but the
  dead object is not in its frame after it returns.
- Item 0b's and 0c's changes make more code checkable and may raise the
  counts. The re-count is the baseline.
