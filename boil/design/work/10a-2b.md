## 1. `_PyStack_UnpackDict`

Today it returns a PyMem array of the positional arguments and the
keyword values, with a free slot before it, and the names through
`PyObject **p_kwnames`. Its three callers are `vectorcall_call_dict`
(the keyword form of `_PyVectorcall_Call`, opaque), the dict path of
`_PyObject_VectorcallDictValueTstate`, and `_PyEvalFramePushAndInit_Ex`
(ceval.c, opaque). The names tuple is held only in the caller's C local
across the call. The keyword values are held only by the array: since
reference counting went, the array's comment says that "the values stay
in kwargs, which the caller holds". That is true only while nobody
mutates the dict. A callee that reaches the same dict by another path
and clears it leaves the array's values unanchored. Upstream's array
held references, so this case was safe before 5c.

**The change.** The array becomes part of the caller's span, as rule 2
lays it out, and the one collecting step is split from the fill, so
that the fill is a non-collecting call and the C mode needs no new
interprocedural rule:

```c
/* kwargs' keys as a new tuple, or NULL with an exception set: a key
   that is not a str raises TypeError here, before anything is
   filled.  Collecting: the tuple's allocation can run finalizers,
   which can change kwargs, so the keys are read after it, and a size
   that changed raises RuntimeError, as dict iteration does. */
PyObject *_PyStack_KwNames(PyThreadState *tstate, PyObject *kwargs);

/* The slots _PyStack_UnpackDict() appends: the free slot for
   PY_VECTORCALL_ARGUMENTS_OFFSET, nargs, then kwargs' values.  -1
   with MemoryError set if the total, with prefix, overflows. */
Py_ssize_t _PyStack_UnpackDictSlots(PyThreadState *tstate,
                                    Py_ssize_t prefix, Py_ssize_t nargs,
                                    PyObject *kwargs);

/* Append to span: PyValue_NULL, args[0..nargs), then kwargs' values
   in the dict's order, which is the order of _PyStack_KwNames()'s
   tuple.  Returns the address of the first argument in the span's
   buffer.  Non-collecting: stores only.  end is the buffer's end;
   debug builds assert that the appends stay before it.  Nothing that
   collects may run between _PyStack_KwNames() and this call, so kwargs
   is as the names tuple was read from it. */
const PyValue *_PyStack_UnpackDict(const PyValue *args, Py_ssize_t nargs,
                                   PyObject *kwargs, _PyValueRoot *span,
                                   const PyValue *end);
```

Each caller, in this order:

1. sizes the buffer with `_PyStack_UnpackDictSlots()`, which keeps
   today's overflow check and adds the prefix to it, and takes a local
   array of `_PY_FASTCALL_SMALL_STACK` slots or, past that, PyMem from
   the start (rule 2; PyMem is non-collecting);
2. pushes the span and appends its prefix, the raw anchors of the
   objects it uses after a collecting call;
3. calls `_PyStack_KwNames()` and appends the result raw;
4. calls `_PyStack_UnpackDict()`, then the callee;
5. pops before the free, on every path.

The prefixes:

| Caller | Prefix (raw unless named) | Why |
|---|---|---|
| `_PyVectorcall_Call`, keyword form (`vectorcall_call_dict` merged into it) | `callable`, `tuple`, `kwargs` | the tuple owns the positional array across `_PyStack_KwNames()`, and an interior pointer in a precise frame is no root; `callable` is read by the result check |
| `_PyObject_VectorcallDictValueTstate` | `callable` as a value, `kwargs` | the positional array is the caller's (rule 3) |
| `_PyEvalFramePushAndInit_Ex` | `func` as a value, `locals`, `callargs`, `kwargs` | `func` and `locals` are used after the names' allocation; `callargs` owns the positional array |

The C mode checks each caller as it checks any function: the prefix
covers what it uses after `_PyStack_KwNames()` and after the callee,
and the names are covered because they are appended. `_PyStack_UnpackDict`
goes on call_effects.py's non-collecting list, with the comment that it
only stores. It is not a precise function, so the inline audit accepts
it inlined by that listing.

- `_PyStack_UnpackDict_Free` goes. Its one external user, "external JIT
  support", is a port and is deferred.
- The positional and keyword values no longer need a PyMem array when
  they fit the small buffer: that allocation goes. The names tuple is
  still allocated for a non-empty dict. The record counts PyMem and
  object allocations per call, before and after, apart.

(Coordinator's ruling, 2026-10-28: the hazard is real and the order,
proof first, is right; `_PyStack_UnpackDict_Free` goes. The ruling
accepted a fill by a collecting callee (0h) with checker conditions on
capacity and reads after the pop. After review round 1 this doc
replaces 0h with the split above, which needs no checker change: the
collecting part returns a result like any call, and the fill only
stores. The capacity condition becomes the debug assertion against
`end`. A read after the pop is a read of a dead local's buffer, which
the C mode's existing liveness already treats as unanchored.)

**Promoted with it:** `_PyEvalFramePushAndInit_Ex` (precise, its
`Py_NO_INLINE` comment removed), the merged keyword form of
`_PyVectorcall_Call`, and `_PyObject_VectorcallDictValueTstate`,
`_PyObject_VectorcallDictTstate` and `PyObject_VectorcallDict`.

**Tests.**

- *The hazard* (review round 1, issue 4). Before this change the
  unpacked array is pointed to by `vectorcall_call_dict`'s opaque frame,
  and plain kill follows PyMem blocks from core opaque frames, so a test

A zero count does not mean that a mark is all a helper needs (review
round 1, issue 1). The C mode checks what a function holds in locals
across a collecting call. An argument array that the function builds is
the creator's to anchor (rule 3), and the opaque frame does that today
by being scanned. Every helper therefore gets an inventory of the arrays
it builds, and each array goes in its frame's span before the dispatch.
The arrays in ceval.c:

| Helper | Array | What only it may hold |
|---|---|---|
| `_PyEval_CallExitWithException` | `stack[5]` | the traceback, which a C `__exit__` can clear from the exception |
| `_Py_BuildString_Values` | `VALUES_TO_OBJECTS`' array | the boxes of inline values |
| `_Py_BuildMap_Values` | `VALUES_TO_OBJECTS`' array | the same |
| `_PyEval_MatchKeys` | `args[3]` | the dummy's value |
| `_PyEval_ImportNameWithImport` (static, under `_PyEval_ImportName` and `_PyEval_LazyImportName`) | `args[5]` | the `fromlist` and `level` objects |

`VALUES_TO_OBJECTS` gets a span form: the conversion appends each box
raw to the frame's span, as `_Py_VectorCallInstrumentation_Values`
appends its two boxes. The other helpers in group a pass their arrays
on from the eval loop's registers, which the eval loop anchors.

Each helper also gets the mark, after which the inline audit checks what
the compiler inlines into it. The statics that the helpers call
(`match_class_attr`, `format_missing`, and the others in the C mode's
list) are marked where the audit finds them inlined, or made
`Py_NO_INLINE` if they are error paths called last, as 10a-2.md's
`*_error` functions are.

The rest of the work is the same in each: rule 1's span over the
parameters used after a collecting call, and rule 5's result slots.
`_PyEval_MatchClass` and `_PyEval_ImportFrom` are the large ones. Their
bodies are long chains of attribute lookups, each result held across
the next. Each such function gets one span over its locals, and its
layout comment lists them.

**Object out-parameters** (review round 1, issue 5). Groups c and d call
`PyObject_GetOptionalAttr`, `PyDict_GetItemRef`,
`_PyModuleSpec_GetFileOrigin` and `PySys_GetOptionalAttrString`, which
return through `PyObject **`. 0e covers `PyValue *` slots only. A raw
span slot holds the object's pointer bits (`_PyValueSpan_AppendObject`),
so it is a `PyObject *` in memory. One checked accessor makes the
address:

```c
/* Append a raw NULL slot to span and return its address as an object
   out-parameter: the callee's store is a raw anchor in the span. */
static inline PyObject **_PyValueSpan_ObjectSlot(_PyValueRoot *span);
```

The C mode accepts its result as an out-parameter into a covered slot,
as 0e accepts `&buf[k]`. A read of the slot after the call is a raw
object, and the object local loaded from it is anchored. No other cast
of a span slot to `PyObject **` is accepted. Fixtures in
test_generated_cases: the accessor's slot used across a collecting
call, which passes; a local's address passed instead, which fails. The
runtime test covers the three outcomes of `PyObject_GetOptionalAttr`
(found, missing and raising) under kill. The value getters 6d is
writing are not a dependency: these helpers keep their object calls.

**The tests.** First, `_PyEval_CallExitWithException`: a C `__exit__` in
`_testinternalcapi`, registered as a precise test range, that clears the
exception's traceback, collects, and reads its traceback argument. It

Then test_patma, test_import, test_importlib, test_exceptions,
