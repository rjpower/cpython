## 1. `_PyStack_UnpackDict`

Today it returns a PyMem array of the positional arguments and the
keyword values, with a free slot before it, and the names through
`PyObject **p_kwnames`. Its three callers are `vectorcall_call_dict`
(the keyword form of `_PyVectorcall_Call`, opaque), the dict path of
`_PyObject_VectorcallDictValueTstate`, and `_PyEvalFramePushAndInit_Ex`
(ceval.c, opaque). The names tuple is held only in the caller's C local
across the call. The keyword values are held only by the array: since
reference counting went, the array's comment says that "the values stay
in kwargs, which the caller holds". That is true only while nobody
mutates the dict. A callee that reaches the same dict by another path
and clears it leaves the array's values unanchored. Upstream's array
held references, so this case was safe before 5c.

**The change.** The array becomes the caller's span, as rule 2 lays it
out:

```c
/* The number of slots the caller's span needs for
   _PyStack_UnpackDict(): its own prefix, then the names, the free
   slot and the arguments. */
#define _PyStack_UNPACK_DICT_SLOTS(prefix, nargs, kwargs) ...

/* Append to span, which the caller pushed over a buffer of
   _PyStack_UNPACK_DICT_SLOTS() slots: the names tuple, PyValue_NULL
   for PY_VECTORCALL_ARGUMENTS_OFFSET, the nargs positional
   arguments, then kwargs' values.  Returns the arguments' address in
   the span's buffer, or NULL with an exception set. */
const PyValue *
_PyStack_UnpackDict(PyThreadState *tstate, const PyValue *args,
                    Py_ssize_t nargs, PyObject *kwargs,
                    _PyValueRoot *span);
```

- The caller sizes the buffer: a local array of
  `_PY_FASTCALL_SMALL_STACK` slots, or PyMem from the start past that
  size (rule 2). It pushes the span, appends its own anchors (the
  callable and `kwargs`), calls `_PyStack_UnpackDict`, and reads the
  names from its buffer (`PyValue_ObjectBorrow(buf[prefix])`). It pops
  before any free, on every path.
- `_PyStack_UnpackDict` makes one collecting call, `PyTuple_New`, before
  it appends anything. It then appends with non-collecting stores only.
  The keys check, which raises, runs after the appends, and the caller
  pops on the error path.
- `_PyStack_UnpackDict_Free` goes. Its one external user, "external JIT
  support", is a port and is deferred.
- The common case allocates nothing: a call `f(*a, **k)` with a few
  arguments uses the local buffer, where today it calls `PyMem_Malloc`.

**The C mode.** A callee that appends to a span passed by pointer is
new to it. 0h: a parameter of type `_PyValueRoot *`, passed the address
of a pushed span, makes the call a span fill. The caller's buffer is
then covered up to the callee's appends, and a read of `buf[k]` after
the call is a covered slot. In the callee, appends to the parameter
span are allowed without a push. Two fixtures in test_generated_cases:
a fill whose caller reads a slot after a collecting call, which passes;
and a fill into a span that is not pushed, which fails.

**Promoted with it:** `_PyEvalFramePushAndInit_Ex` (precise, its
`Py_NO_INLINE` comment removed), the merged keyword form of
`_PyVectorcall_Call` (`vectorcall_call_dict` goes), and
`_PyObject_VectorcallDictValueTstate`, `_PyObject_VectorcallDictTstate`
and `PyObject_VectorcallDict`.

**Tests.**

- kill and ASan: a C callee in `_testinternalcapi` that is called
  through `PyObject_Call(f, args, d)` with `d` a dict it can reach, clears
  `d`, collects, and reads its keyword value. It fails under kill before
  the change, which is the proof that the hazard exists, and passes
  after.
- `f(**k)` with a key that is not a str, through each caller: the
  error path pops and frees.
- `f(*a, **k)` past the small size: the heap buffer.

Group a's zero counts are as the functions stand. Each still needs its
mark, and the inline audit then checks what the compiler inlines into
it. The statics that the helpers call (`match_class_attr`,
`format_missing`, and the others in the C mode's list) are marked where
the audit finds them inlined, or made `Py_NO_INLINE` if they are error
paths called last, as 10a-2.md's `*_error` functions are.

after a collecting call, rule 5's result slots, and 0e's out-parameters
into the span. `_PyEval_MatchClass` and `_PyEval_ImportFrom` are the
large ones. Their bodies are long chains of attribute lookups, each
result held across the next. Each such function gets one span over its
locals, and its layout comment lists them.
