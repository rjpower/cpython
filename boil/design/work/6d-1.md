# 6d rung 1: the hand-offs and the mark

Status: design, revised after review, 2026-10-28. Specification: note 12 sections 2.1, 6.1 to
6.5 and 11 (rung 1), adopted 2026-10-28. Before: 453798173f0.

Coordinator rulings that bind this rung (2026-10-28): the capacity rule
is accepted with note 12's fallback criterion, measured on the Py_STATS
gate; rung 1 starts beside 10a's rung 1b, so ceval.c and ceval.h are not
touched, and the hunks in bytecodes.c and typeobject.c stay inside the
handlers and functions this rung must change; handlers are written to
1b's collecting-call rule (no field, cache or poly-row value held in a C
local across anything that can allocate).

None of this rung changes a slot type. It changes the handler set, the
feedback rows the stores use, the capacity of new heap types, the
layout of `_PyShape` (and so of `PyTypeObject`), and the extension
suffix.

## A. The `_NO_DICT` fold (note 12 6.1)

`LOAD_ATTR_METHOD_NO_DICT` and `LOAD_ATTR_NONDESCRIPTOR_NO_DICT` are
deleted, with their uops. `specialize_attr_loadclassattr()` today picks
them for a type without `Py_TPFLAGS_INLINE_VALUES` and with
`tp_dictoffset == 0`. Such a type has no `ht_shapes` and no slot
capacity, so its instances carry its root shape. The branch now joins the
`INLINE_VALUES` one: `set_shape_guard()` on the owner's shape with
`LOAD_ATTR_METHOD_SHAPE` or `LOAD_ATTR_NONDESCRIPTOR_SHAPE`.

Why the guards prove the same thing:

- `_GUARD_SHAPE` against the root proves the type.
- `_GUARD_SHAPE_VERSION` reads the root's `type_version`, which equals
  `tp_version_tag`. `_PyShape_SetTypeVersion()` writes it, and
  `_PyShape_Generalise()` never reaches a root, since a root owns no
  field.

The specialiser asserts both facts:

- `_PyObject_SHAPE(owner) == _Py_TYPE_ROOT_SHAPE(type)`;
- the root's `type_version == tp_version_tag`, which equals the plan's
  `type_version`.

If an object of such a type ever had another shape, the guard would
fail and the site would stay generic. That is a deopt, not a wrong
answer.

A by-product: a method site that sees two no-dict types (a list and a
deque) now records `LOAD_ATTR_METHOD_SHAPE` rows, so it can become
`LOAD_ATTR_SHAPE_POLY`. Before, the second type replaced the first.

Other changes for A:

- test_opcache's two `_NO_DICT` names become the `_SHAPE` ones.
- `make regen-cases` drops them from the generated tables.

## B. `STORE_ATTR_SHAPE_POLY` (note 12 6.1)

```
op(_STORE_ATTR_SHAPE_POLY, (value, owner -- o))
macro(STORE_ATTR_SHAPE_POLY) = unused/1 + _GUARD_SHAPE_POLY + unused/3 +
                               _STORE_ATTR_SHAPE_POLY + POP_TOP;
```

`_GUARD_SHAPE_POLY` is the load's guard, reused. The body:

1. Find the row again with `_PyFb_ShapeRow()`.
2. `EXIT_IF(!_PyValue_FitsKind(value, poly->slot_kind[row]))`.
3. Store the value at `poly->index[row]`.
4. For a `STORE_ATTR_SHAPE_TRANSITION` row, call `_PyObject_SetShape()`
   with `poly->descr[row]` (the row's `shape_to`). The slot is written
   before the header, as in `_STORE_ATTR_SHAPE_TRANSITION`.

The row lookup, the kind check and the store come before anything that
could allocate, and nothing in the body allocates. So under 1b's rule no
row value crosses an allocation.

Specialiser:

- `set_shape_guard()` already records the observation when a site has
  seen another shape.
- For stores it now looks at rows of any type (`any_type`), as loads do.
- After recording, if the site is `FB_POLY` and every row is
  `STORE_ATTR_SHAPE` or `STORE_ATTR_SHAPE_TRANSITION`, the site becomes
  `STORE_ATTR_SHAPE_POLY`. This is `specialize_shape_poly()`, generalised
  to a family.
- A fifth shape makes the site `FB_MEGA`, and it stays generic.
- The ADD path now computes `shape_to` and its kind before
  `set_shape_guard()`, so the recorded row carries them. Today they are
  written after, so a recorded ADD row would lack them.
- Rows come from `fb_row_of()`: `index` (the `offset` union), `descr`
  (the `shape_to` union) and `slot_kind`. `fb_put_row()` already keeps
  `slot_kind` for both store handlers. The table layout is unchanged.

A row's `shape_to` is a shape of the row's type. The row matched the
owner's live shape at its live version, so that type is the owner's and
is alive, and `shape_to` is live. It is never dereferenced except to
write the header, as in the mono handler.

## C. `LOAD_ATTR_METHOD_LAZY_DICT` (note 12 6.2)

```
op(_CHECK_DICT_WORD_NULL, (dictoffset/0, owner -- owner))
macro(LOAD_ATTR_METHOD_LAZY_DICT) = unused/1 + _GUARD_SHAPE +
    _GUARD_SHAPE_VERSION + _CHECK_DICT_WORD_NULL + unused/2 +
    _LOAD_ATTR_METHOD_SHAPE;
```

The check is `EXIT_IF(_PyObject_DictAt(owner_o, dictoffset) != NULL)`.

In `specialize_instance_load_attr()`, a DICT plan qualifies when all of
these hold:

- the site is a call-pair site (`oparg & 1`);
- the plan's fallback is METHOD;
- the type has no `INLINE_VALUES`;
- `tp_dictoffset` fits in int32;
- the owner's dict word is NULL.

Such a site is specialised before `specialize_dict_hint()`, which today
fails it with `SPEC_FAIL_NO_DICT`. Its entry gets:

- the owner's shape, the root, with the plan's version;
- `dictoffset`;
- the method, as `LOAD_ATTR_METHOD_SHAPE`'s `descr`.

How the guards cover it:

- The root's version guards the class attribute.
- The NULL word proves that no instance attribute shadows it.
- Once the dict exists the check exits, and the generic path either
  specialises `WITH_HINT` or fails, as today.

## D. The capacity rule (note 12 6.4)

```
w = S > 0 ? S + 2 : 6
capacity = min(30, (_PyMem_SizeClass(B + 8w) - B) / 8)
```

`_PyMem_SizeClass(n)` (obmalloc.c, which compiles mimalloc in) is
`_mi_bin_size(mi_bin(n))`: mimalloc's size class for `n` bytes without
its debug padding. `mi_good_size()` adds `MI_PADDING_SIZE`, which is 8
on debug and ASan builds and 0 on release builds, so it would make the
capacity depend on the build (review 2). The policy is the release size
classes on every build. On a padded build a block may be one class
larger than the rule assumes; padded builds are not measured.

- `B` is `tp_basicsize` when `_PyType_SlotCapacity()` runs, from
  `type_ready` and from `_PyType_StaticAttributesChanged()`.
- The instance size is exactly `B + 8 * capacity`:
  - `_PyType_AllocNoTrack` adds `_PyType_AllocSlotsSize()` to
    `_PyObject_VAR_SIZE(type, 1)`, which for an itemless type is `B`;
  - gc_live.c's allocator does the same.
- mimalloc is mandatory in this fork (configure.ac refuses
  `--without-mimalloc`), so the helper needs no fallback.
- `_testinternalcapi.mem_size_class(n)` exposes the helper.
  test_shapes checks it against the classes `capacity_rule.py` models
  (16-byte steps to 64, then four per power of two), so the tool and
  the rule agree. It also checks capacities at class boundaries.
- `_Py_SHAPE_MIN_SLOTS` (6) becomes the `w` for S = 0. The comment in
  pycore_shape.h states the rule.

Tests that change:

- test_shapes' capacity cases: S of 0, 1, 3, 4, 14 and a `B` other
  than 8 (a list subclass), plus the dataclass recomputation;
- test_sys's `getsizeof` cases for instances.

Recorded at the rung's end, not tuned for:

- dictionary-mode entries by reason over the suite on the pystats build
  (gate 2 with its own `PYTHON_STATS_DIR`). The fallback criterion is
  `capacity` > 53,084, twice 6c's 26,542. That is a decision point:
  - if it is exceeded, the rung does not land; I report, and the
    coordinator rules;
  - a fallback commit (six slots for S of 1 to 3) re-runs the same
    Py_STATS gate and the kernels' occupancy;
- `occupancy_types.py` over the 29 kernels, before (baseline build,
  in `boil/bench/results/6d-occupancy-before/`) and after. Its rows
  count dictionary-mode samples per type, so a type pushed into
  dictionary mode shows there;
- the micro rows of note 12 section 10, committed with their before
  values. These are `boil/bench/results/6d-before.json` (instr) and
  `6d-before-pystats.json` (boxes), on 453798173f0 plus the rows;
- RSS of the memory group.

## E. `class_version` (note 12 6.5)

`struct _PyShape` (Include/object.h) gains `uint32_t class_version` after
`type_version`. The struct grows from 64 to 72 bytes, and `PyTypeObject`,
which embeds `tp_root_shape`, grows by 8. That is why the mark (F) lands
in the same commit (review 1). test_sys's sizes change with it: the
static and heap type sizes, the shape table and populated shapes.

The invariant is `shape->class_version == shape->type->tp_version_tag`,
zero included, for every shape. The writers are:

- `_PyShape_InitRoot()` (which `_PyObject_Init()` calls for an unreadied
  static type);
- `_PyShape_InitTypeShapes()` (the dictionary-mode shape);
- `new_shape()` (from the parent);
- `_PyShape_SetTypeVersion()` (root, table, dictionary-mode shape).

`_PyShape_Generalise()` does not write it.

On a debug build `_PyShape_SetTypeVersion()` asserts the invariant over
the type's shapes. The note's assert in the shape guards' slow paths is
not possible: the guards are generated handlers with no slow path, so
the assert lives at the writers.

Handler changes:

- `_GUARD_TYPE_VERSION` reads
  `FT_ATOMIC_LOAD_UINT32_RELAXED(_PyObject_SHAPE(o)->class_version)`.
- `LOAD_ATTR_SLOT` and `STORE_ATTR_SLOT` use `_GUARD_TYPE_VERSION`
  instead of `_GUARD_SHAPE_VERSION`, with no other change to their
  bodies. The specialiser records `tp_version_tag` for them and fails
  with `SPEC_FAIL_OUT_OF_VERSIONS` when it is 0.

`_GUARD_TYPE_VERSION` keeps its other users:

- `LOAD_ATTR_PROPERTY`;
- `LOAD_ATTR_GETATTRIBUTE_OVERRIDDEN`;
- `LOAD_ATTR_CLASS_WITH_METACLASS_CHECK`;
- `TO_BOOL_ALWAYS_TRUE` and the two `POP_JUMP_IF_*_ALWAYS_TRUE`.

Each guards an owner that is an object (the specialisers refuse inline
owners). Every object's header is a shape of its type. Since 6c,
`Py_TYPE` is `shape->type`, so the shape read replaces the type read and
saves a load.

A member's precedence over the instance dict makes the class version
sufficient. A member is a data descriptor, so nothing in the instance
shadows it. Replacing it changes `tp_version_tag`.

## G. The presized conversion (note 12 6.3)

`dict_from_slots()` calls `_PyDict_NewPresizedUnicode(nslots + 1)`
instead of `PyDict_New()`. The `+1` is the store that triggered the
conversion.

`_PyDict_NewPresizedUnicode()` is a new internal entry over
`dict_new_presized(minused, true)`. `_PyDict_NewPresized()` gives a
general-keys table above five entries, which both `WITH_HINT` handlers
refuse (review 3). The names are interned exact strs, so a Unicode
table holds them, and a later non-str key converts it as any dict
does.

No resize is checked on debug builds. `dict_from_slots()` asserts that
the dict's keys object after the fill is the one it was created with.
The debug suite runs that assertion over every conversion.

test_shapes converts an object with seven str attributes (S of 5,
capacity 7) through `vars()`. It then warms a load site and a store
site on it, and expects `LOAD_ATTR_WITH_HINT` and
`STORE_ATTR_WITH_HINT`, which only a Unicode table admits.

## Decisions the note left open

- **Member sites when the shape version is 0.** Both specialisers
  reject `plan.type_version == 0` before the member branch, and that
  check stays. A shape version is 0 only when versions are exhausted.
  A member site there stays generic, which costs a rare case and keeps
  one early check.
- **Kinds in store rows only widen.** A row's `slot_kind` was read from
  the row's shape when it was recorded. A generalisation that reaches
  only the target of an ADD row widens the target's field without
  renewing the parent's version, so the row still matches. Its kind is
  then narrower than the field's. A narrower check admits fewer values,
  all of which fit the wider field, so the stale row is safe. It is
  stated at `_STORE_ATTR_SHAPE_POLY`.

## Risks

- **10a's rung 1b also edits bytecodes.c.**
  - Where: `_GUARD_TYPE_VERSION` and the slot macros are small, separate
    hunks. The new ops sit next to their families, away from
    `_ALLOCATE_OBJECT`.
  - Mitigation: merge the integration branch at every commit boundary.
- **The pyc magic.** 10a may bump it in parallel; the merge takes the
  larger number plus one.
- **`PyTypeObject` grows by 8 bytes.** Static types in extensions
  compiled against the old header would be wrong. The suffix change in
  this rung keeps such binaries out. In-tree modules rebuild.
- **Capacity smaller for S of 1 to 3.** An instance that later adds a
  third or fourth name beyond `S + 2` goes to dictionary mode sooner.
  That is what the fallback criterion measures.

## Review

Round 1 (boil/design/work/reviews/6d-1-review.md, codex), verdict
revise. Each blocking issue is now a change:

1. *The mark landed after the break.* E and F are one commit, with the
   regen and a magic bump (order of commits).
2. *`mi_good_size()` counts debug padding.* The rule uses
   `_PyMem_SizeClass()`, the unpadded size class, the same on every
   build, and a test ties it to the tool's model (D).
3. *Presizing made general-keys tables.* A Unicode presize, a debug
   assertion of no resize, and a test that the `WITH_HINT` handlers
   still specialise (G).

Non-blocking, all taken:

- the layout numbers and test_sys (E);
- store invalidation, dead types, target-only generalisation and
  collector visibility (tests);
- lazy-dict shadowing and negative offsets (tests);
- the micro rows and the before histograms (D);
- the audit arithmetic (F).

The two questions are answered under "Decisions the note left open"
and in D's decision point.
