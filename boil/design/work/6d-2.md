# 6d rung 2: the attribute and descriptor slots on values

Status: design, 2026-10-28. Specification: note 12 sections 2 to 4, 7 to
9 and 11 (rung 2). Starts from 485b13fd9b3, boil/6d at rung 1's end
merged with boil/10a at 4112572f058: 10a's call layer (cc17a7be683 and
earlier) and rung 1b item 3's marks. Line numbers are of that merge.
boil/10a and the integration branch are merged at every commit
boundary.

The rung changes four slot types in place. With each type it changes
every function of that type, so the tree builds at every commit. It
adds the value forms the compatibility layer needs, and the debug checks
that catch a slot of the old form. `wrapperfunc` and `tp_call` stay
object forms until rung 3, and getset getters and setters until rung 4.

## B. The executor on a value owner (Objects/object.c)

- `generic_getattr_value(PyValue owner, ...)` reads the shape with
  `_PyValue_Shape(owner)`.
  - SLOT and DICT plans are impossible on an inline owner, so they
    assert an object.
  - CLASS_VALUE and ABSENT do not read the owner.
  - METHOD (bound here, since `getattr` wants the bound method), DESCR,
    DATA_DESCR and PROPERTY call a descriptor with the owner. An inline
    owner is boxed once, by `box_owner_for_descr()`.
- `box_owner_for_descr(PyThreadState *, _PyValueRoot *span, PyValue
  owner)` returns the owner as an object. An inline owner is boxed and
  the box appended raw to `span`, which the caller pushed and pops after
  the descriptor call returns. It pushes no root of its own, so nothing
  points into its frame after it returns. It fires `_PyGC_SITE_SLOT_BOX`
  (F) after the append. On a failed box it returns NULL with the error
  set.
- `descr_get_value()` loses its canonicalisation and returns the slot's
  value, after `_PyValue_CheckSlotResult` (D).
- `PyObject_GetAttrValue` and `PyObject_SetAttrValue`:
  - If the slot is the generic one, they run the executor on the value.
  - Otherwise they call the slot on the object, which is never inline
    (2.4). Today's receiver box goes.
- `PyObject_GetOptionalAttrValue` (new, `PyAPI_FUNC`) carries
  `PyObject_GetOptionalAttr`'s fast paths: generic, type and module.
  The object form becomes canonicalise, call and box.
- `PyObject_GetAttr` and `PyObject_SetAttr` stay wrappers. They box the
  result, or canonicalise the stored value.
- `getattr(o, n, d)` and `hasattr` call the value form. `hasattr`'s
  Clinic converter becomes `obj: value`, and the wrapper is regenerated,
  so an inline receiver is not boxed at the builtin.
- **The error path on an inline owner.** `set_no_attribute_error` takes
  the owner as a value and names `PyValue_Type(owner)`.
  `_PyObject_SetAttributeErrorContext` takes the owner as a `PyValue`
  (its 10 callers pass `PyValue_FromObject` of theirs) and stores it with
  `PyObject_SetAttrValue`. `AttributeError.obj` is a `_Py_T_OBJECT`
  member, so its setter (D) makes the one box. If the box cannot be made,
  a `MemoryError` replaces the `AttributeError`. A suppressed miss
  (`suppress`, `getattr` with a default, `hasattr`) makes no error and no
  box.
- **The deletion guard.** `object_setattr` refuses a NULL value while an
  exception is set (Objects/object.c, `object_setattr`). The guard moves
  with the dispatch into `PyObject_SetAttrValue`, before any lookup: the
  `SystemError` chains the pending exception, and nothing is changed.
- **Stores keep an object owner** (note 12 3). `generic_setattr_value`
  takes `PyObject *`. A store to an inline int or float can only fail:
  NO_STORAGE raises "'int' object has no attribute", and DATA_DESCR
  reaches a getset that refuses (`(5).real = 1`). So
  `PyObject_SetAttrValue` keeps today's box of an inline owner, on that
  failure path only. The stored value is passed as a value in every
  case.
- **The method path.** `_PyObject_GetMethodValue` boxes the receiver at
  its top today, only to look the name up; the box is not the one the
  call uses. That box goes:
  - `get_method_value` takes the owner as a value. METHOD returns 1 with
    the descriptor unbound and `*self` unchanged, inline or not. The
    receiver box the call needs is made by the call layer:
    `method_check_args` (Objects/descrobject.c) boxes `args[0]` for a
    method of int or float, and holds it for the call. F fires
    `_PyGC_SITE_RECEIVER_BOX` there.
  - DESCR, DATA_DESCR and PROPERTY bind through
    `box_owner_for_descr()`, as in the executor.
  - A custom getattro's owner is an object (2.4). It is called through
    `PyObject_GetAttrValue`, and the result is not boxed.

## C. Hooks, types, modules, super (Objects/typeobject.c, moduleobject.c)

Each is run through `Tools/cases_generator/root_check_c.py
--function`, and the results are recorded in "C mode: hand-off to 10a".
The spans over their parameters are 10a's, with the marks.

- `_Py_slot_tp_getattro` uses `vectorcall_method_value` with
  `[self, name]` as values.
- `call_attribute`:
  - A method descriptor is called with `PyObject_VectorcallValue`.
  - Another descriptor's `tp_descr_get` value is held in a span while
    the call runs.
  - Its result goes to the call, with no box.
- `_Py_slot_tp_getattr_hook` gets the generic executor's value with
  `suppress`.
- `slot_tp_setattro` passes the value to `__setattr__` through
  `vectorcall_method_value`.
- `slot_tp_descr_get` calls the raw `__get__` with
  `PyObject_VectorcallValue`.
- `slot_tp_descr_set` calls `__set__` or `__delete__` with values.
- `_Py_type_getattro_impl` returns a value, and `meta_get` and
  `local_get` results pass through. `_Py_type_getattro_value`, today the
  value core that the object form wraps, is folded into it, and its
  callers are updated.
- `type_setattro` keeps `type_update_dict`'s transaction:
  `_PyType_Modified_Unlocked`, then `_PyDict_SetItem_LockHeld`, which
  takes a `PyValue` and deletes on `PyValue_NULL`, then the slot update
  for a dunder name. Two things change:
  - The value is passed through, with no `PyValue_FromObject` of an
    object form.
  - The old-value lookup goes. It kept the old value alive across the
    lock for its destructor, which the tracing collector never runs at
    removal, and it boxed an inline old value.

  The two boxes per store of the micro row `class_attr_store` go.
  `_PyDict_SetItemValue` is not used: it asserts a non-NULL value.
- **super.** `do_super_lookup`, `_PySuper_LookupDescr` and
  `_PySuper_Lookup` return values (`PyValue`, `PyValue_NULL` on a miss
  or an error, as now). The descriptor's `tp_descr_get` result passes
  through. `super_getattro` and `super_descr_get` return them. All three
  handlers take the value:
  - `_LOAD_SUPER_ATTR`, which `LOAD_SUPER_ATTR` and
    `INSTRUMENTED_LOAD_SUPER_ATTR` share, calls `PyObject_GetAttrValue`
    on the super object;
  - `LOAD_SUPER_ATTR_ATTR` and `_LOAD_SUPER_ATTR_METHOD` push
    `_PySuper_Lookup`'s value.

  These are hunks in three bodies of bytecodes.c. No object form of the
  lookups is kept: their callers are in the core.
  An inline receiver (`super(float, x)` with `x` inline) is boxed today
  by the cases generator: a stack input read with `PyValue_ObjectBorrow`
  is boxed at the handler's entry, rooted in the handler and counted as
  `_PY_BOX_OTHER`. Checked on rung 1's debug build:
  `super(float, x).__repr__()` and `super(int, x).__repr__` with inline
  `x`, cold and warmed. That box stays in this rung; the super object
  keeps `obj` in a `PyObject *` field. Rung 3 retires it: it carries
  `super`'s construction (`super_vectorcall`, `super_init_impl`) on
  values, so `obj` becomes a `PyValue` field and `_PySuper_Lookup` takes
  the receiver as a value, boxing it only to bind a descriptor, through
  `box_owner_for_descr()`. The audit lists the box as rung 3's residue.
- **Forwarding slots forward values.** Wrapping an object result with
  `PyValue_FromResult` would keep the box it was meant to remove, so the
  slots that forward a read call the value forms:
  - `proxy_getattr` (weakref): `PyObject_GetAttrValue` on the referent,
    written out in place of `WRAP_BINARY`;
  - `ga_getattro`: `PyObject_GetAttrValue` on the origin;
  - `local_getattro` (`_thread._local`): `_PyDict_GetItemValue` on the
    local dict, then the generic executor with the dict;
  - `_Py_module_getattro_impl`: the dict's value. A module `__getattr__`
    is called with `PyObject_VectorcallValue`, and its value returned.
    `suppress` keeps its meaning: a suppressed `AttributeError` gives
    `PyValue_NULL` with no error, and no box.
- The module types' slots of 2.1's list, function by function:
  - getattro that read a dict (`Example_getattro`, the four
    `Xxo_getattro`) read it with `PyDict_GetItemRefValue` (new, public,
    `PyDict_GetItemRef` on values) and fall back to
    `PyObject_GenericGetAttr`, a value;
  - getattro that build their result (`Pickler_getattr`,
    `Unpickler_getattr`, `context_getattr`) return
    `PyValue_FromResult` of the object they make, or forward to the
    generic getter's value;
  - setters box only in the branch that needs an object:
    `Pickler_setattr`'s `persistent_id` and `Unpickler_setattr`'s
    `persistent_load`, which keep it in a `PyObject *` field, and
    `context_setattr`'s `traps` and `flags`, which read it as a dict.
    `heapctypesetattr_setattro`'s `value` is a C long, read with
    `PyLong_AsLongValue`, and `Uuid_setattr` only raises. Every other
    branch forwards the value to `PyObject_GenericSetAttr`;
  - `Xxo_setattro` stores into its dict with `PyObject_SetItemValue` and
    deletes with `PyObject_DelItemValue`;
  - `local_setattro` forwards to the generic setter with its dict, and
    `PyCStructType_setattro` and `UnionType_setattro` forward to
    `PyType_Type.tp_setattro` with the value.
- `proxy_setattr` (weakref) forwards with `PyObject_SetAttrValue` on the
  referent.

## D. Descriptors (Objects/descrobject.c, funcobject.c, classobject.c)

- **property:**
  - `property_descr_get` calls `fget` with `PyObject_VectorcallValue`.
  - `property_descr_set` calls `fset` with `[obj, value]`.
  - `fdel` is called with `[obj]`.
- **member** (`member_get`, `member_set`) uses `PyMember_GetOneValue`
  and `PyMember_SetOneValue`. Python/structmember.c's implementations
  become the value forms. `PyMember_GetOne` and `PyMember_SetOne`
  become compatibility wrappers. Every existing behaviour is kept:
  truncation warnings, the handling of negative values for unsigned
  types, offsets, and the readonly and deletion checks. A deletion is
  refused for numbers, `_Py_T_VALUE` and `Py_T_BOOL`, as today, and
  allowed for `_Py_T_OBJECT`, `Py_T_OBJECT_EX` and `_Py_T_VALUE_EX`.
  The rules per member type are note 12 section 4's:
  - `_Py_T_VALUE` and `_Py_T_VALUE_EX` read the field as a value;
  - `Py_T_OBJECT_EX` canonicalises;
  - numbers come from `PyValue_From*`: signed fields from
    `PyValue_FromLongLong`, unsigned ones from
    `PyValue_FromUnsignedLongLong`, floats from `PyValue_FromDouble`;
  - a store to a number field takes an inline int as its `int32_t` and
    an inline float as its double, with today's checks: a negative value
    stored to an unsigned field keeps the `RuntimeWarning` and the
    conversion it has today, and a value out of the field's range keeps
    its `OverflowError` or truncation warning (as an error under
    `-W error`). An inline float stored to an integer field raises
    today's `TypeError`; as in the `PyLong_As*Value` converters, a box is
    made for that error only. A heap value takes today's `PyLong` path,
    `__index__` included;
  - `Py_T_BOOL` gives `True` or `False`;
  - an inline value stored to a `_Py_T_OBJECT` or `Py_T_OBJECT_EX`
    field is boxed with `PyValue_Object`, and the box is stored with no
    collecting call between. On failure it returns -1 and leaves the
    field unchanged.
- **getset** (`getset_get`, `getset_set`) calls the object-form getter
  and returns `PyValue_FromResult`. The setter gets `PyValue_Object` of
  the value, anchored raw. Rung 4 removes both.
- **ctypes fields** (`PyCField_get`, `PyCField_set`, in 2.1's list) keep
  calling ctypes' object-form `getfunc` and `setfunc` converters. The get
  returns `PyValue_FromResult` of the object the converter makes. The set
  appends `PyValue_Object(value)` raw to a span pushed around the
  converter call. The converters have the getset's shape, so rung 4
  converts them with the getsets.
- **`_tuplegetter`** returns the tuple's item value.
- **Functions** return a bound method. **Method** and **wrapper
  descriptors** return their bound objects, boxing an inline `self`
  (2.4). **classmethod** returns a bound method. **staticmethod**
  returns the callable.
- **`method_getattro` and `instancemethod_getattro`** return the
  function's attribute value.

## E. The wrappers (typeobject.c)

`wrapperfunc` stays an object form in this rung:

- `wrap_getattro` is new. Today `__getattribute__` goes through
  `wrap_binaryfunc`'s cast, which would be wrong once the slot returns
  a value. The new wrapper calls the slot, checks the result (F) and
  returns `PyValue_Object(res)`. `wrap_descr_get` does the same. Rung 3
  removes these two boxes.
- `wrap_setattr`, `wrap_delattr`, `wrap_descr_set` and
  `wrap_descr_delete` read the tuple's items as values, in place of
  `PyArg_UnpackTuple`, which boxes.
- An inline argument bound for a `PyObject *` parameter is boxed and
  anchored raw, then validated where the slot did. These parameters are
  `obj` and `type` of `__get__`, `obj` of `__set__` and `__delete__`,
  and `name`. So `object.__getattribute__(o, 3)` still raises the
  `TypeError` naming int.

## F. Debug checks and the injection site

- `_PyValue_CheckSlotResult(PyValue v, PyTypeObject *tp, const char
  *slot)` is a static inline in pycore_value.h, for debug builds only.
  A heap result whose type is exact int with a value that fits in int32,
  or exact float with a non-NaN value, is a non-canonical box. It
  reports and aborts, as the last item of this list describes.
  - It runs on every result of a `getattrofunc` or `descrgetfunc`
    dispatch, immediately after it, before anything converts it. A
    later outer check could blame the wrong slot, and a check after a
    getset's or wrapper's canonicalisation would never fire. The sites,
    from the inventory's dispatch list (A), with what each does with the
    result next:

    | site | result goes to |
    |---|---|
    | object.c `getattr_object_value` (`tp_getattro`) | passed through |
    | object.c `PyObject_GetOptionalAttrValue` (`tp_getattro`), which `getattr` with a default and `hasattr` reach | passed through, or dropped on a suppressed miss |
    | object.c `descr_get_value` (the executor and `get_method_value`) | passed through |
    | classobject.c `method_getattro`, `instancemethod_getattro` | passed through |
    | descrobject.c `classmethoddescr_call`, direct `classmethod_get` | the bound method's call, as an object |
    | typeobject.c `_Py_type_getattro_impl` (`meta_get`, `local_get`) | passed through |
    | typeobject.c `call_attribute` | the call, as a value |
    | typeobject.c `do_super_lookup` | passed through |
    | typeobject.c `type_get_doc`, `type_get_annotate`, `type_get_annotations`, `subtype_dict` | a getset getter's object result: `PyValue_Object`, anchored |
    | typeobject.c `_PyObject_LookupSpecialMethod`, `lookup_method_ex` | their `PyValue` outputs, directly |
    | typeobject.c `_PyObject_LookupSpecial` | an object for its callers: `PyValue_Object`, anchored |
    | typeobject.c `wrap_getattro`, `wrap_descr_get` | the wrapper's box |
    | _lsprof.c, legacy_tracing.c (`tp_descr_get` of a method descriptor) | `PyValue_Object` |

    The object bridges retire with the forms that need them: the getset
    getters in rung 4, the wrappers and `_PyObject_LookupSpecial`'s
    object result in rung 3, which carries `wrapperfunc` and the call of
    a looked-up special method as values. A direct call of a core
    function converted here (`PyObject_GenericGetAttr` from a forwarding
    getattro, `_PyObject_GenericGetAttrWithDict`) returns a value from
    the core's own executor, so it needs no check of its own.
  - It writes the slot, the type and the box's type to stderr with
    stdio and calls `abort()`. `Py_FatalError` is not used: it can
    display the exception and flush Python streams, which runs Python
    code. The check thus makes no collecting call.
- The tracer check (Python/gc_trace.c, `live_visit`): on a debug build,
  an inline encoding that reaches `live_visit` can only come from a
  `PyObject *` field, since `_Py_VISIT_VALUE` filters inline values. It
  stops, naming the owner's type.
- Two injection sites follow 10a's seven (pycore_tstate.h, at
  4112572f058 `_PyGC_SITE_TAKE_OWNERSHIP` is 7 and `_PyGC_SITE_COUNT` 8):
  - `_PyGC_SITE_SLOT_BOX` (8): `box_owner_for_descr()` (B), after the box
    is appended to the caller's span and before the descriptor call. The
    executor reaches it with `getattr(100000, "bit_length")` and
    `getattr(2.5, "real")`.
  - `_PyGC_SITE_RECEIVER_BOX` (9): `method_check_args`, after the
    receiver box is made and held for the call. The method path reaches
    it with `(100000).bit_length()`.
  - `_PyGC_SITE_COUNT` becomes 10.
