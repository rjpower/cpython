# 6d rung 3: calls and wrappers on values

Status: design, 2026-10-28. Specification: note 12 sections 5, 7 and 11
(rung 3). Starts from boil/6d at e0964287861 (rung 2 as gated, with
boil/10a at d5d83aad9f7). Line numbers are of that commit. boil/10a and
the integration branch are merged at every commit boundary.

The rung changes the call slot and the wrapper function types in place,
with every function of each type, so the tree builds at every commit.
`tp_call` returns a value; a `wrapperfunc` returns a value; the call
layer's internal forms return values and the object forms box at their
return. Rung 2's wrapper boxes go. Getsets stay object forms until
rung 4.

## A. The typedefs

- `callfunc`, new in Include/object.h beside `vectorcallfunc`:

  ```c
  typedef PyValue (*callfunc)(PyObject *callable, PyObject *args,
                              PyObject *kwargs);
  ```

  `PyTypeObject.tp_call` becomes `callfunc` (Include/cpython/object.h).
  `ternaryfunc` stays, for `nb_power` and `nb_inplace_power`.
  Python/slots.toml's `Py_tp_call` entry takes `functype = 'callfunc'`,
  and Tools/build/generate_slots.py regenerates
  pycore_slots_generated.h and slots_generated.c.
- `wrapperfunc` and `wrapperfunc_kwds` (Include/cpython/descrobject.h)
  return `PyValue`. `self` and `args` stay objects: a wrapper's receiver
  is an object, as a descriptor's owner is in rung 2 (an inline one is
  boxed by the caller, below), and `args` is the protocol's tuple.
- The result contract is `vectorcallfunc`'s: a canonical value, or
  `PyValue_NULL` with an exception set.

**The inventory.** `slot_inventory.py --where --calls tp_call` (its
typedef map gains `tp_call: callfunc`) lists 34 entries in 27 functions,
`PyVectorcall_Call` in eight types:

- core: `PyVectorcall_Call`, `cfunction_call`, `wrapperdescr_call`,
  `wrapper_call`, `classmethoddescr_call`, `sm_call`, `type_call`,
  `instancemethod_call`, `ga_call`, `proxy_call`,
  `constevaluator_call`, and `slot_tp_call` through `slotdefs`;
- modules: `itemgetter_call`, `attrgetter_call`, `methodcaller_call`,
  `partial_call`, `keyobject_call`, `lru_cache_call`,
  `TaskStepMethWrapper_call`, `scanner_call`, `encoder_call`,
  `pysqlite_connection_call`, `PyCFuncPtr_call`, `_DictRemover_call`;
- test and tool types: `VectorCallClass_tpcall`, `call_return_args`,
  fpcast.c's cast entries, gc_trace.c's `trap_call`.

`PyType_Slot` entries are not type-checked, so the inventory is re-run
after each merge, as in rung 2. The wrappers are typeobject.c's 29
`wrap_*` functions, named in `slotdefs` only.

## B. The call layer (Objects/call.c, pycore_call.h)

Each function keeps 10a's mark and stays clean in the C mode; where a
body changes, the span moves with it, and the stamp rule checks it at
every build (note 12 section 7: 6d moves the marks with the body).

- `_PyObject_MakeTpCall` calls the slot through
  `_PyCFunctionWithKeywords_TrampolineCall`'s value form (D) and
  returns its value after `_PyValue_CheckSlotResult(res, tp,
  "tp_call")` and `_Py_CheckFunctionResultValue`. The
  `PyValue_FromObject` of the result goes.
- `_PyObject_Call` becomes `_PyObject_CallValue`, returning `PyValue`:
  the vectorcall branch returns `_PyVectorcall_Call`'s value, the slot
  branch the slot's checked value. Its callers change with it:
  `PyObject_Call`, `call_method` (C), signalmodule.c's handler call,
  and `CALL_FUNCTION_EX` (E). No object form of the internal function
  remains.
- `PyObject_CallValue(PyObject *callable, PyObject *args, PyObject
  *kwargs)`, new public (Include/cpython/abstract.h), is
  `_PyObject_CallValue` on the current thread. `PyObject_Call` is
  `PyValue_Object(PyObject_CallValue(...))`, the compatibility form.
- `PyVectorcall_Call` returns `PyValue`: it is the function a type puts
  in `tp_call` (typeobj.rst says so), like `PyObject_GenericGetAttr` in
  rung 2, so it changes in place. Its two other callers take the value:
  `cfunction_call` returns it, and _testcapi's `pyvectorcall_call`
  boxes it.
- `_PyObject_Call_Prepend` becomes `_PyObject_Call_PrependValue`,
  returning `PyValue` and taking `obj` as a value, as
  `_PyObject_VectorcallPrependValue` does. Its callers: `call_method`
  and `slot_tp_new`'s call of `__new__` (typeobject.c:11016), which
  boxes its result, a new object.
- `PyEval_CallObjectWithKeywords` boxes `_PyObject_CallValue`'s result.

## C. typeobject.c

- `call_method` becomes `call_method_value`, returning the call's value
  through `_PyObject_Call_PrependValue` or `_PyObject_CallValue`. Its one
  caller is `slot_tp_call`, which returns it: a callable instance's
  result is no longer boxed (`call_instance`).
- `type_call` returns `PyValue_FromResult` of the object it makes.
- The 29 `wrap_*` functions return `PyValue`:
  - a wrapper of an object-returning slot (`wrap_binaryfunc*`,
    `wrap_ternaryfunc*`, `wrap_unaryfunc`, `wrap_indexargfunc`,
    `wrap_sq_item`, `wrap_richcmpfunc` and the `richcmp_*` family,
    `wrap_buffer`) returns `PyValue_FromResult` of it, so an int or
    float result is canonical at the wrapper;
  - a wrapper of a value-returning slot returns the slot's value with no
    box: `wrap_getattro` and `wrap_descr_get` (rung 2's boxes), and
    `wrap_next`, whose `PyValue_Object` goes;
  - `wrap_call` dispatches `callfunc`, checks the result with
    `_PyValue_CheckSlotResult` and returns it;
  - a wrapper of an int or bool result (`wrap_lenfunc`,
    `wrap_hashfunc`, `wrap_inquirypred`, `wrap_objobjproc`) returns
    `PyValue_FromLongLong` or `Py_True`/`Py_False` as values, with no
    allocation for a value in int32;
  - wrappers that return `None` (`wrap_sq_setitem`, `wrap_sq_delitem`,
    `wrap_objobjargproc`, `wrap_delitem`, `wrap_setattr`,
    `wrap_delattr`, `wrap_descr_set`, `wrap_descr_delete`, `wrap_del`,
    `wrap_init`, `wrap_releasebuffer`) return `PyValue_FromObject(Py_None)`.
- `slotdefs`' `_Py_FUNC_CAST(wrapperfunc, wrap_call)` and
  `wrap_init` casts stay casts, to the new type.

The typeobject.c hunks are the wrappers' returns, `call_method_value`,
`slot_tp_call`, `type_call` and the two casts; the bodies keep their
argument handling.

## D. Descriptors and the module types

- descrobject.c: `wrapperdescr_raw_call` returns the wrapper's value.
  `wrapperdescr_call` reads `self` with `PyTuple_GET_VALUE`; an inline
  receiver (`int.__add__(5, 3)`) is boxed into the frame's span, as
  `method_check_args` boxes it in rung 2, and `_PyGC_SITE_RECEIVER_BOX`
  fires after that box too. `wrapper_call` and `classmethoddescr_call`
  return values; `classmethoddescr_call`'s check-then-borrow of rung 2
  goes, since its result is returned as it is.
- methodobject.c `cfunction_call`, funcobject.c `sm_call`,
  classobject.c `instancemethod_call`, genericaliasobject.c `ga_call`,
  weakrefobject.c `proxy_call` (which forwards to `PyObject_CallValue`),
  typevarobject.c `constevaluator_call`: values. A body that ends in an
  object-form call takes the value form where one exists
  (`PyObject_CallValue`, `PyObject_VectorcallValue`), and otherwise
  returns `PyValue_FromResult`.
- The module types: the value form of the call they end in, or
  `PyValue_FromResult` at the return. `partial_call` and
  `methodcaller_call` end in `PyObject_Call` and return
  `PyObject_CallValue`'s value; the rest (`lru_cache_call`'s wrapper,
  `itemgetter_call`'s `PyObject_GetItem`, the json, sqlite3, asyncio and
  ctypes calls) canonicalise their object result with
  `PyValue_FromResult`, which allocates nothing.
- The wasm trampolines (pycore_wasm_trampoline.h,
  Python/wasm_trampoline.c): `_PyWasm_TrampolineCallValue` with
  `callfunc`'s signature, and
  `_PyCFunctionWithKeywords_TrampolineCallValue` on both branches of the
  header, used by `_PyObject_MakeTpCall`. `cfunction_call`'s
  `METH_VARARGS` call and `descr_get_trampoline_call` keep the object
  forms (the getset ones change in rung 4). No gate builds wasm: the two
  trampolines are unbuilt and reviewed by inspection.

## E. CALL_FUNCTION_EX (bytecodes.c)

The three `PyObject_Call` sites of `_DO_CALL_FUNCTION_EX` (5191, 5241)
and `_CALL_FUNCTION_EX_NON_PY_GENERAL` (5322) call `_PyObject_CallValue`
and take the result as the output value; the instrumented path's
C_RAISE and C_RETURN tests read `PyValue_IsNull`. The bytecodes.c hunk
is those three calls and their result handling; generated_ir_cases.c.h
is regenerated. ceval.c's `PyObject_Call` (2340) keeps the object form.

## F. Checks and the injection site

- `_PyValue_CheckSlotResult(res, tp, "tp_call")` after the slot call in
  `_PyObject_MakeTpCall`, `_PyObject_CallValue` and `wrap_call`, the
  three dispatches the inventory's `--calls` lists. An old-form slot
  reached through an unchecked `PyType_Slot` entry returns a pointer
  whose value is an object encoding; a box of an int in int32 or of a
  non-NaN float is caught there.
- `_PyGC_SITE_RECEIVER_BOX` also fires in `wrapperdescr_call` after the
  receiver box (D).
- No new site number.

## G. Docs

- `Doc/c-api/typeobj.rst`: `tp_call` as `callfunc` in the slot table,

  signature where the vectorcall section names it.
- `Doc/c-api/call.rst`: `PyObject_CallValue`; `PyVectorcall_Call`

## Risks

- **10a marks the same functions.** call.c's functions are precise
  already; 10a's rung 2 remainder marks typeobject.c's `slot_*` and
  `vectorcall_method`, and descrobject.c's call functions. This rung
  rewrites `call_method` and `slot_tp_call` and changes the call
  functions' returns. Each body stays in the C mode's subset where it is
  marked, and the hunks touch returns, not anchors, where it is not.
  The coordinator orders the merges.
- **Silent casts.** `PyType_Slot` entries of `Py_tp_call` outside the
  inventory (a merge from upstream or 10a) return an object as a value.
  The check (F) catches a non-canonical box on debug builds; a pointer
  to any other object is a valid value, so the old form works for every
  result but a canonicalisable box.
- **`PyVectorcall_Call` changes signature in place.** A third-party
  caller that uses its result as an object breaks at compile time. In
  the tree there are two (B). Ports are deferred until the API settles,
  so none is checked now; the docs say so.
