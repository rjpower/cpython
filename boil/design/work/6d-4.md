# 6d rung 4: getsets on values

Status: design, 2026-10-28, for review rounds 1 and 2. Specification:
note 12 sections 2.1, 2.2, 4, 8 and 11 (rung 4). Starts from boil/6d at
04ffa14a62b (rung 3 commit 3) after the integration merge that rung 3's
commit 4 makes; line numbers are of 04ffa14a62b. boil/10a and the
integration branch are merged at the rung's start and at its end, as
the procedure of 2026-10-28 says.

The rung changes `getter` and `setter` in place, with every function of
each type, so the tree builds at every commit. A getter returns a
value; a setter takes one. Number-returning getters return inline
values without making an object; setters read a value with the value
accessors, or box it at their top, or box it at a kept field. Rung 2's
canonicalising `getset_get` and boxing `getset_set` go.

## Cut criterion (first, because it decides the rest)

The hard stop is 2026-10-31 12:00 PDT. **Rung 4 is cut to step 6e
unless its conversion commits are through gate 1 on build/default and
build/debug by 2026-10-30 18:00 PDT.** The coordinator applies the cut;
the step agent reports the state at that time.

**The conversion has two families, each converted whole or not at
all:** the getter family (`getter`, every getter function, Clinic's
`@getter`, `PyObject_GenericGetDict`, the getter dispatch sites) and
the setter family (`setter`, every setter function, Clinic's `@setter`,
`PyObject_GenericSetDict`, the setter dispatch sites). Each is one
commit, because a typedef changed with only some of its functions
does not build once the casts are gone (C below). So a cut mid-way
leaves one of three trees, none with a dual form:

1. Neither family converted: rung 2's `getset_get` and `getset_set`
   stay as they are, and note 08's register gets "getset getters and
   setters are object functions" for 6e (note 12 section 8).
2. Getters converted, setters not: `getset_set` keeps rung 2's box at
   its top, which is the rule for setters that box anyway; the register
   row names the setter family alone.
3. Both converted.

A family's branch that is not through gate 1 at the cut is not merged.
There is no per-file or per-module partial state: no getter of the old
form beside one of the new, no adapter that converts one into the
other. The write-up, gate 4 and note 06 section 21 happen whatever is
cut.

## A. The typedefs

```c
typedef PyValue (*getter)(PyObject *, void *);
typedef int (*setter)(PyObject *, PyValue, void *);
```

`self` stays an object (note 12 section 2.4): an inline owner's getset
(`(5).real`, `(2.5).imag`) keeps the binding box that the box audit
lists as a residue, owned by note 12's open question 1. A setter's
deletion is `PyValue_NULL`, as rung 2's slot setters do.

## B. The generic dict functions (note 12 section 2.2)

`PyObject_GenericGetDict` returns `PyValue` and `PyObject_GenericSetDict`
takes one, in place, as `PyObject_GenericGetAttr` did in rung 2. The
dict is an object, so the getter returns `PyValue_FromObject(dict)` and
the setter refuses an inline value with today's `TypeError` ("__dict__
must be set to a dictionary, not a 'int'"), named by `PyValue_Type`,
without a box. The four direct callers (typeobject.c 3723, which is
`subtype_dict`'s fallback and returns the value as it is, and 7598,
funcobject.c 1382 and 1413) read the dict with `PyValue_ObjectBorrow`
after a null test. Identity of the dict and the
refusal of a deletion are unchanged.

## C. The casts and the dispatch sites

- The tree's `(getter)` and `(setter)` casts go (note 12 section 2.1),
  so the compiler checks every initialiser; a function of the old form
  then fails to build. `_Py_FUNC_CAST(getter, ...)` in fpcast.c keeps
  its cast on purpose (the Wasm fixtures) and gets value fixtures, as
  rung 3 did for `tp_call`.
- `getset_get` returns the getter's value through
  `descr_get_trampoline_call`, with `_PyValue_CheckSlotResult(res,
  Py_TYPE(obj), "getter")`: a third-party getter cast to the new type
  that returns a box of an int in int32 or a non-NaN float stops a debug
  build, as the slot checks do. Its `PyValue_FromResult` goes.
- `getset_set` passes the value; its box, span and the comment go.
- posixmodule.c 3568 (`statx`'s result builder calls its getters
  directly) reads the value and boxes it once for the tuple it fills;
  it is the only direct dispatch outside descrobject.c.
- The Wasm trampolines take the new types (`descr_get_trampoline_call`
  returns `PyValue`).

## D. Argument Clinic

- `@getter`: the parser prototype returns `PyValue` and the parser
  sets `data.value_return`, so `CReturnConverter.result_assignment`
  wraps the impl's object in `PyValue_FromResult`. The 17 Clinic
  getters that already declare a return converter (`-> bool`, `-> int`,
  `-> long`, `-> unsigned_int`, `-> unsigned_long`, `-> Py_ssize_t`;
  _asyncio, _ssl, _io) return through the converters'
  `value_conversion_fn` (`PyValue_FromLongLong` and friends) with no
  object. Impls that build a number object without a converter
  (`_hmac.HMAC.block_size` and `digest_size`, `_ssl`'s
  `num_tickets`, `security_level`, `options`, `MemoryBIO.pending`,
  `SSLSession.time`, `timeout`, `ticket_lifetime_hint`,
  `_sqlite3.Cursor.arraysize`) keep their object return in this rung:
  changing an impl's declared return is a per-module change with its
  own tests, listed in the hand-off; `PyValue_FromResult` canonicalises
  their result, so the attribute reads as an inline value either way,
  at the cost of the object they make.
- `@setter`: the parser takes `PyValue arg`; `SETTER_PREAMBLE` tests
  `PyValue_IsNull(arg)`; `render_setter_value` uses the converter's
  `parse_value_arg`, which reads an int or float converter's value
  without a box and boxes for `object` (box at the top). The impl is
  unchanged.
- `GETSETDEF_PROTOTYPE_*` lose their casts.
- clinic.test.c's expected output and test_clinic follow; `make clinic`
  leaves the tree unchanged (gate 3).

## E. The hand-written conversion

The rules, applied per function by the step agent or by subagents
working one directory each under these rules, with the compiler as the
first check and the step agent's review of each diff as the second:

1. **Getters.** The return type becomes `PyValue`. Each `return NULL`
   becomes `return PyValue_NULL`. A return of a number constructor
   becomes the value constructor on the same C expression. `Py_RETURN_
   NONE/TRUE/FALSE` become `return PyValue_FromObject(Py_None)` etc.
   Any other `return expr` becomes `return PyValue_FromResult(expr)`.
   A getter whose result an object-typed caller uses directly (found by
   the build) has that caller read it with `PyValue_Object`.
2. **Setters.** The value parameter becomes `PyValue value`. A setter
   that reads a number (`OSError_written_set`, `_decimal`'s
   `context_set*`, `Dialect`'s) reads it with the value accessor
   (`PyLong_AsLongValue`, `PyLong_AsSsize_tValue`,
   `PyFloat_AsDoubleValue`), with today's errors. A setter that keeps
   or passes on an object boxes at its top: `PyObject *value_o =
   PyValue_Object(value)`, null-tested, with deletion tested first; a
   setter that stores into a `PyObject *` field stores that box (note 12
   section 4, native fields box). No setter holds its box across a
   collecting call without its owner's field or a local the stack scan
   covers; the precise functions among them are listed by the C mode
   (H).
3. **Rung 2's interim forms go:** typeobject.c's `descr_get_object`
   (its two callers read the getter's value), descrobject.c's comments
   at 186 and 246, and the box audit's "getset" note.
4. **Out of scope, said in the code:** ctypes's per-format converters
   (`setfunc`, `getfunc` in cfield.c) are not getsets; `PyCField_set`
   boxes at its top, which is the setter rule, so rung 2's comment at
   cfield.c 269 is rewritten to say so and loses "until rung 4". Their
   conversion is a ctypes change for the ports phase.

## Risks

- **Size.** About 340 hand-written functions in 78 files. The rules
  are mechanical and the compiler checks every initialiser once the
  casts are gone; the risk is a missed semantic, chiefly a setter that
  used `value == NULL` as deletion after a box (rule 2 tests deletion
  first). Each subagent's diff is reviewed against the rules by the
  step agent before it is committed.
- **Callers of getters as functions.** A getter called directly
  (`func_get_code`, `PyObject_GenericGetDict`) changes type; the build
  finds every one.
- **Third-party getters.** A getset table of an unconverted extension
  is an ABI mismatch, as every slot of note 12 section 2.1; the debug
  check catches a box that should be inline, nothing more. Ports are
  deferred.
- **Merge with 10a.** 10a rung 2b holds its typeobject.c items until
  this rung lands, and this rung does not touch call.c; descrobject.c's
  hunks are the two dispatch functions only.
