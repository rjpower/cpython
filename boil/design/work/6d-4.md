# 6d rung 4: getsets on values

Status: design, 2026-10-28, revised after review rounds 1 and 2 (both
revise; Review below). Two rounds are the cap; the coordinator rules on
the round 2 revisions. Specification:
note 12 sections 2.1, 2.2, 4, 8 and 11 (rung 4). Starts from boil/6d at
04ffa14a62b (rung 3 commit 3) after the integration merge that rung 3's
commit 4 makes; line numbers are of 04ffa14a62b. boil/10a and the
integration branch are merged at the rung's start and at its end, as
the procedure of 2026-10-28 says.

The rung changes `getter` and `setter` in place, with every function of
each type, so the tree builds at every commit. A getter returns a
value; a setter takes one. Number-returning getters return inline
values without making an object; setters read a value with the value
accessors, or box it at their top, or box it at a kept field. Rung 2's
canonicalising `getset_get` and boxing `getset_set` go.

## Cut criterion

The hard stop is 2026-10-31 12:00 PDT. **Rung 4 is cut to step 6e
unless its conversion commits are through gate 1 on build/default and
build/debug by 2026-10-30 18:00 PDT.** The coordinator applies the cut;
the step agent reports the state at that time.

**The conversion has two families, each converted whole or not at
all:** the getter family (`getter`, every getter function, Clinic's
`@getter`, `PyObject_GenericGetDict`, the getter dispatch sites) and
the setter family (`setter`, every setter function, Clinic's `@setter`,
`PyObject_GenericSetDict`, the setter dispatch sites). Each is one
commit, because a typedef changed with only some of its functions
does not build once the casts are gone (C below). So a cut mid-way
leaves one of three trees, none with a dual form:

1. Neither family converted: rung 2's `getset_get` and `getset_set`
   stay as they are, and note 08's register gets "getset getters and
   setters are object functions" for 6e (note 12 section 8).
2. Getters converted, setters not: `getset_set` keeps rung 2's box at
   its top, which is the rule for setters that box anyway; the register
   row names the setter family alone.
3. Both converted.

A family's branch that is not through gate 1 at the cut is not merged.
There is no per-file or per-module partial state: no getter of the old
form beside one of the new, no adapter that converts one into the
other. The write-up, gate 4 and note 06 section 21 happen whatever is
cut.

## A. The typedefs

```c
typedef PyValue (*getter)(PyObject *, void *);
typedef int (*setter)(PyObject *, PyValue, void *);
```

`self` stays an object (note 12 section 2.4): an inline owner's getset
(`(5).real`, `(2.5).imag`) keeps the binding box that the box audit
lists as a residue, owned by note 12's open question 1. A setter's
deletion is `PyValue_NULL`, as rung 2's slot setters do.

## B. The generic dict functions (note 12 section 2.2)

`PyObject_GenericGetDict` returns `PyValue` and `PyObject_GenericSetDict`
takes one, in place, as `PyObject_GenericGetAttr` did in rung 2. The
dict is an object, so the getter returns `PyValue_FromResult(dict)`:
`_PyObject_EnterDictMode` and `ensure_nonmanaged_dict` return NULL when
the dict cannot be made, and `PyValue_FromResult` turns that into
`PyValue_NULL` with the exception kept (`PyValue_FromObject` requires a
pointer). The setter refuses an inline value with today's `TypeError` ("__dict__
must be set to a dictionary, not a 'int'"), named by `PyValue_Type`,
without a box. The four direct callers (typeobject.c 3723, which is
`subtype_dict`'s fallback and returns the value as it is, and 7598,
funcobject.c 1382 and 1413) read the dict with `PyValue_ObjectBorrow`
after a null test. Identity of the dict and the
refusal of a deletion are unchanged. Test 4 fails the dict's creation
for both layouts (a managed dict, through `_PyObject_EnterDictMode`, and
a dict at `tp_dictoffset`, through `ensure_nonmanaged_dict`): `__dict__`
raises `MemoryError`, and the attributes stored before read back.

## D. Argument Clinic

- `@getter`: the parser prototype returns `PyValue` and the parser
  sets `data.value_return`, so `CReturnConverter.result_assignment`
  wraps the impl's object in `PyValue_FromResult`. The 17 Clinic
  getters that already declare a return converter (`-> bool`, `-> int`,
  `-> long`, `-> unsigned_int`, `-> unsigned_long`, `-> Py_ssize_t`;
  _asyncio, _ssl, _io) return through the converters'
  `value_conversion_fn` (`PyValue_FromLongLong` and friends) with no
  object. Impls that build a number object without a converter
  (`_hmac.HMAC.block_size` and `digest_size`, `_ssl`'s
  `num_tickets`, `security_level`, `options`, `MemoryBIO.pending`,
  `SSLSession.time`, `timeout`, `ticket_lifetime_hint`,
  `_sqlite3.Cursor.arraysize`) keep their object return in this rung;
  `PyValue_FromResult` canonicalises their result, so the attribute
  reads as an inline value either way, at the cost of the object they
  make. Their retirement is step 6e's, listed per module in the 6e
  inputs (note 06 row 6e), as ruled. The list for that manifest also
  takes `frame.f_lineno`, `frame.f_lasti`, `_ThreadHandle.ident`, and
  `_SSLContext.minimum_version`, `maximum_version` and `protocol`; note
  06's 6e row gains the manifest in this rung's docs commit.
- **Forwarding impls convert here, not in 6e.** An impl that only
  forwards an attribute through the object protocol boxes an inline
  result for the parser to canonicalise again. Each such impl, and the
  helper it shares, returns a value with Clinic's `-> value` return
  converter:
  - `_io._Buffered.name` and the other `_Buffered` getters that call
    `PyObject_GetAttr` on the raw stream take `PyObject_GetAttrValue`;
  - `_io.TextIOWrapper.name` and its kin delegate through
    `buffer_getattr`, which becomes a value function;
  - `socket.timeout` calls `sock_gettimeout_impl`, which becomes a value
    function (`PyValue_FromDouble`, or `None`); `gettimeout()`, its other
    caller, boxes the value with `PyValue_Object` at its return, the
    method being an object function until the method step.
  The audit adds `BufferedReader.name` of a raw stream whose `name` is
  an uncached int, and a socket's non-`None` timeout: 0 boxes and 0
  allocations each.
- `@setter`: the parser takes `PyValue arg`. The converters that
  define `parse_value_arg` (`bool`, `int`, `long`, `long long`,
  `Py_ssize_t`, `float`, `double` and `value`) read the value without a
  box. The others (the unsigned and fixed-width ones, `uint32` of
  `Cursor.arraysize` and `_ssl`'s among them) return `None` from
  `parse_value_arg`; the parser then boxes `arg` once, null-tests the
  box (returning -1 before the impl on failure), and runs today's
  `PyArg_Parse` fallback on it. Reading those converters' values
  without a box is step 6e's, with the getters (Hand-off).
  - A setter that refuses deletion (`SETTER`): `SETTER_PREAMBLE` tests
    `PyValue_IsNull(arg)` and raises as today.
  - A setter that allows it (`SETTER_AND_DELETER`: `frame.f_trace`,
    `function.__annotations__`, ctypes's accessors): the impl's
    parameter keeps its `NULL` initialisation, and the conversion,
    boxing included, sits inside `if (!PyValue_IsNull(arg))`, where
    `arg != NULL` is today, so a deletion reaches the impl as `NULL`
    and is never taken for a failed box.
  - Generator cases in clinic.test.c for both kinds: deletion, `None`,
    an ordinary assignment, and a conversion failure, each with a value
    converter and with a boxing one.
- `GETSETDEF_PROTOTYPE_*` lose their casts.
- clinic.test.c's expected output and test_clinic follow; `make clinic`
  leaves the tree unchanged (gate 3).

## E. The hand-written conversion

The rules, applied per function by the step agent or by subagents
working one directory each under these rules, with the compiler as the
first check and the step agent's review of each diff as the second.
Rule 0 comes before rules 1 and 2: a mechanical reading of 1 and 2 makes
round trips where the storage already holds a value.

0. **Value storage and value protocols.** A getter whose attribute is
   held as a value returns it as it is, and a setter stores the value
   with the value API; neither makes an object.
   - `cell_get_contents` returns `_PyCell_GetValue(cell)` after its
     empty test; `cell_set_contents` stores with `PyCell_SET_VALUE`
     (today the getter boxes with `PyValue_Object` and rule 1 would
     canonicalise the box back, and the setter's `PyCell_SET`
     canonicalises the object its caller boxed).
   - Dict-backed accessors (`module_get_annotations` and
     `module_set_annotations`, `type_get_annotations` and their kin)
     read with
     `PyDict_GetItemRefValue` or `_PyDict_GetItemValue` and store with
     `_PyDict_SetItemValue`; deletion keeps `PyDict_Pop`.
   - A getter that calls a value protocol (`PyObject_GetAttrValue`,
     `PyObject_GetItemValue`) returns its value.
   The box audit gains cell reads and writes (`cell_contents`) of
   uncached ints (100000 + n) and floats (2.5 * n): 0 boxes and 0
   allocations per iteration.
1. **Getters.** The return type becomes `PyValue`. Each `return NULL`
   becomes `return PyValue_NULL`. A return of a number constructor
   becomes the value constructor on the same C expression. `Py_RETURN_
   NONE/TRUE/FALSE` become `return PyValue_FromObject(Py_None)` etc.
   Any other `return expr` becomes `return PyValue_FromResult(expr)`.
   A getter whose result an object-typed caller uses directly (found by
   the build) has that caller read it with `PyValue_Object`.
2. **Setters.** The value parameter becomes `PyValue value`. A setter
   that reads a number keeps its conversion's protocol, through the
   value form of the same function:

   | today | value form | setters |
   |---|---|---|
   | `PyNumber_AsSsize_t(v, exc)` (`__index__`, overflow as `exc`) | `PyNumber_AsSsize_tValue(v, exc)` | `OSError_written_set` (`PyExc_ValueError`) |
   | `PyLong_AsSsize_t(v)` (int only, `OverflowError`) | `PyLong_AsSsize_tValue(v)` | `_decimal`'s `context_setprec`, `setemin`, `setemax`, `setcapitals`, `setclamp` |
   | `PyLong_AsLong(v)`, `PyLong_AsInt(v)` | `PyLong_AsLongValue(v)`, `PyLong_AsIntValue(v)` | each by its call |
   | `PyFloat_AsDouble(v)` | `PyFloat_AsDoubleValue(v)` | each by its call |
   | `PyObject_IsTrue(v)` | `PyObject_IsTrueValue(v)` | each by its call |

   Each setter's conversion is read when it is converted and mapped to
   the value form of the same function; a conversion with no value form
   boxes at the top. `_decimal`'s `context_setattrs` calls six of the
   setters directly with objects from `Context.__init__`; it passes
   `PyValue_FromObject(arg)` of each. A setter that keeps or passes on
   an object boxes at its top: `PyObject *value_o =
   PyValue_Object(value)`, null-tested, with deletion tested first; a
   setter that stores into a `PyObject *` field stores that box (note 12
   section 4, native fields box). No setter holds its box across a
   collecting call without its owner's field or a local the stack scan
   covers; a precise function's anchor holds the raw box (a canonical
   value of an inline int roots nothing). The precise functions among
   them are listed by the C mode.
3. **Rung 2's interim forms.** typeobject.c's `descr_get_object` has five
   callers, not two: `type_get_doc`, `type_get_annotate`,
   `type_get_annotations`, `subtype_dict` and `_PyObject_LookupSpecial`.
   The four getters call the descriptor's `tp_descr_get` value form,
   check it with `_PyValue_CheckSlotResult(res, Py_TYPE(descr),
   "tp_descr_get")` and return the value without a box.
   `_PyObject_LookupSpecial` stays object-returning (rung 3 section H)
   and keeps `descr_get_object`, its one remaining caller, so the
   check and its diagnostic stay; `DebugCheckTests.test_descr_get` runs
   unchanged, and a case through `type_get_doc` is added. descrobject.c's
   comment at 186 goes in commit 1, at 246 in commit 2, and the box
   audit's "getset" note in commit 3.
4. **Signatures.** With the casts gone, a getter or setter declared with
   a typed `self` (`BinaryReaderObject *` in _remote_debugging/module.c,
   and the others the build finds) takes `PyObject *self` and casts in
   its body, as the slot functions do.
5. **Out of scope, said in the code:** ctypes's per-format converters
   (`setfunc`, `getfunc` in cfield.c) are not getsets; `PyCField_set`
   boxes at its top, which is the setter rule, so rung 2's comment at
   cfield.c 269 is rewritten to say so and loses "until rung 4". Their
   conversion is a ctypes change for the ports phase.
