## What changes, by commit

Each commit is preceded by gate 1 on the set named with it, on
build/default and build/debug. The precise functions the rung edits
(`collect_from_entry()`, `_Py_RunGC()`, `_PyGC_LiveCollectHere()`,
`_PyGC_CollectNoFail()`, `collect()`) pass the C mode
(`Tools/cases_generator/root_check_c.py Python/gc_live.c`, which the
build runs as `GC_PRECISE_CHECK`) at each commit; any new precise mark
passes the outlined-callee audit at gate 3.

1. **Node queue and batch** (gc_live.c). `live_call` becomes a node;
   `struct _gc_live_state` holds head and tail; `queue_push()` appends
   a node to a batch; `run_queue()` pops the head and frees the node
   after the call; the memmove and `running_queue` count go. The
   callback node is allocated before `_PyWeakref_ClearRef()`. A
   collection's batch is spliced onto the collecting queue (no routing
   yet), so behaviour is unchanged. `gc_queue_fail_alloc()`. Gate 1:
   test_gc, test_weakref, test_finalization.
2. **Domain in the result, owner lookup, phases, drain permission**
   (gc_trace.c, pycore_gc_trace.h, gc_live.c, pycore_gc.h,
   pylifecycle.c, _testinternalcapi.c). `_PyGC_LiveOwner()`.
   `phase` (initialising, open, retiring, closed);
   `_PyGC_LiveOpenQueue()` at the end of `pycore_interp_init()`;
   `live_python_ok()` gates `run_queue()`, `invoke_gc_callback()` and
   `debug_write()`'s Python path; `_Py_RunGC()` collects if due and
   allowed, then drains if open and non-empty; `_PyGC_Fini()` drains (if
   ever opened) and closes, keeping the state; `get_live()` refuses a
   closed state; `_PyGC_CollectNoFail(NULL)` does nothing.
   `gc_queue_info()`, `check_signals_loop()`. Debug builds count
   misrouted calls in `gc_queue_info()["misrouted"]` (non-zero on the B
   repro until commit 3). This commit alone ends the crash. Gate 1:
   test_gc, test_weakref, test_capi.test_misc, and the one-line repro
   `PYTHON_GCSTRESS=1000 ./python -c 'import _testcapi;

3. **Routing, the pin, delivery markers** (gc_live.c, gc_trace.c,
   pycore_interp_structs.h, ceval_gil.c, pystate.c,
   _testinternalcapi.c). `route_calls()` splices the batch by owner

## Invariants the rung relies on

- A heap block's segment's sub-process is that of the interpreter whose
  thread allocated the block, until absorption moves it to the main
  interpreter's (note 13 section 2).
- The domain has one GIL (commit 8; until it lands, the all-true
  `InterpreterConfigTests` row is the only creator of the other case,
  and it runs on one OS thread).
- No Python code runs between a collection's batch and its splice.
- Every mark holds the head lock from `live_domain()` to the end of the
  heap walk, the pin holds from `live_domain()` to the splice, and the
  adoption takes the head lock with no pin held, so a collection sees
  an interpreter either in the domain or adopted, and none it names is
  freed before its splice.
- `_PyGC_LiveVisitRoots()` runs for every domain interpreter, so every
  queue, waiting list and adopted state is a root of every domain
  collection.
- Every path that clears an arena's abandoned bit takes the arena's
  `abandoned_visit_lock` first (`mi_option_visit_abandoned` on, reclaim
  on free off); debug builds assert both options at startup.

## Risks

- **A test that waited for another interpreter's callback on the
  collecting thread.** Commit 3's set runs every interpreter and
  threading suite; a failure is traced (PROCESS.md section 4) and is
  either a test that assumed the old rule (adjusted, with the reason in
  its commit) or a missed drain point.
- **A main-interpreter call waiting on an idle subinterpreter** (3.5).
  A test that expects a main-interpreter finalizer to run at once when
  its object is reached from an idle subinterpreter's finalizer now
  sees it wait. The dependency is real; such a test is traced.
- **Draining with collection off.** Commit 2 makes `_Py_RunGC()` drain
  under `gc.disable()`; a test that disables gc to keep finalizers from
  running between two statements now sees a queued call run at the next
  breaker. That is when it ran before an inline collection left it
  queued; traced if a test shows it.
- **The pin.** A collection that leaves `collect()` without unpinning
  blocks every deletion. Every exit is covered by the debug assertion
  at `collect()`'s end, and 9.16 runs under ASan.
- **Absorption.** `_mi_subproc_absorb()` edits mimalloc's abandoned
  bookkeeping. Its preconditions (no thread of the retired sub-process,
  the GIL held, the head lock held, the lock order of 5.3) are asserted
  in debug builds; 9.7 (e) runs it a hundred times and 9.18 under
  concurrent isolated allocation, both under ASan.
- **Retirement reentry.** Free functions run with the interpreter
  retiring; 9.5 (c) covers collection, GIL release, queued calls and a
  refused new extra.
- **The registration refusal** breaks an extension that watches or tags
  another interpreter's object on a shared heap. None is known in the
  tree; test_capi.test_watchers and test_code run in commit 5.
- **Heap immortals of adopted states** live as long as the process (the
  `all` and `any` of every deleted legacy interpreter and what they
  reach): recorded in 9.7 (e)'s RSS.
- **The close's metadata walk** costs a heap walk of the closing
  interpreter's sub-process per shared-heap teardown; recorded in note
  13 section 11's teardown numbers.
- **`take_gil()` cost.** One relaxed load and a branch per acquisition;
  measured by the pipe-read loop.
- **Concurrent rungs.** 10a edits gc_trace.c's verifier,
  pycore_gc_trace.h, codeobject.c, _testinternalcapi.c and test_gc.py;
  6d edits typeobject.c. The 7a hunks are its own blocks; each merge of
  the integration head is checked with `git diff` over those files
  before the next commit.
