## What changes, by commit

Each commit is preceded by gate 1 on the set named with it, on
build/default and build/debug. The precise functions the rung edits
(`collect_from_entry()`, `_Py_RunGC()`, `_PyGC_LiveCollectHere()`,

(`Tools/cases_generator/root_check_c.py Python/gc_live.c`, which the

1. **Node queue and batch** (gc_live.c, _testinternalcapi.c).
   `live_call` becomes a node; `struct _gc_live_state` holds head and
   tail; `queue_push()` appends a node to the collection's batch;
   `run_queue()` pops the head and frees the node after the call; the
   memmove and `running_queue` go. The callback node is allocated before
   `_PyWeakref_ClearRef()`; node failure takes collect()'s failure path

   collecting queue (no routing yet), so behaviour is unchanged.
   `gc_queue_fail_alloc()`. Gate 1: test_gc, test_weakref,
   test_finalization.

The rung relies on:

  heap walk, and the pin holds from `live_domain()` to the splice.

## Risks

- **A test that waited for another interpreter's callback on the
  collecting thread.** Commit 3's set runs every interpreter and
  threading suite; a failure is traced (PROCESS.md section 4) and is
  either a test that assumed the old rule (adjusted, with the reason in
  its commit) or a missed drain point.
- **Draining with collection off.** Commit 2 makes `_Py_RunGC()` drain
  under `gc.disable()`; traced if a test shows it.
- **The pin.** A collection that leaves `collect()` without unpinning
  blocks every deletion: the debug assertion at `collect()`'s exit, and
  9.16 under ASan.
- **`take_gil()` cost.** One relaxed load and a branch per acquisition;
  measured by the pipe-read loop.
- **Concurrent rungs.** 10a edits gc_trace.c's verifier,
  pycore_gc_trace.h, _testinternalcapi.c and test_gc.py. The 7a hunks
  are their own blocks; each merge of the integration head is checked
  with `git diff` over those files before the next commit.
- **9.16's second-pass module (not traced).** In 47 of 80 loaded runs
  the subinterpreter's `_testinternalcapi` module dies in the explicit
  collection's second pass; in the rest it outlives the barrier, and
  in 0 of 6 unloaded runs does it die there. Which retention differs is
  not traced. The likely cause is a conservative word that holds the
  module at the second pass, or the order of the first pass's own
  finalizers. The test does not depend on it (`remapped >= 10`,
  `remapped_other == 0`). It becomes a hand-off when a test fails on
  it, or when 10a's precise frames change the rate.

- Test 9.17's module `m_free` is covered through its call kind,

  `gc_queue_never_open_for_test()`) landed with commit 3's, all in one
  `_testinternalcapi` block. `gc_queue_never_open_for_test()` makes the
  initialisation fail where the queue would open
  (`_PyGC_LiveOpenQueue()` returns a status; the hook is
  `_PyGC_LiveFailOpenForTest()`); its isolated case queues a finalizer
  call, so 9.5 (b) reads `discarded["finalize"]`.
- 9.16's hook is a deletion barrier (`gc_delete_barrier()`, after the
  landing review; it replaced a timed pause after the mark). Armed, the
  next deletion of a subinterpreter stops after its close, before its
  pin wait. The main interpreter's next collection whose domain names
  that interpreter lets it go after its mark, and waits until it blocks
  on the pin before it routes. That wait is bounded at 10 seconds
  (`BARRIER_WAIT_NS`): a deletion thread that died or hung fails the
  test on `timed_out` instead of hanging it. `gc_queue_info()["barrier"]`
  reports whether the deletion was seen blocked on the pin or the wait
  timed out; the calls remapped from a closed owner to the main
  interpreter, and how many of them had an owner other than the
  interpreter at the barrier; and sequence numbers for the last such
  routing and for the deletion passing its pin wait.
- In the fork child, `_PyInterpreterState_DeleteExceptMain()` clears the
  other interpreters from the main interpreter's thread; their queues
  cannot run there and are closed as never opened (spliced to the main
  interpreter, or discarded) until rung 2's disposal. The close drains
  only when the current thread state belongs to the interpreter being
  closed; before this fix the drain would have run another
  interpreter's calls on the main thread, or spun on a queue it could
  not empty. The 7a agent found it reviewing commit 3's diff before
  committing it. The fix agrees with note 13 section 5.5: the calls go
  to the main interpreter under 5.4. The child's
  `interpreter_clear()` still asserts and uses a thread state before
  its last collection, as before 7a; that path, and the disposal that
  replaces it (`dispose_after_fork()`), are rung 2's.
- test_gc's `test_progress_during_finalization` (9.12) no longer expects

  original test delivered 19 callbacks in 19 runs of 20 (10 of 10 at
  1a17992b09b). The trace (PROCESS.md section 4):
  - `gc_live_roots_of(addr)` on the survivor gives 0x20: only C stack
    words reach it. The next main-interpreter collection frees it.
    `PYTHON_GCVERIFY=retain` shows the same: retained, not freed.
  - Stack hits in the subinterpreter's collection (`PYTHON_GCSTACKHITS=1`
    without `-I`, which turns it off) reach the object through a tuple.
    The return-address slots on the stack, read through /proc/self/mem
    and matched against `manual_frame_pointer_unwind()`, place the word
    160 bytes above the slot that returns into `_PyObject_MakeTpCall()`

### The landing review (2026-10-28, codex; reviews/7a-1-landing.md)

Verdict: fix first, with six blocking findings. Dispositions:

1. **Readiness for every thread** (fixed, 3db9ff26c4b). `queue_splice()`
   sets `queue_ready` whenever it splices onto an open queue, the local
   splice included. `run_queue_ex()` clears it with the last node, and
   the close clears it. The flag now means "open and non-empty", with
   one writer for the set. `test_ready_for_every_thread`: a thread
   collects inline and blocks on a lock; the main thread, with automatic
   collection off, delivers every dead object's callback while the
   collector is still blocked. The test fails without the fix.
2. **Collection after the close** (fixed, 3db9ff26c4b).
   `collect_from_entry()` fetches the live state once and returns 0
   without one (closed, or no memory). It passes the state to
   `collect_pass()` and `collect()`. `_PyGC_LiveCollectHere()` returns 0
   without one. `test_collect_after_close` closes a legacy
   subinterpreter's collector, then enters it by every entry; nothing is
   collected, allocated, queued or delivered. Without the check the test
   crashes.
3. **Gates at the landing head.** The ladder is rerun at the final head
