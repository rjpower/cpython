## What changes, by commit

Each commit is preceded by gate 1 on the set named with it, on
build/default and build/debug. The precise functions this rung edits
(`collect_from_entry()`, `_Py_RunGC()`, `_PyGC_LiveCollectHere()`) pass
the C mode (`Tools/cases_generator/root_check_c.py Python/gc_live.c`,
which the build runs as `GC_PRECISE_CHECK`) at each commit.

1. **The domain in the mark result and the owner lookup** (gc_trace.c,
   pycore_gc_trace.h). `live_domain()` copies its interpreters and
   sub-processes into `_PyGCMarkResult`; `_PyGC_LiveOwner(res, op)` maps
   `_mi_gc_segment_of(op)->subproc` to the domain's interpreter, a
   retired sub-process to the main interpreter, and asserts a segment.
   Debug builds assert in `run_queue()` that the owner of each call is
   the draining interpreter, **reported, not aborting**, in this commit
   only: a count `misrouted` in `gc_queue_info()` that the B repro
   shows non-zero before commit 3 and zero after; commit 3 turns it into
   an assertion. Gate 1: test_gc, test_weakref.
2. **The opening, the close and the predicate** (gc_live.c,
   pylifecycle.c, pycore_gc.h, _testinternalcapi.c).
   `struct _gc_live_state` gains `open` and `dropped[4]`.
   `_PyGC_LiveOpenQueue(tstate)` at the end of `pycore_interp_init()`
   sets `open` and, if the queue is non-empty, the thread's GC bit.
   `live_python_ok(ls) = ls->open && !ls->no_python` gates `run_queue()`,
   `invoke_gc_callback()` and `debug_write()`'s Python path.
   `_PyGC_Fini()` drops what is left (5.2: `wr_callback = NULL`,
   `_PyGC_SET_FINALIZED`), adds the counts to the main interpreter's
   `dropped` (to its own at the main interpreter's close) and writes the
   DEBUG_UNCOLLECTABLE line to the C stderr. `gc_queue_info()` and
   `gc_queue_close_for_test()`. This commit alone ends the crash: a
   closed queue keeps the main interpreter's calls until the
   subinterpreter opens, where they still run on the wrong interpreter.
   Gate 1: test_gc, test_weakref, test_capi.test_misc, and the one-line
   repro `PYTHON_GCSTRESS=1000 ./python -c 'import _testcapi;
   _testcapi.run_in_subinterp("x = 1")'` 10 runs in 10.
3. **Routing** (gc_live.c, pycore_interp_structs.h, ceval_gil.c).
   `route_calls(ls, &res, first)` after `queue_destroy_hooks()`:
   moves the calls of `[first, qtail)` owned elsewhere to their owners'
   tails with `queue_push()` on the owner's state, compacts the rest,
   updates each touched state's `queue_ready`. Skipped when
   `res.ndomain == 1` with no retired sub-process. `first` is the
   collecting queue's tail at the start of `clear_callback_weakrefs()`.
   `run_queue()` and `queue_push()` maintain `interp->gc.queue_ready`;
   `update_eval_breaker_for_thread()` sets `_PY_GC_SCHEDULED_BIT` when
   it is set. The misrouting count becomes a debug assertion. Gate 1:
   test_gc (the new class: 9.2, 9.3, 9.4, 9.6 of note 13), test_weakref,
   test_capi, test_threading, test_interpreters, test__interpreters,
   test_concurrent_futures.test_interpreter_pool, test_sys, test_atexit,
   test_io.
4. **Retired heaps** (pystate.c, gc_live.c, gc_trace.c).
   `free_interpreter()` calls `_PyGC_LiveRetireHeap(interp)` for a
   shared-heap interpreter whose sub-process has abandoned segments,
   instead of leaving the sub-process; the main interpreter's live state
   keeps an array of retired sub-processes (C `malloc`, no lock: the
   caller holds the head lock or is the only thread). `live_domain()`
   appends them to the sub-process table after the interpreters;
   `live_page_of()` searches the whole table; `live_walk_heaps()` visits
   their abandoned blocks. After the sweep, `collect()` deletes a
   retired sub-process whose `abandoned_count` is zero. `stash_set()`
   and `stash_get()`. Gate 1: test_gc (9.7 a, b, c), under
   `PYTHON_GCVERIFY=kill` on debug as well, test_capi.test_misc.
5. **Watcher masks per owner** (gc_trace.c). `struct live_walk`'s
   `dict_watchers` and `type_watchers` become arrays indexed by domain
   entry, set from each domain interpreter's tables, the retired
   entries using the main interpreter's; `live_walk_heaps()` sets the
   current index; `live_has_destroy_hook()` and `live_destroy_hook_of()`
   take the owner. Gate 1: test_gc (9.9), test_capi.test_watchers.
6. **One GIL per domain** (pylifecycle.c, test_misc.py,
   subinterpreters.rst). `init_interp_settings()` returns
   `_PyStatus_ERR("an interpreter that shares the main interpreter's
   object allocator must share its GIL")` for `use_main_obmalloc` with
   `PyInterpreterConfig_OWN_GIL`. Gate 1: test_capi.test_misc,
   test_interpreters, test__interpreters, test_embed.
7. **Records and the measurement tool**: gc.rst, note 06's 7a section,
   note 08's row, `queue_latency.py`, the as-built record here.

Test-only and tooling changes after a gate line rerun the levels they

## Invariants the rung relies on

- A heap object's segment's sub-process is its allocating interpreter's
  for the object's life (note 13 section 2); retired sub-processes are
  the main interpreter's.
- The domain has one GIL (commit 6; until commit 6 lands, the all-true
  `InterpreterConfigTests` row is the only creator of the other case,
  and it runs on one OS thread).
- No Python code runs between a collection's appends and its move
  (`route_calls()` precedes the sweep and the "stop" gc.callbacks).
- `_PyGC_LiveVisitRoots()` runs for every domain interpreter
  (`live_mark_roots()`), so every queue is a root of every domain
  collection.

## Risks

- **A test that waited for another interpreter's callback on the
  collecting thread.** Commit 3's set runs every interpreter and
  threading suite; a failure is traced (PROCESS.md section 4) and is
  either a test that assumed the old rule (adjusted, with the reason in
  its commit) or a missed drain point.
- **`take_gil()` cost.** One relaxed load and a branch per acquisition.
  Measured by the pipe-read loop of note 11 question 7 (2·10^6
  detaches) against the baseline.
- **Retired segments.** mimalloc must free blocks of an abandoned
  segment from a thread of another sub-process without reclaiming it
  (`mi_option_abandoned_reclaim_on_free` is off, and reclaim checks the
  sub-process), and `mi_subproc_delete()` must see `abandoned_count`
  reach zero. Test 9.7 (c) covers both; if the count never reaches zero
  for a fully freed segment, the retired entry stays (memory, not
  correctness) and the record says so.
- **The fork child.** `_PyInterpreterState_DeleteExceptMain()` clears
  interpreters with no current thread state and under the head lock, and
  `interpreter_clear()` collects. This predates 7a and is not changed;
  the rung checks that `_PyGC_LiveRetireHeap()` is safe there (no lock,
  no allocation through the collector) and records the clear path as a
  hazard with owner step 7 if test_os's fork tests with subinterpreters
  show anything.
- **Concurrent rungs.** 10a edits gc_trace.c's verifier,
  pycore_gc_trace.h, _testinternalcapi.c and test_gc.py. The hunks here
  are disjoint; each merge of the integration head is checked with
  `git diff` over those files before the next commit.
