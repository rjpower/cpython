## What changes, by commit

Each commit is preceded by gate 1 on the set named with it, on
build/default and build/debug. The precise functions the rung edits
(`collect()`, `collect_from_entry()`, `_Py_RunGC()`,
`_PyGC_LiveCollectHere()`, `_PyGC_CollectNoFail()`) pass the C mode
(`Tools/cases_generator/root_check_c.py Python/gc_live.c`, which the
build runs as `GC_PRECISE_CHECK`) at each commit; any new precise mark
passes the outlined-callee audit at gate 3.

1. **Node queue and batch** (gc_live.c, _testinternalcapi.c).
   `live_call` becomes a node; `struct _gc_live_state` holds head and
   tail; `queue_push()` appends a node to the collection's batch;
   `run_queue()` pops the head and frees the node after the call; the
   memmove and `running_queue` go. The callback node is allocated before
   `_PyWeakref_ClearRef()`; node failure takes collect()'s failure path
   with the batch so far spliced. The batch is spliced onto the
   collecting queue (no routing yet), so behaviour is unchanged.
   `gc_queue_fail_alloc()`. Gate 1: test_gc, test_weakref,
   test_finalization.
2. **Domain in the result, owner lookup, phases, drain permission**
   (gc_trace.c, pycore_gc_trace.h, gc_live.c, pycore_gc.h,
   pycore_interp_structs.h, pylifecycle.c, _testinternalcapi.c).
   `_PyGC_LiveOwner()`; the phase (initialising, open, closed) in the
   interpreter's GC state; `_PyGC_LiveOpenQueue()` at the end of
   `pycore_interp_init()`; `live_python_ok()` gates `run_queue()`,
   `invoke_gc_callback()` and `debug_write()`'s Python path;
   `_Py_RunGC()` collects if due and allowed, then drains if open and
   non-empty; `_PyGC_Fini()` drains (if ever opened) until empty, then
   closes; `get_live()` refuses a closed state; `_PyGC_CollectNoFail()`
   of a closed interpreter does nothing. A never-opened interpreter's
   queue is discarded with the count (isolated) or spliced to the main
   interpreter (shared heap) (5.4). `gc_queue_info()`,
   `check_signals_loop()`, `gc_queue_never_open_for_test()`. Debug
   builds count misrouted calls in `gc_queue_info()["misrouted"]`
   (non-zero on the B repro until commit 3). This commit alone ends the
   crash. Gate 1: test_gc, test_weakref, test_capi.test_misc, and the
   one-line repro `PYTHON_GCSTRESS=1000 ./python -c 'import _testcapi;
   _testcapi.run_in_subinterp("x = 1")'` 10 runs in 10.
3. **Routing, the pin, delivery at execution** (gc_live.c, gc_trace.c,
   pycore_interp_structs.h, ceval_gil.c, pystate.c,
   _testinternalcapi.c). `route_calls()` splices the batch by owner
   (skipped when the domain has one member); a closed shared-heap owner
   maps to the main interpreter; `queue_ready` maintained by splice and
   drain; `update_eval_breaker_for_thread()` sets the GC bit when it is
   set. The pin: `live_domain()` increments the count under the head
   lock; `collect()` decrements it after `route_calls()` on every path
   that took it, the failure path included, with a debug assertion at
   `collect()`'s exit; `PyInterpreterState_Delete()`'s unlink waits for
   zero (3.2). `run_queue()` sets `_Py_GC_DEL_CALLED_FLAG` before
   `tp_del`, and `queue_legacy()` no longer does (3.6).
   `gc_pause_after_mark()`, `gc_hold_on_stack()`, `stash_set()`,
   `stash_get()`. The misrouted count becomes a debug assertion. Gate 1:
   test_gc (note 13 tests 9.1 to 9.6 (a, b), 9.11, 9.12, 9.15, 9.16,
   9.17), test_weakref, test_capi, test_threading, test_interpreters,
   test__interpreters, test_concurrent_futures.test_interpreter_pool,
   test_sys, test_atexit, test_io.
4. **One GIL per domain** (pylifecycle.c, test_misc.py,
   subinterpreters.rst). `init_interp_settings()` rejects
   `use_main_obmalloc` with `PyInterpreterConfig_OWN_GIL` (PROCESS.md
   0.2). Test 9.8. Gate 1: test_capi.test_misc, test_interpreters,
   test__interpreters, test_embed.
5. **Record**: gc.rst, note 06's 7a section (rung 1 part), the as-built
   record here.

Test-only and tooling changes after a gate line rerun the levels they
can touch (PROCESS.md, the rerun rule).

## Invariants

At landing, note 13 section 8's invariants 1, 2, 3, 4, 6, 7, 10 and 11
hold. Invariants 5 across owners, 8, 9 and 12 await rung 2; 5 holds
within each owner.

Until rung 2's retirement, the closed-owner mapping of commit 3 runs a
closed shared-heap interpreter's destroy hooks on the main interpreter,
which reads their watcher bits and code extras through its own tables,
as every collection does today. A deleted shared-heap interpreter's
heap stays outside the domain, as today (the hole 5.3 closes in rung 2).

The rung relies on:

- A heap block's segment's sub-process is that of the interpreter whose
  thread allocated the block (note 13 section 2).
- The domain has one GIL (commit 4; until it lands, the all-true
  `InterpreterConfigTests` row is the only creator of the other case,
  and it runs on one OS thread).
- No Python code runs between a collection's batch and its splice.
- Every mark holds the head lock from `live_domain()` to the end of the
  heap walk, and the pin holds from `live_domain()` to the splice.

## Risks

- **A test that waited for another interpreter's callback on the
  collecting thread.** Commit 3's set runs every interpreter and
  threading suite; a failure is traced (PROCESS.md section 4) and is
  either a test that assumed the old rule (adjusted, with the reason in
  its commit) or a missed drain point.
- **Draining with collection off.** Commit 2 makes `_Py_RunGC()` drain
  under `gc.disable()`; traced if a test shows it.
- **The pin.** A collection that leaves `collect()` without unpinning
  blocks every deletion: the debug assertion at `collect()`'s exit, and
  9.16 under ASan.
- **`take_gil()` cost.** One relaxed load and a branch per acquisition;
  measured by the pipe-read loop.
- **Concurrent rungs.** 10a edits gc_trace.c's verifier,
  pycore_gc_trace.h, _testinternalcapi.c and test_gc.py. The 7a hunks
  are their own blocks; each merge of the integration head is checked
  with `git diff` over those files before the next commit.

Deviations from the plan above, accepted by the coordinator on
2026-10-28:

- The queue's head and tail, its phase, the ready flag, the pin count
  and its event, and the discard counters are fields of
  `struct _gc_runtime_state` (pycore_interp_structs.h), not of the
  malloc'd live state: the queue exists for the interpreter's whole life
  and routing allocates nothing. Note 13 sections 3.1 and 5.1 say so.
- Test 9.17's module `m_free` is covered through its call kind,
  `CALL_DESTROY`, by a capsule destructor and a buffer release: no
  fixture module records its `m_free`, and the capsule case stands for
  it.
- The test helpers of commit 2 (`check_signals_loop()`,
  `gc_queue_never_open_for_test()`) landed with commit 3's, all in one
  `_testinternalcapi` block. `gc_queue_never_open_for_test()` makes the
  initialisation fail where the queue would open
  (`_PyGC_LiveOpenQueue()` returns a status; the hook is
  `_PyGC_LiveFailOpenForTest()`); its isolated case queues a finalizer
  call, so 9.5 (b) reads `discarded["finalize"]`.
- `gc_pause_after_mark()` busy-waits in the main interpreter's
  collections between the mark and the routing, holding the GIL, and
  `gc_queue_info()["pin_waits"]` counts the pauses at whose end a
  deletion was waiting; 9.16 retries until one has.
- In the fork child, `_PyInterpreterState_DeleteExceptMain()` clears the
  other interpreters from the main interpreter's thread; their queues
  cannot run there and are closed as never opened (spliced to the main
  interpreter, or discarded) until rung 2's disposal. The close drains
  only when the current thread state belongs to the interpreter being
  closed; before this fix the drain would have run another
  interpreter's calls on the main thread, or spun on a queue it could
  not empty. The 7a agent found it reviewing commit 3's diff before
  committing it. The fix agrees with note 13 section 5.5: the calls go
  to the main interpreter under 5.4. The child's
  `interpreter_clear()` still asserts and uses a thread state before
  its last collection, as before 7a; that path, and the disposal that
  replaces it (`dispose_after_fork()`), are rung 2's.
- test_gc's `test_progress_during_finalization` (9.12) no longer expects
  all twenty callbacks by its first check. On ASan under kill it failed
  19 times in 20: a stale stack word kept one object alive past the
  subinterpreter's collection, so 19 callbacks had run. The test now
  checks that every object that died had its callback, on the main
  interpreter. It then overwrites the stack and collects until every
  weakref has fired (20 and 20), so a lost call still fails the test.
  The close cannot show this, because there the weakrefs become garbage
  with their referents, and a garbage weakref's callback does not run.

Invariants 5 across owners, 8, 9 and 12 await rung 2; 5 holds within
