## Source boundaries and activation order

Keep these changes reviewable separately, with explicit dependencies:

1. Registration freeze and owner-thread metadata retirement: preserve
   error precedence, detach extras before free callbacks, and restart the
   heap walk after each callback. Define the frozen API errors before
   implementation. The no-callback child variant is a separate operation.
2. Stable active-dispatch identities and cooperative shutdown: track
   callbacks through their full return and error reporting, including
   C-level thread-state switches. Keep admission open while waiting;
   latch only at the successful final stopped-world readiness check.
   Ordinary foreign watcher dispatch needs the same owner-table lifetime
   protection, even though its execution context remains the mutator.
3. Shared-owner adoption: transfer metadata-retired heaps, registered
   roots, immortal registries, kept thread state and pending calls before
   freeing their old owner. Closing a shared owner must not promise to
   drain a dependency on an idle foreign interpreter. The reviewed
   direction adopts its READY/WAITING calls into main after quiescence;
   update note 13's old strict-drain rule with the implementation.
4. Fork quiescence and child disposal: finish other threads' dispatches
   before committing fork, preserve a surviving main-thread dispatch,
   and dispose foreign state without Python or inherited-lock recursion.
   Parent/error admission restoration and void embedding-API errors need
   explicit review. Do not manufacture completion for a vanished thread.

These boundaries are source assignments, not permission to activate an
incomplete lifecycle. Retirement, quiescence and adoption must agree before
owner storage can be freed. The completion scheduler activates only after
all required close/fork paths preserve its roots and node identities.
The SCC rank-policy proposal and native-cleanup protocol have their own
reviews; neither is implemented by this plan.
