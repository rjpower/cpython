# Explicit VM state candidate: independent review

Disposition: **ACCEPT for bounded experiment planning**, after the two scope clarifications below. This grants no source implementation, build, native execution, timing, backend adoption or qualification. The exact final `boil/design/vm-design-candidate.md`, including its final provenance links, has SHA-256 `c666f58cc077a8ee00ecbf92c5e75205fca383dae77e0ef22b9293bd8d8fc665`. An identical snapshot is retained at `build/vm-design-canvas-20261101/reviewed-candidate-body.md`. Semantic changes require a successor review; later publication wrappers do not alter this reviewed identity.

The design preserves the existing operation/effect source, register-slot representation and nonmoving tracing semantics. The current tail ABI and handler generation already exist in `Python/ceval_macros.h:94–145` and `Tools/cases_generator/ir_generator.py:1807–1820,1956–1959`. The retained H1 source at `94ab98e8fd3` already passes frame; reconciling that implementation is the right scope. There is no reason to rediscover it as a new VM or assume its old source and limited correctness results establish current benefit.

The proposed first increment retains slots and passes frame explicitly, avoiding the disproved assumption that reconstructing slots is automatically cheaper. The current baseline transports slots, thread state, IP and word and reloads frame from thread state. A matched GCC computed-goto/Clang computed-goto/Clang tail comparison separates compiler effects from backend effects before changing this ABI. Ordinary helper calls can still spill state. Inspecting actual complete branch paths is useful attribution, while elapsed workload results decide benefit. The rejected 3dd experiment remains rejected; it supplies neither a tail-backend speed estimate nor causal proof of a particular register-allocation cost.

The Python/native/root contract is sufficient for this planning stage. `IRStack.keep/store` rejects an unrooted temporary across a collecting call (`ir_generator.py:1329–1358`); `flush` retains inputs until the appropriate exit, and spill/reload relies on managed slots already being current (`1403–1471`). The new ABI must preserve this rather than carrying live Python values only in handler-local registers. Frame changes, early result publication, exception offsets, wrapper/same-word and predicted entries, direct labels, initial sentinel arguments and throw entry are all explicitly in scope. The entry trampoline must outlive the handler chain; handler-local root registrations must not survive a musttail transfer. There is no fatal architectural contradiction if those obligations and the actual linked precise/preserve-none metadata remain enforced.

The official [Clang attribute documentation](https://clang.llvm.org/docs/AttributeReference.html#musttail) supports the compatible-signature and local-lifetime constraints. Its [preserve_none description](https://clang.llvm.org/docs/AttributeReference.html#preserve-none) expands general argument registers and declares an unstable ABI; on x86-64 RSP/RBP remain preserved. Thus precise-preserve-none is the collector's actual walk classification, not a claim that every hardware register is clobbered. The candidate appropriately makes compiler identity part of the experimental input.

The [Python 3.14 documentation](https://docs.python.org/3.14/whatsnew/3.14.html#tail-call-interpreter) expressly recommends PGO as the tested improved-performance configuration. The design's initial common O3 comparison has a useful limited question, but cannot settle optimized-release performance. A separately frozen later PGO comparison is an appropriate boundary; it must not become an after-the-fact rescue run. LuaJIT's actual [x64 VM source](https://github.com/LuaJIT/LuaJIT/blob/v2.1/src/vm_x64.dasc) assigns BASE to a non-callee-saved register and explicitly saves/reloads native transition state. The design correctly transfers the deliberate convention, without claiming that assembly eliminates these obligations or that trace-compiler optimizations belong to baseline interpreter staging.

The final additions preserve the literal retained H1 order `(slots, tstate, frame, next_instr, ir_word[, lastopcode])` as part of the frozen experiment. I checked the cited [upstream 3.14 source](https://github.com/python/cpython/blob/3.14/Python/ceval_macros.h): it indeed passes frame explicitly, with a different stack-reference ABI. The short [Deegen author comparison](https://sillycross.github.io/2022/11/22/2022-11-22/) is an appropriate generation-from-semantics middle ground. Its 2022 absence of a public preserve-none convention is historical, not a current Clang limitation. The candidate makes that distinction and does not transfer its Lua performance claims to Python or authorize a meta-compiler project.

Two requested clarifications have been incorporated:

- **Budget feasibility.** Preparation/execution table numbers are provisional ceilings, not a schedule or permission to overrun. Each activation must fit the actual integration deadline and downstream qualification, or explicitly defer that experiment. Exact commands, primary threshold, regression controls, samples, noise rule and clock still require a frozen experiment plan before execution.
- **GC1 inventory scope.** Object-start enumeration is limited to initialized managed objects in selected object-heap domains. It retains separate raw PyMem/interior-pointer inventory, abandoned/domain handling and lifecycle mutation rules. This matches the concrete split in `gc_trace.c:live_walk_heaps`: object block enumeration and raw-memory page inventory are distinct consumers. Huge singleton handling and omitted/stale-start negative controls are appropriate proof obligations, not evidence of an already correct implementation. The separate GC1 stage review remains required.

Both Mermaid diagrams express the current lowering/execution organization and the proposed transport/publication separation without claiming that an ABI removes the managed state. No render-dependent layout assertion is needed for this source review. Single-configuration adoption, no permanent experimental switches, no text-size veto, no extra counter-permission probes and no automatic retiming remain appropriate. This is a coherent next question before assembly, not approval for a general rewrite or for bundling GC, helper effects and compiler optimization changes into one result.
