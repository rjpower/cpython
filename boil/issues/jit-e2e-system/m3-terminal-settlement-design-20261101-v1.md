# Preserve baseline admission after terminal recorder exhaustion

Design only; frozen source `90cdb7bbda9d1547f1d1ccdcef2388a5b82744c5`, its image, and the failed batch remain unchanged. No candidate execution or correction authority is implied.

The first actual batch built successfully and ran all 36 methods: 35 passed, including all eight observed-loop methods; the retained `TestNativeMethods.test_loop_python_call_c_call_and_dunder` errored on missing `work_info["entry_seen"]`. The final info therefore described an inactive code state. The source explains that result: the explicitly compiled `work(0, ...)` returns without visiting its nominated loop; `RecordAfter` marks its pinned artifact `recording_exhausted`. The next live-frame `PrepareActivation` detaches that artifact and returns zero. The later calls with 1, 7 and 12 iterations do not establish the 64-call/256-backedge heat required for natural recompilation. This is a baseline-admission regression; preserve the old test and its coverage assertions.

Use the existing cold replacement transaction to settle the exhausted recording artifact into an ordinary baseline at the **next valid live-frame admission**, then enter that baseline during the same admission. Do not recover a semantic code owner from a completed RETURN or retain one across the callee.

1. In `Python/jit_runtime.c::_PyJit_PrepareActivation`, first validate the current linked frame, exec/word identity, logical PC range, interpreter, generation, epoch and observer policy. Save the logical word offset before any callback-capable work. Ordinary units keep the existing path.
2. For an exhausted recording unit only, take one temporary artifact pin and construct a local context with this live frame, borrowed code/exec, current PC and unit. Mark the state's existing `record_attempted` bit. Call `_PyJit_ReplaceRecorded(&temporary, NULL)`. That existing transaction builds an ordinary baseline because the one-attempt bit forbids another recording unit. It already spans allocations and cleanup with BUILDING plus the same-code TLS guard, roots code only during construction, reserves the aggregate byte/unit budgets, restores the old RESUME head before detaching, and validates source/generation/epoch before publishing.
3. Always release the temporary activation exactly once. Preserve a replacement error through release and propagate any new cleanup error. The pin protects only artifact bytes/metadata; release clears borrowed pointers before callback-capable frees. No old exec/unit field may be read after release without a fresh lookup.
4. Reacquire the actual current unit once. Revalidate current frame/code identity, unchanged exec/word backing and saved logical PC, source stamp, generation, epoch, interpreter, observer policy and entry offset. Recompute the native address from this freshly pinned unit and its normal prologue/word map. Require an ordinary, non-exhausted unit; never recursively retry settlement or follow an old native continuation. On optional construction/quota failure, the existing transaction detaches the recorder and leaves ordinary interpretation; on observer invalidation, interpretation resumes at the same unexecuted word. A genuinely changed exec backing during the cold boundary remains an explicit error, as in the existing retirement check.

This introduces no field, hotness policy, selector, permanent recorder hook, or semantic operation replay. Other methods keep their units. The old recording artifact remains charged and mapped through every active pin; the replacement is charged before allocation, including the transient overlap. In the normal failure case, short calls regain their explicitly installed baseline immediately instead of waiting for new heat.

The correction should touch only the runtime admission/settlement path and an existing focused fixture. Keep all 36 IDs and old 28 method ASTs intact. Extend the existing zero/alternate-loop fixture with an explicitly compiled fresh loop method: call it first with zero iterations, then one iteration containing a real Python call; assert the result/ledger once, active ordinary baseline, entry and caller-return witnesses, no recording hooks, and one additional cold compilation only. Repeated short calls must not recompile. Retain the alternate-hot-loop 4096-event case. Preserve resource/observer behavior rather than weakening success assertions.

Cheap validation is exact source review, existing 35 host methods, changed-runtime syntax-only check and roster/projection checks in a separately granted correction worktree. Then root may authorize a fresh finite build plus the unchanged 36-method batch. The failed image and its complete raw outcome remain historical evidence; this design claims neither a corrected runtime result nor performance.
