Restore universal PyValue with reference counting

DESIGN ONLY. No source changes, builds or candidate execution. Preserve RC and cyclic collection as the single runtime policy; preserve all failed GC/JIT attempts. This restores a required representation and value API, not a collector experiment.

One representation and ownership contract

Choose one public64-bit PyValue across frame homes, fork-managed containers, cells, attribute slots, argument/result arrays and semantic operations. Remove the parallel _PyStackRef naming in that implementation cut; do not build a second wrapper or selectable representation. Select the current RC ownership-aware encoding as the single payload: NULL1, ERROR2, existing pointer borrow/immortal bit, internal index region and NaN partition/int32 payload. Old NULL0/raw-pointer-only PyValue helpers must be adapted, not kept as a second format. Keep exact-type canonicalization, None/bools as immortal singleton references, boxed NaNs/bignums/subclasses and existing fork value identity. Internal NULL/ERROR/index remain distinct and cannot enter language containers.

RC needs ownership even with this encoding. Reuse the current pointer ownership bit and explicit New/Borrow/Steal/Dup/Close/MakeHeapSafe operations under the PyValue API. All generic heap fields own strong or immortal references; a mortal borrowed value cannot be stored without promotion. Canonicalization must not hide an early DECREF. A pure prepare operation reads the exact primitive and returns its canonical immediate while transferring a consumed source box into an explicit pending-release owner. The caller publishes the canonical destination and other live state first, then closes that pending owner and any displaced destination owner in the required semantic order, then revalidates callback-sensitive facts. A borrowed input remains rooted by its real source owner or is promoted before allocation; no returned immediate excuses a dangling evaluated argument. This small scoped preparation record is an ownership transaction, not a second stored value format. Pointer identity masks ownership bits; canonical numeric identity remains value-based. A raw bit copy is a move/borrow only when its contract says so, never an implicit second owner.

Platform and policy closure

Initial supported profile is the already qualified64-bit Linux/x86-64 GIL core with ordinary debug/release builds. Free-threaded/32-bit and the global StackRef-ID debug checker are unsupported until they implement this SAME value contract; they must not silently select a boxed alternative. Remove PYTHON_TAGGED_VALUES parsing, tagged_values_enabled state/guards, boxed constant-handler mapping and its old negative subprocess expectations from the restoration source. All supported interpreters use canonical PyValue. Speculative scalar JIT declines still enter generic PyValue semantics, not a representation mode. Debug ownership checking may use out-of-band records without replacing stored payloads with table IDs.

For example, an owned-object boundary can expose PrepareFromOwnedObject(source, &retired_box): it returns the canonical PyValue and moves a consumed primitive box into retired_box without decref. For a non-inlineable object it transfers that owned reference into the value and leaves retired_box NULL. After the caller publishes the canonical destination and detaches any moved source holder, it releases retired_box and the displaced owner, preserving errors/revalidating afterward. The temporary retired_box is a scoped PyObject* cleanup obligation, not a noncanonical heap/frame PyValue. Borrowed-source preparation instead returns a borrow/immediate; storing it requires the explicit owning promotion.

What to reuse; what to replace

The old source did not make every C slot value-native: Include/object.h still had boxed unaryfunc/binaryfunc/ternaryfunc even though getattro/iternext/vectorcall and METH_O/FASTCALL were migrated. The target therefore includes all core generic operations and call paths, not just restoring a historical subset. Shared semantic entry points accept/return PyValue; migrate core built-in slot/method consumers together, and isolate genuinely opaque object-only C code behind the explicit owned bridge. Object metadata such as PyTypeObject pointers and proven-Unicode name tables need not masquerade as generic values.

Reuse old value-aware list/tuple/dict/set algorithms, iteration, hashing/comparison, slot offsets, shared semantic operations, Clinic/value-call converters and tests as reference code. Keep CURRENT RC object headers/type layout, cyclic collector, deallocators, weakrefs/finalization, current attribute/type/version semantics and shared JIT owner/Action/state-map contracts. Do not restore old header-shape object headers, INCREF/DECREF no-ops, tracing collector/free policy, conservative/interior-pointer roots, gc_trace value-root chains, GC-on-box-OOM retry or an owning collector selector.

Add PyValue Visit/Clear/Store primitives for RC containers: visit only strong object edges (mask pointer ownership tags), skip immediates/internal sentinels; clear/move slots before decref; publish new value and structural metadata before releasing displaced owners. Apply existing list/dict clear/resize/watcher order rather than replacing it with blind array assignment. Snapshot/own evaluated inputs before callback-capable conversions; revalidate location/type/shape after callbacks. Typed slots still carry PyValue; their guards are promises, not a permanent alternative storage format.

The real native-API issue

The old GET_ITEM boxing macro returned a fresh box as a nominal borrowed pointer and aborted on OOM. Its ObjectArray returned an interior pointer into collector-owned storage with no explicit release. Neither has a valid unchanged RC lifetime. A raw non-inline PyValue array also cannot be cast to PyObject** when borrow tags can be present.

Recommended target: an explicitly versioned private value-native ABI, migrated throughout core and bundled modules. Value accessors return PyValue; native O/FASTCALL/vectorcall and value-aware attribute/iteration/descriptor routes exchange values with documented borrowed inputs/owned results. Boxed object bridges return owning references with an error channel, and temporary PyObject* argument arrays own every element until callback completion, then release on every exit. Do not silently redefine an owned pointer as borrowed. Rebuild extensions and reject old ABI artifacts. This proposal selects that private value-native ABI: migrate/remove the legacy borrowed-PyObject getters for inline-capable storage and replace object consumers with owning, fallible getters. Do not implement a permanent scalar boxing cache, allocate-and-abort borrowed getter, unowned returned box, or collector-owned interior-pointer buffer. Exact legacy binary compatibility is outside this selected contract; old binaries must be rejected, not silently cast to the new signatures.

Cohesive implementation breakdown

1. Value/ownership foundation plus real consumers: merge current StackRef ownership and old canonical payload into Include/pyvalue.h/pycore_value.h/Python/pyvalue.c, migrate frame/RegIR/generated handlers, and implement owned/error-reporting object bridges and native argument/result contracts. Add actual RC lifetime/error tests, not alias-only headers. Keep a single backend; adapt JIT imported-owner/recovery logic to the canonical frame invariant.
2. Containers and iteration together: migrate list/tuple/structseq storage, dict/set keys+values, cells and their value-native hot operations/iterators. Change GC traverse/clear, all deallocation/mutation/slicing/sort/copy paths and iterator invalidation, plus call/Clinic consumers in the same bounded dependency chain. No boxing on each store/read merely to preserve an old internal helper signature.
3. Attributes and complete core call surface: migrate managed/shared-key instance values, slot descriptors and core generic fields; preserve __getattribute__/__setattr__/data-descriptor/MRO semantics above storage. Port current shape specializations to PyValue fields without the discarded header-shape rewrite. Finish value-native C methods, vectorcall, get/set/descriptor/iternext adapters and bundled-module usages; keep opaque foreign layouts behind explicit owning object bridges. Final source census must show no accidental boxed generic-value field or silent function-pointer ABI cast.

These are dependent commits of one universal representation, not competing runtime modes or a per-op architecture vote. Source grants should bind exact manifests from the changed API/storage consumers; the old887-file rollback is not a restoration patch to invert wholesale. Select one explicit current RC+JIT base before edits; do not mix historical whole-object trees into95be or main.

Include destructor reentry/weakrefs/cycles, dict hash equality and delete/reinsert/watchers, list sort mutation, NaNs/signed zero/subclasses/bignums, conversion OOM and cleanup. Performance selects specific implementations; it does not vote again on the user's universal-value requirement.
