# Cython

A build tool: ports that generate C with Cython name it in `build_ports`, so
their extensions are generated by this patched copy. It builds as pure
Python (`NO_CYTHON_COMPILE`), since only code generation runs it. The
generated C targets only the PyValue C API: it stops with an error without
`Include/pyvalue.h`, or with `Py_LIMITED_API` or `CYTHON_LIMITED_API`.

`code-cache-roots.patch`: wherever `PyGC_AddRoot` exists
(`Py_HAVE_PYGC_ADDROOT`), the code object cache keeps its code objects in a
dict that is a collector root, since the cache's entries live in
`PyMem_Malloc` memory that no `tp_traverse` visits.

`item-values.patch`: tuple and list items are values, so the utility code
builds tuples and lists with `SET_ITEM`/`SET_VALUE`, slices and `list.pop()`
move `PyValue` arrays, and `PySequence_Fast_ITEMS()` is declared to return
`PyValue *`.

`cyfunction-weakref.patch`: `PyCFunctionObject` has no `m_weakreflist`, so
the Cython function type sets `Py_TPFLAGS_MANAGED_WEAKREF`.

`value-calls.patch`: the `METH_O` and `METH_FASTCALL` def wrappers, the
Cython function's vectorcall entry points, `tp_iternext` (of `__next__` and
of Cython's generators and coroutines) and the utility code's own method
tables take and return values, unboxing with `PyValue_Object()` and boxing
with `PyValue_FromResult()` only at that boundary; calls into those
conventions convert likewise, and the limited API and a type's
`tp_vectorcall` (`CYTHON_VECTORCALL_TPNEW`) are never selected.

`tests/values.py` translates, compiles and imports `tests/cyvalue.pyx`,
which covers each of these conventions with inline ints and floats.
