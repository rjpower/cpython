# numpy

Built with meson-python and `-Dallow-noblas=true`; its Cython code is
generated by the Cython port (`build_ports`).

`gc-roots.patch`: makes numpy's references visible to the tracing collector.
Each DType registers the object fields of its `dt_slots` (the casting
implementations, the sort and real/imag methods, the legacy cast dict) and
its singleton and scalar type as roots (`PyGC_AddRoot`), since legacy
DTypes live in `PyMem` memory and are traversed as static types. ufuncs
visit their loop dicts, and `_ArrayMethod`, `_BoundArrayMethod` and the
array function dispatcher, which are not GC types, get a `tp_traverse`.
The four ArrayMethods that numpy builds by hand start zeroed, since the
traverse reads their wrapping fields.

Most of numpy's core objects are not GC types, so the patch also gives each type
that holds references a `tp_traverse`:
- `ndarray` visits its descriptor, base, memory handler and, for dtypes
  that hold objects, the objects in its items;
- descriptors visit their scalar type, metadata, fields, names and subarray.
  dtypemeta.c installs this on every DType class, since a non-GC type does
  not inherit `tp_traverse`. StringDType also visits its `na_object`;
- `flatiter`, `broadcast`, the neighborhood iterator, `nditer`, the
  fancy-indexing `mapiter`, the flags object, `_array_converter` and the
  void scalar visit what they hold.

Memory that holds references but that no object traverses is a PyMem
block, which the collector scans when the C stack reaches it: the buffers of
an iterator over a dtype with references, and, when the default allocator
is current, the data of such an array (`pymem_reference_allocator`). A
ufunc that casts to the object dtype holds both only on its stack.

`ndarray`, `nditer` and `mapiter` set `Py_TPFLAGS_DEALLOC_READS_REFERENTS`,
because their deallocs read the descriptor, the memory handler or the
operands. The neighborhood iterator's dealloc skips, under `Py_GC`, a decref
that reads its array.

The roots, traverses and flags are in every build: outside `Py_GC` they
inform the tracing verifier, and `tests/held.py` holds an instance of each
type so that `ports check` verifies them. `tests/collect.py` collects often
while numpy casts, sorts and fills object arrays.
