# 6d rung 3: calls and wrappers on values

Status: design, 2026-10-28, revised after review rounds 1 and 2. Specification:
note 12 sections 2.3, 5, 7 and 11 (rung 3). Starts from boil/6d at
e0964287861 (rung 2 as gated, with boil/10a at d5d83aad9f7). Line
numbers are of that commit. boil/10a and the integration branch are
merged at every commit boundary.

The rung changes the call slot and the wrapper function types in place,
with every function of each type, so the tree builds at every commit.
`tp_call` returns a value; a `wrapperfunc` returns a value; the call
layer's internal forms take and return values, and the object forms
box at their return. Rung 2's wrapper boxes go. Getsets stay object
forms until rung 4.

## A. The typedefs

- `callfunc`, new in Include/object.h beside `vectorcallfunc`:

  ```c
  typedef PyValue (*callfunc)(PyObject *callable, PyObject *args,
                              PyObject *kwargs);
  ```

  `PyTypeObject.tp_call` becomes `callfunc` (Include/cpython/object.h).
  `ternaryfunc` stays, for `nb_power` and `nb_inplace_power`.
  Python/slots.toml's `Py_tp_call` entry takes `functype = 'callfunc'`,
  and Tools/build/generate_slots.py regenerates
  pycore_slots_generated.h and slots_generated.c.
- `wrapperfunc` and `wrapperfunc_kwds` (Include/cpython/descrobject.h)
  return `PyValue`. `self` and `args` stay objects: a wrapper's receiver
  is an object, as a descriptor's owner is in rung 2 (an inline one is
  boxed by the caller, D), and `args` is the protocol's tuple.
- The result contract is `vectorcallfunc`'s: a canonical value, or
  `PyValue_NULL` with an exception set. The slot's `callable` is the
  object whose type holds the slot, never inline: no type with a
  `tp_call` has inline instances.

**The inventory.** `slot_inventory.py --where --calls tp_call` (its
typedef map gains `tp_call: callfunc`) lists 34 entries in 27 functions,
`PyVectorcall_Call` in eight types:

- core: `PyVectorcall_Call`, `cfunction_call`, `wrapperdescr_call`,
  `wrapper_call`, `classmethoddescr_call`, `sm_call`, `type_call`,
  `instancemethod_call`, `ga_call`, `proxy_call`,
  `constevaluator_call`, and `slot_tp_call` through `slotdefs`;
- modules: `itemgetter_call`, `attrgetter_call`, `methodcaller_call`,
  `partial_call`, `keyobject_call`, `lru_cache_call`,
  `TaskStepMethWrapper_call`, `scanner_call`, `encoder_call`,
  `pysqlite_connection_call`, `PyCFuncPtr_call`, `_DictRemover_call`;
- test and tool types: `VectorCallClass_tpcall`, `call_return_args`,
  fpcast.c's `CALLABLE_TYPE` entries, gc_trace.c's `trap_call`.

The dispatches are `_PyObject_MakeTpCall`, `_PyObject_Call` and
`wrap_call`; `PyType_GetSlot(.., Py_tp_call)` is read in
_testcapi/type.c. `PyType_Slot` entries are not type-checked, so the
inventory is re-run after each merge, as in rung 2. The wrappers are
typeobject.c's 29 `wrap_*` functions and the `richcmp_*` family, named
in `slotdefs` only.

## B. The call layer (Objects/call.c, pycore_call.h, abstract.h)

The value forms are note 12 section 2.3's: the callable is a value, as
in `PyObject_VectorcallValue`.

```c
PyAPI_FUNC(PyValue) PyObject_CallValue(PyValue callable, PyObject *args,
                                       PyObject *kwargs);
PyValue _PyObject_CallValue(PyThreadState *tstate, PyValue callable,
                            PyObject *args, PyObject *kwargs);
PyValue _PyObject_Call_PrependValue(PyThreadState *tstate, PyValue callable,
                                    PyValue self, PyObject *args,
                                    PyObject *kwargs);
PyAPI_FUNC(PyValue) PyVectorcall_Call(PyObject *callable, PyObject *tuple,
                                      PyObject *dict);
```

- **An inline callable** is rejected before any pointer access:
  `PyValue_IsInline(callable)` raises `TypeError: '%s' object is not
  callable` with `PyValue_Type(callable)->tp_name`, without a box. The
  module suggestion of `object_is_not_callable` applies to objects only.
  `_PyObject_MakeTpCall`'s box of an inline callable "for the error"
  goes with this rule.
- `_PyObject_Call` becomes `_PyObject_CallValue`: the vectorcall branch
  returns `_PyVectorcall_Call`'s value; the slot branch calls the slot,
  checks it (F) and returns its value after
  `_Py_CheckFunctionResultValue`. Its span keeps `_PyObject_Call`'s
  anchors (callable, args, kwargs).
- `PyObject_CallValue` is `_PyObject_CallValue` on the current thread.
  The object compatibility entries canonicalise the callable with
  `PyValue_FromObject` and box the result after the last use of their
  arguments: `PyObject_Call`, `PyObject_CallObject` and
  `PyEval_CallObjectWithKeywords`.
- `_PyObject_MakeTpCall` calls the slot through the value trampoline (D)
  and returns its checked value; the `PyValue_FromObject` of the result
  goes.
- `PyVectorcall_Call` returns `PyValue`, declared in place in
  Include/abstract.h. It is the function a type puts in `tp_call`
  (typeobj.rst says so), like `PyObject_GenericGetAttr` in rung 2, so it
  changes in place. Its two other callers: `cfunction_call` returns its
  value, and _testcapi's `pyvectorcall_call` boxes it.
- `_PyObject_Call_Prepend` becomes `_PyObject_Call_PrependValue`, with
  `callable` and `self` as values; its array is its span, as now. It
  returns the call's value.
- No object form of the internal functions remains. Their callers:
  `call_method_value` (C), `slot_tp_new`'s call of `__new__`
  (typeobject.c:11016), which boxes its result, a new object, and
  signalmodule.c's handler call, which drops its result after a NULL
  test and so takes the value.
- Each function keeps 10a's mark and stays clean in the C mode; where a
  body changes, the span moves with it, and the stamp rule checks it at
  every build (note 12 section 7: 6d moves the marks with the body).

## C. typeobject.c

- `call_method` becomes `call_method_value`, returning the call's value
  through `_PyObject_Call_PrependValue` or `_PyObject_CallValue`. Its
  callers:
  - `slot_tp_call` returns it: a callable instance's result is no
    longer boxed (`call_instance`);
  - `slot_tp_init` tests the value: `PyValue_IsNull` is an error,
    anything but `Py_None` raises "`__init__() should return None, not
    '%s'`" with `PyValue_Type(res)->tp_name`, so an inline result is
    named without a box.
- `type_call` returns `PyValue_FromResult` of the object it makes.
- The 29 `wrap_*` functions and `richcmp_*` return `PyValue`:
  - a wrapper of an object-returning slot (`wrap_binaryfunc*`,
    `wrap_ternaryfunc*`, `wrap_unaryfunc`, `wrap_indexargfunc`,
    `wrap_sq_item`, `wrap_richcmpfunc` and `richcmp_*`, `wrap_buffer`)
    returns `PyValue_FromResult` of it, so an int or float result is
    canonical at the wrapper;
  - a wrapper of a value-returning slot returns the slot's value with no
    box: `wrap_getattro` and `wrap_descr_get` (rung 2's boxes), and
    `wrap_next`, whose `PyValue_Object` goes;
  - `wrap_call` dispatches `callfunc`, checks the result (F) and returns
    it;
  - a wrapper of an int or bool result (`wrap_lenfunc`,
    `wrap_hashfunc`, `wrap_inquirypred`, `wrap_objobjproc`) returns
    `PyValue_FromLongLong` or the bool as a value, with no allocation for
    a value in int32;
  - the wrappers that return `None` return `PyValue_FromObject(Py_None)`.
- `slotdefs`' `_Py_FUNC_CAST(wrapperfunc, wrap_call)` and `wrap_init`
  casts stay casts, to the new type.

The typeobject.c hunks are the wrappers' returns, `call_method_value`
and its two callers, `type_call`, `slot_tp_new`'s call and the two
casts; the bodies keep their argument handling.

## D. Descriptors, the other core types and the modules

- descrobject.c:
  - `wrapperdescr_raw_call` returns the wrapper's value.
  - `wrapperdescr_call` reads `self` with `PyTuple_GET_VALUE`. An inline
    receiver (`int.__add__(5, 3)`) is boxed into the frame's span before
    any `Py_TYPE(self)`, as `method_check_args` boxes in rung 2; a failed
    box returns `PyValue_NULL` with `MemoryError`, and
    `_PyGC_SITE_RECEIVER_BOX` fires after a box is made.
  - `wrapper_call` returns `wrapperdescr_raw_call`'s value.
  - `classmethoddescr_call` keeps rung 2's check of `classmethod_get`'s
    result, a bound method it then calls; the bound method is held in
    the frame's span, and the call is
    `_PyObject_VectorcallDictValueTstate` on the tuple's items
    (`_PyTuple_ITEMS(args) + 1`, values), whose value it returns. The
    `_PyTuple_Objects` array goes.
- `cfunction_call` returns `PyVectorcall_Call`'s value, and for
  `METH_VARARGS` `PyValue_FromResult` of the function's object result.
- `sm_call` and `instancemethod_call` end in `PyObject_Call`: they
  return `PyObject_CallValue`'s value. `proxy_call` forwards to
  `PyObject_CallValue`. `constevaluator_call` and `type_call`
  canonicalise their object result with `PyValue_FromResult`, which
  allocates nothing.
- `ga_call` and `ga_vectorcall` share `set_orig_class_value(PyValue
  res, alias)`: an inline result is returned as it is, since setting
  `__orig_class__` on an int or float raises `AttributeError`, which
  `set_orig_class` already ignores; an object result is set as now.
  `ga_call` takes `PyObject_CallValue`'s value, and `ga_vectorcall`'s
  box of an inline result goes.
- The module types, by their return expressions:
  - `itemgetter_call` and `attrgetter_call` return
    `itemgetter_call_impl`'s and `attrgetter_call_impl`'s values; their
    `PyValue_Object` goes;
  - `partial_call` and `methodcaller_call` end in `PyObject_Call` and
    return `PyObject_CallValue`'s value;
  - `lru_cache_call`: the wrapper type (`lru_cache_ternaryfunc`)
    returns `PyValue`, with its three wrappers. The uncached one
    (`maxsize=0`) returns `PyObject_CallValue`'s value. The unbounded one
    (`maxsize=None`) reads a hit with `_PyDict_GetItemValue_KnownHash`
    and stores a miss with `_PyDict_SetItemValue_KnownHash`, two
    internal forms added to dictobject.c beside `_PyDict_GetItemValue`
    and `_PyDict_SetItemValue`, so neither boxes. The bounded one keeps
    `link->result`, a `PyObject *` field: a miss boxes once to store it
    (a kept field), and a hit returns the field as a value;
  - `keyobject_call`, `TaskStepMethWrapper_call`,
    `scanner_call`, `encoder_call`, `pysqlite_connection_call`,
    `PyCFuncPtr_call` and `_DictRemover_call` return
    `PyValue_FromResult` of their object result.
  Any other `PyValue_Object(x)` at a `tp_call` return found in the
  implementation returns `x`.
- fpcast.c: `zero` to `four` are shared by methods, getsets and the
  call fixtures. The call fixtures get their own value-returning
  `call_zero` to `call_four` (None as a value), cast to `callfunc`; the
  other consumers keep theirs.
- The wasm trampolines (pycore_wasm_trampoline.h,
  Python/wasm_trampoline.c): `_PyWasm_TrampolineCallValue` with
  `callfunc`'s signature, detecting arities 0 to 3 as the object form
  does, and `_PyCallFunc_TrampolineCall` on both
  branches of the header, used by `_PyObject_MakeTpCall`.
  `cfunction_call`'s `METH_VARARGS` call and `descr_get_trampoline_call`
  keep the object forms (the getset ones change in rung 4). No gate
  builds wasm: both are unbuilt and reviewed by inspection, and the
  fpcast fixtures test the native path only.

## E. CALL_FUNCTION_EX (bytecodes.c)

- The three `PyObject_Call` sites of `_DO_CALL_FUNCTION_EX` (5191,
  5241) and `_CALL_FUNCTION_EX_NON_PY_GENERAL` (5322) call
  `_PyObject_CallValue` with the callable's value and take the result as
  the output value.
- **The monitored result is rooted.** In the instrumented branch, the
  result is held across the `C_RETURN` callback, which can run Python
  code and collect. The result goes into a `_PyValueRoot` pushed before
  the call (beside `arg0_root`), is read from it after the callback, and
  is published to the output; both roots are popped on success, on a
  failed callback (the result is dropped, and the output is an error),
  and on a failed call (`C_RAISE`). The eval loop is precise, so no
  stack scan covers a C local there.
- **The callable.** The uninstrumented path passes `func_st` to
  `_PyObject_CallValue` as a value, and tests it with
  `PyValue_Type(func_st)` where it tests `Py_TYPE(func)`, so a callable
  is not converted to an object there. An inline callable is never
  callable: it reaches B's rejection, which needs no box. Two
  conversions stay, both on paths that end in "not callable" for an
  inline value or that need an object: `_MAKE_CALLARGS_A_TUPLE` passes
  the callable to `_Py_Check_ArgsIterable` when `*args` is not a tuple,
  and the instrumented path passes it to the monitoring callbacks. The
  helper does not read its callable; removing the parameter is a
  ceval.c change, outside this step's files, and is on the hand-off
  list. Tests: an inline int and float as the callee of `f(*a)` and
  `f(*a, **k)`, cold and warmed, raise `TypeError`, with no box on the
  tuple path (box audit).
- The bytecodes.c hunk is those three calls, their result handling, the
  callable's type tests and the root; generated_ir_cases.c.h is regenerated and root_check runs on
  it at the build. ceval.c's `PyObject_Call` (2340) keeps the object
  form.

## F. Checks and the injection site

- `_PyValue_CheckSlotResult(res, tp, "tp_call")` after the slot call in
  `_PyObject_MakeTpCall`, `_PyObject_CallValue` and `wrap_call`, the
  three dispatches. An old-form slot reached through an unchecked
  `PyType_Slot` entry returns a pointer whose value is an object
  encoding; a box of an int in int32 or of a non-NaN float is caught
  there. The check does not establish calling-convention compatibility:
  that is the compiler's for direct initialisers and the inventory's for
  `PyType_Slot` entries.
- `_PyGC_SITE_RECEIVER_BOX` also fires in `wrapperdescr_call` (D). No new
  site number.

## H. The rung 2 residues and their owners

- `object.__getattribute__(p, NAME)`: the wrapper's result box goes
  here (C).
- `super(int, big).__repr__`: one box, made by `LOAD_SUPER_ATTR_ATTR`
  for the inline receiver (box audit, `-v`, at 571203ba9f9). The lookup
  binds a slot wrapper, and the method-wrapper it returns keeps the
  receiver in its `self` field, so the box is a kept field and the
  minimum. The audit's residue reason says so; no step owns it.
- `unpack`'s `__length_hint__` box: `PyObject_LengthHint` calls the hint
  through `_PyObject_CallNoArgs`, which boxes the int it returns. It
  takes `_PyObject_VectorcallValueTstate` and reads the value with
  `PyLong_AsSsize_tValue`, so the audit's `unpack` case leaves the
  residue list. The semantics stay (Objects/abstract.c:101):
  `NotImplemented` gives the default; a `TypeError` raised by the call
  is cleared and gives the default; a result that is not an int (by
  `PyLong_Check` on its type, so bools and int subclasses pass) raises
  `TypeError`; a negative result raises `ValueError`; an overflow raises
  `OverflowError`. Each case is in test_iterlen or gains a test there.
- `_PyObject_LookupSpecial`'s object result: its 22 callers call the
  result or test it, so it stays an object function. A bound method is
  an object; an inline result (a property returning an int) is boxed
  and then fails to call, as today. It is not a bridge, and the rung 2
  table's retirement note is corrected.

## Risks

- **10a marks the same functions.** This rung rewrites `call_method`,
  `slot_tp_call` and `slot_tp_init` and changes the call functions'
  returns, while 10a's rung 2 remainder marks them. Each marked body
  stays in the C mode's subset, and the hunks touch returns, not
  anchors, where it is not. The coordinator orders the merges.
- **Silent casts.** `PyType_Slot` entries of `Py_tp_call` outside the
  inventory (a merge from upstream or 10a) return an object as a value.
  The check (F) catches a non-canonical box on debug builds; a pointer
  to any other object is a valid value.
- **`PyVectorcall_Call` changes signature in place.** A third-party
  caller that uses its result as an object breaks at compile time. In
  the tree there are two (B). Ports are deferred until the API settles,
  so none is checked now; the docs say so.

## Hand-off

- **ceval.c's owner: `_Py_Check_ArgsIterable`'s unused callable.**
  The helper (Python/ceval.c:3428, declared in
  Include/internal/pycore_ceval.h:272) never reads `func`, and its one
  caller, `_MAKE_CALLARGS_A_TUPLE` (Python/bytecodes.c:5148), converts
  the callable to an object to pass it. The change: drop the parameter,
  `int _Py_Check_ArgsIterable(PyThreadState *tstate, PyObject *args)` in
  both files, and call `_Py_Check_ArgsIterable(tstate, callargs_o)` in
  the handler, then regenerate generated_ir_cases.c.h. The starred path
  then converts no callable before the call (E).
