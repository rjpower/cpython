## Concrete proposed assignment

Compare the existing frame-reloading tail-call convention with one that
passes `_PyInterpreterFrame *frame` through the same generated handler and
label interface. Preserve every diagnostic position store, root anchor,
input clearing, operand layout, monitoring rule and eval-breaker. Decide on
matched release elapsed time, with instructions, spills and code generation
explaining the result. An inconclusive result keeps the existing convention
(note 14 rule 1). No runtime option or permanent dual convention is added.

Today ceval_macros.h:91-97 passes slots, tstate, next_instr and ir_word;
Py_STATS adds lastopcode. generate_handler emits a tail-call-local reload
from tstate->current_frame (ir_generator.py:1763-1766). Generated labels
call TAIL_CALL_LOAD_FRAME (1858), as does UNKNOWN_OPCODE (1942). Every
ordinary generated handler publishes frame->instr_ptr unless no_save_ip.
IR_JUMP omits that store but still needs frame for jump addressing. Removing
the diagnostic publication is not a way to make this experiment cheaper.

The source therefore establishes a repeated load; it does not establish a
current dynamic cost. Note 14's approximately one frame reload and position
store per word, 106-instruction loop and historical handler counts were
measured at 6d, not this head. Do not present those historical numbers as a
new c5cf measurement. No new performance measurement has run in this audit.

Use the parameter as the actual mutable current-frame variable. Call,
return, yield, resume and unwind already update frame and tstate together
(bytecodes.c:1441, 1697, 4237, 5416, 5768). Tail calls must pass that updated
value. Refreshing from tstate at every entry would defeat the experiment;
reusing the original callee after a frame transition would be wrong.

## Exact source closure and first falsifiable control

Owned implementation would be limited to:

- ceval_macros.h: TAIL_CALL_PARAMS/ARGS, TARGET interface,
  TAIL_CALL_LOAD_FRAME and explicit Py_STATS/non-stats JUMP_TO_PREDICTED
  argument lists;
- ceval.c: initial start_frame and throw/error tail-call entries at
  1288-1301, passing the actual current frame;
- ir_generator.py: eliminate handler/label/unknown reload redeclarations
  for the passed convention; keep generated prototypes coherent;
- regenerated ir_targets.h and generated_ir_cases.c.h;
- generator/IR and frame-transition tests, keeping ROOTS checker classes
  and compiler phase fixture untouched.

First semantic oracle: after an inlined call returns, and independently
after yield/resume and exception unwinding, assert at the next generated
entry that the passed frame equals tstate->current_frame. Execute a value
whose result depends on the caller's locals/code, with collecting monitoring
callbacks, so a stale-frame transfer cannot pass by returning an unrelated
constant. A copied omitted-frame-update control must fail the identity or
semantic assertion at that transition, not just a source-string check.
Retain the existing PRE_DISPATCH_GOTO debug equality check. Explicitly
cover start_frame, throw/error entry, predicted deopt, monitoring redispatch,
UNKNOWN_OPCODE's signature and Py_STATS/non-stats argument lists.

A generator check for a missing textual reload is only supplementary.
Inspect compiled leaf arithmetic and frame-heavy call paths to prove the
load was eliminated and whether the extra argument caused spills. Do not
add a speculative dependency analyzer merely to remove a load from a
handler whose mandatory position store already depends on frame.

## Checker and compiled-root prerequisites

Handlers have preserve_none precise declarations in ir_targets.h via
function_proto (ir_generator.py:1910-1912). pycore_gc_walk.h:30-39 places
them in py_gc_precise_pn, whose pending-register ownership differs from
ordinary precise functions. root_check checks uops through analyzer.py:1064;
the C checker separately checks marked core functions through the build's
gc_precise.stamp (Makefile.pre.in:984-1016). A frame pointer parameter is not
a new object root or permission to hold a PyValue in an unanchored C local.

Before implementation qualification, ROOTS must hand off current positive
and negative checker fixtures and compiled-stack attribution controls for
the exact compiler/configuration. Re-run actual owner/policy assertions at
collection, especially preserve_none handlers and opaque callees. Zero
fallbacks alone do not prove that a root was attributed to the right frame.
No H2 liveness map, helper span removal or clearing-store retirement belongs
here. Keep current slot coverage and initialized spans unchanged.

## Build-policy prerequisite and comparison

The local default/Og builds are GCC non-tail-call builds; they cannot measure
the passed-frame convention. ROOTS owns existing tailcall and ASan builds
and is qualifying its matrix. Do not reconfigure, rebuild or borrow them
without a quiescent handoff and current source/config/binary provenance.
Do not assume O1 adoption: this lane's qualified debug baseline remains Og.

Separate the calling-convention experiment from frame-pointer policy.
configure.ac:2827-2867 defaults to retained frame pointers, despite its
help text saying default no; ceval.c:1163 additionally forces GCC's eval
unit to no-omit-frame-pointer within its no-SLP attribute. The policy fix
would remove only that forced frame-pointer term and preserve the targeted
GCC no-SLP workaround. ASan retains frame pointers. Compare baseline and
passed-frame variants with identical compiler, optimization, frame-pointer,
PGO/LTO and stats settings; never attribute a build-flag change to passing
frame. Note 14's no-frame-pointer matrix is a future qualification target,
not a property of the current local builds.

Record exact compiler version and flags from execution, not just a build
directory name. Use two frozen source states sequentially in an approved
existing build, with gates through the shared lock/slots; no live source
swap during gates or new build trees merely for an experiment. Measure
micro/kernels release elapsed time and instruction counts, plus calls,
generators/coroutines, exceptions and frame-heavy workloads. Keep benchmark
inputs and warm-up identical; retain uncertainty and regressions with owners.

First implementation checkpoint estimate after checker/build handoff:
60-90 minutes for the coherent interface/generator change, transition
oracles and targeted release/debug checks; compiled attribution and matched
performance follow at their actual matrix runtime. Re-estimate if the
needed tail-call configuration is not currently qualified. This draft does
not authorize canonical guard changes or changes to shared checker tooling.
