# Full-suite process accounting gate

The retained 7baf census has 423 uncounted launches: 293 predict `-E`/`-I` suppressing `PYTHONSTATS`, and 130 predict an unset/dropped environment. There are 194 distinct `(tag, reason, argv)` launch shapes. It has 586 unfinished run markers, 174 distinct `(tag, argv)` shapes; four marker records have extra fake fields because their raw `/proc/self/cmdline` contains newlines. The current tag-only lists accept every new command under an already listed test, so neither class is an adequate admission rule.

Retain the legacy tag lists as a coarse first check, then require a reviewed exact admission rule for every marker or uncounted launch. A rule identifies its tag, mechanism/reason, structured argument vector (or escaped marker command line), and maximum count per full suite. Count only exact matches. A changed argument, reason, missing metadata, duplicate rule, or count above the cap fails. An empty initial rule manifest deliberately leaves this census failing; observed commands are candidates for review, not approved by collection. Keep the existing failures for core debt, invalid attribution, owner-table drops, unreadable dumps and resets.

For `.spawn`, preserve the JSON audit record's `argv` list, event and parent PID in the folded summary instead of joining arguments. A legacy TSV line or malformed JSON must yield an accounting error, not disappear. Normalize only the known build executable and stats directory when writing reviewed rules; do not collapse `-c` payloads or arbitrary paths. The auditor predicts whether a launch will count but does not prove it exited normally, so accepted reasons should stay narrow.

For `.run`, write the command line as an escaped single logical line at emission. Escape backslash and control bytes including newline, carriage return and tab; preserve the process marker id, PID, parent PID, tag and command. The marker's launch family needs a reviewed intentional-termination disposition, not merely a matching tag. A later stronger gate can pair parent PID and launch audit record with exit status, but the current audit hook lacks child PID/exit status, so it cannot claim that proof today. New or unpaired markers remain failures.

Focused negative fixtures: an allowed tag with new `-c` payload; same argv with a changed suppression reason; two matching launches where cap is one; a malformed JSON spawn line; a legacy TSV spawn line without reason; a `.run` with missing pid/ppid/argv; and a `-c` payload containing newline that remains one escaped marker record. Positive fixtures admit one exact launch/marker under its rule and preserve existing zero-box/owner checks.
