# Original keyword dictionary: v3 merged validation

The earlier merged landing (`checkpoint-original-kwargs-long-values`) passed builds and integer-format checks but failed two AST/keyword-call cases in a 5,091-test release run. The type-call helper required the per-class vectorcall fields to equal the built-in `type` functions. Ordinary Python classes and `object` have both fields null, so they fell through to keyword unpacking before their `__new__` or `__init__` descriptor could run. The result was an early `keywords must be strings` error; upstream calls the descriptor first. The pointer finding and source review are recorded in `ast-original-kwargs-peer-review-v3.md`.

The v3 additive patch accepts the selected type-call pair only when both actual per-class vectorcall fields are inactive. It reads the fields at the metatype's declared offsets, following `_PyValue_VectorcallTstate`'s selection rule. Active built-in and custom vectorcall paths remain selected by the normal dispatcher, and exact `type` retains its explicit exclusion.

The merged v3 attempt at `build/pyjit-link-wave1/checkpoint-closure/checkpoint-original-kwargs-v3` passed the release, debug and stats builds, each checking 117 modules with no failed imports. Value-API lint found zero failing findings. Release and debug each passed 430 `test_ast`/`test_call` tests (2 skipped). The retained `differentials/status.json` reports no failures: the 412-case integer-format matrix, the original-keyword direct C/descriptor/recursion cases, and the two direct C `object()` cases match the upstream control on both builds. This supersedes the earlier two AST failures; full functional qualification and the strict R27 gate remain separate integration checks.
