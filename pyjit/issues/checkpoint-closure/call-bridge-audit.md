# Call bridge audit

Read-only audit of runtime `7baf96ed017`, 2026-11-05. Existing suite site counts identify locations that project values, not proof of the number of distinct callers or current post-integration debt. Core-to-core exits must not be reclassified as external boundaries. The user-facing object APIs remain real compatibility entries.

## Prepend and one-argument bridges

`Objects/call.c:_PyObject_VectorcallPrepend` has two direct in-tree callers, both in object-facing method-call implementations in `Objects/call.c`: the formatted method helper and `PyObject_VectorcallMethod`. Existing `_PyValue_VectorcallPrepend` already accepts borrowed value callable/receiver and value-window arguments, retains/restores the offset slot, and returns an owned value. Existing `_PyValue_VectorcallMethod` performs the method lookup and receiver convention directly in values. Port the *core callers feeding* those object APIs to these providers where their arguments and result can continue as values; a public PyObject-returning caller must retain its real object exit. The formatted helper additionally uses `_Py_VaBuildStack` and `_PyBorrow_TupleItemsFor`: preserve its format, tuple-unpacking, `PyCallable_Check`, error text, keyword/offset convention, and object ownership, or propose a separate value formatting continuation. Do not assume changing the two public helpers alone removes their result boxing.

`PyObject_CallOneArg` is an actual object-form API in `Objects/call.c`; `_PyValue_CallOneArg(tstate, callable, arg)` already provides the value counterpart. Port each core call site plus its result consumers and home, rather than relabeling the object API. In-tree examples include dict missing-key dispatch, type attribute hooks, bytearray/float/complex subtype results, error/exception hooks, and weakref callbacks; some legitimately require object-owned homes, while others can remain values. The old manual census found over a hundred object-call sites, so first identify hot caller stacks from fresh attribution and assign disjoint coherent families. For each family retain callback and error order, concrete-type checks, cleanup, and arbitrary return types; add/check a compatibility mark only after all declared core users are ported. Relevant narrow checks: `test_call`, `test_descr`, `test_dict`, exception/weakref tests selected by touched families, and direct keyword/offset/recursion/error probes. A new full stats capture is needed to establish which callers explain the historical 1.136M/923k bridge counts.

## Type `__new__` wrapper

`Objects/typeobject.c:tp_new_wrapper` is the METH_FASTCALL|METH_KEYWORDS implementation installed by `add_tp_new_wrapper`; direct Python `T.__new__(Subtype, ...)` uses it. A candidate value METH_VALUE|METH_KEYWORDS wrapper must keep the receiver and first-argument type checks, subtype and static-base/tp_new safety checks, error messages/order, and `nargs` semantics. `_PyTuple_FromValueArray(args + 1, nargs - 1)` and `_PyValue_StackAsDict(args + nargs, kwnames)` can construct argument containers without projecting numeric entries. The hard remaining boundary is `type->tp_new(subtype, tuple, dict)`: it is an object-returning slot, so constructors such as int can still project a primitive result. Dispatching the type's general value vectorcall is not automatically equivalent because it may invoke metaclass call or `__init__`; an explicit paired value-new contract or narrowly proven per-type `tp_new` value body is needed. Keep the object entry for actual C callers, and do not treat its result box as an external boundary when core invoked it. Preserve immutable/mutable type and custom `__new__` dispatch, and arbitrary subclass return. Tests: direct `object.__new__`, `int.__new__`, non-type and wrong-subtype errors, unsafe static-base errors, custom constructor/metaclass, keyword and return types, and `_testcapi` object entry. This is a design proposal, not a claim that the 674k site disappears after argument conversion.

## `frozendict` vectorcall

`Objects/dictobject.c:frozendict_vectorcall` is currently assigned as `PyFrozenDict_Type.tp_vectorcall`; the type advertises `Py_TPFLAGS_BASETYPE`, so subclass behavior matters. Pair the object vectorcall thunk with `tp_value_vectorcall` using the established immutable built-in vectorcall pattern and confirm inherited subtype dispatch continues to follow the type machinery. A value body takes `const PyValue *args`, checks positional arity before allocation, preserves the exact-frozendict single-argument identity fast path only after an object/type guard, creates an untracked result, performs update, inserts each keyword with `_PyDict_SetValue_Take2` or an equivalent value-native any-dict setter, then tracks only on success. Retain exact failure cleanup and order.

The positional input currently flows through object-only `dict_update_arg` and its mapping/sequence continuations; inline int/float are invalid but must fail with the same lookup/iteration errors without projecting. Object mappings and iterables need the existing behaviors and callbacks; decide whether a narrowly guarded inline-invalid branch plus the existing object path suffices, or port a value-aware update continuation if arbitrary iterator results need to stay values. Preserve subclass/override and frozendict identity cases, dict/list/generator inputs, keyword values, malformed pairs, callbacks, and GC tracking. Narrow tests: `test_dict` frozendict cases, subtype/metaclass, invalid inline numeric input, keyword inline values, failure cleanup and identity. No new helper or value slot is approved by this audit.
