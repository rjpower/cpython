# `_ctypes` raw `py_object` ownership contract

Status: agreed design for an implementation packet; source and tests still require post-review. The earlier `ctypes-b-objects-home.diff` and the mutable region-snapshot proposals are rejected. This contract covers the supported GIL build and per-interpreter module instances.

`O_set` writes a real `PyObject *` into foreign memory. Its keep token may be canonicalized by the public `_objects` dictionary, so `_objects` cannot be the sole owner of an exact int or float box. A private, GC-traversed RawPin map owns the raw object independently. The map is keyed by the physical address of each managed foreign `py_object` slot; a RawPin holds one owned raw `PyObject *`. The root CData object owns the map, and casts/nested views share that root map. The map is not exposed through `_objects`. The RawPin type is a module-state heap type, created, visited and cleared with the module; `_ctypes` declares per-interpreter support. Its `tp_traverse`/`tp_clear` visit and release the raw owner without PyValue canonicalization.

For a direct O setter, compute the destination from the current direct-buffer offset or dereferenced-pointer offset after all fallible preparation. Find or atomically install the address's RawPin before writing; allocation can invoke GC/finalizers and a nested setter, so take the actual installed holder and recheck the destination address. Hold a raw new-owner reference. The final address check, `O_set` write, and holder owner swap have no Python callback or allocation between them. Release the old owner only after the new holder and bytes agree. Run the existing visible `KeepRef` afterward; if it fails, the already changed bytes stay pinned. A pointer retarget creates a different address key, so its prior physical slot remains pinned while this root exists.

`_PyCData_set` also copies simple and aggregate instances by bytes without calling O_set. For this path, use the same physical-address map. Before changing bytes, scan source pins whose complete pointer slots lie in the source byte range and whose current raw slot bits equal their pinned owner; those are the source's live managed pointers. Compute their destination addresses by offset. Collect every destination pin whose pointer slot intersects the overwritten range. Preallocate/atomically install all needed destination holders and scratch capacity. After every allocation or callback, re-read source and destination buffer addresses and rescan the pin map; retry if the candidate set/capacity changed. Then, without a callback: take raw strong references to the selected source owners into scratch, `memmove` the bytes (also defined for overlap), transfer those references into corresponding destination holders, and clear overwritten destination holders with no selected source pin. Only after every holder and byte is consistent may old raw references be decref'd. This snapshots source owners even for self/overlapping copies and bounds live pins by actual managed slot addresses. Later `GetKeepedObjects`/`KeepRef` may fail without dangling the already copied pointer.

Foreign memory populated outside these CData write paths, including `from_address` and arbitrary C writes, retains its existing external ownership responsibility. The map never dereferences an old foreign pointer merely to decide whether it owns it; it compares pointer bits against an already owned RawPin. Callback result `py_object` transfer and PyCArg argument storage are separate raw-reference paths and need explicit source audit, not automatic CData pinning.

When a value-native setter must materialize an inline value specifically to store an actual `PyObject *` in foreign memory, use a dedicated `_ctypes` boundary helper with `BOX_SITE_FIELD`, `BOX_KIND_CALL_ADAPTER`, and `_Py_BOX_OWNER_FOREIGN`. The existing static checker allows this owner only in `_ctypes`; the stats reader classifies it as foreign rather than core debt. The helper must hand the new raw object directly to the pin transaction. This classification applies only to actual O-slot materialization. Numeric/boolean/float scalar fields, `Simple.value`, constructors, descriptors, KeepRef and ordinary internal results stay value-native; do not use the foreign owner as a generic boxing escape.

Validation: exact int and non-NaN float identities through direct `py_object`, array/field/pointer assignment, cast and pointer retarget; source mutation/destruction and `gc.collect()` after a simple or aggregate copy; repeated and overlapping copies; `KeepRef` allocation failure after bytes changed; finalizer reentry during holder creation and old-owner release; one second interpreter instance; and a stats probe proving only actual O-slot materialization receives the foreign adapter kind. Compile all touched `_ctypes` units and run focused `test_ctypes` groups before merged integration.
