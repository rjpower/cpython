# `_ctypes` raw-pointer pin source review, round 1

Status: design/source still open. The original `ctypes-b-objects-home.diff` remains rejected. This review covers the later `ctypes-rawpin-wip.diff` and `ctypes-rawpin-setdefault-wip.diff`, not an integration-ready patch.

The address-keyed RawPin path fixes the direct `O_set` problem in principle. It takes a raw strong reference to the exact object before changing foreign memory, re-reads direct or dereferenced destination addresses after fallible preparation, writes the pointer without a callback, publishes the new pin before releasing the old owner, and keeps the pin if visible `KeepRef` later fails. An atomic install-or-find is required for a holder because allocating a candidate holder may run a reentrant setter for the same physical address. Terra is changing this to `_PyDict_SetDefaultValue`.

The source is incomplete for `CDataObject` copies. `_PyCData_set` can copy a simple or aggregate instance with `memcpy` and return `GetKeepedObjects(src)` without calling `O_set`. A copied `py_object` pointer then has a new physical address but no destination raw pin. The visible destination dictionary can canonicalize an exact numeric keep token; later source destruction or source slot replacement can free the raw box still pointed to by the destination. A direct `py_object` source copied into an array/field is the minimal reproducer; structs and arrays containing `py_object` extend the same mechanism. Retaining the source anchor or its mutable RawPin holders does not snapshot the old owners. The packet needs a GC-traversed, destination-owned raw-owner snapshot for each copied region (or exact mapped destination slots), installed without an allocation/failure window after `memcpy`. A reusable group keyed by destination physical start and size avoids retaining every historical snapshot on repeated writes. Source direct pins and prior copied-region groups both contribute owners to later copies. A focused regression must copy, discard or mutate the source, collect, then read the destination and check identity/lifetime.

The WIP also adds a process-static mutable `RawPin_Type`. `_ctypes` declares `Py_MOD_PER_INTERPRETER_GIL_SUPPORTED` and creates its other private types per module instance. Review a per-module heap holder type and module-state traverse/clear, or establish that this static type is safe across supported interpreters before integration.

I initially raised two free-threaded races in anchor publication and shared-address writes. The canonical design excludes free-threaded builds, so I retracted those as checkpoint blockers. GIL reentrancy through allocation, finalizers and dictionary hooks remains in scope; it does not by itself require the added two-object lock layer. Preserve the supported target critical-section convention and prove that no callback occurs between final address check, foreign write and pin publication.
