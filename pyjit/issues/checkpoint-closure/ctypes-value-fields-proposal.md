# `_ctypes` scalar fields and pointer values

The existing `_ctypes` core units are marked value-native, but several internal continuations still enter object-form descriptors, slot adapters and field callbacks. Current raw attribution identifies scalar setters/getters and pointer subscription as high-volume boxes. An adapter inside `_ctypes` is a core path; it is not a foreign ABI boundary.

## Census and interface

`Modules/_ctypes/ctypes.h` defines `GETFUNC` returning `PyObject *` and `SETFUNC` accepting/returning `PyObject *`. These pointers live in `StgInfo`, `fielddesc` (including swapped variants) and `PyCFieldObject`, are copied for anonymous fields in `stgdict.c`, and are consumed in `cfield.c`, `_ctypes.c`, `callproc.c` and `callbacks.c`. A setter result is an owned keepalive token consumed by `KeepRef`, not simply a success boolean. Scalar setters normally return None; pointer/string/`py_object` setters may return an object needed to keep foreign storage alive. `_CTYPES_DEBUG_KEEP` intentionally keeps the original input. Callbacks and foreign returns also use the same function table, so changing only descriptor wrappers cannot close the chain.

Add explicitly paired value getter/setter callbacks to field metadata, with one owner contract: getter returns owned `PyValue`/null on error; setter borrows its input and returns an owned keepalive `PyValue`/null on error. Keep object-form compatibility entries only for real object C interfaces and migrate all core table dispatch before marking them as boundary thunks. Update normal and swapped table producers, metadata initialization/copy, and field descriptor cloning together; audit direct function-pointer identity checks for `c`, `u` and `O`. Ensure no uninitialized or mismatched pair exists. An alternative all-at-once replacement of GETFUNC/SETFUNC is acceptable only if every call site, callback and platform variant is migrated in one reviewed batch.

`KeepRef` consumes its token even on failure and currently stores a non-None token either directly in `CDataObject.b_objects` (`PyObject *`) or in a dict. Scalar None must remain allocation-free. Pointer/string keepalive tokens are real pointer-space objects and retain the existing ref ownership. Before supporting an inline non-None keep token, especially under `_CTYPES_DEBUG_KEEP`, design a value-native home for the direct `b_objects` case and its traverse/clear/public descriptor lifecycle; do not project an inline value just to satisfy the old field. Preserve the existing rule that memory may already have changed when KeepRef fails.

## Scalar and descriptor continuation

- `Simple.value` currently has object-only Clinic getter/setter wrappers, calls `info->getfunc`/`setfunc`, then `KeepRef`; `Simple_init` parses an object tuple. Pair descriptor value slots and a value constructor/initializer path so integer and float inputs never reach an object thunk. Keep the receiver, setter input, owning CData buffer and keep token alive across index/float/truth callbacks. Preserve critical sections and `Simple_init` omitted versus explicit values, keyword and error behavior; mutable subclasses must use normal allocation/initialization dispatch. `_SimpleCData` itself is immutable, but public types such as `ctypes.c_int` are mutable subclasses, so copying the exact-immutable Context fast-entry strategy would not solve the common constructor path. Before constructor implementation specify and review how generic value type-call dispatch observes current `tp_new`/`tp_init` and handles Python overrides without boxing its argument window. An immutable-base-only fast path is insufficient and must not be reported as constructor closure.
- Integer callbacks are generated by `FIXINT_GETSET` and `FIXINT_GETSET_SW` in `cfield.c`. Port the generator and emitted definitions, not only generated output. Inline values use value native-byte/span extraction; pointer-space indexable objects retain `__index__` callback behavior. Preserve truncation/modulo, signedness, bitfields, swap order, error text, and partial-write behavior. Getter constructs integer `PyValue` directly, including 64-bit values that require heap storage. Normal and swapped callback pairs must remain correctly identified by all metadata consumers.
- Bool/VARIANT_BOOL setters call value truth conversion directly; float/double/long double use value-aware conversion with existing exception semantics and bitwise layout. Getter outputs use `PyValue_FromDouble`/integer value constructors. Complex pointer-space inputs keep `PyComplex_AsCComplex` callbacks; direct inline numeric handling requires the same reviewed conversion equivalence as `_struct`. Preserve conditional libffi complex support.
- Character/string/pointer setters validate representation before projection and preserve their distinct bytes, Unicode, buffers and keepalive requirements. `py_object` (`O`) stores a real `PyObject *` in foreign memory, so a primitive must be materialized at this actual foreign representation boundary; the resulting object must be kept alive exactly as before. This is a true FFI boundary, not a relabeled core adapter. Pointer-to-memory fields (`P`, `z`, `Z`, `s`, `U`, Windows `X`) need individual review of null, address conversion, allocation, release and keep tokens before porting.
- `PyCField` uses object descriptor get/set slots and delegates to `PyCData_get`/`PyCData_set`. Add paired value descriptor slots and value-aware continuations; preserve class access, deletion errors, field offset/size, locks, anonymous fields and base-object owner lifetimes. Native subclass and nested struct/array cases still use the existing pointer-space objects when those objects are genuinely required.

## Pointer subscription

`Pointer_subscript` is object-form and first converts the index. Pair `_Py_value_subscript` with the actual object thunk. For index values call `_PyValue_IndexCheck` and `_PyValue_AsSsize_t(..., PyExc_IndexError)` directly, retaining exact `__index__`, overflow and negative-index semantics. Slice inputs are concrete heap slices; borrow them only after a type guard, and use existing value fields directly for start/stop/step conversion. Preserve required stop, negative-step start, zero step, output type (`bytes`, `str`, or list), null-pointer checks, locks, element ordering and callbacks. Pass each element through value-native `PyCData_get`; filling a list uses owned value operations. Do not unconditionally box a returned integer to call the old `Pointer_item` wrapper.

Pointer assignment has separate object `sq_ass_item` and field setter paths; it must share the same value `PyCData_set` continuation and deletion semantics, including KeepRef. Array item access and assignment call the same helpers and must be audited simultaneously so metadata has no mixed contracts. Preserve all source owners and output buffers across user callbacks and keep the exact lock/critical-section boundaries.

## Validation and rollout

Peer-review the paired callback and keepalive/home contract before implementation. Land bounded families: scalar metadata + integer/float/bool helpers; descriptor/constructor continuation; pointer and array slots; then remaining pointer/string/foreign callback cases. No packet may present a half-populated table as complete. Compile each touched `_ctypes` translation unit and run narrow `test_ctypes` groups for integer wraparound/bitfields/swapped endian, float and bool callback failures, `Simple.value`, pointer index/slices/nulls, nested fields, `py_object` identity and keepalive after GC. Test `_CTYPES_DEBUG_KEEP`, free-threaded, Windows and opposite-endian only on appropriately configured real builds; report unavailable variants. The coordinator owns combined tests, exact raw attribution and performance comparisons.

## First packet: `b_objects` lifecycle

Both `CDataObject` and the layout-identical prefix of `PyCFuncPtrObject` must change `b_objects` together to an owned `PyValue`; preserve offsets and alignment. Initialize to `PyValue_NULL`, store a stolen newly allocated dict or immortal None, use `_Py_VISIT_VALUE` in traverse and `PyValue_CLEAR` in clear, and change the read-only `_objects` member to `_Py_T_VALUE` so null still exposes None. `PyCData_GetContainer` must preserve root traversal, its critical section, lazy dictionary/None initialization and allocation failure. `cast_lock_held` must share the owner with `PyValue_XDUP`, check pointer-space before a dict projection, and publish/release replacement owners safely. Do not silently change the existing source-versus-container choice in this packet.

Existing object-form `SETFUNC` returns only object-owned keep tokens, so preparatory migration can preserve their current invariant with explicit `PyValue_FromObjectSteal` storage and known-object borrows; this is not the final value-setter admission. The second coherent layer introduces `KeepRefValue` and value-returning `GetKeepedObjectsValue`, changes every consumer of the keep token and `b_objects` to carry owned values, and preserves the direct-home/dict choices, lock, consume-on-failure and pointer keepalive semantics. In particular `_PyCData_set` currently returns object tokens to three downstream consumers; do not materialize an inline debug keep token at those calls. Both layers must be integrated together before any value setter can return inline `_CTYPES_DEBUG_KEEP` tokens or before claiming the field path complete.

Public scalar classes are mutable, but generic `_PyValue_TpCallAdapter` already builds a tuple from value words. Keep normal type dispatch and port `Simple_init` to read tuple value items without projecting; verify actual allocator and initialization code before claiming no remaining projection. Mutable `__new__` and `__init__` replacement must be observed on each call. This avoids a new exact-type fast path or a broad generic type-call rewrite.

## Rejected home packet: raw FFI identity

`ctypes-b-objects-home.diff` is rejected and must not be integrated. It converted object keep tokens directly with `PyValue_FromObjectSteal`. For `py_object` (`O_set`), the foreign memory already contains the actual `PyObject *`: canonicalizing an exact int or float can free that box while foreign code still holds its address. A value word cannot serve as the sole raw-pointer keeper.

The same audit must include the pre-existing object-token dictionary branch: it uses `PyDict_SetValue` with a canonical borrowed value and then decrefs the object token. Determine whether an exact numeric object written to foreign memory can lose its last raw strong reference there; do not assume a Python dictionary value preserves the box. The existing direct `PyObject *` home and dictionaries have different raw-identity properties under PyValue.

A revised design needs separate raw FFI-owned strong references from normal value/debug keep tokens. It must explain per-field replacement, sharing through casts and base objects, traversal and cycle collection, clear/deallocation, mutation/failure atomicity, and `_objects` visibility. A raw holder cannot simply be a normal Python tuple/list/dict of numeric values, because those containers canonicalize values as well. Review the foreign pointer lifecycle and the existing dictionary path independently before implementation. Only actual foreign-memory `PyObject *` storage may request object materialization with accurate FFI attribution; numeric scalar fields remain value-native.

### Candidate transaction for raw foreign slots

A safe implementation needs a two-phase update under the same target/root lock, not just a pin after `O_set`. For an `O` write, snapshot the previous raw slot bytes without dereferencing them, retain strong local owners for the previous visible/pin entries, and retain the new object before changing the slot. Foreign memory supplied through `from_address` can contain arbitrary prior bytes, so blindly INCREFing the old raw pointer is unsafe. Write the new pointer while its local owner is live; preallocate a numeric capsule when needed. Update the visible `_objects` entry and then install or remove the sidecar pin. Only after both publications succeed may the old owners be released. If either publication fails, restore the old slot and old entries while their local owners still exist, then release the new owner. The dict keys are exact `unique_key` Unicode strings, but implementation must prove that rollback of an existing entry cannot allocate or fail; otherwise this protocol is insufficient and needs a reserved/nonallocating rollback mechanism. In particular, a failed pin insertion must not release the old pin before the previous raw pointer is restored.

`O_set` is reached through explicit field setters, nested `_PyCData_set` dispatch and direct Simple setters. Establish one authoritative helper for all CData writes so each one participates; callbacks returning `py_object` have a different documented foreign-reference transfer and require separate audit. Raw pins are needed only when the visible value canonicalizes an exact integer or non-NaN float. These numeric objects cannot form GC cycles, so a private capsule owning their raw ref can be a sidecar value without hiding a cyclic reference from GC; never put arbitrary objects in this capsule. The sidecar dictionary itself is visited and cleared normally. Casts and base roots must share the same sidecar with the matching visible `_objects` dictionary, including lazy creation and already-existing casts. This is a proposal, not an implemented or approved fix.

### Alternative: preallocated raw-pin transaction

The rollback approach above is not yet proven: a public `_objects` dict may have watchers, and restoring an entry after another allocation fails is not automatically nonallocating or reentrancy-safe. An alternative is a shared, GC-tracked sidecar anchor with a keyed private `RawPin` holder for each actual `py_object` foreign slot. Each holder owns raw `PyObject *` current and pending references and traverses/clears them, so arbitrary object graphs and cycles remain visible to GC. Create/locate the anchor, key and holder before mutating foreign memory; if allocation fails, the old slot is untouched. Stage a strong raw reference to the new object in the holder, then call `O_set` and the existing visible `KeepRef`. On success promote the staged pin and release the previous pin. If visible publication fails, leave the staged object pinned because foreign memory has already changed. Before a subsequent attempt, rotate the previously published pending pin into current so repeated failures cannot leave a live slot dangling. This avoids requiring a fallible dictionary rollback while preserving the existing possibility of memory mutation on KeepRef failure.

The holder must distinguish prepared-but-not-written from written-pending states and handle reentrant setter calls: no callback or finalizer may replace a newer committed value with an older pending value. Stage, write and promotion need a version/transaction discipline, or a proof that no Python callback can occur in the protected interval; existing dict watchers make the latter unsafe to assume. Casts must share an anchor even when no pin exists yet, and nested views must address the correct root and field key. A separate value/debug keep-token home is still needed; do not put a numeric box in a `PyValue` field or normal dict. This candidate is not approved or implemented.

A further candidate removes the rollback and pending-state requirements if its sequencing is proven. Before any CData `O_set`, allocate/find a GC-tracked per-key `RawPin` in the shared sidecar and take an owned reference to the new raw object. `O_set` itself only writes the pointer and increments the object; it cannot invoke Python or fail. Immediately after that write, swap the prepared owner into `RawPin.current` before decrefing the old current. A destructor that reenters then sees a foreign pointer and current pin that already agree. Run visible `KeepRef` afterward, but never rewrite this pin afterward: a nested setter can have superseded it. If visible KeepRef fails, the existing changed foreign pointer remains valid through the pin. A first-time sidecar/key/holder allocation failure occurs before the foreign write. This relies on every CData O setter reaching the same helper, the old pointer never being dereferenced during replacement, a stable shared root/cast anchor and an actual lock/ownership proof. Callback `py_object` result transfer remains a separate path. It is awaiting peer review.
