# Decimal methods with optional context: peer review

Approved the bounded migration of 17 macro-family Decimal methods: 14 `Dec_BinaryFuncVA`, two `_NO_CTX` variants, and one `Dec_TernaryFuncVA`. The proposed private `optional_context_value` returns a borrowed `PyObject *`. It should be defined after the conditional `CURRENT_CONTEXT` macros so its `None` branch can call the existing macro inside an object-returning function, preserving the established thread-local and context-variable ownership paths. A supplied context must be a proven object before `PyDecContext_Check`; inline or wrong-type values raise the existing “optional argument must be a context” TypeError.

Every method validates its optional context before operand conversion, as the current macro does. The concrete Decimal receiver can enter `convert_op_value` as `PyValue_FromObjectBorrow(self)`; the converter creates an owner, and other/third arguments remain borrowed values. Each later conversion failure releases earlier converted operands. Preserve the context-free mpdecimal operation in the two `_NO_CTX` methods, and preserve status/trap handling in the other 15. Successful Decimal results transfer with `PyValue_FromObjectSteal`; errors return `PyValue_NULL`. This approves the interface and ordering, pending source and focused behavior review.
