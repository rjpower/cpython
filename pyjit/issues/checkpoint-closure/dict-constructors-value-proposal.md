# Dictionary constructor value continuation

Proposed against runtime `7baf96ed017` plus the in-progress dictionary integration. Scope: `Objects/dictobject.c`; no blocked ctypes or LRU work.

Pair each static built-in type's `tp_vectorcall = _PyValue_VectorcallThunk` with its `tp_value_vectorcall` body, matching tuple/list/set. Each body accepts `(PyThreadState *, PyObject *type, const PyValue *args, size_t nargsf, PyObject *kwnames)` and returns owned `PyValue`/null on error. Keep `_PyArg_CheckPositional` before allocation, then allocate with current `dict_new` or untracked `frozendict_new_untracked`. Preserve frozendict's exact-type/one-argument/no-keywords identity shortcut after guarding `PyValue_IsObject` and checking exact frozendict. Successful frozendict construction tracks only after all insertion; failure releases the untracked object exactly as today. Keyword names remain concrete Unicode metadata and keyword values use `_PyDict_SetValue_Take2` with duplicated key/value owners (which accepts PyAnyDict, including frozendict), preserving order, hash, error and cleanup.

Add private `dict_update_arg_value(self, arg)` with a borrowed argument. For object-space values call existing `dict_update_arg` with guarded `PyValue_AsKnownObjectBorrow` while the value window stays rooted. Inline values are exact int/non-NaN float, neither has `keys` nor iteration; call `_PyValue_GetIter(arg)` to produce the existing non-iterable TypeError directly and return failure. No numeric projection, new boundary or error replacement. Existing object `dict_update_arg` consumers continue unchanged.

Port `merge_from_seq2_lock_held`'s `PyIter_Next` item to `_PyValue_IterNext`: preserve exhaustion/exception handling, call existing `_PyValue_SequenceFast` on the borrowed item, keep its owned value alive through fast conversion and the exact current TypeError note, then close it in each error/success path. Pair extraction, size diagnostics, insertion, index increments and lock boundaries remain unchanged. This closes the object continuation for malformed inline iterator items, as well as constructor input. Mapping merge retains existing callback behavior; it is a separate continuation, not claimed fully ported here.

The type fast vectorcall runs only where existing dispatch chooses the current vectorcall; it must not bypass mutable subclass `__new__`, `__init__`, metaclass `__call__`, or override selection. Verify type machinery rather than assuming that setting both fields extends the fast path. Tests: focused `test_dict` frozendict and dict constructor cases, direct int/float invalid inputs with exact errors and notes, dict/frozendict positional mappings and generators (including malformed inline entries), keyword inline values, identity fast path and subclass constructors overriding `__new__`/`__init__` and metaclass `__call__`, partial-construction exceptions and GC. W5 shadow build must restore source under the shared lock.
