# Direct `__init__` and `type.__call__` wrapper continuation

Read-only proposal against the phase-two source. General construction and direct `__new__` have value continuations, but the `init_` slot row is marked `WRAPPER=NONE`, and `PyType_Type` has no paired `tp_value.call` for its `type_call` slot. Direct Python calls to these slot descriptors can therefore still enter `wrapperdescr_value_raw_call`'s object adapter, materializing inline receivers or results. Root is measuring the actual current binary; no residual count is assumed here.

## Direct initializer descriptor

Change only the cold `init_` row wrapper column from NONE to a new INIT family; retain its row index and signature. Teach the wrapper-family enum/selector to recognize the existing `FLSLOT(__init__, tp_init, ..., wrap_init, ..., PyWrapperFlag_KEYWORDS)` and return a new `wrap_initvalue`. It receives the descriptor's checked borrowed receiver, original positional value window and kwnames, and **the descriptor's captured `d_wrapped_value`** as `_Py_initvaluefunc`. Call that exact function once and return `PyValue_None` on nonnegative status, `PyValue_NULL` on error. Do not redispatch through `PyValue_TYPE(self)->tp_value.init_`: `object.__init__(subclass_instance, ...)` deliberately invokes the object base's captured initializer, even when the instance's type overrides it. Preserve `wrapperdescr_value_call`'s receiver validation and keyword flag before invoking the wrapper; don't impose a new arity check, since each actual initializer decides its own argument rules. Hold receiver, args and kwnames throughout; no object projection is needed for inline int/float receivers.

Check how `PyDescr_NewWrapper` and slot-update logic capture `d_wrapped_value` and the exact object slot beside it; use existing paired-row invariant checks and ensure object descriptor entries still call `wrap_init` for genuine C/object use or unpaired slots. Test direct `object.__init__(5)` and float, subtype/base selection where an overriding init would raise or increment a counter, omitted/excess arguments, keywords and wrong descriptor receiver, Python-defined and object-only extension initializers, exceptions, and slot mutation/inheritance. Compare exact errors with upstream and private box counts on the current stats build.

## Direct `type.__call__` descriptor

The call row already has `VALUE_WRAPPER_CALL` and `wrap_callvalue`, but `PyType_Type.tp_value.call` is currently null even though its object `tp_call` is `type_call`. Consider pairing that **exact** object slot with a value function which calls `type_call_value` for its checked type receiver, with the original window and keywords. This is direct slot-descriptor dispatch: it must honor the descriptor's captured type-call implementation even when the argument's metaclass has an overridden `__call__`; routing through `type_value_vectorcall` would incorrectly select the dynamic metaclass call and add its recursion guard. Do not substitute a newly looked-up current metaclass function for the captured value function. Ensure the value pair may be inherited only beside the identical object `tp_call`, and that debug pair validation covers the static builtin pair.

Before that pairing, make `type_call_value` cover the object `type_call`'s one-argument `type(x)` case after its tuple/dict construction, including the distinction between no keyword names, an empty keyword set and nonempty keywords, and otherwise retain its exact 1-or-3-argument errors. The existing `type_value_vectorcall` fast path retains its own current behavior and recursion guard. The direct wrapper must not introduce a recursion guard absent from `wrap_call`'s direct slot call. Check that an empty `kwnames` is handled like the existing wrapper, which creates a keyword dict only for nonempty names. A paired `type_call` value slot can also affect other tp_call dispatch sites; audit all such users and guard exact selected slot identity rather than claiming descriptor-only effect.

Minimal tests: `type.__call__(int, 17)`, `type.__call__(float, -0.0)`, `type.__call__(type, x)` and invalid argument/keyword forms, a class with metaclass `__call__` override proving explicit base descriptor bypasses that override, mismatched receivers, reentrant constructors, and direct object C slot calls. Add paired-row inheritance and override checks, source review, debug invariant tests and a private stats comparison before claiming closure. Implement initializer and type-call wrappers as separate peer-reviewed increments if either identity or keyword behavior needs more investigation.
