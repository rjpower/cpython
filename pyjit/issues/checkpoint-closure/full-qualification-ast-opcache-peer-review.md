# Peer review: selected type call with original keyword dictionary

`full-qualification-ast-opcache-proposals.md` correctly identifies the two regressions. The dict/frozendict inheritance fix must recognize the exact built-in `__getitem__` descriptor provider and copy its declaring type's object/value subscript pair only when the MRO still selects that descriptor. The reviewed `r27-dict-inheritance-values.diff` does this without changing generic slot conflict handling; runtime qualification remains necessary.

For AST constructor calls, keep `_PyValue_StackUnpackDict` strict: active vectorcalls require Unicode keyword names. The exception is the exact selected built-in type-call pair receiving an existing kwargs dictionary through the tuple/dict call API. Ordinary classes have an active `tp_vectorcall = _PyValue_VectorcallThunk` and `tp_value_vectorcall = type_value_vectorcall`; a guard requiring no vectorcall would miss them. A private predicate in `typeobject.c` should verify those exact selected pointers, `_Py_type_call`, and its paired value call, excluding custom metaclass vectorcalls.

In `Objects/call.c:_PyValue_Call`, scan actual kwargs keys without callbacks. If a non-Unicode key exists and that predicate holds, call a private `_Py_type_call_dict_value(tstate, type, args_tuple, original_kwds)` returning an owned PyValue. The helper follows `_Py_type_call`'s order: the `type(x)`/three-argument checks, missing `tp_new` error, borrow-scope entry, selected object `tp_new` with the original tuple/dict, result check, actual-result-type `tp_init` only for an instance, scope exit, and value result transfer. A successful scalar returned by an object-only slot remains an explicit rare core bridge; it is not an external boundary or proof of zero-box constructor closure.

The direct C object entries `_Py_slot_tp_new` and `_Py_slot_tp_init` also unpack nonempty kwargs before lookup. Their non-Unicode-key paths must keep the original tuple/dict through the current method/descriptor lookup and call, preserving lookup-before-keyword-validation effects. Keep their Unicode-key value windows unchanged. Validation must include both failing AST tests, direct C `PyObject_Call`, Python `CALL_FUNCTION_EX`, custom metaclass vectorcall, bad and duplicate keys, and lookup callbacks that raise or mutate state.
