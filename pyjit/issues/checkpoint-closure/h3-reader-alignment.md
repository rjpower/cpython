# H3 reader alignment receipt

The additive patch `h3-reader-alignment.patch` applies to the current runtime tree after the H3 producer. It preserves box-owner aggregation while making handler-entry metadata a checked input to every dump, JSON reload, cohort merge, and two-cohort comparison. Metadata is not summed. Raw counted entries and producer-declared family totals are reported separately from semantic specialization events. Adaptive, specialized, and other entry counts partition the counted total; the report no longer treats guard misses as a separate executed entry or infers a hit count by subtracting misses.

The reader rejects duplicate flat or JSON keys, missing or incomplete metadata triples, invalid IDs and canonical bases, counters for nondispatch handlers, invalid pair endpoints, and conflicting producer contracts. It retains the existing box-site, kind, and owner reports.

Validation: 13 focused synthetic reader tests passed, including duplicate/missing facts, mixed cohort mode, JSON round-trip, family versus event counts, IR-only and no-feedback targets, and complete rendering. Python syntax checks and `git diff --check` passed. `git apply --check` passed against the coordinator's current runtime tree. The reader parsed and rendered the coordinator's unchanged real `h3-handler-domain-v2/crash-probe` dump: one file, domain 319, 298 metadata entries, dispatch mode 1, 418,493 counted entries, including 191 `BINARY_OP_ADD` target entries. The known `Stats process:` diagnostic is skipped explicitly. The coordinator's rebuilt stats binary passed the exact malloc-debug/stats crash reproducer; this reader validation did not run the binary.
