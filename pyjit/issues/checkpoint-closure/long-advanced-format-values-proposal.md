# Value-native advanced integer formatting

Design proposal against current integration source; no implementation yet. The exact integer `__format__` value entry in `Objects/longobject.c:int___format___impl` currently boxes `self` before `_PyLong_FormatAdvancedWriter`, and `Objects/stringlib/unicode_format.h:render_field` selects that object writer for exact heap ints while an inline integer falls through generic format dispatch. Preserve the existing formatting engine and actual C object entry; a fresh matching stats run must determine any benefit.

## Integer conversion providers

Add internal `_PyLong_FormatWriterValue(writer, PyValueBorrow value, base, alternate)` and `_PyLong_FormatValue(value, base)` in `Objects/longobject.c` / `Include/internal/pycore_long.h` or `pycore_long_value.h`, with the existing ownership and error contracts: borrowed integer in; status or a new Unicode object out. For an inline exact int, materialize `_PyLongSpan` with a local `digit[_PyLong_WORD_DIGITS]` whose lifetime covers the synchronous digit-to-writer/string operation. For base 10 reuse `long_to_decimal_string_internal` / `long_to_decimal_writer_span`; an inline int is too small for the decimal digit-limit or `_pylong` threshold, as `_PyLong_WriteDecimal` already documents. For bases 2/8/16 refactor the existing `long_format_binary` digit kernel to consume a span, with its object entry extracting a span after the same type checks. Do not create a heap PyLong or duplicate the binary algorithm. Prefix, negative sign, zero, base-specific digit counts, writer growth/failure and Unicode ownership must remain identical. For object-space longs and subclasses route directly to existing object paths, including the >1000-digit `_pylong` switch and digit-limit checks; the input value remains owned by the caller throughout. Preserve invalid-base assertions/errors and the current object writer / bytes-writer entry behavior.

`format_long_internal` in `Objects/unicode_formatter.c` becomes value-borrowing. Preserve validation order for precision, negative-zero option, sign/alternate flags on `c`, and all locale/width/grouping calculations. For `c` use `_PyValue_AsLong(value)` with the same sentinel/error and Unicode range checks. For numeric presentations, exact-integer fast paths call `_PyLong_FormatWriterValue`; the general sign/prefix/grouping path calls `_PyLong_FormatValue` and continues to own its temporary Unicode through `fill_number`. Existing `PyLong_CheckExact` predicates become `PyValue_LongCheckExact`, so bool and int subclasses retain their previous slow path and callback behavior. Preserve uppercase, grouping and locale formatting without changing the existing `InternalFormatSpec` parser.

## Advanced writer and consumers

Add `_PyLong_FormatAdvancedWriterValue(writer, value, spec, start, end)` with the existing object `_PyLong_FormatAdvancedWriter` as a thin boundary forwarding a borrowed object. For an empty spec, use `_PyLong_WriteDecimal` for exact ints and the existing `_PyValue_Str`/writer path for subclasses, preserving subclass `__str__` dispatch. For nonempty spec pass `PyValue_TYPE(value)` to the unchanged parser and the borrowed value to the integer formatting body. For float-style specs `e/E/f/F/g/G/%`, call `_PyValue_Float(value)`, keep its owned `PyValue` through `format_float_internal`, close it exactly once; preserve subclass `__float__`, overflow and exception ordering. Form invalid-presentation errors with `PyValue_TYPE(value)->tp_name`, as before. Check that the object bridge cannot canonicalize and invalidate an object whose identity matters across callbacks: its caller owns the object and subclass values remain pointer-space.

Switch `int___format___impl` directly to the value writer and remove the parser box. In `render_field`, select the value writer only for `PyValue_LongCheckExact` (which includes inline exact int, not bool or subclasses); leave subclasses' generic `__format__` dispatch and exact Unicode/complex cases unchanged. The receiver remains borrowed from the field owner and the spec object remains owned through the writer and any callbacks.

After replacing every production `_PyLong_FormatAdvancedWriter` core caller, add its manual object/value alias and `Py_VALUE_COMPAT` mark with an exact writer/spec/range/status ownership description, matching the reviewed float alias. Do not mark the broader `_PyLong_FormatWriter` alias: other existing callers remain. Keep the object C entry callable for true object-form consumers.

## Required review and checks

Review span buffer lifetime, zero/sign and prefix arithmetic, fast versus slow equivalence, and `_pylong` heap fallback before implementation. Compare upstream for bases b/o/d/x/X/n, `c`, alternate forms, signs, fill/alignment, large widths, grouping, precision and invalid specs, int51 boundaries and very large heap ints, `sys.set_int_max_str_digits` behavior, locale where available, float-style overflow, bool/int subclasses overriding `__str__`, `__format__` and `__float__`, and mutation/reentrant callbacks. Run narrow `test_format`, `test_int` and relevant `test_str`/`test_unicode` cases plus direct descriptor/format-field probes. Use root's merged build and startup-inclusive stats for final evidence; never assert zero boxes from source inspection alone.
