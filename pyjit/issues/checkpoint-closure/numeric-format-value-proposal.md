# Value-native numeric formatting

Status: design for peer review, 2026-11-06. Source basis: current runtime `Objects/{longobject,floatobject,unicode_formatter,abstract}.c` and `Objects/stringlib/unicode_format.h`. The existing `int.__format__` and `float.__format__` Clinic entries receive a borrowed `PyValue`, then materialize it before calling the object-only advanced writers. Formatting an inline value with a nonempty spec therefore records a core box. The field renderer also reserves its direct-writer fast path for object-backed exact ints and floats. An empty int spec already has a value fast path in `_PyValue_Format`; that does not close nonempty specs or direct numeric methods.

## Contract and source ownership

Keep the public/object `_PyLong_FormatAdvancedWriter` and `_PyFloat_FormatAdvancedWriter` signatures, and the direct object entries, for real object callers. Add private value-writer twins declared in `Include/internal/pycore_long.h` and `pycore_floatobject.h`, defined in `Objects/unicode_formatter.c`. The object writers delegate with `PyValue_FromObjectBorrow(obj)`; the value writers accept `PyValueBorrow` and do not consume it. `int___format___impl` and `float___format___impl` pass their borrowed self directly, retaining the existing writer init/dealloc/finish paths. `render_field` recognizes `PyValue_LongCheckExact` and `PyValue_FloatCheckExact` before the object-only dispatch and invokes the value writers with the existing format-spec substring. Its owned `fieldobj` remains live across all formatting callbacks. Subclasses keep the existing lookup route, including overridden `__format__` and `__str__`.

Only `Objects/longobject.c` owns span-to-digit conversion. Expose narrow private `_PyLong_FormatValue(PyValueBorrow, int base)` and `_PyLong_FormatValueWriter(_PyUnicodeWriter *, PyValueBorrow, int base, int alternate)` providers there, built from the existing decimal span formatter and a factored `long_format_binary` core that accepts `_PyLongSpan`. Keep its existing object wrapper and byte-writer behavior. The span points into either an inline scratch `digit[_PyLong_WORD_DIGITS]` or an object held by the caller, so it must not escape the call. Preserve digit-count overflow checks, the decimal digit limit and `_pylong` handoff for large heap ints; factor only the inline path where the handoff cannot apply. Avoid a second base-2/8/16 digit algorithm.

## Formatting behavior

In `Objects/unicode_formatter.c`, make `parse_internal_render_format_spec` take the value's type name or `PyTypeObject *` for its one type-specific error; all parsing, validation and error order remain shared. Make `format_long_internal` take a borrowed value. `%c` uses `_PyValue_AsLong`; ordinary numeric presentations use the new span providers for both the direct writer fast path and temporary digit string. Retain its existing precision, negative-zero, sign, grouping, locale, width, prefix and fill logic. For `e/E/f/F/g/G/%`, `_PyValue_Float` returns an owned value, passed to the float internal formatter and closed on every path. This removes the current float-object projection inside the long formatter.

Make `format_float_internal` accept a borrowed value and keep its `_PyValue_AsDouble` result as `double`; the rest of the current `PyOS_double_to_string`, locale and writer code stays unchanged. This preserves signed zero, NaN, infinity, `%`, rounding, precision and conversion failure behavior. For an empty spec, the value writers use `_PyValue_Str` for floats and `_PyLong_FormatValueWriter` for exact ints; object subclasses continue through their existing `format_obj` path. Unknown-presentation errors use `PyValue_TYPE(v)->tp_name`, preserving the exact type name without projecting an inline value.

The lowest-risk implementation order is (1) shared float value writer plus direct method and field callers, then (2) long span digit provider and long value writer. The formatter cannot claim closure until both direct `__format__` and field rendering avoid numeric core boxes. Keep any object slot thunk at the actual object API boundary; do not relabel an internal formatter box as a thunk.

## Focused admission

Compare exact output and exception type/message against the upstream control for direct `int.__format__`/`float.__format__`, `format()`, `str.format`, f-strings and `format_map`. Cover bases, alternate prefixes, grouping, locale `n`, fill/alignment, very large width/precision, `%c` bounds, int-to-float presentations, signed zero, subnormals, infinities, NaNs, and invalid spec/error order. Include int/float subclasses overriding `__str__`/`__format__`, a field callback that drops the outer owner, and direct object C entry behavior. Focused `test_format`, `test_float`, `test_long`, and `test_str` should pass. A private stats probe compares repeated inline int and float nonempty specs with an empty loop and requires zero new core numeric boxes at `int___format___impl`, `float___format___impl` and `render_field`; count actual call sites rather than reclassifying them.

This packet does not change complex, Decimal, or user-defined formatting. Numeric locale and digit-limit behavior remain owned by the existing formatter and long conversion code.
