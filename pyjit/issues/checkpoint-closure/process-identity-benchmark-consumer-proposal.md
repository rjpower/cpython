# Benchmark consumer for paired Py_STATS identity

The stage-two producer adds `<stem>.done` beside each completed `<stem>.txt`, so `pyjit/bench/run.py:pystats_counts()` cannot keep its current “one new file in `/tmp/py_stats`” rule. This is a consumer contract proposal, not an implementation. It must land with the C producer and R27 reader, before another box-count measurement.

Give every `pystats_counts` invocation a fresh private directory beneath the benchmark run's scratch directory, with a monotonically increasing invocation number independent of whether `--pystats-records` is enabled. Pass `-X pystats -X pystats_dir=<absolute-private-dir>` in `ctx.command`, using a fixed-width invocation component so warmup/low/high startup paths have equal argument length. Keep the child environment otherwise as before. This removes unrelated global `/tmp/py_stats` writers from attribution and makes a child that unexpectedly spawns another stats process visible as extra files.

After the child exits successfully, require the directory to contain exactly one regular `<stem>.txt` and one regular `<stem>.done` with the same valid stem, and no `.run`, `.zero`, `.tmp`, orphan, extra dump or unknown file. Parse the existing marker fields strictly: one positive pid, nonnegative ppid, tag and byte-escaped argv list. Decode argv with the same byte-to-filesystem-string rule as `check_r27.py`. Require marker pid and tag to equal the dump's single `Stats process: pid=... tag=...` line, ppid to equal this runner's pid, and marker argv to equal the exact `ctx.command` sent to `subprocess.run`. A unique benchmark tag in the child environment is useful but optional; if added, compare it in both records. Do not infer a successful child from a prelaunch audit event. Any mismatch or malformed identity is a measurement error; do not fall back to the first text file.

For `--pystats-records`, append one journal record containing the original `.txt` and `.done` bytes (losslessly represented), their hashes, both original paths, the full command, invocation number, benchmark and loop count. Write that record before counter parsing, so duplicate/missing-counter failures retain the raw evidence. On failure, do not unlink either file; on success, remove only the verified pair from the private directory. The existing temporary benchmark run directory is removed at command exit, so checkpoint qualification should always supply an external `--pystats-records` journal. No global stats directory cleanup is permitted. Keep the existing strict duplicate-counter and handler-metadata checks.

Focused tests should cover the valid pair, mismatched stems/pid/ppid/tag/argv, missing and duplicate files, `.zero` and `.run`, malformed/empty marker, invalid byte-escaped argv, extra child dump, and duplicate counter after a valid pair. Verify failed parsing journals both raw records and leaves the pair untouched while an unrelated file outside the invocation directory is preserved. An integration probe must run one benchmark under the new producer and inspect all three warmup/low/high records before the 29-kernel gate is repeated.
