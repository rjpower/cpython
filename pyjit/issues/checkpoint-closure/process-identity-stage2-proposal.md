# Finished-process identity for the R27 stats gate

Source proposal against the `af82c03c4e5` stats producer and reader. No runtime change is made by this document. The stage-one worker audit records remain launch *events*, not child processes; the exact admission-rule manifest stays empty.

## Producer contract

On Linux, `run_marker_create` already writes a unique `<stem>.run` with pid, ppid, tag and byte-escaped `/proc/self/cmdline` argv. Preserve that *start-time* identity at completion rather than reconstructing argv at dump time: after `<stem>.tmp` has been closed and successfully renamed to `<stem>.txt`, atomically rename `<stem>.run` to `<stem>.done` and clear `run_stem`. If the marker cannot be renamed, leave it and the finished dump in place; the reader must reject the mismatched pair. The existing zero-stats branch currently unlinks its marker without a dump. Rename that marker to `<stem>.zero` instead, retaining the identity and making the no-dump outcome explicit and fail-closed. `run_marker_create` after `sys._stats_dump()` will still issue a fresh stem for subsequent intervals. Forked children already call `run_marker_create` in `_Py_StatsAfterFork`, so each gets its own identity. Windows behavior is unchanged; the checkpoint's Linux stats gate is the target.

The completion rename must not change the stats result or Python exception behavior. It is reporting metadata. The reader treats a failed or missing rename as an accounting error. Do not copy a mutable `/proc/self/cmdline` at completion or infer identity from the dump's current `Stats process` pid/tag line: an exec or argv mutation can make that differ from start-time argv. The existing dump line remains useful as a cross-check of pid and tag.

## Reader contract

`Folded.fold_dir(delete=True)` currently removes `<stem>.run` with each folded dump. Stop deleting markers there and retain each successfully folded dump stem and parsed dump pid/tag, including dumps removed during periodic folding. `read_markers` then parses `.done`, `.zero`, and residual `.run` using the same strict raw-byte argv decoder already used for `.run`. Require exactly one completed identity per folded dump, identical stem, pid and tag; reject missing, duplicate, malformed, empty or contradictory records. A `.done` without a folded dump, `.run` with a folded dump, and every `.zero` are explicit accounting failures until an exact source-backed disposition is reviewed. A residual `.run` without a dump remains an unfinished-process failure. Persist bounded identity samples and counts in the summary so a reviewer can inspect launch/finish coverage without retaining thousands of full argv lists in memory. Keep predicted-true audit events in a separate list for diagnosis; neither their count nor `Popen`+`posix_spawn` double announcements prove child count.

This pairing does not yet prove every child was captured: a process can fail before `run_marker_create`, and prelaunch audit can fire for a launch that fails. A later, separate post-success receipt needs an actual child pid from the Linux return paths in `posixmodule.c` (`posix_spawn[p]`, `fork`, `forkpty`; `fork1` on platforms that build it) and `_posixsubprocess.c` (`do_fork_exec`, including its `vfork` path). Record a successful parent-side `pid > 0` even if a later parent hook or warning makes the Python API return an error: the child already exists. Pair each receipt to a `.done`, `.zero`, or `.run` pid/ppid. Receipt absence, duplicate receipts, or unmatched child identity then fails; no tag-wide exemption or subprocess monkeypatch substitutes for that evidence. Once complete, native post-success receipts are the primary child-coverage evidence. Python audit records remain diagnostic for launch intent and unresolved shell commands; their prelaunch events do not form a parallel child-count mechanism. A finite build-specific source audit must cover any additional active `spawnv` or platform launch paths before claiming exhaustive receipt coverage.

## Focused acceptance checks

Use synthetic directory fixtures for `.txt`+`.done`, folded-away `.txt`+`.done`, missing and duplicate sidecars, `.run`+`.txt`, orphan `.done`, `.zero`, empty/malformed sidecars, pid/tag mismatch, and byte-escaped non-ASCII/invalid filesystem argv. A real stats child that exits normally must produce a matched `.done`; a child cleared to zero must produce `.zero`; `sys._stats_dump()` followed by another interval must use distinct stems. An `os.fork` child and a `subprocess.Popen` child should each have their own pid/ppid pair. Run the focused checker fixtures and these small stats probes before a full R27 suite attempt. The gate must remain red for unknown or incomplete identities.
