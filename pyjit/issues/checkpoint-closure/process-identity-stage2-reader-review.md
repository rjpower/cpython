# Stage-one audit and stage-two identity reader review

Final source verdict, 2026-11-06: **approved for coherent integration** of `process-accounting-stage1-current-main-357.patch` followed by the final `process-identity-stage2-reader.patch`, together with the separately reviewed C producer and private benchmark consumer. This is source approval, not a claim that full R27 process coverage passes. Luna reports 57 focused checker/worker tests passing, one expected skip. The coordinator owns the merged real-process probes and full suite.

The first stage-two draft left three gaps: an early string-command audit path iterated an arbitrary custom environment mapping; relative executable aliases could be classified as proven nonproducts without cwd/PATH evidence; and completed `.done` argv was discarded from the reader's identity records. The final patch makes unknown command/environment shapes opaque without invoking their callbacks, treats every unresolved relative executable as ambiguous, and retains filesystem-decoded argv in each completed identity and bounded summary samples. It also rejects a folded dump stem seen twice. The final source still treats prelaunch audit events as intent; no predicted `counts=True` event is accepted as proof that a child existed.

The reader now keeps the dump stem/pid/tag through periodic `.txt` deletion and pairs exactly one `.done` marker with each finished dump. Missing, malformed, orphan, contradictory `.run`/`.zero`, duplicate, and mismatched identities set accounting errors; suite admission requires `identity_coverage.complete is True`. It decodes the C marker's byte-escaped JSON argv with the filesystem codec, retaining invalid bytes via surrogateescape. Empty/truncated/unreadable spawn and audit-error ledgers fail closed. The worker preserves command argument boundaries and detects a short record write. Existing box-counter and owner checks remain intact.

Native post-success child receipts are still required to prove exhaustive child coverage; a launch audit can fire for a failed call or more than once for one child. The strict admission-rule manifest remains empty. I reviewed the coordinator's `process-identity-probe.py` after it added actual `Popen` pid checks, fork-child `ppid` checks, distinct repeated stems, zero-stats rejection, and argv byte round-trip; its source is approved for the coherent producer/reader integration run.
