# Native child receipts for the R27 gate

Status: implementation proposal, 2026-11-06. Stage-two `.txt`/`.done` pairing establishes which *observed* Python processes finished. It cannot prove every child was observed. This packet adds post-success native child receipts; it does not classify every external image in one step. The canonical contract is [process-accounting.md](../../design/process-accounting.md). Stage-one audit events remain intent only.

## Wire contract and failure state

Linux `Py_STATS` only. Append a versioned strict receipt file `<parent-stem>.<serial>.child` to the same stats directory as the parent's marker. Its fields are `version: 1`, `parent_pid`, `child_pid`, `parent_stem`, `serial`, `source`, `parent_image_dev`, `parent_image_ino`, `candidate_count`, and `candidates`, where `candidates` is a JSON list of raw executable-path bytes escaped in the same `\u00xx` representation as marker argv. Source is one of `spawn`, `spawnp`, `fork`, `fork1`, `forkpty`, `fork_exec`; direct spawn has one candidate, fork has none, and fork_exec retains all ordered candidates. Pids and serials are positive decimal integers; image device/inode are nonnegative and must match preflight identity before admission. Candidate count is explicit and bounded by the producer's C array length. Unknown/duplicate fields, truncated JSON, bad source/candidate shape, unsupported version, and nonregular files fail closed. File publication is `<name>.tmp` created with `O_EXCL`, one checked write loop, checked close, then same-directory `rename`; a left-over `.child.tmp` is a failure artifact.

The C producer holds a process-local `next_serial` and sticky `receipt_errors`. Every post-success call from a stats-configured interpreter consumes one serial, including calls while counting is toggled off. A process with no allocated stats structure has never entered the measured interval and emits no receipt; enabling stats later starts a new marker. If a configured process has lost its interval stem, a successful child creation increments the sticky error instead of disappearing. An `open`, write, close, rename, path-truncation, or image-stat failure also increments `receipt_errors` without changing Python API behavior. Emit `Stats child receipt errors: N` in every subsequent parent dump; the reader requires the field and requires zero. If the parent exits before a dump, its `.run` remains and the gate fails. Reset the child's inherited serial/error state during `_Py_StatsAfterFork`; the child creates its own marker only when collection is enabled. A child born during a counted parent's off interval therefore leaves an unresolved native receipt. No Python allocation or callback runs in the receipt helper.

Extend the start marker (version 2) with exactly two required fields, `image_dev` and `image_ino`, from `/proc/self/exe`; keep its existing pid, ppid, tag, and raw argv fields byte-for-byte. The reader rejects v1 for stage-three admission and rejects missing, duplicate, or extra v2 fields. These fields record the *actual running image* at interpreter start and bind it to the coordinator's preflight `stat`/ELF build ID. They cannot be inferred from argv or a prelaunch path. A failed image lookup leaves an explicit malformed marker and fails admission. Both parent receipt and child marker must identify the measured build, or the child image remains unresolved. An `exec` in one pid creates an image transition rather than a new child: the prior interval dumps or remains `.run`, and the new interpreter's marker identifies its new image. Preserve all intervals, even when a pid repeats.

The controller itself has no `Py_STATS` marker. Before admitting a run, `check_r27.py` writes an explicit root-launch manifest for each actual `subprocess.Popen` it starts: returned child pid, controller pid, exact argv bytes, configured executable, and the measured executable's preflight dev/ino/build ID. It records the pid only after `Popen` succeeds and checks the first child marker against this one launch. A root marker needs this manifest; an arbitrary ppid outside the marker set is never enough. A failed launch records an error and cannot mint a root. The benchmark harness uses the same rule for its one launched process, retaining its launch manifest with the raw journal. Native receipts account for descendants of admitted roots. A process that loses its parent or is reparented cannot become a new root by ppid alone.

## Source locations and callback ordering

Declare a C-only `_PyStats_ChildCreated(pid_t child, source, const char *const *candidates, size_t n, const char parent_stem[41])` and `_PyStats_CopyIntervalStem(char out[41])` in `Include/internal/pycore_pystats.h`; define them in `Python/pystats.c`. The copy helper only copies the existing fixed C stem and runs before any parent callback can call `sys._stats_dump()` and rotate it. If no valid parent stem exists, set sticky failure and still record the child in a failure sidecar when possible. The writer runs after fork locks are released, does only libc I/O, and preserves the current Python exception state and `errno`.

| Producer | Snapshot parent stem | Publish `pid > 0` receipt |
| --- | --- | --- |
| `Modules/posixmodule.c:py_posix_spawn` | immediately after successful `posix_spawn[p]` | before `PyValue_FromInt64(pid)` or cleanup |
| `Modules/posixmodule.c:os_fork_impl`, `os_fork1_impl`, `os_forkpty_impl` | parent branch immediately after `fork[pty]` returns | unconditionally after `PyOS_AfterFork_Parent()` releases locks, before warning/result paths |
| `Modules/_posixsubprocess.c:fork_exec` | after `do_fork_exec` returns positive pid, before signal-mask and parent-hook callbacks | after any required `PyOS_AfterFork_Parent()`, before cleanup/result construction |

The `do_fork_exec` receipt covers its `vfork` branch; do not call Python or write from the vfork child. `PyOS_AfterFork_Parent()` returns `void`, so even a later warning or result error cannot skip the receipt statement. An after-fork callback that itself creates another child may publish its own receipt first; serial order is publication order, while the saved parent stem records the original launch interval. If a callback terminates the parent, the original parent's `.run` is unfinished and admission fails. `posix_spawnp` is not assumed to resolve its PATH target. `fork_exec` candidate order is preserved, and no candidate is declared the winner merely because the parent received a pid. Audit any additional Linux `spawnv` implementation in the selected build and add its success point before claiming exhaustive hooks.

## Reader and admission

`Tools/build/check_r27.py` reads all `.child` files and rejected `.child.tmp` files. It pairs a receipt to a valid parent interval by `parent_stem`/`parent_pid`, and to the child's marker(s) by `child_pid`/`ppid`. An observed child marker with no receipt or enumerated root launch, a receipt with no child marker or reviewed external-image disposition, duplicate receipts for one child pid, or pid reuse without sufficient identity is unresolved and fails. A process with several dump intervals has one native creation receipt, not one per interval. The marker's image device/inode distinguishes a measured Python child from an external image; direct path strings and stage-one `counts=True` predictions never substitute for image proof. The first reader increment may leave every markerless external child unresolved; keep the gate red until individual source-backed external dispositions are reviewed.

`pyjit/bench/run.py`, its focused tests, and `pyjit/issues/checkpoint-closure/process-identity-probe.py` must change in the *same integration packet* as marker v2. The private benchmark consumer checks the exact v2 field set, pid, ppid, tag, argv and image dev/ino against its Popen launch and preflight identity, journals the raw `.txt`/`.done` bytes plus launch manifest, and rejects any `.child` or other extra artifact. No v1 fallback or silent field filtering is allowed. The probe asserts real Popen pid, first-child ppid, image identity, repeated dump stems, and raw argv round-trip. The strict reader, benchmark consumer, and probe must all accept v2 together before the producer is enabled in a merged build.

## Focused proof

Test a failing spawn (no receipt), successful `posix_spawn` and `Popen` (one receipt each despite multiple audit events), `fork` and `forkpty`, `vfork` if active, a successful child followed by a parent warning/error, `sys._stats_dump()` from an after-fork callback (saved parent stem), and a fast-exiting external child (unresolved, retained). Include a configured parent that toggles stats off around `fork`: its native receipt must remain and its markerless child must fail admission. A child created before stats was first activated must not create a retroactive receipt or sticky error when the parent activates stats later. Synthetic reader fixtures cover an enumerated root launch, an unenumerated orphan marker, duplicate/truncated/unknown-source receipts, missing parent stem, child ppid mismatch, image mismatch, sticky-error nonzero, and pid reuse. Benchmark fixtures reject v1, extra marker fields, mismatched image identity, and unexpected child receipts. Check the raw marker and receipt byte escapes for non-ASCII and invalid filesystem bytes. Execute these focused probes on one coherent stats binary and reader before the full R27 suite.
