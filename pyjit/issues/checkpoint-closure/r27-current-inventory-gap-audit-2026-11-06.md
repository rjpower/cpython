## Remaining API continuation families

1. **Type lookup and descriptor consumers.** `_PyType_LookupRef` remains in `Objects/typeobject.c:get_dict_descriptor` and `_Py_slot_tp_getattr_hook_value` (`__getattr__` and `__getattribute__`); `Objects/classobject.c:method_getattro` and `instancemethod_getattro`; `Objects/moduleobject.c` lazy-submodule recheck; `Python/ceval.c` self-hint and `type_has_special_method`; `Python/specialize.c` STORE_SUBSCR diagnostic; `Python/pylifecycle.c` list-append and base-getattribute bootstrap; `Modules/_lsprof.c` built-in method naming; and test-only `Modules/_testcapi/gc.c`. `_PyType_LookupValue` returns an owned value, but its current status 0 covers missing and can coexist with an exception. Preserve each caller's actual missing/error policy, keep values owned across descriptor/hash/callback work, and only project after proving a genuine object-only consumer. Attribute-hook and method-getattro families need paired value dispatch and explicit method-descriptor binding, lazy slot reset and reentrancy review; diagnostics that only inspect type or pointer identity can be smaller ports. Lifecycle global homes need proof their results are known objects. See `type-lookup-ref-census.md` for an earlier bounded decomposition.
2. **Generic attributes with an explicit dictionary.** `_PyObject_GenericGetAttrWithDict` object callers remain `Modules/_threadmodule.c` local get paths, `Modules/_pickle.c` Pickler getattro, and `Objects/lazyimportobject.c`. The existing `_PyObject_GenericLookupAttrValue` has different suppression semantics; design a value provider that preserves the explicit dict, suppress flag, descriptor precedence, exception augmentation and lazy import behavior before marking any equivalent alias. `_PyObject_GenericSetAttrWithDict` still appears in `_threadmodule.c` local setattro; pair the slot and lend the incoming value through the existing value setter while preserving the dictionary and deletion sentinel across callbacks.
3. **Call and method adapters.** `_PyObject_Call_Prepend` still appears in `Objects/typeobject.c:call_method` (the Python init value continuation no longer uses its prior slot-new object path). `_PyValue_VectorcallPrepend` consumes a value window, not an object tuple/dict; preserve tuple/dict and receiver owners and exact bound/unbound lookup behavior. `PyVectorcall_Call` remains in `Objects/methodobject.c` as object-call compatibility dispatch and in test C API. `PyObject_VectorcallMethod` remains in `Objects/descrobject.c` mappingproxy `get`, `Modules/_asynciomodule.c` call scheduling, `Python/importdl.c`, and Windows `_winapi.c`; classify each result and boundary rather than replacing the function name mechanically. Mappingproxy needs a value-returning producer and kept mapping/argument owners; asyncio callbacks may discard only after closing the owned value and preserving exception order.
4. **No-arg and one-arg method calls.** Object-form callers remain in `_io`, `Objects/abstract.c`, `Objects/weakrefobject.c`, `Objects/odictobject.c`, `_pickle`, `_sqlite/connection.c`, `_asynciomodule`, `_datetimemodule`, `_collectionsmodule`, lifecycle/traceback and platform modules. Some receive concrete strings, bytes, file objects or actual FFI objects; others can return numeric/None values. Trace each full producer/consumer window, preserve receiver ownership over callbacks, and only use the value method providers where the continuation can consume an owned value without a new internal projection.
5. **Formatting and scalar homes.** `Objects/stringlib/unicode_format.h` still selects `_PyLong_FormatAdvancedWriter` for nonempty inline integer format specs; design a direct integer value writer with existing sign, width, grouping, precision, overflow and callback/error order. The candidate float writer does not settle this. Keep true C-object writer entry points as boundaries, and verify both normal and error cases with a fresh raw count.
6. **Owner/inventory completeness.** `PyMethod_GetSelfRef` and `PyCFunction_GetSelfRef` can expose scalar homes but no declared owned-value provider was found in the earlier scan; current production use must be rechecked before introducing a provider. `PyDict_Next` in `typeobject.c` is under `Py_GIL_DISABLED`, outside the supported PyValue profile. Slot thunks, varargs parsers and presence-only reads are not automatically TOML ownership pairs. Continue a declaration/definition/caller census across all compiled production units, classify true C boundaries explicitly, then peer-review any proposed completeness marker against static and dynamic gates.

## Cached richcompare call-throughs

`Modules/_bisectmodule.c` saves `tp_richcompare` in both left/right search loops and uses that saved function when its original object/type fast-path conditions hold. `Objects/listobject.c` saves `key_richcompare` during sort precheck and calls it from `unsafe_object_compare`; inline long/float and other scalar paths already have value-aware alternatives. Both are live review families, not blanket port instructions. A safe proposal must capture the value row **at the same time** as the selected object slot, preserve the originally selected callback identity across comparison and `key`/truth callbacks, preserve `NotImplemented`, exception and truth-conversion ordering, and retain operands/result through reentrant mutation. Do not substitute a generic current-type dispatch after callbacks: it can choose a different function. Cover mutable type slots and custom comparator/NotImplemented/error paths in focused tests.
