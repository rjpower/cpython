## Copied slot pointers

The current `math_sumprod_impl`, bytearray initializer, abstract sequence-slice, and `_bisect` `sq_item` sites capture paired value rows before callbacks. Collections and itertools no longer have the earlier copied-`tp_iternext` calls. `Objects/call.c`'s captured `tp_call` references serve explicit object-call compatibility dispatch; availability tests in `typeobject.c` and `specialize.c` do not call through a saved pointer.

Two call-through families remain for review. `_bisectmodule.c` captures `tp_richcompare` in both search loops (`~105`, `~353`), and list sort saves it in `ms.key_richcompare` (`Objects/listobject.c:2799`, called near `2516`). Both must preserve their selected callback identity, NotImplemented behavior, error propagation and reentrant type mutation. Capture the paired value row at the same point as the object row, and use that saved row when its original fast-path preconditions hold; otherwise retain the existing object fallback. Do not call `_PyValue_CallRichCompare` blindly after a callback: it consults the type's *current* row and can change the function chosen by the original cached-slot algorithm.

## Priority

1. Close the SQLite optional-string lookup with its full bind/adapt value chain, then inventory and mark the pair.
2. Port the small `_io` method-return continuations and mappingproxy `get`; verify receiver lifetime and actual C object boundaries.
3. Design the `_PyType_LookupRef` and generic attribute-with-dict continuations across their callers; these have status/descriptor semantics and need peer review before bulk edits.
4. Admit the no-production-caller manual aliases only after checking exact signatures and output ownership. Review saved richcompare rows as a separate finite slot packet.

The inventory stays open until the declared provider/mark checker and a fresh current-source caller census pass together. This audit excludes blocked ctypes and LRU ownership designs and does not add 32-bit or free-thread admission requirements.
