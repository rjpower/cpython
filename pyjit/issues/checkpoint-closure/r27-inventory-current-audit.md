# R27 inventory and indirect-slot audit on the merged runtime

This is a bounded source audit of the current `pyvalue-rc-universal` candidate, after the bisect and itertools ports. It does not establish a complete ownership inventory. `Tools/build/value_ownership.toml` still contains 146 `[[row]]` entries and nine `[[manual]]` entries; `r27_complete` remains unset. The checker validates listed declarations/providers but cannot discover an eligible declaration omitted from the list.

## Unlisted twin candidates

| Object API | Existing value provider | Remaining core use or interface issue |
| --- | --- | --- |
| `PyMapping_GetOptionalItemString` | `_PyValue_MappingGetOptionalItemString` | `_sqlite/cursor.c` still consumes `PyObject **`; use the owned `_PyStatusValue` and preserve missing/error distinction. The provider already exists. |
| `PyIter_NextItem` | `_PyValue_IterNext` | `Objects/memoryobject.c` and three `Objects/dictobject.c` loops consume object items. Port each status and owned-item lifecycle before marking. |
| `_PyMapping_GetOptionalItem2` | `_PyValue_GetOptionalItem` | Different result/status shape; inventory as manual, with the caller's `int *err` behavior checked. |
| `_PyType_LookupRef` | `_PyType_LookupValue` | Many core lookups in `ceval`, `specialize`, `pylifecycle`, `typeobject`, `classobject`, `moduleobject`, and `_lsprof`; individual consumers need owned-value continuation. The current provider is status-bearing. |
| `_PySuper_Lookup` | `_PySuper_LookupValue` | Status and `method` out-parameter differ; object wrapper is a real compatibility entry, while generated bytecode already uses the value provider. Audit remaining callers before a manual mark. |
| `_PyObject_Call` | `_PyValue_Call` | The provider adds a value callable argument and returns owned `PyValue`; `typeobject.c` and `signalmodule.c` still call the object entry. Keep tuple/dict args and call statistics/error precondition. |

`PyObject_GetOptionalAttrString` is also unmarked, but it has no matching string-name value provider. Its internal callers in `sysmodule`, `_csv`, `pyexpat`, `_remote_debugging`, and `capsule` require a Unicode-name owner plus `_PyValue_GetOptionalAttr` status conversion. A new string helper is optional only if repeated call sites justify it; do not invent a sibling solely for metadata. `PyObject_GenericGetAttr`, `_PyObject_GenericSetAttrWithDict`, vectorcall adapters, and variadic `PyArg_*` functions have distinct object-ABI or control-flow contracts and need separate dispositions rather than mechanical rows.

## Confirmed copied-slot calls

| Source | Current call | Required disposition |
| --- | --- | --- |
| `_bisectmodule.c`, left/right loops | Cached `sq_item` fallback; exact-type `tp_richcompare` call | Bisect already has a value entry and paired item fast path. The object fallback remains for types without a value item slot. Preserve its exact comparison order and `NotImplemented` behavior; treat fallback as a compatibility adapter only with a concrete caller/slot proof, not a blanket lint exclusion. |
| `bytearrayobject.c`, iterable slow path | Cached `tp_iternext` | Convert the owned item to `_PyValue_IterNext` status and pass its value to `_getbytevalue`, then close it. Preserve `StopIteration` clearing, append order and partially initialized bytearray cleanup. |
| `mathmodule.c`, `sumprod` | Cached `p_next`/`q_next` | Port both together to value iterator statuses, retaining the current p-then-q callback order, length mismatch error, numeric fast paths and cleanup. This is larger than a slot pointer substitution because `p_i`/`q_i` continue through arithmetic. |
| `abstract.c`, `_PyValue_SequenceGetSlice` | Aliased `mp_subscript` | Use the paired value subscript dispatcher when available while retaining the owned slice key; retain a deliberate object-slot adapter for third-party types without a paired slot. Avoid projecting a value result merely to return from this value helper. |

The six previous `itertoolsmodule.c` iterator captures have been ported in the current source. `listobject.c` stores `tp_richcompare` for identity comparison before invoking the value comparison path; `specialize.c` reads slot identities; `call.c`'s `tp_call` captures are in object ABI or explicit call adapters; `object.c` is the generic object comparison adapter. These are not additional value-producing loop calls. Re-scan this finite set after the named ports; a general data-flow alias checker is unnecessary for the current closure gate.

Do not set `r27_complete` or add manual marks as a substitute for the caller ports. The next inventory admission step is to pair each unlisted API with a reviewed implementation/caller disposition, update the manual inventory, and rerun the static checker and focused API tests.
