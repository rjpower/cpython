# `_struct` value-native packing continuation

The existing `Struct.pack`, `Struct.pack_into`, and module-level Clinic paths already lend a `const PyValue *` argument window to `s_pack_internal`. That loop projects every item with `_PyValue_AsObjectAt(..., BOX_SITE_PARSER)` before testing a format code. `formatdef.pack` then accepts `PyObject *`; the same callback is reused across native, big-endian and little-endian tables, including `init_endian_tables` callback substitution. This accounts for the repeated core boxes in integer-heavy benchmarks. Keep the input window borrowed and live through each callback and keep byte writer/buffer ownership in the existing Clinic callers.

## Interface and complete callback census

Change `formatdef.pack` to `int (*pack)(..., PyValueBorrow, const formatdef *)`; port all 39 `np_*`, `bp_*`, and `lp_*` callback definitions and every helper they call in one coherent layer. Keep `formatdef.unpack` unchanged. The tables, runtime endian-table optimization, format order, pointer arithmetic, alignment, repeat handling, memset and byte writes retain their current structure. `s_pack_internal` lends `PyValue_Borrow(args[i++])` directly; its outer overflow remapping uses `PyValue_LongCheck(v)` and the original exception predicate. No object thunk is needed for the internal function pointer.

- Integer formatters `bBhHiIlLqQnNP` use a new `get_pylong_value`: return an owned duplicate for an integer value, otherwise check `_PyValue_IndexCheck`, call `_PyValue_Index`, and retain that result through extraction. Missing `__index__` keeps the existing `struct.error` text; index callback exceptions propagate. Replace the six scalar reader helpers with existing exact-integer `_PyValue_AsLong`, `_PyValue_IntAsUnsignedLong`, `_PyValue_AsLongLong`, `_PyValue_IntAsUnsignedLongLong`, `_PyValue_IntAsSsize_t`, and `_PyValue_IntAsSize_t`. The native pointer case uses `_PyValue_IntAsVoidPtr`. Close every owned index value after extraction, including failure; retain current per-format range/error remapping.
- The four endian long-long callbacks currently call `_PyLong_AsByteArray`, which can write low bytes to a `pack_into` destination before reporting overflow. A simple checked 64-bit extraction would change that visible failure side effect. Add a narrowly scoped exported `_PyLong_ValueAsByteArray(PyValueBorrow, ...)` over the existing `span_as_byte_array` and `_PyLong_SpanOfValue`, preserving its exact byte writes, signed/unsigned negative handling, return value and `with_exceptions` contract without boxing. Use it in all four callbacks; keep their exact `struct.error` remapping and native/endian table substitution. Independently review the helper interface and its borrow/stack-digit lifetime.
- Float `e/f/d` paths use `_PyValue_AsDouble` with the existing `-1 && PyErr_Occurred()` test, remapping conversion errors to the same `struct.error` before the unchanged `PyFloat_Pack*` or native memcpy. Boolean `?` calls `_PyValue_IsTrue` directly and preserves exception behavior and exact evaluation order.
- Complex `F/D`: for pointer-space inputs retain the existing `PyComplex_AsCComplex` path, held by the argument window across arbitrary `__complex__`/`__float__` callbacks. Inline integers/floats use `_PyValue_AsDouble` as the real part and zero imaginary part, matching the old numeric conversion; preserve the existing `struct.error` remapping and byte-packing errors. Before implementation verify that `_PyValue_AsDouble` has identical `PyComplex_AsCComplex` behavior for inline numeric inputs; add a typed value helper if it does not.
- `c`, `s`, and `p` accept only concrete bytes/bytearray as today. Check `PyValue_IsObject` before projecting and keep the window's owner live while reading; an inline invalid input takes the same format-specific `struct.error` path. Preserve truncation, zero-size Pascal strings and length-byte behavior. No arbitrary buffer fallback is introduced.

`pack_into`'s already-acquired writable `Py_buffer` must remain held for the whole operation and released by the existing Clinic cleanup on every error. Sequential conversion and partial writes stay as they are; do not pre-convert or reorder arguments. A test object may mutate later inputs or the destination during `__index__`, `__float__`, `__complex__`, or `__bool__`, so the caller window and any input objects remain held through callbacks.
