# Paired value construction for direct `__new__` calls

Status: design for peer review; no runtime source change. The current `tp_new_wrapper` is a `METH_VALUE|METH_KEYWORDS` method and its arguments are values, but it calls `type->tp_new` and canonicalizes the returned object. The generated `long_new` and `float_new` object slots call `long_new_value` or `float_new_value`, then `_PyValue_THUNK_EXIT(..., BOX_SITE_CALL)`. Thus an inline result of `int.__new__(int, 17)` or `float.__new__(float, 1.5)` is materialized inside this core-to-core call and immediately converted back to a value. The 6aec full-suite census attributed 673,697 boxes to the older `tp_new_wrapper` path; that count predates the value method wrapper and is **not** a measured count for this remaining result path. A later bounded probe on stable stats build ID `99fd50733810eff6d596cabe7d25efee3e019acb` measured exactly 100 call-site thunk boxes for 100 direct `int.__new__` calls and exactly 100 for 100 `float.__new__` calls; the matching empty-loop control had zero. The source/build limitations and raw evidence are in [tp-new-stats-probe/receipt.md](tp-new-stats-probe/receipt.md).

## Contract and selection

Add a cold `tp_value.new_` row paired with `PyTypeObject.tp_new`, typed as `PyValue (*)(PyTypeObject *subtype, const PyValue *args, Py_ssize_t nargs, PyObject *kwnames)`. The caller owns every argument word throughout the call. The provider borrows them and returns one owned `PyValue`, or `PyValue_NULL` with an exception. `kwnames` follows the existing vectorcall keyword-window convention. `tp_value.new_ == NULL` means use the selected object `tp_new` through the existing adapter; it never authorizes calling a different type's value constructor. This is a **new-only** operation: it must not call `tp_init`, a metaclass's general vectorcall, or `type_call`.

Append the field to `_PyValueSlots` and `_Py_VALUE_SLOT_TABLE` as a cold `NEW/NONE` row, with the corresponding type, layout, generated slot metadata, and invariant checks. Keep the 16 hot fields and existing row indices fixed. `type_ready_set_new` runs before `type_ready_inherit_value`, so an inherited object `tp_new` takes the paired value side only from a base whose object pointer is identical. An explicit object `tp_new` override starts with a null value side. In `update_one_slot`, the existing special case for the generated `tp_new_wrapper` must copy both `type->tp_new` and its checked `tp_value.new_`; replacing `__new__` with a Python function installs the `slot_tp_new` pair, while an unpaired extension override clears the value side. Add the `slot_tp_new` pair to the central pair table and debug row validation. A dispatch should read the selected type's object/value pair and check the row invariant before using the value provider. No match based only on subtype ancestry or equal behavior is sufficient.

Register `long_new_value` with `long_new` on `PyLong_Type` and `float_new_value` with `float_new` on `PyFloat_Type`. The generated Clinic object slots remain for C callers, where their object result is required. The existing value parsers already accept a `PyTypeObject *`, a value argument window and `kwnames`, and already return owned values for exact int/float while allocating a true object for a subtype. The wrapper must select the pair from its **bound defining type**, then pass the explicitly supplied subtype to the provider. For example, `int.__new__(MyInt, 17)` invokes the int provider with `MyInt`; it does not dispatch through `MyInt.__new__` or run `MyInt.__init__`.

Give `slot_tp_new` a paired `slot_tp_new_value` for Python-defined `__new__`. It performs the same `type.__new__` attribute lookup as the object slot, holds the callable, then uses `_PyValue_VectorcallPrepend` with the subtype and the original value arguments. Close the callable after the call and return the owned result, including inline scalars. Its object slot remains a thin value thunk for genuine object callers. This path preserves a Python `__new__` that returns an object of an unrelated type, and it does not invoke `__init__`. If a custom metaclass lookup returns a noncallable inline value, the value call raises the same noncallable error without projecting it.

This pair does not by itself make ordinary `MyClass(...)` value-native: `type_value_vectorcall` still falls back to the object `type_call` path for general classes. The phase-two constructor continuation below is mandatory before the R27 checkpoint; the first implementation may remain a bounded new-only increment, but it cannot be counted as closing generic construction.

## Wrapper, ownership and error behavior

Keep the wrapper's existing validation and order: bound self is a type; at least one explicit argument; argument zero is a type; it is a subtype of the bound type; the static-base `tp_new` safety check. Keep `self` and `args[0]` owned by the method call window across all subsequent work. To preserve its existing allocation/error order in the first increment, continue building the positional value tuple and keyword value dict before dispatch, even for a paired provider. They own duplicate words through the call and are closed in the same order as today. The value provider receives the caller's still-owned window (`args + 1` and `kwnames`); the containers are lifetime anchors, not object projections. Retain the existing borrow scope around either call. The object fallback calls the exact selected `type->tp_new` once and retains `_Py_CheckFunctionResult` plus `_PyValue_FromObjectResult`. The paired core provider follows the existing value-call null/error assertion contract; it does not project a successful inline result to run the object-result check.

The selection must be made after the static-base check and after argument-container construction, as in the current wrapper. Under the supported GIL profile, the selected object/value pair cannot change between its adjacent reads without a callback; validate their pairing in debug builds. Release the provider result only through the caller's value ownership path. If a provider fails, close tuple, dict and borrow scope on exactly the same exits as the object fallback. Do not treat the internal object fallback as a permanent external boundary: it remains explicit debt for unpaired core `tp_new` implementations that produce inline values.

## Validation and admission

Focused cases: `int.__new__(int, 17)` and `float.__new__(float, -0.0)` with a fresh private stats dump; inline limits and heap-large results; `int.__new__(IntSubclass, 17)` and float subtype allocation; direct object C `tp_new` entry; omitted/keyword/duplicate arguments; invalid first argument, wrong subtype, and unsafe static-base messages. Add a Python `__new__` returning an inline int and another returning a different type, with an `__init__` counter proving direct `__new__` does not initialize. Exercise changing a heap class's `__new__` after readiness and a static extension subtype overriding only object `tp_new`, then check the paired-row invariant on debug builds. Run focused `test_type`, `test_descr`, `test_int`, `test_float`, and one `_testcapi` constructor probe, followed by the coordinator's merged builds/tests and a fresh attribution count.

The direct object C API still returns objects and may legitimately materialize an inline result. The acceptance evidence must distinguish those true C boundaries from boxes reached because `tp_new_wrapper` in core called an object slot. A coherent stats process and exact source/build identity are required before claiming the 673,697 historical boxes were removed.

## Mandatory phase two: general type calls and initialization

`type_value_vectorcall` currently preserves only the exact `type(x)` fast path; its general branch calls `_PyValue_TpCallAdapter`, which builds value containers but invokes object `type_call` and canonicalizes its result. A Python class whose `__new__` returns an inline scalar therefore still boxes inside core. Add a separate `type_call_value` continuation for the selected `PyType_Type.tp_call == type_call` case, guarded by the actual metatype call-slot identity. An overriding metaclass `tp_call` stays on its selected object/value call path; neither an inherited vectorcall field nor `PyType_Check(callable)` alone proves that `type_call` is selected. Keep `type(x)`, three-argument `type(...)`, the recursion guard and their error order as currently implemented.

`type_call_value` takes the callable type and an owned-by-caller value argument window. It constructs the same positional tuple and keyword dict, keeps one borrow scope covering new and init, calls the selected `tp_value.new_` provider when paired or the exact object `tp_new` adapter otherwise, and holds the returned owned value. A null result fails before init. For a non-null result, use the no-callback equivalent of `PyObject_TypeCheck`: compare `PyValue_TYPE(result)` with the requested type and its MRO. If it is not an instance, return the value unchanged; **do not initialize it**. If it is an instance, read `PyValue_TYPE(result)->tp_init`, not the originally requested type's `tp_init`, exactly as `type_call` does. On init failure, close the result and propagate the error. Keep the legacy object `type_call` entry as the true object-result boundary; the new value path must not call it and re-canonicalize its result.

Add a cold `tp_value.init` pair with `tp_init` when an inline receiver can reach initialization. Its typed signature takes a borrowed receiver and the same value args/kwnames and returns status, not a result value. Register a value `object_init` that performs the existing excess-argument checks using the argument count and keyword count, `PyValue_TYPE(receiver)`, and the selected `tp_new`/`tp_init` pointer tests; this covers exact inline int and float without materializing the receiver. Register `slot_tp_init_value` for Python-defined `__init__`: preserve `call_method`'s `lookup_method` and bound-versus-unbound dispatch, including keyword arguments, while carrying the receiver and result as values. Require the returned value to be `None`, and on a different inline result raise the existing `"__init__() should return None, not '<type>'"` error using `PyValue_TYPE` before closing it. Its object slot remains an object-entry thunk. As with new, the pair inherits only beside an identical object `tp_init` and is cleared by an unpaired override. An object-form init adapter is allowed only for a genuinely selected extension/object-form native; a core path that boxes an inline receiver remains debt.

Phase-two focused tests must include a Python `__new__` returning an inline int/float from a nonmatching class (init counter remains zero), a matching heap-subtype result (actual result type's init runs once), `__init__` returning inline 1 or 1.5 (same TypeError and no box), exact int/float calls with and without accepted arguments, inherited/custom metaclass call slots, and C `type_call`/`tp_init` entry probes. Stats attribution must show the direct new-only site and generic type-call site separately. Do not mark the constructor area closed until both are zero in core on the accepted kernels and full-suite gate.

### Phase-two source recipe and ordering

The existing `type_value_vectorcall` is the value entry for `PyType_Type`'s vectorcall. Keep its exact `type(x)` one-argument fast path. After entering its existing `" while calling a Python object"` recursion guard, read `Py_TYPE(metatype)->tp_call` **before** tuple/dict construction, as `_PyValue_TpCallAdapter` currently does. Only `tp_call == type_call` selects the new continuation; every other metaclass call keeps the actual selected object-call adapter. In particular, a metaclass override must not be bypassed merely because it inherits `type_value_vectorcall`. Do not recursively invoke `_PyValue_VectorcallTstate` on this same type.

For the selected `type_call`, build `_PyTuple_FromValueArray(args, nargs)` then `_PyValue_StackAsDict` when there are keyword names, matching the adapter's allocation and error order. The tuple and dict stay owned until **after** new and init. Then perform the exact `type_call` `type(x)`/three-argument validation, `tp_new == NULL` check, and one borrow scope. Select the `tp_value.new_` pair **after** container construction because keyword insertion can invoke callbacks and mutate a heap type's slots. A value provider receives the stable borrowed window; an unpaired provider receives the already-owned tuple/dict through its selected object slot. Run `_Py_CheckFunctionResult` for the object result immediately after the object `tp_new`, before the instance check or init, as old `type_call` does. A value provider uses `_PyValue_ASSERT_RESULT`. On failure, skip init, exit the borrow scope, then close the containers in the adapter's order. On success, check `PyValue_TYPE(result) == type || PyType_IsSubtype(PyValue_TYPE(result), type)` without projection. If false, return the owned result after normal cleanup. If true, read the **result's** `tp_init` pair after `tp_new` callbacks, invoke its value side when paired, or its exact object side for a non-inline receiver. Close the owned result on init failure; retain it on success. Exit the borrow scope before releasing containers and leaving the recursion guard. This preserves `type_call`'s choice of init and prevents an object-return check from moving past user callbacks.

Append a cold `init_` row beside `tp_init` after `new_`, with a status-returning signature `int (*)(PyValueBorrow receiver, const PyValue *args, Py_ssize_t nargs, PyObject *kwnames)`. The row's pairing machinery must cover `object_init` and `slot_tp_init`; because both are currently `static` in `Objects/typeobject.c` while the central pair table lives in `Objects/value_pairs.c`, give their object functions internal declarations instead of omitting debug pair validation. `object_init_value` uses the existing `excess_args` condition expressed as `nargs || (kwnames != NULL && PyTuple_GET_SIZE(kwnames))`, then the same `tp_init`/`tp_new` pointer checks and error text. For `slot_tp_init_value`, keep `call_method`'s owned receiver, positional tuple, keyword dict, `lookup_method`, and bound/unbound choice. Use `_PyValue_VectorcallPrepend` only for the unbound method, `_PyValue_VectorcallTstate` for a bound method, with the caller-owned argument window and `kwnames`; close the owned callable and result on every path. The returned status is zero only for `PyValue_None`. A non-None inline return raises the existing exact TypeError using `PyValue_TYPE(result)->tp_name` and closes the result; it must never be projected to an object merely to form the error.
