# `tp_new_wrapper` value continuation

Status: source design for review; no runtime change. A private `json_loads` startup sample attributed 144 core boxes to the generated `tp_new_wrapper` object-call adapter. Recount on the coherent candidate before claiming their removal.

Change only the generated `__new__` method entry in `Objects/typeobject.c` from `METH_FASTCALL|METH_KEYWORDS` to `METH_VALUE|METH_KEYWORDS`. The producer accepts borrowed `PyValue` arguments and returns an owned value. It keeps the existing validation order: bound self is a type; at least one explicit argument exists; argument zero is a type and is a subtype of the bound type; then the static-base `tp_new` safety check runs. Guard `args[0]` with `PyValue_IsObject` before `PyType_Check`; use `PyValue_TYPE` for the existing error's type name so inline invalid arguments do not project. Do not skip or reorder the static-base loop.

After validation, duplicate only `args[1:]` into an exact tuple via `_PyTuple_FromValueArray`, and build keyword dict with `_PyValue_StackAsDict(args+nargs, kwnames)` only when keywords exist. Both containers own their value words, including inline scalars, through the callback. Invoke the selected `type->tp_new(subtype, tuple, kwds)` exactly once under a borrow scope if the legacy object parser requires borrowed projections, check the C result with the same convention as the current wrapper, release tuple/dict and scope on all paths, and return `_PyValue_FromObjectResult(result)`. Preserve the current `NULL` kwargs boundary. Do not call the general type vectorcall or `tp_init`: `T.__new__(T, ...)` creates without initialization, while `T(...)` may initialize.

Focused validation: direct `int.__new__(int, inline)` and a heap scalar; invalid inline subtype, wrong subtype and unsafe static-base errors; positional/keyword and duplicate-key behavior; custom `tp_new` with `tp_init` counter to prove no initialization; direct object C-call boundary and a mutable subtype. Run existing `test_type`, `test_descr`, and small constructor probes, then use a fresh stats process to attribute the changed boxes. The public object entry remains an actual method-call adapter for C callers; a value producer must not be replaced by a hidden CORE-to-THUNK projection.
