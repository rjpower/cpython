# Remaining `_PyType_LookupRef` continuations

Read-only census against the current runtime while phase two is under integration. `_PyType_LookupRef` materializes an object for an inline result. `_PyType_LookupValue` returns an owned value; its current `status == 0` also covers a lookup error, so a caller that distinguishes missing from failure must inspect `PyErr_Occurred()` as well as the value. Any assigned counts require a fresh matching stats capture; this census does not infer hotness from call counts.

## First bounded port: descriptor get

`Objects/typeobject.c:slot_tp_descr_get_value` already returns an owned value and calls `_PyValue_Vectorcall`; its sole `_PyType_LookupRef` result is the borrowed callable for `__get__`. Replace the object local with the owned lookup value, retain it across the same stack construction and call, then close it. Check missing/error exactly as today before the existing guarded slot-pair removal; an inline noncallable must reach `_PyValue_Vectorcall` unchanged and raise the same TypeError. The descriptor receiver and owner/type inputs remain live as before; do not change null-object-to-None behavior. Object entry remains its existing `_Py_VALUE_THUNK_DESCRGET`. Minimal probes: descriptor `__get__` normal and missing, inline int/float `__get__`, replacement/deletion, raised lookup and call exceptions, and reentrant descriptor callback; selected `test_descr` cases. This is a single-function continuation with no shared-header change.

## Next: Python attribute hook family

`Objects/typeobject.c:_Py_slot_tp_getattr_hook_value` looks up `__getattr__` and `__getattribute__` as objects and routes through object-returning `call_attribute`; `_Py_slot_tp_getattro_value` also calls an object-form method helper. A coherent port should retain owned lookup values, guard actual object wrapper-descriptor checks, use value descriptor binding and value calls, and preserve the fast default-getattribute check, lazy slot-pair replacement, lookup/callback order, AttributeError-only fallback and exception propagation. Keep receiver, name and both hook owners alive across arbitrary callbacks, and preserve cleanup order. Test integer/noncallable hooks, descriptors returning inline/noncallable values, custom/default getattribute, deleting/changing hook during callbacks, AttributeError vs other exceptions, and metaclass/subclass slot invalidation. This is broader than the first port and needs a separate exact-source proposal and review before editing.

## Other call sites

- `Objects/classobject.c:method_getattro` and `instancemethod_getattro`: object-form getattro results and `_PyType_LookupRef` should be paired value getattro continuations together with `_PyValue_DescrGet` and fallback `_PyValue_GetAttr`; guard descriptor object projection, preserve readiness and descriptor precedence, and retain method/function/receiver owners. They need paired type rows and independent descriptor/weakref/reentrancy tests.
- `Python/ceval.c:type_has_special_method` and the self-hint comparison only inspect a type or pointer identity. Owned lookup values can be inspected with `PyValue_TYPE` or `PyValue_IsObject`/identity and closed without boxing; preserve each function's current exception policy exactly, including 0/error ambiguity. Small diagnostic-only batches, not inferred startup contributors.
- `Python/specialize.c`'s stats-only STORE_SUBSCR diagnostic tests for exact Python function and otherwise classifies OTHER; inspect type on an owned value and close after code inspection. Respect current stats/error policy.
- `Objects/typeobject.c:get_dict_descriptor` requires a genuine descriptor result but can first reject inline values with no data-descriptor slot; preserve its callers' error behavior and only project a known object after its descriptor test. Module-object lazy-recheck similarly only inspects descriptor type and can retain the owned value, but the surrounding object-form module attribute continuation is separate.
- `Modules/_lsprof.c` function naming can feed `_PyValue_Repr` the owned lookup value directly, preserving fallback and cleared-error behavior. Lifecycle initialization expects known built-in method descriptors held in global object homes; first prove exact-object invariants and do not silently relabel a scalar projection. Test-only `_testcapi/gc.c` is not production closure.

Every family requires a source-specific peer review before implementation. True external object C APIs may still return object references; internal callers must not be routed through those boundaries merely to suppress a count.
