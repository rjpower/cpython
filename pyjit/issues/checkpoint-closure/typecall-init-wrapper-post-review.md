# Type-call and direct-init wrapper source review

Reviewed `r27-typecall-pair.diff` and `r27-init-wrapper-values.diff` against the phase-two constructor source. The pair selects `_Py_type_call_value` only when the captured object `tp_call` remains `_Py_type_call`; the existing value-call dispatcher supplies the `tp_call` recursion guard. The type value body retains its tuple/keyword ownership, new-result check, subtype initialization rule, and cleanup. The `INIT` descriptor wrapper calls the captured value initializer and maps its status to the existing `None` or error result.

The original `r27-call-init-wrapper-tests.diff` has a wrong expectation: upstream `object.__init__(17, 1)` and `object.__init__(1.5, 1)` return `None`; an exact `object()` receiver with an extra argument raises `TypeError`. The additive `r27-call-init-wrapper-test-fix.diff` corrects the fixture. I checked these direct calls, the metaclass override bypass, and `type.__call__(type, 17)` against the upstream `3a440b6` interpreter. The two source patches and corrected composite test are approved for the coordinator's linked-build validation. This is a source review, not a claim that the merged runtime tests have run.
