## Bounded first increment

In `Objects/unicodeobject.c` and `Objects/stringlib/unicode_format.h`, pair `str.format` with a `METH_VALUE|METH_KEYWORDS` entry. Its `PyValueBorrow` self must be guarded/borrowed as the concrete string receiver, and its borrowed positional values and `kwnames` can be copied into a tuple with `_PyTuple_FromValueArray` and a keyword dictionary with `_PyValue_StackAsDict`. Both containers own their words through `do_string_format`; release on every exit. Keep the existing formatting logic and `str.format_map` behavior. This removes the object adapter for format arguments, without claiming the whole 32-box count until recaptured. Preserve keyword order, argument count, allocation errors, recursive format spec handling and true C object call boundaries. The method signature convention must match existing `METH_VALUE` wrappers, including the receiver/descriptor path.

Change `get_field_object` to return an owned `PyValue`/null. Its first mapping or sequence lookup uses the already-owned result directly; preserve the current replacement-index `IndexError` rewriting exactly. Nested attribute and item helper continuations accept borrowed values and return owned values from `_PyValue_GetAttr`, `_PyValue_SequenceGetItem`, or `_PyValue_GetItem`; use an inline integer index value rather than creating a boxed key. Keep the current sequence-vs-mapping decision, string-name owner and evaluation order. A successful next lookup replaces the previous owner only after it succeeds; each failure closes all live values. This retains ownership across arbitrary getter/item callbacks and recursive formatting.

`output_markup` holds the owned field value through conversion, recursive spec expansion and rendering. `!s`, `!r`, and `!a` use the existing `_PyValue_Str`, `_PyValue_Repr`, and `_PyValue_ASCII`; transfer their checked Unicode results to owned values and release the previous field only after success. The non-conversion path preserves the original owner. For object-space values, retain current exact Unicode/int/float/complex direct advanced-writer fast paths, guarded by `PyValue_IsObject`, and preserve the generic `_PyValue_Format` fallback for subclasses and custom `__format__`. For an inline field, generic `_PyValue_Format` supports empty int specs without projection; nonempty integer and float `__format__` currently project through their own object-only advanced writers. That remaining work is explicitly not claimed closed: a later reviewed value-native formatter (in `Objects/unicode_formatter.c`, plus long/float `__format__`) must preserve all format flags, precision, exception ordering and big-int formatting. Do not relabel those boxes.

Tests should cover `test_str` format cases plus focused positional/named/mapping fields; nested attribute/index callbacks that mutate or release earlier objects; `!r/!s/!a`; recursive format specs and field-numbering errors; int/float/custom `__format__`, invalid return types and error precedence; object `format_map`; subclasses; and the direct C object-call boundary. Capture raw counters after the coherent candidate is integrated. This increment does not touch blocked ctypes or LRU designs and does not claim zero startup boxing.

Implementation detail: numeric nested mapping keys come from a parsed `Py_ssize_t` and may exceed the inline range. Construct an owned `PyValue_FromInt64(index)`, check for null before lookup, and close it after the callback. Do not assume this conversion cannot allocate. The argument window must remain stable across `_PyTuple_FromValueArray` allocation as required by its contract.
