# `%vR`, `%vS`, `%vA` value formatting continuation

`unicode_fromformat_value_object()` in `Objects/unicodeobject.c` is used only by the three value conversions. It reads an owned-by-caller `PyValueBorrow`, immediately projects it to a new object with `BOX_SITE_REPR`, and hands the object to `_PyValue_Repr`, `_PyValue_Str`, or `_PyValue_ASCII`. This materializes an inline int or float in core before invoking an operation that already accepts a value. The documented `%v` contract requires the caller to keep the value alive through the format call.

Remove the projection helper. In each `F_VALUE` arm of the `R`, `S`, and `A` switch cases, read `PyValueBorrow value = va_arg(*vargs, PyValueBorrow)`, assert that it is non-null as the current helper does, duplicate it into a local owned `PyValue`, invoke the matching `_PyValue_Repr`, `_PyValue_Str`, or `_PyValue_ASCII` on that owner, and close the owner after the call. This preserves the old helper's strong local reference across a callback that may replace its source field, without boxing an inline value. Keep the ordinary object arm, the null-result check, the single `unicode_fromformat_write_str(writer, result, width, precision, flags)` call, and the result `Py_DECREF` exactly as they are. Thus the conversion callback runs before the writer, and width, precision, alignment, signal/exception behavior, and string cleanup retain their existing order. Exact int and float have value `repr` slots; their `tp_str` is null, so `_PyValue_Str` delegates to value repr. `_PyValue_ASCII` uses value repr before escaping non-ASCII characters.

The frozen patch `unicode-value-format.patch` adds a no-argument internal C probe that constructs inline int and negative-zero float values and formats all three conversions. Existing `ValueFormatTests` cover the ordinary object path, width, precision, signed zero, invalid formats, and callback errors. A new internal C probe borrows an item directly from a one-element list; its `__repr__` clears the list during formatting. The stats regression clears counters immediately before the no-argument inline probe and requires zero repr-site and zero numeric boxes. The caller still owns the borrowed input through the call; the formatter owns a duplicate while a callback runs.
