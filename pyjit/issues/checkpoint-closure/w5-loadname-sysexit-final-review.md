# LOAD_NAME and SystemExit corrected-patch review

The revised `w5-loadname.diff` addresses the must-fix from the first review. Locals and builtins use `value_load_from_dict`, which returns an owned value or a distinct missing/error status and holds the owner through lazy-import reification. Globals retain direct `PyDict_GetValue`, so a dict subclass's overridden `__getitem__` is bypassed as before; a found lazy import is reified using globals as its namespace and its old owner is closed. The generated `LOAD_NAME` instruction stores the returned owner directly. `test_scope.test_load_name_globals_dict_subclass` probes the exact prior regression, and passed in Terra's focused release run.

The `w5-sysexit.diff` also addresses the constructor-result issue from peer review. The SystemExit code is an owned value home with value-member access, close and traversal. `_PyErr_SetObjectValue` keeps the original object path for null and object inputs, and calls the exception constructor with an inline argument directly. If that constructor returns another `BaseException` subtype, the helper delegates with the result's actual type, preventing a second constructor call while preserving existing context and traceback handling. The direct `_testinternalcapi` Factory regression exercises this case. Exit-code parsing reads int/None values without projecting them; non-int output still projects for printing and remains a separate CORE-box follow-up.

The combined release build passed, and `test_scope`, `test_sys` and `test_exceptions` passed 267 tests with 11 skipped. No further must-fix finding in these two corrected source patches.
