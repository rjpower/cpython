# C49: saved activations, replacement costs and one ablation

**Do not promote C `24d97fa8c3b`.** The stable two-pair screen against frozen A48 `5559f60093e` reports DeltaBlue 1.15213, logging_silent 1.21281 and nbody 0.99705. Both DeltaBlue and logging pairs are worse. The counter census records 25,504 actual elisions, including 25,023 BinaryConstraint input/output hits; coverage is real but does not establish a cheaper path. Evidence: `measure49-call-pair48/{summary,status,identity-before,identity-after}.json`, `coverage49-leaf.json`. No runtime edits, native execution, builds or commits by this reviewer.

## What each selector now pays

The ordinary exact prefix still performs PEP 523, function-version, arity, stack-space and recursion checks. The new gate loads code/CodeExec/leaf. Its out-of-line helper decodes the call again and repeats version/code/arity facts before checking providers, observer state, current RESUME and pending epoch. The observer predicate scans sixteen global event bytes on every hit; compiled code retains that loop and an external clearing-immortals query.

A conditional selector evaluates three paths: predicate left, predicate right, selected result. For BinaryConstraint this means one argument shape read, one global plus class-scalar read, then one selected argument shape read. All four reads call `_PyIR_InstrFeedback`; it decodes the immutable opcode, indexes the generic format and switches on the field location before addressing feedback. `_PyCode_InstrFbIndex` is inlined **inside that helper**, so this is four external metadata calls, not eight. Three `ir_leaf_read_path` calls also remain real C boundaries. The caller then acquires its result, builds a bounded generic alias/multiplicity table, checks counts, detaches/closes the window and publishes through the existing return setter.

The removed work is a genuine activation, independent child code-owner traffic, RESUME/RETURN dispatch and child cleanup. Existing exact calls already overlap arguments and use initialized storage; no full argument copy or full slot sweep was removed. The replacement has repeated decoding and a general owner ledger for a common unary case. The matched profile reported by root—helper 14.38%, metadata 8.50% and path 5.65% of flat samples—supports investigating these concrete costs before another layout/annotation experiment.

The current ELF contains `ir_try_complete_leaf_call` (0xe5b) and `ir_leaf_read_path` (0x2e7). Raw global/shape/class probes have **no standalone symbols**: they were inlined. Exact-call handler size grows from 0x582 to 0x602; ordinary shape/class/global bodies shrink. Size is not execution cost, but it rules out the explanation that every ordinary raw read newly calls an outlined helper. No inlining annotation change is proposed.

## Logging distinguishes the costs

The repeated Logger.debug has `*args, **kwargs`; its hot isEnabledFor callee has a try/except table. Both are outside the certificate. Steady logging therefore should not execute the leaf body on that hot chain: it mainly pays the new NULL-summary gate at eligible exact calls and the shared ordinary read changes. This is a source inference, not a logging hit census. Do not attribute logging's regression to DeltaBlue's 25,504 helper executions.

On measured LP64, CodeExec grows from 32 to 40 bytes once per executing code object. Each successful certificate adds one 88-byte scalar record. Construction is once per CodeExec, not once per activation; the benchmark driver warms before timing. Header/metadata effects remain a possible residual, but allocation is not the per-hit explanation.

`fb_begin_ex` clears private bodies before respecialization; every path subsequently publishes a new handler or returns to generic, and no supported GIL leaf reader runs inside that interval. `specialize` publishes after field writes; historical POLY/MEGA state retains the newest private proof. Leaf already checks a supported live handler, typed entry and valid installed state. Thus the same installation preconditions can serve both consumers; a raw helper must not accept an arbitrary caller-supplied payload as such a proof. Serialization/reset yields cold private entries, not installed leaf proofs. Forged private feedback is not authorized by this contract.

Object/inline discrimination is still necessary: the current receiver may differ from the one that installed the handler. Existing ordinary pointer-space and current `PyValue_IsObject` tests differ in NULL/invalid-value handling; do not delete the discrimination based only on the handler name. A shared probe should have an explicit canonical non-NULL language-value input contract, installed typed metadata, and current mutable guard/read obligations, with positive producer validation. This is one checked API, not an unchecked fast helper alongside a checked one. Retain old bounds/NULL/mutable guards in the first optimization; they are not all newly added checks.

## One clean ablation, before optimization

Use the coordinator's gate-off variant: remove only the emitted leaf gate/helper/DONE block from plain exact CALL. Keep ordinary shared probes/comparisons, CodeExec layout, certificate construction, metadata and all ordinary fallback behavior. No runtime switch, benchmark change, extra annotation or owner-proof change. This disables elision intentionally; positive leaf-hit assertions are not evidence for that diagnostic variant.

Compare frozen C, gate-off and frozen A48 with the same harness/loops and retained identities. C versus gate-off estimates the total marginal leaf-hook execution/saved-activation effect. Gate-off versus A48 measures the residual ordinary-probe/header/metadata change; do not label the entire residual as probe cost. Record whether compiled ordinary reader bodies change when the unused leaf helpers disappear. The ablation is diagnostic, not a promotable feature or complete attribution by itself.

## Only if helper execution is isolated: bounded C2 facts

First cache the certified feedback **unit** next to each global/attribute PC in scalar metadata. Unit bounds, ordinal, kind and extent are already checked during construction. At runtime use PC for the supported current handler and the stored unit for direct typed feedback addressing, then retain header/state and full mutable guards. Immutable words/feedback geometry do not relocate during specialization or instrumentation; current code ownership pins them. Store neither pointers nor borrowed values. This removes repeated generic metadata decoding without another evaluator or provider.

The checked exact prefix can also supply the already selected code as a scalar helper argument instead of forcing a second cached-version/arity proof. Positive prefix/IO/order validation and the GIL-held no-effect interval must justify that trust. The current function/window still anchors the selected code, providers/observers/pending entry work still need admission, and a valid installed version remains an explicit producer premise. Do not pass a large list of scalar arguments merely to avoid a small decode, or invent a call-plan record/second frame ABI.

A common unary TEMP completion may use two scalar owners instead of constructing the nine-entry table, provided explicit `[func,NULL,arg]` and split-self `[func,self]` forms both detach their complete windows, output lies within that window, and callable/argument alias multiplicity is checked after result acquisition. LOCAL/discard/general shapes must use an explicit cold checked path or ordinary MISS before effects. This is a general call-window shape, not a method/name recipe. Keep the generic owner tests; total complexity must beat simply parking C and retaining A. No C2 implementation is approved by this audit.
