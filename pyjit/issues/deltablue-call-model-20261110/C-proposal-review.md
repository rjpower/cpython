## Whole-body certificate findings

The proposed 32-word/four-path/two-step/one-compare/two-return representation is bounded and covers the observed conditional family without a second opcode interpreter. Folded argument/constant provenance, complete CFG accounting, dominance, branch sense and physical slot reuse are essential; treating slots as permanent SSA definitions would miscertify changed/reused values. Reject dead raising reads and unreachable extra words as proposed. Effects are conservative rejection facts plus explicit runtime obligations, not a proof that generic LOAD_ATTR or COMPARE is pure.

Construction must validate indices and source metadata before retaining them: word/branch bounds, valid feedback unit/type/size for each supported source word, name/constant/argument bounds and constslot provenance. Only positively recognized original handler forms are admissible. `code.replace` must derive a fresh record and cannot inherit a syntactic certificate. No loop/call/store/exception/cell/freevar/default-binding expansion is needed. Budget failure is ordinary decline, not partial-body execution.

`_PyCodeExec.leaf` is a suitable derived home without serialized format changes. Its scalar-only storage avoids GC edges and code cycles. Account for optional storage, free it on exec teardown, initialize static cleanup execs, preserve allocation alignment and handle the existing no-feedback early return. An optional allocation miss must leave the prior exception unchanged. Runtime counters must be distinct from immutable syntax facts and do not establish hit coverage until observed.

## Shared reader and environment findings

Original callee words define the path; live feedback only supplies predictions. Require supported current handler/proof kind before interpreting typed entries. Normal class handlers189/190 now use B's independent guarded field, and their metaclass guard precedes class-value use. A shared class probe must retain that order. Shape reads need type/version plus actual shape/layout/filled-slot proof; never trust only the cached offset. An entry-zero/shared/reset/unsupported wrapper must decline before payload access.

Globals must come from the **current captured function**. Current LOAD_GLOBAL_BUILTIN semantics include globals-key absence/version proof as well as builtin dictionary version/index/presence; preserve both. Current-value rebinding does not change keys, so always load the live slot. Same code/version does not imply identical globals/builtins/defaults. Root/attribute chains remain protected by original window/function/environment owners through a GIL-held interval with no allocation, decrements, polling, specialization or generic descriptor/operator call. Probe failure may repeat harmless reads in the ordinary body, but may not change the exception or inputs.

Shared raw helpers must separate read/guard semantics from ordinary publication/retirement. Calling a full ordinary attribute handler would close its receiver and violate the probe contract. Conversely, leaving the ordinary opcode wholly unchanged while duplicating its guards inside a separate leaf implementation would fail the intended shared-semantics design.

## Entry and owner proof findings

The admission proposal correctly goes beyond RESUME equality: trace/profile/PEP523 and tracing recursion, any global monitor, selected code monitoring state, stale epoch/live entry handler, pending work, DTrace/LLTrace policy, pending caller redirect, immortal clearing and unsupported builds all decline. Conservative debug decline is acceptable; debug tests must report fallback behavior rather than claim positive leaf hits. Preserve exact arity/self, current provider, recursion and stack guards before the marker. Unsupported entry prefixes never execute as leaves.

The aggregate nonfinal proof is valid for the current GIL CLOSE implementation. `PyValue_RefcountOnObject` identifies actual decrements; `Py_DECREF_MORTAL` invokes destruction only when decrementing to zero, and deferred RC is absent here. After canonical result acquisition, strict `Py_REFCNT(o) > release_multiplicity(o)` for every identity group proves no planned release can deallocate. It covers callable/self/argument owners plus either old LOCAL or discarded result, at most nine releases. It also prevents transitive code/globals destruction through the function close. No temporary pins may manufacture the inequality.

Count aliases by object identity, including function-as-argument and window/old-LOCAL/result aliases. Overlapping temporary destinations are counted only through the original window; nonoverlapping temporaries must be NULL. Discard counts its acquired result, while a stored result retains that owner. On MISS, releasing only the acquired duplicate is nonfinal because its original protected owner chain remains intact. Do not run generic normalization/boxing as result acquisition.

There must be no hidden original-home mutation, source retirement, extra decrement, scratch-owner cleanup, code pin release, periodic check or GIL release after preflight. The helper must enumerate the exact operations it performs and assert all post-commit publication closes were preflighted. If implementation needs an additional release, extend/review the multiset before enabling it; do not rely on per-owner MayDealloc tests.

## Terminal producer proof

The hook is only for plain CALL_PY_EXACT_ARGS after the complete checked prefix. Bound-method exact shares the old initializer and has already retired its wrapper: dedicated plain-exact marker/wrapper plus positive exclusion tests are required. Validate actual guard statements/IO/window/format and untouched destination, not merely names or presence of a marker.

MISS leaves all original owners unchanged and continues the old initializer. DONE detaches/NULLs once, performs only preflighted nonfinal closes, publishes with pending_redirect proven zero, and dispatches the actual next instruction. Since no callback/poll can occur, this narrow path legitimately avoids general committed-call redirect/error recovery. It must not execute child save/push, recursion decrement, stale owner flush or delayed result move. No fallback exists after commit. Full early-body observation still uses an ordinary frame because its admission guard misses.

The existing `_PyFrame_SetReturnValue` is reusable under these proved noncallback preconditions; it does not supply general ordinary completion safety by itself. A result type `{next,status}` fits the existing two-word convention; no addressable transaction record belongs in the handler. Compiler validation must reject any new producer path that consumes before MISS can be ruled out or dispatches an invented child after DONE.
