# C2 proposal review

**GO as a future bounded design, not implementation authorization or a speedup claim. Close this round at useful 48; park C49 and gate-off.** Reviewed `C2-proposal.md` against actual C `24d97fa8c3b`, frozen A48 and the writer/reader sources. The gate-off screen separates a substantial gate/transaction cost from an unresolved ordinary-path residual: logging remains 1.08961 versus runtime 48 after removing the gate. C2 must not promise to explain or recover that residual.

The design combines three related corrections to the measured execution path: choose eligible calls once, retain already certified metadata addresses, and avoid constructing a general release table for the common unary window. This is more coherent than adding separate constant/getter recipes or new annotations. Its stop condition must remain cheaper and simpler than retaining A and parking C.

## Specialized sibling: bounded identity cost

One `CALL_PY_LEAF_EXACT_ARGS` sibling is reasonable. `function_kind` already materializes CodeExec during normal call specialization; select the sibling only for valid exact-call code with a complete certificate. Existing function-version checks still control mutation/deopt. Certificate availability never comes from a benchmark/name whitelist, and no code/region pointer belongs in feedback. Ordinary exact CALL must have neither optional-summary gate nor leaf helper call.

Use retired opcode 112 with an explicit format 64419 revision, following A's handler 111/magic 64418 precedent, unless the next packet has already consumed that slot. Replace its parsed removed marker, update the pinned magic/table fixtures, and regenerate opcode identities, deopt/base/name/target/cache/stats/instrumentation tables together. The uint8 specialization route still suffices; wide IR-only specialization is unnecessary for this increment. CALL feedback geometry and the frame/call ABI stay unchanged.

Both siblings should reuse the same checked uops in the same order. If the DSL supports a small existing composite, use it; otherwise duplicate only the uop names in two macros and validate equal normalized prefixes. Do not build a new macro framework or copy guard bodies. The new marker's positive contract must include its exact callable/window relationship, fields/cache selectors and no-effect interval. Follow existing CALL-family source/shadow conventions and canonical CALL deopt/base mapping; do not add an observer-specific mapping exception. After warming the new sibling, enabling monitoring/profile/PEP 523 must still reach the real ordinary call/entry observations.

Selection is prediction, not an owning lifetime proof. Before dereferencing a live summary, check the selected current execution/certificate and decline before effects if absent/ineligible. Do not silently replace that with an unchecked cached pointer. Unsupported GIL/debug/DTrace/Emscripten configurations retain explicit decline; free-threaded/deferred tests establish fallback only, not new hit coverage.

## Certified feedback and checked entry

Caching bounded `(word, feedback_unit)` scalar pairs is sound. Construction already validates the unit/ordinal/kind/payload extent against immutable code. Runtime still checks supported current handler, typed installed private entry and current owner/environment versions before borrowing payload. CodeExec geometry is fixed while the selected code is owned; specialization/instrumentation do not relocate feedback. This directly removes generic handler→format→field decoding from every read without duplicating semantics.

Passing the already checked function as the fourth scalar argument is also sound under the positively validated GIL-held interval: no callback, allocation, release or GIL drop occurs after the version/arity checks. Its untouched window home anchors selected code/environment. Keep current providers, observer/pending/clearing/current-frame/RESUME/epoch admission, valid installation premise and final asynchronous check. No new owner or argument record is needed. Passing many more scalar arguments would undermine the proposed simplification.

The [ordinary guard audit](C-performance-audit49.md) identifies writer-backed installed invariants: cached versions nonzero, inline layout after type-version match, and Unicode key layout after nonzero keys-version match. It cites their actual producer, type-layout and key initialization/version sources. The same checked installed-proof contract can serve ordinary and leaf readers. Do not create checked and unchecked semantic APIs or delete current object/dict/version/shape/index/NULL guards merely because a handler name matched. Invariant cleanup is valid design work; it is not measured attribution for logging's remaining 9%.

## Unary scalar and cold general ownership

The unary shape is structural: checked formal arity 1, either `[function,NULL,arg]` or `[function,self]`, with a TEMP destination inside the entire consumed window. Exclude LOCAL and discard. Detach the NULL self home too. After result duplication, count function/argument releases by actual count ownership: one each when distinct, two when they own the same object. Strict post-acquisition count bounds cover result aliases without temporary pins. An object/inline discriminator remains necessary; current receiver values can differ from installation values.

The existing general proof may remain cold if splitting it stays small. It must receive the acquired result owner exactly once and own both outcomes: close it on MISS while original roots survive, or publish/retire it on DONE. Include its own final pending epoch check before first mutation. No second evaluator/admission or repeated probe/result acquisition belongs there. A unary proof miss returns ordinary MISS rather than retrying a second release proof. If preservation requires another transaction record or substantial hot setup, stop for an explicit approved scope cut; do not silently weaken general positive tests.

Required evidence: both unary layouts and every overlapping TEMP position; function/argument/result alias boundaries and observable final-owner misses; unchanged LOCAL/discard/multiargument general positives; code/global/class/shape/provider mutation; observer/pending/recursion fallback; malformed unit and killed-source rejection. Release counters must prove real new-handler hits. Inspect actual compiled output for no ordinary exact gate, no hot generic feedback decoding and no common unary owner-array frame. Then use matched measurements against frozen48/full C/gate-off and retain negative results. If the design cannot meet these structural conditions or recover the measured regression, keep C parked and do not expand syntax to rescue it.
