# Cancellation/restoration proposal peer review

Docs/source review only during the native27 timing freeze. No runtime edits or
worker native jobs. The bounded first PRE real-LINE rung is directionally
approved, subject to the explicit fail-closed conditions below. Later saved-local
restoration, POST phase publication, context exits and suspension remain separate
implementation admissions.

## Source-grounded contract

LOAD_FAST_AND_CLEAR reads its LOCAL_MOVE B, clears that named home, and publishes
its old value through actual destination A. Genuine NULL is meaningful state.
The current codegen_push_inlined_comprehension_name uses it to isolate outer
bindings, with MAKE_CELL where necessary. COPY's new window tail duplicates the
origin and SWAP permutes endpoints. STORE_FAST consumes explicit A into LOCAL_OUT
B. These encoded roles support a derived obligation proof; source names, later
stores or static equality alone do not.

At a proved ordinary real-LINE PRE phase there is no running semantic handler
holding the cancelled operation's input owner in C. Input scratch can therefore
be detached if the target does not need it and all protocol obligations remain
valid. This differs from source/post-branch callbacks and from a pending child
whose overlap still owns the window. Existing source/error/current-child gates
must remain part of the positive phase factory, not be inferred from event names.

## Required conditions

- Losing, overwriting or retiring every known token home leaves its saved-local
  obligation active but unavailable. It must never turn unknown state into an
  empty save context. A NoDst or local-destination save remains a save operation;
  unsupported geometry refuses the request.
- Only restoration of the TOP active saved-local context by its own token to
  its own named local pops the context. A copied ancestor token written to that
  same name cannot skip a nested save. Other uses are conservative losses, not
  implicit successful restoration.
- Same-caught implicit saved-previous-exception roots still belong in the Plan,
  even if raw target scratch operands are empty. Cancellation must not bypass
  the existing context-node/survival proof or close those roots.
- Target availability is independent of current disposable expression inputs.
  Current protocol roots remain obligations. Positively empty current/target
  save states are required for this first rung, not absence of an identified
  comprehension opcode near either endpoint.

The proposed later transaction order is sound in outline: allocate/revalidate,
detach all saved/displaced/surplus owners, install final restored locals and PC,
then close with no later writes. Nested same-name restoration must choose the
outermost exited binding without exposing intermediate states. Genuine saved
NULL needs the explicit warning/binding policy; cell restoration needs an actual
cell-object proof or refusal. These are not yet code approvals.

## First evidence ladder

Keep original expression/unpack/call redirects and comprehension behavior. Add
active-save rejection plus completed-comprehension positive in one code object;
verify no whole-function blacklist. Include a token-loss/NoDst negative and a
nested same-name ancestor-token negative in derived proof tests. Preserve caught
exception identity under a callback-owned handled exception. Verify detached
expression owners may reenter after the final target/locals are committed.

The with/loop expectations cited by B match the required distinction: skipped
with exit is not synthesized, retained outer exit needs its real roots, loop
locals keep their last binding, and comprehension outer bindings require an
actual restoration action. None of this adds an executable release boundary or
ordinary per-dispatch metadata interpreter.
