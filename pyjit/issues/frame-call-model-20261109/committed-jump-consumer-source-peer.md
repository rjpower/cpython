# Committed neutral JUMP consumer source peer

Actual frameobject/test source reviewed and approved for the coordinator's native
gate. No worker build, candidate execution or regeneration was run.

The capture validates scoped POST/JUMP association, pointer bounds/alignment,
positive generated FORMAT_VALUE, zero read/write/through extents, no owner roles
or semantic outcome, unconditional TAKEN edge and actual encoded successor.
Same-generation authority additionally requires exact site/return_pc. A changed
generation can only supply a separately checked committed real-PRE landing;
the old edge is not reused as its state.

The stopped view borrows exact site rows because the certified operation is
owner-neutral. It does not use the global destination meet or invoke a mutable
token-creation transfer. The current committed rung requires inherited context
and a target with no incoming scratch owners, then uses the existing saved-local
origin/no-reentry/NULL-binding checks and detach/install/commit transaction.
Warning reproof recaptures scoped authority; an OTHER candidate is not promoted.

Four focused methods cover bound and genuine-NULL cold/warm restoration,
required target-owner and lost-token refusal, and a later close-time redirect
observing restored bindings. Their actual opcode checks distinguish the JUMP
stop from a real LINE wrapper. No concrete source blocker remains. This does
not admit arbitrary POST providers, SOURCE_POST cancellation, yield or suspended
frames.

The final preservation refinement was also reviewed: only the new cancellation
permission requires committed inherited context plus an empty target scratch
requirement. Other targets retain the prior strict FOR/caught recipes with
cancellation disabled, rather than being rejected solely because a valid neutral
JUMP now has a scope. This preserves existing authority without reconstructing
new protocol roots; an active saved binding still needs restoration permission.
