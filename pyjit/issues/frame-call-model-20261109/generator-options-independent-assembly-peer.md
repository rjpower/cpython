# Generator/coroutine alternatives: independent source and assembly peer

At runtime `488e85fa3a8`, the six accepted cycle recordings have flat reports in `E11/ninth-workload-profile-reports/`. `commands-and-results.json` records each exact `perf report` command, input/output paths and hashes, return code and lost-sample check. All six reports returned zero, contain samples, report zero lost samples, and left their input `perf.data` hashes unchanged. These are one-record code locations, not attributable time savings.

**Prefer the decoder-only part of option 1 as the first isolated experiment.** On the VM-child return path, `_PyEval_CompleteGeneratorReturn` already loads the executing site word for A/B, then calls `_PyIR_BaseOpcode(_PyCode_InstrHandler(code, offset))` and `_PyCode_InstrOparg(code, offset)` before the generic eight-argument `_PyEval_CompleteStep`. The current compiled route contains both calls; the coroutine recording places 4.03% of samples in the return helper and 5.24% in Step, while the generator recording places only 1.28% and 1.45% there. The different distributions make a broad completion rewrite an unproven first bet.

Generated `SEND`, `SEND_GEN`, `FOR_ITER` and `FOR_ITER_GEN` formats have `_PyIR_FORWARD` and `.imm = _PyIR_LOC_D`. For this positive format, `_PyCode_InstrOparg` returns `IR_DS` from the immutable code word. A narrow decoder may avoid the out-of-line metadata calls while retaining the shared publication, observer and owner-retirement implementation. Its admission proof must tie the actual parent site to the immutable word, use generated handler-base/format facts for specialized and instrumented forms, and exclude other formats or changed execution words. It must also preserve the current assertion that only SEND/FOR semantics enter this route. A direct read of `IR_D` from the executing word is not equivalent to the immutable `IR_DS` result. Verify the compiled call removal, code size, both monitored and unmonitored completion, aliases, local/NoDst destinations, exceptions and owner exits before paired timing. If this small change does not help, the shared normal-commit specialization remains a separate option with a larger code-size and correctness surface.

Option 2 is weaker as a first experiment: a completion pointer/kind enlarges or repurposes the frame header and imposes writes on every resume, including repeated yields before a single completion. It needs a full constructor, copy, redirect and custom-entry proof before comparing performance. Option 3 may remove real creation work, but `RETURN_GENERATOR` currently moves a bound thread frame into a newly allocated object; `make_gen` initially exposes `FRAME_CLEARED` without an executable, and `_Py_MakeCoro` derives origin from the current incomplete frame chain. Direct heap binding therefore needs an explicit partial-construction GC root, pinned code/binding contract, origin semantics and failure cleanup. It should be studied separately if the bounded completion experiment fails to address the repeated losses.

The current matched PMU counters show generators +5.60% and coroutines +5.22% instructions against golden, with elapsed four-pair losses of 7.06% and 8.66%. The flat symbol percentages cannot assign those increments to either decoder call or predict an option's gain. Keep nbody separate: it executes fewer instructions and has higher CPI at this source.
