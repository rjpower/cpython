# Committed nonneutral POST view: design peer

Disposition: **accept the bounded first packet for source implementation
review**. It addresses the pinned monitoring conditional callback without
granting SOURCE_POST or the separate peepholer NULL permission.

The proposed single request-owned copied row fits the existing
`register_context_normal()` transfer. In current source that transfer
mutates shared parent tables for `PUSH_EXC_INFO` and
`LOAD_FAST_AND_CLEAR`; rejecting those token creators before calling it
is essential. `STORE_FAST`, COPY and SWAP update only the passed
save/origin rows, so a checked copied row is sufficient for this first
case. The captured scope must validate the actual site, selected edge,
physical successor, frame/event, generation and generated observer fact
before binding. Decode physical and old-cut facts from the pristine
encoded word; a replacement VALUE or NULL at a retired input home cannot
restore its old origin.

The proposed Plan limit is appropriate: context zero, positively empty
save columns, and an owner-safe target. It cannot fall through to a
PRE-site FOR/caught survivor recipe. Keep the copied row owned by
`RegisterResumeAnalysis` and borrowed by the phase descriptor; allocate
at least one integer when the checked count is zero, or treat a zero-size
allocator result separately. After warning-time Python execution, discard
the old row, recapture authority and rebuild the Plan. Changed
generation invalidates the original committed edge; only a separately
proved fresh PRE landing may proceed.

Review the actual implementation against those gates and the negative
saved-token, alias, nested warning and stale-generation tests before
native admission. No code or native workload was changed for this peer.
