# Cold must-NULL transfer: source shape for the first PRE packet

Source-only preparation at runtime `488e85fa3a8`; no header/runtime/test edit or native execution. This supplies the shared query requested by `null-only-pre-implementation-brief.md`, not a second unwind engine or a debugger permission on its own.

The query takes the immutable encoded word, its decoded argument, selected normal edge, one physical scratch home and `[nlocalsplus, frame_limit)`. Return `{PRESERVE, SET_NULL, UNKNOWN, TRANSPORT(source_home)}`. `TRANSPORT` means the caller reads the **old** incoming row for every destination before writing any next bit; COPY/SWAP must never be applied in place. Invalid handler, edge, field, extent or out-of-frame geometry returns UNKNOWN. A source outside tracked scratch cannot supply must-NULL. The caller starts from the old row, applies each home's result simultaneously and intersects rows at every reachable join. An unknown result clears a bit; it never supplies an owner or an old-origin token.

| Encoded success case | Exact physical fact | Source proof |
| --- | --- | --- |
| COPY, valid decoded `base, arg` | `base+arg` transports old `base`; base itself preserves | `Python/bytecodes.c:COPY` duplicates `bottom` into `top`; generated output publication puts the top at the window end. |
| SWAP, valid decoded `base, arg` | `base` transports old `base+arg-1` and vice versa; other homes preserve | `SWAP` exchanges the two C values; generated final stores publish both endpoints. |
| STORE_FAST, valid scratch input A | A becomes NULL; local B is outside this scratch query | `_SWAP_FAST` moves A into the local and `POP_TOP` retires the displaced local; generated input consumption clears A before the retirement callback. |
| FOR_ITER completion edge, valid decoded base/base+1 | Both homes become NULL | VM child return and native/specialized/instrumented exhaustion all enter `_PyEval_CompleteStep` with FOR kind; it detaches both cells before observer POST and owner closes. The body edge is **not** a NULL clear. |
| Any declared output or possibly consumed input lacking one of those proofs | UNKNOWN at affected home | `_PyIR_DefinesHome` and the semantic outcome locate affected homes, but neither certifies the new value is NULL. |
| Untouched home | PRESERVE | Use generated roles/extents and semantic outcome to rule out writes/retirement; an opaque child activation forgets the potentially overlapped scratch tail. |

Here `base` is decoded from the format's BASE role: COPY/SWAP encode it in raw A, while FOR_ITER encodes it in raw B. `arg` is the decoded immediate, not always raw B. A physical COPY transport does not make a missing source into a valid input; reader capability is checked separately.

Output facts have precedence over generic affected-home fallback, but a transport cannot erase another same-home alias or a later final store. In particular, `WINDOW_DST_FIRST` means a physical destination mapping, not a NULL value; leave its affected homes UNKNOWN until an exact emitted move/clear proof exists. For LOAD_GLOBAL with its single-output argument shape, the generated row has `writes=1` and A is the only output: A+1 is untouched, so the optional-self scratch home there preserves NULL. A two-output form must treat that home as affected. No generic `_PyIR_NullableHome` or `_PyIR_Outcome` value can by itself create a must-NULL bit.

The header query should be deliberately small: reuse generated format roles/extents and existing `_PyIR_DefinesHome`/`_PyIR_Outcome` to find affected homes; add only the four exact semantic overrides above. It must reject overflow before computing `base+arg`, `base+arg-1` or extent endpoints. It should not inspect handler names to select a fast path, parse arbitrary generated C, or infer heap-object provenance. B's forward graph retains ordinary PRE exceptional edges separately and may initially clear all scratch facts there; source POST error facts require a positive completed-edge declaration and are outside the first three witnesses.

Source-level raw-query tests should encode: COPY transport from known NULL and UNKNOWN source; SWAP simultaneous exchange with one NULL endpoint; STORE_FAST clearing A even with a displaced local; FOR done clearing decoded base/base+1 but body not clearing them; LOAD_GLOBAL single-output preserving A+1 and two-output affecting it; invalid/out-of-frame geometry returning UNKNOWN; and an output alias overriding a supposed preservation. The known-NULL COPY source is a transfer-function witness, **not** a valid executable owner recipe. B's consumer tests must show that required-read ownership still rejects that case, a forward join of NULL and non-NULL loses must-NULL, a required alias or mixed VALUE/NULL_ONLY demand refuses, and warning/handler changes reprove rather than reuse stale facts.
