# Next debugger capabilities after restoration

Design only. Ordinary PRE full-exit restoration is the admitted source increment.
SOURCE_POST, yield cancellation, retained protocol roots and caught exits are not
authorized by this sketch. Reclassify failures after that increment's actual
native gate; the38 trace errors in ownership28-wide-v2 are baseline witnesses,
not a prediction that one change repairs38 cases.

## One phase-state view

Keep the existing Analysis/Plan and sparse graph. Add a request-owned stopped
state view instead of another opcode stack engine. It names the actual owner
site, exact physical continuation, normal edge, handled context, per-local save
tops/origins and physical availability. PRE borrows the analysis row before its
word. A committed outcome derives one transient row with the existing normal
transfer and shared cold owner decoder. Target rows remain the existing global
analysis; do not mutate a landing's merged row to represent one stopped edge.

Scoped observer association and provider generation are prerequisites. A public
event name, reported branch source or current line cannot identify owner state.
Use actual owner site separately from reported SEND branch source for
END_ASYNC_FOR. An older generation invalidates the old outcome; only a separately
proved committed landing may supply fresh PRE authority.

## Source-only LINE first

The remaining each-LINE comprehension witnesses include callbacks whose physical
PC is a predecessor, not a PRE instruction at the reported line. For SOURCE_POST:

1. Validate the scoped record against actual source cursor/record, from/to/edge,
   owner site and original generation. The producer must prove its output commit
   complete; the enum alone cannot certify a legacy handler with later stores.
2. Derive the stopped context/save/origin state from the actual from row and
   selected normal outcome. Do not require it to equal a global merge at to when
   a stronger edge-specific fact is available.
3. Use the same target availability, ordinary-local restoration and caught-root
   constraints as PRE. No restoration can fabricate an unavailable token or
   acquire target protocol owners from its cancelled current expression.
4. Commit before closes; source adapter observes generation and abandons its old
   cursor. A setter followed by callback error uses the new target EH. A prior
   activation recipe is invalidated at actual commit; later reentrant installs
   survive.

Start with a landing-wrapper source callback after a completed ordinary dispatch
and a committed terminal provider. Inline nonterminal source hooks need their
own positive commit proof. Constructor source-EH proof and debugger physical
availability share the decoder, but old-origin cuts remain separate: a new
non-NULL replacement is not an old required receiver.

Tests must distinguish PRE and SOURCE_POST at the same apparent line, include
two ingress edges with different saved-local states, saved NULL, a shared
landing merge, same-PC redirect and setter-then-raise. Keep original each-LINE
lists and actual old refusal cases.

## Yield-ready cancellation

The original jump-from-yield observes PY_YIELD before suspension. Its frame is
still executing and the outgoing value still has a frame owner. This is not an
already-suspended frame. A typed adapter may supply YIELD_READY only before
generator/exception/recursion links change, with an independently owned callback
payload copy. On redirect it must skip the entire pending yield transition and
dispatch the committed target; no stale resume recipient or outgoing C borrow
can be published afterward. Compare generation after callback and payload
retirement, not merely PC.

Reuse the same state view, full-exit action plan and same-context target proof.
Keep actual suspended frames unavailable until their resume-input recipient,
delegation, event ordering and exception-chain attachment have a complete
transition recipe. Tests count one real yield/resume, verify outgoing owner
collectability after cancellation, callback errors, nested redirect and
unchanged generator exception/recursion state.

## Retained with/loop roots

Inner-with to outer-body and with-inside-for witnesses require actual surviving
target roots, not an empty-target shortcut. Factor a shared owner-survival slice
from existing FOR/caught slices: actual producer+output home, successful-edge
availability, dynamic generation witness, and no defining/killing operation,
unsupported transport, opaque child overlap or unwind clear on any admitted
path. Entry dominance and generation survival are both required. A skipped setup
must refuse; equal values or the same static producer after reentry are not a
substitute.

Use the sparse forward/reverse graph already built once per request. A preserved
root set is an input to the same Plan, alongside restoration actions. Do not add
one setter branch for each with/async-with opcode. First validate an ordinary
outer with anchor and an outer FOR pair, then add asynchronous protocols after
their suspension/await owners are explicitly represented. Context-manager exit
policy must be chosen explicitly; preserving Python control behavior does not
require reproducing a historical cleanup instruction inventory.

## Caught exits remain a resolver problem

The matched upstream probe demonstrates that a blind exc_info write clobbers a
callback-owned exception and its later POP_EXCEPT can resurrect the old target
exception. Preserve our refusal until a resolver identifies the target's actual
parent exception link and every intervening callback saved-prev owner. Restore
the target without changing sys.exception() inside the callback, then ensure
callback exit restores the new target parent. No direct tstate->exc_info swap,
fake POP_EXCEPT or numeric EH-depth equivalence is acceptable.

B owns phase-state and Analysis/Plan consumers; A owns scoped provider commit,
yield adapter and source-error lifecycle; the shared cold constructor/outcome
worker owns the encoded declaration/decoder proof. Agree those interfaces before
source edits. Root owns native gates and integration. Remaining21 diagnostic
wording assertions can be ported separately while preserving precise ValueError
and no-fabrication checks; they are not reasons to restore stack projection.

## Concrete next consumer interface after native29

Keep the stopped view request-owned, with `site`, physical `next`, edge and
phase plus borrowed or owned `context`, `save_tops` and `origins` rows. PRE
borrows the existing row. SOURCE_POST allocates one row pair and calls the
existing `register_context_normal` transfer once on the exact source edge.
Shared physical observed-home facts describe missing/NULL/value boundaries;
they do not restore an old saved origin merely because a replacement exists.
Do not write this row into Analysis. Every temporary row is freed with the
request, including refusal and warning-reproof paths.

Refactor the existing saved-local action builder to read current rows from that
view; targets still read Analysis. Binding-safety, token-generation witnesses,
NULL checks and detach/install/commit remain the same Plan consumers. The first
SOURCE_POST rung should require inherited handled context and a target with no
incoming scratch requirements. It need not pretend a pre-site caught/FOR
survival slice certifies a post-edge stop. Extending retained roots requires the
separate exact-edge endpoint proof, not a fallback to the global landing row.

The source provider must match the scoped source record, actual cursor, from,
edge and physical next, and retain the original generation. A landing-wrapper
source event is supported only where the provider guarantees all predecessor
outputs already reside in final homes. A terminal provider needs the shared
positive committed-outcome declaration. Legacy inline hooks without that
barrier remain unsupported. Callback redirects invalidate old views; warning
callbacks require a new scoped snapshot and the same full plan reproof.

YIELD_READY uses the executing pre-yield row rather than a fictional successful
suspension edge. Its provider adapter must own the callback payload independently
and return a typed cancellation result before suspension/frame-chain changes.
The setter uses the same Plan. On redirect, the provider retires its payload and
then honors the latest generation/PC without performing any old yield store or
suspension. Actual suspended frames remain outside this packet.

Ownership boundaries: B changes only frameobject view/Plan consumers and focused
context tests; A owns provider scopes and typed cancellation; H owns shared
encoded owner/nullable/binding facts and constructor proof. No new state belongs
in the interpreter frame or ordinary dispatch. Native29 evidence must precede
source admission for this next packet.

A's bounded peer disposition accepts this design subject to two independent
checks: the producer has a positive commit declaration before normal transfer,
and the shared physical-home facts agree with actual owners. A replacement
output cannot revive an old save token. For YIELD_READY, keep the original value
frame-owned until cancellation is chosen and recheck intent after closing the
independently held payload. This records design review only; no additional
phase authorization is implemented or admitted by this note.
