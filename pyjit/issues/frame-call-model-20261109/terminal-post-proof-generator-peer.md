# Terminal POST encoded proof: generator peer

The revised cold proof direction is approved for planning. Source implementation
and native validation remain separate gates.

The generator can attest VALUE versus defined-NULL per observed arm from actual
path storage assignments and the same final store mapping it emits. It cannot
infer NULL from an absent output or certify a whole composed handler from one
marker token. Full provider terminality and direct-helper census remain necessary.
The ordinary emitter must stay byte-for-byte unchanged outside the independently
justified observed provider migration.

I raised an original-owner lineage ambiguity: retiring an input and then writing
an aliased output must not restore the old input's identity. Availability of a new
value at the same home is not preservation of the original receiver/cursor. The
revised proposal retains this old-origin cut and conservatively rejects requiring
a replacement cursor without separate provenance. Fresh FOR item B+2 can be
available independently. Unknown aliases/transports refuse rather than acquiring
old owner identity from a fresh-definition bit.

FOR body needs an explicit semantic override for cursor and result, including
B+2 after folded-local/NoDst transfer. Actual current `through=1` preserves only
iterator B; a future format variation must not turn updated cursor into unchanged
ownership accidentally. The constructor must require a temporary FOR A to equal
B+2 under the current emitter, or reject the encoded mismatch. Named-local and
NoDst destinations retain their distinct transfer/detach rules.

The proposed shared cold decoder and worklist can consume these checked facts.
They must retain separate ordinary compute-PRE and observer-POST EH obligations,
and must not infer nullable state from reader capability. Existing completion
checks remain clients of one proof. Debugger context/restoration obligations are
still additional requirements, not consequences of scratch availability alone.
