# Option 5 independent peer review

Approve a bounded ADD_INT implementation with the stated proof and fallback;
no SUB extension before evidence. Source/proposal reviewed; this reviewer did
not execute a runtime. Reported surviving selected native B clear establishes
that generic compilation has not already removed the target store, but does
not establish A==B reach frequency or a dynamic gain.

The existing ExecutionVariant mechanism already distinguishes executable from
canonical handlers and supports local/temp facts. A==B overwrite and C!=B need
additional explicit geometry authority; they cannot be inferred solely from
both fields being temporaries. Preserve ordinary ADD_INT as the fallback before
any input mutation; arbitrary pristine IR must not install the refinement by
bypassing specialization/admission. Canonical family restoration must include
feedback rows and instrumentation, not only generic deoptimization.

For the generator certificate, an annotation or spelling match to ADD_INT is
insufficient. Inspect the actual analyzed body/commit suffix: fallible result
production and its error checks must precede the suppressed clear; subsequent
C consumption/release must remain inline-only under its successful guard; no
callback, escape, poll, deopt/error edge, frame switch or allocation may occur
before the exact same-home result store. Fail generation for inserted unknown
or escaping suffix calls, even when the operation name is unchanged. Existing
retirement-publication proof tests demonstrate the repository's pattern for
rejecting an escaping suffix; add analogous semantic negative cases here.

B==C must remain excluded, output discard and local B must fall back, and boxed
overflow result ownership must remain anchored until installed. Input inline
proof says nothing about result representation. Debug entry/exit assertions
must express the actual refined invariant rather than demand an intermediate
NULL that is deliberately omitted. Do not count already-eliminated inline
closes as extra removed work.

No unresolved design blocker if these certificate checks are implemented.
Independent post-review must inspect generated success/overflow/error/fallback
paths and root's native disassembly. Reject no-hit or negative breadth; no
synthetic result justifies a workload throughput claim.
