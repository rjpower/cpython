## Source assessment

**Admission and entry semantics.** The enable field, setter, initialization and
runtime consumers are gone. A tracked-source search finds only the test that
asserts the removed setter is absent. Existing exact cell/nonempty base-tuple
sites always set young age and the pending hint; empty immortal tuples and
subclass allocation paths retain their treatment. Generation zero selects the
minor regardless of verifier/stress or automatic enable state. Unsupported
main/GIL/mimalloc contexts raise explicitly. Generations one/two, default,
automatic, C full-collection and shutdown entries preserve major routing and
their existing enable semantics. No replacement policy switch was added.

**Retained ledger.** `gc_trace.c:3096–3256` stages a sorted union, carrying old
records and A/B-marked young records, retiring unmarked young records, and
preserving older provenance on duplicate identities. Prior-q root-reappearance
reports are suppressed for both ages on a minor. Exact managed lookup precedes
record-header reads. Still-present old storage unmarked by the completed old
boundary fails closed. The ledger is never inserted into tracing roots.

**Transactions and OOM.** Replacement q and required KILL membership finish
before publication or B-mark removal. Failure retains the original q and
diagnostic hint, clears scratch marks and frees/promotes nothing. KILL's optional
origin-buffer failure can omit a report record but cannot change the completed
kill-membership set or quarantine eligibility. Inventory failure happens after
the completed comparison's ledger commit and leaves ages unpromoted. Later
lifecycle-preparation failure retains the safe survivor promotion already
committed, undoes death flags and preserves debt. Young dead records retain
their age/pending work. `live_fini` releases both new scratch q and membership
storage without taking ownership of the published replacement twice.

**Attempt sequence and KILL domain.** A configured verifier increments once
after initial scratch setup and HEAD_LOCK, before quarantine release/pages.
Early/reentrant failures do not reach that point; later OOM does. B uses the
same sequence. Minors list and kill only young B candidates; old boundary
objects remain protected. Release uses `now - 16` before page construction,
and quarantine tags/report origins share `now`. Each actual follow-up mark
attempt counts separately. The post-collection full-reachability checker still
excludes ordinary minors; explicit full verification stays a major.

**Storage lifetime refinement.** The private-constructor resize path found in
preview is real: an unpublished tuple can be B-retained, then move through
`_PyTuple_Resize`/`PyObject_Realloc`, which frees old storage without ordinary
`PyObject_Free`. The coordinator-approved refinement retires its diagnostic
at existing object-map invalidation sites. True frees retire before allocator
free. Successful realloc retires only on movement or loss of object-header
storage; failed and valid in-place realloc preserve the record. For a move,
the underlying allocator may already have freed the old block; address-only
retirement/map update occurs before another Python allocation, callback or GIL
release under the existing supported allocator contract. No stale header is
read. This is not foreign-interpreter infrastructure or a new object store.

**Diagnostic hint and cost.** Every q publication, matching-address removal,
GC initialization and trace teardown maintains
`diagnostic_q_nonempty == (trace != NULL && trace->nq != 0)`. The helper and
state getter assert this; teardown clears the hint before discarding trace
state. Ordinary checker-off invalidation adds a scalar branch, with no trace
function call or per-allocation search. Nonempty diagnostics require a binary
search; actual removal uses memmove. That diagnostic cost is bounded by q size,
but the ordinary invalidation overhead remains unmeasured. Quarantine owns
copied records independently, so q retirement does not alter its storage or
expiry.

**Debt, inspection and public observations.** Only a successful major resets
allocation debt. Accepted mark/preparation OOM now applies a saturating finite
retry probe while preserving debt and stress behavior. Inspection lists ages
without invoking snapshot collection. Minor statistics/callbacks use generation
zero; aggregate byte/pause totals remain in generation two. Remote GC offsets
are generated with sizeof/offsetof; the fresh build must provide matching
runtime/extensions. The changed remote-statistics tests now check generations
zero and two, consistent with their explicit requests.
