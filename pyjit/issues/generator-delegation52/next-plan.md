# Next performance plan

Golden51 stays selected. Both round52 candidates are rejected; this is the next
decision plan, not an active implementation queue. The [report](report.md),
[full tables](benchmark-tables.md) and [cold review](cold-review.md) own the evidence.

The central hypothesis is that **one resume/transfer contract for descent,
suspension and completion** can remove repeated activation work more effectively
than yield-only routing fusion. It must retain Python protocol, ownership,
exception, recursion and observation behavior without requiring source positions
or a second evaluator. A semantic instruction alone does not reduce those costs.

## Ranked options and decision gates

1. **Attribute real transition work first.** On selected golden51, measure
   creation, resume, suspension and completion, plus exact/provider calls,
   successful/failed forwarding eligibility and chain-depth distribution.
   Use diagnostic counting separately from quiet timing, with matched source and
   native identities. Generators, coroutines and DeltaBlue remain the hot set;
   logging silent and comprehensions are guards. Distinguish coroutine completion
   from actual yielding. Deliver a weighted cost map and a falsifiable work-removal
   hypothesis before selecting source changes.
2. **Separate cheap admission from cold recovery.** If weighting supports it,
   use actual owner/continuation discrimination before expensive eligibility and
   materialization work. Define one coherent input/recipient/PC transaction and
   a cold miss tail. Preserve epoch synchronization, redirects and observer error
   authority. Admit only if native paths remove weighted work and shallow/plain
   yields and ordinary calls do not pay new common-path preparation.
3. **Recover provider specialization where it matters.** If virtual/asend sites
   carry measurable weight, give them provider-specific admission within the same
   semantic completion contract. Misses must precede effects; providers cannot
   be replayed. This can recover a lost optimization but does not address exact
   generator losses, so it cannot substitute for the overall transition design.
4. **Design iterative exact-child resume and completion.** Walk real child
   frames through one entry/return loop, retaining each frame's owner, input,
   executing-state, recursion and observable links. Stop cleanly at hooks,
   generic providers, redirects and errors. Use no persistent chain cache.
   Specify how observation remains stable across a proven nonescaping region,
   including materialization before an escaping operation. Choose this lane only
   if phase/depth measurements show enough repeated work to justify its scope.
5. **Defer lazy frames and native JIT lowering.** Larger reductions in per-level
   state work need explicit contracts for logical recursion, introspection, GC,
   callback failure and frame materialization. Treat this as a separate later
   architectural proposal, not a shortcut around current proofs or qualification.

## Delegation and integration contract

The coordinator owns the measured source, integration and decisions. One Sol
agent should produce the phase/native cost map while another audits the existing
resume/completion ABI and proposes the smallest coherent shared transaction.
Use one broad Astra review of the resulting group of options; use independent
Sol review for component changes and debugging. Terra/Luna agents can keep
consumer ports and documentation in sync under explicit whole-file ownership.
Do not run competing builds or diagnostics during quiet timing.

Each chosen lane follows propose → peer review → implement → focused test →
post-review → integrate. Separate worktrees hold competing hypotheses. Require
an actual compiled-path check alongside protocol/ownership/observer tests;
binding the DSL producer is not a proof of its backend terminal. State any
remaining trusted compiler boundary explicitly. Add meaningful bounded terminal
contract checks rather than tests that duplicate emitter lines.

Screen each coherent integration against the actual selected golden with two
balanced pairs. Confirm target gains and material losses with six pairs; include
all29 unchanged kernels and direct upstream comparison before promotion. Reject
ineffective lanes rather than accumulating an unbounded rescue queue. Run full
release/debug qualification only for a candidate worth promoting, preserving
the established debugger/LLTrace limits and the narrow GDB quarantine. Publish
source/native provenance, raw vectors, rejected options and a cold admission
review with every checkpoint.

Success requires repeated application improvement with acceptable breadth,
explicit ownership and a simpler common execution contract. Fewer dispatches,
fewer boxes, smaller assembly or a lower sample share alone do not meet the gate.
