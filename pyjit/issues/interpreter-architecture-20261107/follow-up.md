## 1. Resolve the shape-read tradeoff without another execution model

The canonical temporary store removes a proven redundant conversion and wins
on the declared direct whole-workload check, but folded-local microtargets
regress. The accepted GCC review identifies two extra companion-slot address
calculations on one local route. Inspect their placement and executed work
before changing the emitter. A smaller handler is not itself the objective.

Terra medium should propose one bounded emission/dataflow simplification;
Sol independently checks the producer premise, generic and specialized paths,
temporary/local destinations, callbacks and error ordering. Preserve one
shared flush-preparation routine and the existing ownership representation.
Avoid a handler-name table, runtime validity cache or speculative dispatch
rewrite. Retain the current exact ELF as the control.

Run generator/contract tests and the changed local-reentry semantic tests on
release/debug, then the paired shape cases and a balanced whole-kernel screen.
Keep all payloads and both destinations. Remove a performance-only variant
that cannot justify its complexity or introduces a material workload loss.

## 2. Measure accepted call shapes before the next call-path edit

Separate overlap success from guard decline, consuming binder, keywords/EX,
generator-owned frames, native adapters and monitoring. Use a bounded
hot-region stats capture to count those routes; sampled helper share alone
cannot tell which guard or preparation step dominates. Keep counters out of
the release path used for admission.

Sol scopes the source/protocol proposal; Terra medium implements the smallest
supported common-route improvement after peer review. Keep owners rooted
through fallible preparation and final guards, and commit once with no failure
or reentry before publication. Do not replace this with a second general call
ABI. Use focused signature/default/varargs/kwargs/monitoring tests, a basic
integration screen and fresh cold source review. Run full suites only when
the next coherent batch is ready.

## 3. Build the recovery contract's first executable slice separately

The accepted Action/FrameState design is ready to guide a bounded baseline
adapter, not an optimizing backend claim. First implement the prepared-owner
ledger and shared once-only transfer commit. An overlapping child must not
overwrite parent homes during fallible preparation. Distinguish fault and
resume PCs, raised and handled exceptions, and completed effect prefixes.

Sol reviews this interface before implementation; Terra medium can implement
the bounded adapter and fixtures. Offline shape checks precede actual forced
native exits, which must exercise allocation failure, callback invalidation,
exactly-once effects and owner transfer. Keep canonical homes at helper/effect
boundaries initially; post-effect fallible materialization requires its own
OOM route. Method and tracing entry then share this recovery interface and
optimizing IR. Do not infer that baseline register words are typed SSA.

Rebuilt native object adapters remain a profile-driven porting opportunity.
Use Terra/Luna medium for proven mechanical ports and minimal affected tests;
batch full validation at integration points. A new exhaustive zero-box census
or startup/RSS campaign is not required to start useful throughput work.

For the next broad campaign, predeclare one CPU-affinity policy for every role
and check it in native children. The direct R4/R5 check used CPU15; the reused
three-role collector did not pin execution and still has substantial row
variation. Review that protocol change before collecting a new baseline;
