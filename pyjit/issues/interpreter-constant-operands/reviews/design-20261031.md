# Independent constant-operand design review

2026-10-31. Coordinator review of the design against integrated source
`d98291018c9665ae3db6952da0b0a40a4e04992b`.
Design SHA-256: `5b223af69087659cfb6353c0f343b760da051de2c3286e7207bf9070ea5b2892`.

**Accept for a bounded host-only representation prototype.** This does not
accept runtime source, authorize a native batch or establish a speedup.

The proposed work exists in the sealed O3 image: the RHS slot read/admission
and constant producer store/dispatch survive. The report correctly excludes
duplicate decoding already removed by the compiler. Saved helper samples
neither identify constant sites nor predict this increment's gain.

The same-word operand avoids an unchecked mutable-slot promise. Inspection of
`Objects/frameobject.c:mark_stacks` and the `f_lineno` target search confirms
that adjacency alone would not justify removing a slot guard. Extending the
existing folded-input reader is the right place to describe materialization.
The implementation must preserve semantic stack depth, error cleanup and
publication before generic arithmetic can run Python; removing a physical
input does not remove its logical stack effect.

The generator's `HandlerDomain`, `_PyCode_InstrOparg`, `choose_handler`,
`IR_DEOPT_BINARY_OP` and specialization installation currently assume one
operand layout per family. The design names those assumptions rather than
letting a generic miss reinterpret an immediate as a slot. The prototype must
produce one shared relation for operation and operand form, including pristine,
specialized and restored handlers. Transparent monitoring wrappers must use
that relation. No parallel arithmetic bodies or effect tables are acceptable.

The initial family is coherent: six generic operations, three integer and
three mixed-float specializations, and sequence EXTEND for multiplication.
Existing specialization guards exclude other forms, but installation must
reject an incompatible projection rather than silently change its layout.
Boundary values, entry zero, destination aliases, multiple/implicit uses,
exceptions, local rebinding and legal debugger entry need useful controls.
The serialized representation requires the stated magic-number update.

Proceed with the proposed 90-minute host-only budget and 30/60-minute
checkpoints in an isolated worktree. At the deadline, accept a complete,
reviewable representation candidate for separate native feedback or reject
the attempt. Missing reader/observer proofs, handwritten semantic copies or
unchecked producer facts are rejection grounds. Ordinary slot forms remain
necessary for dynamic operands; they are not a runtime optimization switch.
