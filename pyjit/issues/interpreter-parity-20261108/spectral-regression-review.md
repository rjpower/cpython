# Spectral-norm regression review

2026-11-08. Bounded source, disassembly, and retained-evidence review of R5 against integrated runtime `0267d428808`. No build or workload was run for this review.

Evidence is under `python-boil-the-ocean/build/pyjit-link-wave1/interpreter-parity-20261108/`: `final-vs-r5/summary.json`, `spectral-perf-summary.json`, `spectral-perf-stat/{status.json,invocations.json,*result.json}`, `spectral-perf-record/{status.json,*result.json,*perf.data}`, and `warmed-shape-comparison/candidate-spectral-shapes.txt`. The kernel source and generated handler source are in the canonical and runtime checkouts, respectively.

## Observation and scope

The retained four-round direct ELF comparison reports candidate/R5 elapsed ratios of 1.095006, 1.087011, 1.081631 and 1.080558 for `spectral_norm` (geometric mean 1.086037). All four rounds exceed 1.08. The same comparison reports `logging_silent` at 0.840163 and the 29-kernel geometric mean at 0.980981. This is a real control regression in the direct comparison, alongside a substantial target improvement. The two retained ELF executables use the current shared modules and standard library, so the comparison isolates their main executables but is not a fully frozen R5 runtime environment.

The unchanged kernel (`pyjit/bench/internal/kernels/spectral_norm.py`) makes repeated Python `eval_A(i, j)` calls from the two matrix-vector loops. `eval_A` computes integer subexpressions before a float division. The source contains no dictionary subscripting or explicit boolean conditional in this inner function. Thus the M1 dictionary first-probe fast path has no evident direct match here, and the M2b checked-boolean NOP continuation has no evident direct match in `eval_A`. These statements are source classifications, not measured opcode-route counts.

## Code path

The P3 change adds a distinct `call_transaction_run_guarded_python_vector` entry for guarded Python calls. The retained candidate ELF's bounded disassembly shows this function initializing a call transaction, calling `call_transaction_overlap_python`, then calling `call_transaction_push_python_fallback` only if overlap declines. It omits the generic entry's method expansion, callable-type, vectorcall, and custom-evaluator checks, consistent with the source's prior guards. The R5 and candidate `call_transaction_run_vector` disassemblies have the same branch structure and instructions in the inspected function, apart from relocated addresses. The saved warmed candidate shapes show both inner `eval_A` calls specialized as `CALL_PY_EXACT_ARGS`. That generated handler pushes the frame directly through `_INIT_CALL_PY_EXACT_ARGS`; it does not call P3's guarded transaction. P3 therefore has no demonstrated direct effect on the dominant inner call route.

P1/P2 replaces code-home creation at frame entry with a pointer borrow of known code and returns early from successful refresh. The bounded `call_transaction_refresh` disassembly confirms that candidate success returns before R5's second frame/code check. Candidate `CALL_PY_EXACT_ARGS` is 0x501 bytes versus R5's 0x5f4; `call_transaction_overlap_python` is 0x7ff versus 0x86e, while its fallback grows to 0x99d versus 0x917. The inspected `BINARY_OP_ADD_INT`, `BINARY_OP_TRUEDIV_FLOAT`, and `UNPACK_SEQUENCE_TWO_TUPLE` handlers have identical lengths and matching hot-path instructions, aside from address relocation. Function size alone cannot assign cost or explain the elapsed regression.

## Gated hardware counters and samples

The completed spectral diagnostic has 18/18 valid `perf stat` invocations, unchanged identities, and three valid paired cycle/instruction groups. The collector labels retained R5 as `upstream`; it is **not** CPython upstream in this comparison. Its gated interval starts after setup and warmup, and the child checks CPU 15, hash seed zero, JIT off, and source identity before and after. Counter running time is 100% for the paired groups. Per kernel loop, candidate/R5 retired-instruction ratios are 0.99492, 0.99491 and 0.99491 (ratio of role medians 0.994914), while cycle ratios are 1.08531, 1.09075 and 1.07886 (ratio of role medians 1.080979). The corresponding CPI ratios are 1.09086, 1.09633 and 1.08437. The slowdown is therefore accompanied by **fewer retired instructions and more cycles per instruction**, not by an increase in total retired work. That does not tell us whether the cause is instruction mix, dependencies, instruction delivery, or another stall.

Branch totals are slightly lower on candidate in the valid pairs. Branch-miss counts are small and inconsistent between pairs; the cache-miss group varies substantially, without a stable candidate excess. The one paired DWARF cycle recording has zero lost samples in both roles and about 2,000 samples each. The leading symbol is `BINARY_OP_ADD_INT` at 14.84% R5 and 14.80% candidate; other hot symbols are arithmetic, tuple unpacking, exact-args calls, iteration, and frame retirement. Sample percentages move among these common symbols and do not isolate a new dominant helper. The report reader prints `Invalid HEADER_EVENT_DESC` for both files, while `perf evlist` identifies `cycles:u` and `dummy:u` and the cycle reports are readable. This limits header metadata interpretation, not the independent `perf stat` counts. Relocation and changed handler layout remain plausible explanations for the higher CPI, but the available counters and samples do not establish either as causal. The sampled recording is a separate interval from the stat pairs, so its percentages cannot be multiplied into a precise per-loop cost attribution.

## Decision boundary

Keep the integrated batch at this checkpoint. The target and broad aggregate improve, while this one control is consistently slower. The paired counters rule out a simple added-retired-work explanation and the samples reveal no narrow helper to fix. A performance-only source edit based on symbol percentages or code alignment would be speculative. Record `spectral_norm` explicitly as an accepted measured tradeoff for this checkpoint, with the cause unresolved. This does not claim the regression is harmless in general or that the parity objective is complete.

If spectral cost becomes a gate, the next discriminator is a matched direct spectral/counter pair at the already integrated P1/P2 source state (`0539e0c1ff9`) against R5, followed by the same pair at the full `0267d428808` state. The existing P1/P2 screen omitted this kernel. These two comparisons would localize whether the cycle increase appears with the frame-entry change or only after subsequent increments; neither outcome alone would prove a microarchitectural cause. Inspect per-instruction samples or design a layout experiment only for the interval that first shows the increase.
