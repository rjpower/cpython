# M2: natural method execution over a useful generic helper slice

Read-only implementation proposal, 2026-11-01. Base is frozen
`15987a03c236d5257b8a7b944bf858ee20e52fc3`. No source, compiler or target authority
is conferred here. The fixed six-program matrix is `workload-matrix.json`;
its method names are diagnostics, never compilation filters.

## One source cut

Within one proposed 90-minute source cap, broaden ordinary object/loop semantics
and naturally enter whole-method code from selected CALL/backedge sites. Keep
the existing Action ABI, fixed-home baseline LIR, emitter and artifact owner.
Do not implement speculative SSA, storage changes or a new frame engine here.

Generate adapters for LOAD_ATTR/STORE_ATTR and their NOFB forms, GET_ITER,
FOR_ITER, END_FOR/POP_ITER, BUILD_LIST/BUILD_TUPLE/BUILD_MAP/
BUILD_CONST_KEY_MAP, UNPACK_SEQUENCE, STORE_SUBSCR, CONTAINS_OP and CALL_KW;
COPY_FREE_VARS/MAKE_CELL and LOAD_DEREF/STORE_DEREF close ordinary closure entry.
These are a fixed first set from the existing DSL, not hand-copied C semantics.
Retain explicit unsupported reasons for other operations, including
CALL_FUNCTION_EX and native generator/async execution. An adapter with an
unclassified nonlocal transfer is not declared complete merely by adding its
name to DIRECT.

FOR_ITER exhaustion and conditional NOT_TAKEN skips need the actual generated
successor contract. Extend the common edge-description/decoder only enough to
represent those two normal edges, retaining M1's exact-PC AFTER fallback for
an unexpected committed successor. Test ordinary iteration success/exhaustion
and effects before admitting a loop as fully compiled. STORE_ATTR remains a
generic semantic helper in this cut, with real descriptor/custom-hook/RC
behavior; the separately accepted typed-SSA proposal supplies its next lowering.

## Natural nomination and initial policy

Use three execution-only same-family handlers: CALL_JIT_WARM,
JUMP_BACKWARD_JIT_WARM and RESUME_JIT,
appended after the existing 0–301 IR indices, with every old ID/format unchanged.
They have CALL/JUMP_BACKWARD/RESUME semantic bases and formats. They are never valid
pristine/serialized code; close constructor AND shared marshal validation,
dis/feedback/base-opcode/restore readers, and instrumentation restoration.
If this cannot be proved in the first metadata checkpoint, stop rather than
change cache magic or renumber existing instructions.
The actual IDs are appended 302–304 in the IR generator. Map their base/shadow
before every uint8 opcode/cache-table consumer; publish with the IR handler
setter, never the uint8 specialization API. Shared `_PyCode_Validate` must
reject them on marshal as well as the public constructor's full check_words.

CALL specialization can nominate actual Python functions/bound methods,
guarding function/code identity and current versions. Eligible sites use
CALL_JIT_WARM's shared generic call body while warming, preserving source
ownership and errors. Use `_PyFbHeader.hits` only after proving a nonzero
FB_CALL entry; it is currently reserved and unwritten. Keep the adaptive
specialization counter independent. At **64 eligible executions of that site**,
attempt one bounded whole-method compilation, publish its entry head, then
restore the site's ordinary call specialization. A target change resets that
site's heat/nomination after the ordinary function-version guard fails; no
borrowed callee pointer becomes a permanent dependency.

Backedge heat is **not** in feedback entry0 or FB_BRANCH. Actual RegIR
JUMP_BACKWARD/IR_JUMP formats have no feedback operand despite the generic
feedback-family declaration. Seed only pristine interruptible JUMP_BACKWARD
sites with a validated earlier target when making the executing copy; charge
this one cold word pass explicitly. Do not nominate IR_JUMP, synthetic
FOR_ITER relaxation bridges, or JUMP_BACKWARD_NO_INTERRUPT/await loops.
JUMP_BACKWARD_JIT_WARM consumes a saturating **per-exec `loop_heat`**, allocated
lazily in the existing JitState domain, and attempts compilation after
**256 such backedges**. It performs the original periodic service first;
successful OSR enters at the already-committed loop target in canonical homes,
without replaying RESUME, the poll or earlier loop work. This supersedes the
working notes' tentative suggestion that hits existed per actual backedge.

Static coverage is cached once per immutable code/helper-generation identity.
Cache a structured unsupported reason and restore ordinary site handlers so
unsupported functions/loops do not repeatedly count, scan or allocate. Initial
automatic eligibility requires **every pristine word** to have an implemented
helper, including exception-handler words, plus ordinary supported flags and a
valid entry RESUME. Methods with unsupported handlers stay interpreted; report
wrapper coverage separately from body coverage. Suspension exclusions remain
explicit. Do not confuse temporary
observer state or optional allocation failure with immutable unsupported code.

Initial bounds, chosen to test a mechanism rather than predict speed: at most
4096 words per method (M1 bound), **64 installed/retired-live Units and 8 MiB
retained metadata+code per process**, and **4096 eligible-site events** before
retrying a resource failure. Charge retired pinned artifacts until actual
release. Cold atomic budget reservation/release avoids new Python roots or a
budget pointer that dangles after interpreter teardown. Keep interpreter-ID
checks; cross-interpreter cache reuse is not enabled. Permit one automatic
compilation in flight per process; defer reentrant different-code nominations
without poisoning their support status. Compiler scratch is separately bounded
by the 4096-word emitter limit and reported; 8 MiB is not a whole-process RSS cap.
No eviction or threshold
search is required for this slice. Report cap exhaustion, never silently extend
the budget. Observers defer entry; a later unobserved epoch can re-arm eligible
sites without permanently poisoning the method.

## Explicit transfer and continuation ownership

Remove M1's unconditional full PrepareActivation lookup from ordinary frame
start/return. Publishing a Unit patches only that method's executing entry
RESUME to RESUME_JIT. Validate `code->_co_firsttraceable` in range and pristine
RESUME with ordinary entry location; COPY_FREE_VARS/MAKE_CELL can precede it.
Those prefixes still run once in the interpreter. IR_SKIP_RESUME's exact
handler test stops skipping the patched head. The shared original RESUME body
performs instrumentation/poll service, then the JIT-specific tail requests
PrepareActivation at its committed successor. If service retries at the same
RESUME, instrumented/restored words or epoch changes take the existing retry
or ordinary dispatch route; never replay a completed poll or spin on a stale
stub. A backedge request enters at its committed target, with no frame push.

An armed M0 semantic-step request for the claimed frame takes priority over
RESUME_JIT and executes its pristine semantic helper route, so the eight M0
tests cannot silently turn into native execution. This uses the existing
bounded request seam, not a new runtime selector.

This is the same production publication path for the six existing manually
compiled M1 fixtures; no new retaining C wrapper is added, and the natural
ephemeral-code finalizer test remains an ordinary Python call. M2 workload
diagnostics themselves use no manual compilation API. Detach restores the
entry head before dropping publication or freeing metadata; instrumentation
restores/detaches before its own rewrites. Re-arm only after fresh valid policy
and epoch checks, never by leaving a dangling RESUME_JIT head.

Use one lazily allocated evaluator-local `JitFlow`, created before an eligible
call/OSR effect while canonical BEFORE state is valid. It has **64 scalar pending
caller records**: linked caller-frame identity, call word and postcall word,
plus a local generation token. It holds no code/function reference, Unit pin or
native body address across a Python callee. Allocation failure with no PyErr
declines admission; hook-set PyErr propagates BEFORE the call. No allocation is
needed to push a record after ENTER_PREPARED. Capacity overflow skips only the
current transfer's compiled resume; older valid records remain intact.

Before a native CALL helper can transfer, record its caller/word provenance in
ctx while that frame is live. On ENTER_PREPARED/STARTED, consume that scalar
provenance before clearing borrowed native fields and releasing the old active
pin. Preserve existing start_frame versus _PUSH_FRAME ownership; do not run
recursion entry twice. After the actual caller return-slot store, match the
top pending frame AND logical continuation, pop it, and resolve a fresh valid
Unit through a proper entry prologue. Never call a stale native body label.
The ordinary paths retain at most cheap evaluator-local pending/request
branches, not code scans, counters, observer loops or compiler calls. These
branches and cold-copy/frame footprint are real costs to inspect and measure;
this is not a claim of zero unrelated-code overhead.

Retire records before their caller frame is cleared/reused. If an exception
unwinds into a still-live waiting caller, retire that normal-success record
before its handler; preserve outer records when an error is caught inside the
callee. Free JitFlow on every evaluator exit, preserving pending errors through
callback-capable cleanup. No semantic code/constants pin may delay finalizers.

Generator creation returns through RETURN_GENERATOR, not RETURN_VALUE. Add a
source-generated pending-return consumer **after** its real result placement;
keep the generator body interpreted. Ordinary generator iteration inside the
generic FOR_ITER helper is a published C/reentrant boundary. SEND/yield/throw/
close transfers without an implemented consumer must take documented exact
BEFORE fallback and retire the relevant pending expectation, never retain a
normal-return record that can match a reused frame. No native stack address
survives suspension.

Cold nomination/compilation reuses M1's same-code BUILDING guard and PyMem domain.
Before any callback-capable flow/metadata allocation, retain real owning,
heap-safe snapshots of the already-evaluated call inputs (including borrowed
locals) with correct move/cleanup. Merely publishing a borrowed local does not
keep its old value alive if a callback replaces that local/container. The
generic call consumes the original evaluated operands exactly once; admission
revalidation must not resample operands and change the call's semantics.
Publish inputs/BEFORE state before callbacks; afterward recheck current frame,
site, actual callable/inputs, code/exec, source, versions and observer epoch.
Feedback history alone is never permission to enter. Terminal Actions stay
ahead of old frame/exec reads; C callbacks retain their active native pin until
machine return, with exact AFTER continuation and fact invalidation.

## ABI and source boundaries

The scalar Action return and generated helper `(ctx, const DecodedOp*)` remain.
Context gains only explicit flow and pre-transfer caller/word state;
the evaluator has the sole owning flow pointer. JitState gains static-coverage,
loop-heat and cooldown fields. No `_PyInterpreterFrame` field, strong code root,
alternate executor, value representation or heap-storage mode is added.

Expected source surface: existing `pycore_jit.h`, `pycore_ir.h`,
`pycore_feedback.h` (document field use), `bytecodes.c`, `ceval.c`,
`ceval_macros.h`, `jit_runtime.c`, `jit_baseline.c`, `ir.c`, `specialize.c`,
`instrumentation.c`, `Objects/codeobject.c`, helper/IR/metadata generators and
their existing generated products, `_testinternalcapi.c`,
`test_generated_cases.py`, `test_jit_method.py`. Emitter changes are limited to
explicit transfer provenance/edge metadata if needed; keep native entry ABI
and W→RX lifetime. Root prepared `build/worktrees/jit-natural-method`, branch
`boil/jit-natural-method`, at `15987`. Only a future explicit grant permits edits
there. The M1 worktree/images and prior candidate worktrees stay frozen.

## Finite sequence and evidence

One 90-minute attempt may use two source commits: shared helpers/flow first,
natural site policy second, frozen as one coherent increment. At **30 minutes**
show stable old metadata plus new exec-only rejection/readers, meaningful
generated attribute/iteration code and real pending return/error consumers.
Report a missing transfer/helper as a scope blocker; do not claim zero EXITs or
rewrite workloads to hide it. Freeze early when coherent; no automatic extension.

Cheap host generation/classification/edge tests and allowed bounded syntax
checks precede a fresh focused behavior run under a separate grant. Extend
existing M1 fixtures with natural threshold transitions, negative-cache and
resource/observer separation, CALL target replacement, per-exec backedge heat,
exact FOR_ITER exhaustion, pending-stack limit/error/frame-reuse cleanup and
RETURN_GENERATOR. Keep descriptor/finalizer/boxing/callback ordering tests.

Then the fixed six registered programs run naturally, without test APIs
compiling a selected function. Diagnostic targets require actual entry and
post-call continuation in Richards/deltablue/container callers; generator and
coroutine bodies require explicit fallback. A wrapper below the fixed heat
threshold is a no-admission control, not claimed compiled coverage. A focused
varying caller repeatedly creates/drives the actual coroutine function at
small inputs to prove RETURN_GENERATOR and suspension return to a naturally
compiled caller. That is a semantic test, not altered scored kernel work.
Missing coverage is reported before interpreting elapsed data as compiled work.
Cold compile/cache records and release seen markers are separate from debug-only
frequency diagnostics; do not infer release frequency from boolean witnesses.
The proposed unchanged-driver 24 scored processes/120 values plus 12 diagnostic
processes remain held until separately reviewed/granted. Report every row,
whole-process/RSS and cold/warm cost; no adaptive samples or all29-per-op vote.

After this useful mixed method slice, implement one observed loop using shared
typed SSA/PHIs, effects/ownership and FrameState, then call-aware allocation and
guarded field/arithmetic lowering. M2 must not become an open-ended campaign
to polish generic helper-call overhead instead of building that optimizer.
