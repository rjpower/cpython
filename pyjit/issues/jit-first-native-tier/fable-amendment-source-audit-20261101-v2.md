# Independent source audit of Fable's second JIT review

2026-11-01. **AMEND the advice; do not adopt its reduced observer predicate.** This audits the frozen second Fable review against RC dce654018d5 source and the word-selected seven-site candidate. No JIT implementation, compiler, target or timing ran. Exact source references are in `build/jit-fable-amendment-audit-20261101-v2/source-facts.json`.

## Two reductions lack the required proof

**Skipped RESUME + tracing depth zero + code instrumentation version zero is insufficient.** `instrumentation.c:_PyMonitoring_SetLocalEvents` changes local event masks and calls `force_instrument_lock_held` without incrementing the global version. `force_instrument_lock_held` writes that unchanged global version to the code. At initial version zero, enabling local LINE events can therefore leave both versions zero. `initialize_lines` explicitly excludes RESUME from line wrapping, while later words acquire INSTRUMENTED_LINE. The entire proposed predicate can hold with an active local observer. `tstate->tracing` measures active tracing depth; zero is not an independent absence-of-hooks proof.

Startup state does initialize the version to zero through the static interpreter initializer, and fresh code sets its version to zero. That is not a promise about arbitrary site/startup hooks. Global event changes advance the version, but local event changes do not; final interpreter clearing also resets it. Thus “no monitoring has ever been enabled in the process” is false. Keep the candidate's actual global/local instrumentation, trace/profile, reentry, PEP 523 and breaker guards. A conservative fast test may reject all non-null `code->_co_monitoring` in addition to the other necessary guards; version zero alone cannot replace it. Recheck after cold work and retain explicit decline counts so a zero-admission comparison cannot masquerade as useful execution.

DTrace and lltrace are separate domains. `ceval_macros.h` gates line dispatch with `PyDTrace_LINE_ENABLED`, function notifications have their own probes, and debug `maybe_lltrace_resume_frame` reads `__lltrace__`/PYTHON_LLTRACE independently of monitoring versions. Preserve those guards and each entry path's existing notification order. Skipping RESUME is not their absence proof.

**Do not replace all four temporary NULL checks with assertions at both hooks.** Ordinary `_PyFrame_PushOverlapping`/`PushUnchecked`/`EvalFramePushAndInit` paths initialize the remaining homes, so a path proven to be a fresh ordinary call can exploit that fact. However public `PyEval_EvalFrame`/Ex pass a supplied frame to `_PyEval_EvalFrameDefault`, which jumps to `start_frame` without establishing fresh allocation/initialization. Ordinary initial IP alone is not a demonstrated freshness provenance contract. Keep checked decline on the shared entry until the patch proves a narrower supported entry gate. Keep the two explicit non-NULL argument checks before compact-int accessors, whose pointer-space path can dereference NULL. This audit does not claim a native counterexample to the temporary invariant; it rejects the missing source proof.

## Useful advice, with explicit limits

- A descriptor/sentinel lookup before code-object and observer loads is sensible. Cache structural ineligibility from immutable words; do not confuse transient argument/observer declines with a proven structural negative. All dynamic admission checks still follow the positive path. Count its actual load/branch cost on controls; the exec-header access is not free merely because another macro uses the header.
- Descriptor-time tagged-value policy is source-supported for a descriptor owned by the same interpreter/code execution lifetime. `pystate.c` has one startup assignment, while `ir.c` fixes boxing forms when creating the executing copy. Do not treat a mutable environment variable or a process-global assumption as that ownership proof; retain compile-time inline-value support and the established interpreter boundary.
- Correct the frame wording: twelve eight-byte fields plus small fields/alignment place `owned_slots` at byte **104**, thirteen words, on the supported LP64/GIL layout. `sizeof(_PyInterpreterFrame)==112` includes `owned_slots[1]`. Six homes follow from the actual slot helper; 112 is not the payload-free header. Keep helper-based sizing.
- Keep the selected **nonnegative dividend // literal 2** guard and logical shift. Arithmetic shift may be mathematically valid on x86, but widening the frozen lowering is unnecessary. No alternative region or lowering is selected by this audit.
- The emitter gaps are real: no RET helper, no 32-bit store helper, immediate arithmetic and shifts currently force REX.W, and new forms need exact encoding/overflow/exit checks. Existing 32-bit register arithmetic does not supply those missing encodings. W-to-RX ownership, checked capacities/fixups and failure cleanup remain native-entry prerequisites. `_Py_JIT` publication is presently compiled away; the already accepted bounded no-call/RSP-preserving experiment may defer profiler/unwind coverage only with that limitation explicit. No stage duration is proven.

## Exec lifetime is manageable, not automatic

`_PyCode_ClearExec` is the one normal dynamic-exec free site and is called by code deallocation. Appended descriptor fields can preserve existing field offsets, but must also preserve word alignment and the exec-before-words invariant used by `IR_NLOCALSPLUS`, `make_exec`, the static init-cleanup exec and entry trampoline. Extend allocation/initialization/sizeof accounting and static sentinel handling together. Remote frame readers use explicit `ir_words` and do not presently hardcode the exec size; retain their source offset interface.

Teardown must release installed and partially built descriptor/native owners exactly once, excluding NULL/ineligible sentinels and static execs. `_PyCode_ClearExec` runs after code names/constants are decref'd, so its cleanup must not dereference borrowed metadata that has already died. A scalar-only descriptor plus raw allocation/registration handles avoids that new Python ownership problem. A single existing free function does not prove all future builder/emitter/map failures are covered.

The seven-site home-version graph, exact-int CSE and transactional two-store commit remain useful bounded design input. The source-derived call count and final specialized handlers do not measure native-entry frequency or speed. Preserve the C-contract then native stages, focused failure/observer/ownership tests, actual varying-input entry witness, and the fixed elapsed decision. This audit grants no source patch or execution and changes no RC qualification result.
