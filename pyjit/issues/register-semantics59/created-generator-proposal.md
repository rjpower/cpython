## Initial admission

Start with exact positional Python-function calls made by a generator or
coroutine frame (`frame->owner == FRAME_OWNED_BY_GENERATOR`). Support zero
arguments and every admitted nonzero arity; do not special-case a benchmark.
Thread/interpreter callers retain the ordinary path initially. Admit exact
coroutines, then plain generators through the same constructor; exclude async
generators, method expansion, keywords, defaults, varargs/varkwargs,
cell/free-variable initialization and nonoptimized locals.

Require current function/version and standard vectorcall, exact positional
arity with zero keyword-only parameters, no defaults and no closure/cell
requirements. Pin the selected code independently of mutable `func_code`.
Constant homes must be disjoint from the actual argument prefix; their normal
shared initializer therefore cannot replace an argument owner.
The code must already have an executable with the actual admitted initial
RETURN_GENERATOR source/created-copy contract and
`_PyIR_PLAN_ALL_CREATED_EMPTY`. The whole-image flag alone is insufficient:
validate the actual initial entry and the ordinary resume-prefix handling,
not a later RETURN_GENERATOR reached after effects. Derive the post-marker PC
and first-send recipient from that checked site, not from flags or a guessed
slot. First scope accepts a bounded scratch resume recipient or `IR_NO_DST`,
which is the actual ordinary coroutine entry in the retained census. Local
or altered constructed-entry shapes fall back.

Decline PEP523, active creation observation/tracing/profiling/LLTrace/DTrace,
pending instrumentation refresh and nonzero coroutine-origin tracking before
ownership commitment. Retain the recursion-space check and the temporary
recursion decrement/increment around allocation: its GC callbacks otherwise
get a different remaining-depth budget. Free-threaded builds retain ordinary
creation. Misses before commitment preserve original inputs and execute the
existing call route. There is no post-allocation restart.

## Exact source interfaces

Use one creation provider in the existing CALL family, with role-derived forms
generated by the existing call-role machinery rather than an arity/type matrix.
Provisional base name: `CALL_PY_CREATE_EXACT_ARGS`; its NO_SELF form shares the
same provider. An already supplied self is an ordinary positional input;
there is no method expansion in this provider. Selection belongs beside
the existing exact-function specialization, after ordinary version/code
preparation. Its reached guards include the current heap-caller condition.
Ordinary exact calls acquire no new branch to test for this provider.

The actual marker exports the existing `LEARNED_ONLY` effect, including its
NO_SELF form: constructor, replace and marshal images cannot install a cached
creation entry. Its ordinary function-version and exact-arity guards precede
the provider. Version invalidation carries immutable code/default/closure and
created-entry qualification; the hit does not recheck plans or tool arrays.
Cold nomination stores the monitoring protocol's actual `uint32_t` version in
a named union view of the existing CALL binding payload, with a size assertion.
Global/local changes, tool removal and restart advance that version and refuse
overflow (`instrumentation.c:global_version`, `set_global_version`, SetEvents,
SetLocalEvents and restart). The hit compares the global version, retaining
mutable heap-caller, hook, origin and debug LLTrace gates. Cross-thread changes
therefore cannot be hidden by an old thread-local snapshot. No frame field,
payload allocation or new monitoring protocol is introduced.

Use the existing two-register `_PyCallResult` convention: miss before effects,
error, or completed call with no child. A private C provider in `ceval.c`,
`call_create_generator_exact`, owns preparation, roots,
allocation and publication. The marker/lowerer must return through the existing
call-completion endpoint, not fabricate an arena `child`, enter `_PUSH_FRAME`,
or flush an old DSL result after completion. The successful endpoint must load
the callback-current continuation after publication/cleanup, as the existing
Python return path does; blindly using the native-call endpoint's captured
fallthrough would be wrong after an accepted redirect.

The generator source contract explicitly records actual input commitment and
the reached completed-call outcome. Helper spelling or code flags grant no
normal/error home map. An opaque allocating provider remains on the existing
initialized NULL-control error path until actual receipts justify more.

Keep the common `_Py_MakeCoro` constructor body for allocation and metadata setup.
Its direct-frame entry supplies the actual caller for origin capture: allocation
can enable origin tracking after initial admission. The ordinary wrapper retains
its existing incomplete-child origin derivation. Add a
small final-frame initializer that reuses the existing `_PyFrame_Initialize`
body and constant-slot filling. If necessary, factor an owned-code inner
initializer so the snapshot code owner transfers into `f_executable`; ordinary
callers keep their current borrowed-code wrapper. Do not hand-copy a second
header layout or add a frame/exec field.

## Commitment, snapshots and roots

The selected exact path transfers evaluated inputs into an arena child before
`_Py_MakeCoro` can run GC. The direct path should commit at the same boundary,
not DUP every scratch argument while leaving a second owner in its old home.

1. Complete guards and reserve a small native PyValue buffer with an existing
   checked heap-buffer fallback for larger arities. Buffer reservation precedes
   commitment; if it can reenter, refresh and rerun the guards before taking
   any input. Allocation failure here leaves ordinary inputs for error cleanup.
2. Independently acquire the bound code once. Move the callable and each actual
   supplied scratch argument into initialized staging entries, clearing its
   source home without callbacks. CALL's argument window is materialized
   scratch storage today. A future named-local argument mode would need one
   DUP before reentry; it is not silently included here.
3. Link an existing `_PyTransitionRoots` EXTERNAL node with
   `_PyTransitionPrefix`, referring to the real caller and the initialized
   native entries. Mark the actual CALL window taken and its continuation
   state before any callback. No root-kind, bitmap or synthetic frame is added.
   The node owns function, code and all arguments; code alone is insufficient.
4. Allocate using the pinned function/code. No original argument/home pointer,
   mutable `func_code`, or unowned callable projection is consulted afterward.
   The function object may have changed code/defaults during GC: this call's
   binding is already committed. Do not select a second callee after allocation.

Arrange staging consumption so failure retires argument owners in reverse
parameter order, then function and code, matching the existing child clear
schedule. Every entry is detached from the prefix before close or transfer.
NULL entries and the zero-argument case remain fully initialized. Keep code
pinned through the final recipe/home read. Original window cells cannot double
as EXTERNAL storage unless a separate proof transfers their container-edge
authority; this proposal does not assume that or leave positive stale owners.

## Final heap frame and completion

`make_gen` currently creates a tracked object with `FRAME_CLEARED` and
`gi_iframe.f_executable == NULL`. Preserve that safe incomplete-object state
through allocation. Immediately place the returned owned object in the existing
transition result root before any further potentially reentrant operation.
Its frame may become created only after complete initialization.

With no callback between the following steps: initialize all final homes to
NULL; transfer the owned function/code into the shared header initializer;
transfer arguments into their actual parameter homes; fill actual constant
slots; and publish owner=GENERATOR, previous=NULL, phase=CREATED and
FRAME_CREATED. Use `owned_slots` as the base. Preserve the initializer's
pending/visited/frame-object/local/header policies. Advance `instr_ptr` to the
checked RETURN_GENERATOR site's successor and install that site's actual A
as the first-send recipient. Do not confuse A with the window base B, the
caller's result A, or assume `return_pc` also advances: retain the ordinary
initializer/copy path's initial continuation fields.

The initialization interval must be nonfallible/nonreentrant. If implementation
introduces a new failure point after header ownership starts, stop and peer its
partial-object cleanup instead of publishing a half-built frame. While
FRAME_CLEARED, traversal visits only the separately initialized metadata/code,
not uninitialized frame owners. After FRAME_CREATED, the real heap frame owns
its complete graph and the staging prefix is empty.

Retain current cheap metadata timing: `make_gen` reads function name/qualname
after allocation, so do not snapshot those attributes earlier. Origin tracking
and special creation hooks remain excluded. Parent function/code/argument
binding is fixed; function attributes are not all frozen by that decision.

Publish the ordinary owned object through the **existing Python return-slot
operation**, including old-local replacement/retirement and discard behavior.
The real caller's continuation/recipient is installed before allocation.
Hold the result root through redirect cleanup. Factor the existing return
writer's actual publication point to consume this existing result root: clear
its owner/present fields when ownership passes to the destination, before an
old-local close can call Python; for discard, detach before closing. Existing
unrooted callers retain their current wrapper/body. This is one root-handoff
parameter at the shared writer, not a second writer or root representation.
Do not leave a duplicate root claiming the count after transfer or add a
result DUP merely to avoid the handoff: that could delay generator finalization
inside a displaced owner's callback. If this small shared transfer cannot be
implemented without changing ordinary writer semantics, stop and peer it.

Honor pending redirects and reload the recipient/continuation after any
callback. Never reload inputs from cleared homes or retain a stale destination
pointer across a finalizer. Do not stage the result through B0 or silently
adopt native CALL's different periodic/local publication schedule merely
because the provider is written in C.

On allocation failure, leave caller input homes consumed, restore the recursion
decrement before owner-retirement callbacks, drain EXTERNAL owners exactly once,
then report the original
CALL error through existing source/error ingress. The skipped RETURN_GENERATOR
frame was incomplete; its removal must not add or remove a Python traceback
frame. Preserve the original error across cleanup reentry. On success or
failure disarm/pop roots only after their owners/authority are empty. A callback
must not turn a committed failure into a guard miss or replay this call.

## Cost and qualification

Do not claim an argument-transfer saving. Conservative staging gives
window→prefix→heap: two value moves per argument. Selected heap callers already
do window→arena→heap, also two; selected thread callers overlap and need only
one, which is why they are excluded first. Scratch-owner moves require no extra
INCREF/DECREF. Charge buffer reservation, root push/pop, code pin, source clears,
argument moves and all guards. The candidate saving is arena child reservation,
header initialization/copy/clear/pop and the RETURN_GENERATOR dispatch, not
object allocation, final NULL initialization, constant slots or argument counts.

Source closure: `bytecodes.c` CALL member/terminal marker; existing generator
call recipe, effects and completion endpoint; `specialize.c` exact-call
selection; `ceval.c` provider and existing transition roots; shared frame
initialization; `genobject.c` allocation only if a small construction helper is
needed; generated variant/admission/instrumentation mappings and focused tests.
No general transaction redesign, new root list, public encoding or backend.

Minimum checks: zero, one and large exact arities; heap and excluded thread
callers; coroutine and generator lifecycle/first send/completion/throw/close;
scratch/local/discard call results and mortal aliases; allocation failure
before/after commitment; allocation-triggered GC that mutates caller locals,
drops external function/argument owners and mutates function code/defaults;
name/qualname mutation, last-owner cleanup and traceback attribution; recursion
boundary; all public image routes and wrong/noninitial/altered RETURN_GENERATOR
or missing created proof; hooks/origin/monitoring fallbacks and observation
enabled during allocation. Use actual GC/failure hooks rather than count-only
mocks for the lifetime controls.

Root's native falsifier is the whole call→created-object path: no arena child,
RETURN_GENERATOR entry, header copy, arena clear/pop or transient child result
publication, while preserving one object allocation and complete final homes.
Count actual moves/pins/guards/spills/text and result-retirement order. A smaller
constructor alone is insufficient. Screen coroutines, generators and the full
eight-case sentinels once; reject broad losses rather than search layouts.
