## Source contract and cold certificate

Reuse `canonical_result_source`'s existing local-snapshot producer receipt
(`ir_generator.py:6821` in selected57), the generated LOCAL_DUP transfer and
their actual reached owning publication. The existing contract checks the
complete pure scalar source, local input field, DUP and canonical output;
seeing LOAD_FAST_BORROW's name alone is insufficient. No second C parser is
needed. A source change must revoke the preparation recipe or fail generation.

At the common normal-replay fixed point, before the LOAD transfer, require:

- Reached incoming state and the checked source-local/read geometry.
- Destination is a real scratch home with positive NO_HOME and no MAY_OWNER.
  This is logical vacancy, not physical NULL. The prepared final binding uses
  existing `IR_PUBLISH_CANONICAL_TEMP` (`ceval_macros.h:570`), which writes and
  checks the new value without examining the old word. It must not use
  `IR_STORE_CANONICAL_TEMP`, whose debug NULL check would require a different
  physical proof. No rejected builder/FRESH packet or new publication macro
  is needed.
- Next immutable word is an ordinary CALL-family word with the supported
  positional window protocol; decoded argc is positive and destination lies
  in `[B+2, B+2+argc)`. Source local is outside the scratch window. CALL's
  ordinary admitted input/role proof remains required, including self holes.
- The LOAD receipt has no extra effect, address escape, callback or early
  publication. The ordinary prefix poststate is exactly the CALL prestate.

This does not manufacture local boundness. Plain selected LOAD_FAST_BORROW has
an asserted nonNULL local precondition and DUP; retain that exact producer.
LOAD_FAST_CHECK and any producer with a real unbound/error path stay ordinary
initially. They are not silently changed into assertion-only loads. Their
exceptions keep the original LOAD PC. Future inclusion needs their actual
error receipt rather than a source-line equality rule.

The one-home certificate may exist while unrelated homes make the global
`complete` flag false. Consume only that positive per-home fact, never recover
global completeness or grant a frame/error map. Existing joins intersect
NO_HOME and union MAY_OWNER; a genuinely unknown predecessor cannot create the
certificate. Unknown or merely unowned bits without positive NO_HOME decline.

Use the existing common replay in `Objects/codeobject.c`, not compiler-only
liveness or a new per-pair analysis. Extend `_PyCode_BuildSemanticPlan` with an
optional executing-word output. `make_exec` copies immutable words before that
call; its existing inspection replay may nominate eligible heads into this
unpublished copy. Replay reads the immutable image throughout. Constructor,
replace and marshal validation still use the same proof with no executing
output; every resulting executable is nominated by that same common proof.
No extra persistent vector or proof pass is needed. If the fixed point cannot
prove vacancy, the valid image simply keeps its ordinary LOAD/CALL.

## Carry the proof in the existing head word

Install an execution-only `LOAD_FAST_CALL_PENDING` alias at each proved LOAD.
Its A/B/C/D bits remain exactly the original LOAD's bits. Its target table entry
is **the existing `_TAIL_CALL_LOAD_FAST_BORROW` function**, not a new wrapper or
duplicate LOAD body. Its generated logical format/base/shadow matches that
LOAD. Thus it carries a cold nomination without adding executed instructions,
a feedback bit, code-plan row or per-hit proof lookup.

When CALL quickening selects a supported exact/descriptor role, the shared
writer may replace that pending head with the corresponding prepared head.
Four active heads cover the two source consumers and their two call roles;
one pending alias makes five new IDs. IDs are allocated only on the selected57
experiment branch, not borrowed from rejected packets. Generate the bounded
head-kind/extent and successor→head selector from one `PreparedCall` declaration;
the selector is a cold four-case switch. All private IDs reject through common
constructor/replace/marshal admission using explicit execution-only provenance.

An active head's logical origin is still the LOAD word. Native effect/BOXES
facts cover prefix plus CALL, while ordinary semantic proof continues to read
the original two words. Do not export a fictitious combined single-word normal
or ERROR program. The prefix/call receipt composition must verify that the
inner CALL's generated action/error/completion receipts equal its standalone
ones. Execution introspection exposes the private head and unchanged interior
word; immutable introspection remains byte-identical.

## Generate one body from the existing producers

Factor `emit_handler`'s TARGET envelope from its instruction-body emission;
keep its two-pass role checking, bridge bounds and existing CALL lowering.
One `PreparedCall` entry selects the existing local producer, its A fresh output
binding and an existing CALL handler. It does not contain copied C or a provider
name/body matcher.

The emitted body has two lexical scopes:

1. At the LOAD PC, decode its local B and argument home A. Emit the existing
   local producer with the reached fresh/canonical binding. Acquire one owning
   snapshot and publish it into that original argument home. This removes
   generic local/sink destination classification; it removes no required count.
   The final publication selects existing `IR_PUBLISH_CANONICAL_TEMP` only after
   both the actual acquisition/canonical receipt and cold vacancy certificate;
   no old bits are loaded, asserted readable or converted to NULL.
   There is no callback between acquisition, publication and the next scope.
2. Load the following CALL word once, advance `next_instr` to its semantic
   site, and enter the **same inner CALL emitter** used by the standalone
   handler. Its prologue establishes `this_instr`, CALL attribution, feedback,
   operand decode, role state and bridge workspace normally. Preserve each
   existing guard/provider/recursion/error/completion path and final scheduling.

The ordinary LOAD's post-DUP C bits are not a second owner after publication.
No such local crosses into the CALL scope. The CALL uses its usual own
`value_temps` bound, result/current-token facts and input retirement protocol.
The generator must refuse a missing acquisition/publication receipt rather
than falling back to an unsafe fused body.

After prefix publication, all specialization misses target the interior CALL
with its original word and `this_instr`. They must never target the LOAD or
repeat acquisition. Existing `JUMP_TO_PREDICTED`/transaction fallback is reused
inside that CALL scope. Interior independent entry likewise runs the ordinary
CALL only. The first semantic error originates at LOAD if its source contract
ever has one; CALL guards/provider/error cleanup originate at CALL. Ordinary
EH and source-recovery records stay attached to those original sites, including
different handlers at the two PCs. No line/column restriction substitutes for
those actual prefix states.

## All word writers and observation

Introduce one code-and-site-aware executing-handler writer around the existing
raw handler-bit store. Before replacing a site it examines that site and the
bounded preceding sites for a pending/active head covering it (extent two here;
at most two predecessors allowed by the interface). Restore affected heads to
their immutable ordinary LOAD identity before the requested rewrite.

For ordinary CALL quickening only, carry the previously valid nomination in a
native cold boolean while doing that rewrite. If the successor is supported
and neither site is observed, reinstall its active prepared head. If unsupported
but still unobserved, reinstall the pending alias, which runs the ordinary LOAD.
Never derive a new nomination merely from adjacency after the old alias is gone.

Required writer closure in selected57:

- `Python/specialize.c:set_opcode`, including its existing FT atomic branch,
  and all specialize/unspecialize/PIC uses of that function.
- `Python/instrumentation.c:set_word_opcode`, wrapper installation/removal,
  saved-opcode restoration and whole-code instrumentation loops.
- `Python/ir.c` executable initialization/handler selection; audit direct
  `_PyIR_SetHandler`, atomic word stores, memcpy and test-CAPI writers. Initial
  unpublished-copy construction is the explicit exception, not a public bypass.
- Base/shadow/role and `_PyCode_HandlerFor` restoration maps must return the
  ordinary LOAD and original CALL. Wrapper byte-sized opcode storage sees the
  semantic base, never a truncated private ID.

First runtime scope is GIL builds, since it has no concurrently executing
writer between the two callback-free scopes. FT retains ordinary execution;
its atomic writer semantics are preserved. Enabling LINE/INSTRUCTION/profile/
trace observation at either site removes the head before any event can be
skipped. Disabling observation may retain ordinary execution for this first
packet; fresh cold admission can nominate again. There is no unchecked sticky
eligibility bit or required re-nomination on each subsequent CALL hit.

Debug can exercise the prepared ownership path with LLTrace off. With
`frame->lltrace >= 5`, the head falls back to the original LOAD **before**
acquisition, so normal dispatch produces the interior CALL diagnostic. This
debug-only guard is absent in release; it is not an epoch/geometry rescan.
Ordinary Python observation uses the writer invalidation above in both builds.
Source errors, hooks and an observer enabling itself during the later CALL use
the unchanged CALL protocols, after its complete prefix state is published.
