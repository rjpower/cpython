**Noncalling ENTERING addendum, agreed with source author and relayed to root:**
the frozen text's instruction to install a None input during ENTERING
materialization must not be implemented literally. The materializer cannot
call the callback-capable setter, including for a count1 root with a local
recipient. It leaves that recipient's existing owner unchanged. Early
C-entry failure clears root without publishing an unused None input.
Successful fallback/continuation establishes ordinary root RUNNING links and
exactly one root recursion debit, then uses the existing setter once. It must
not subsequently enter start_frame and debit again; it honors actual PC and
redirect selected by that callback. This clarifies the already approved
noncalling materializer and single-input-publication rules without narrowing
recipient coverage. Source author must retain this explicit addendum.

The first allowed increment is inert storage/constructor/optional certificate
foundation. Independent review will check complete `nloops` size/ownership/free
accounting, every actual constructor, unchanged generic primitives and absence
of activation. A foundation is not an eligible runtime packet. Later source
and generated-product review must close the full entry/yield/pop/error,
allocation/callback, observer/copy/GC and remote lifecycle before nomination.

Required proof/behavior witnesses remain those of design68, including the
